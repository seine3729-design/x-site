# 10 · 非功能需求与验证策略

> 状态：初始目标草案  
> 最后核对：2026-10-23  
> 权威范围：SLO、性能、容量、可靠性、兼容性、可观测、测试与交付证据  
> 注意：数值基于小型首发社区假设，压测后必须校准。

## 1. 质量属性优先级

1. 权限与隐私正确性；
2. 数据不丢、状态可追踪；
3. 核心反馈流程可用；
4. 移动端与无障碍可用；
5. 响应速度；
6. 运营效率与可观测性；
7. 扩展性和成本优化。

当性能与权限正确性冲突时优先正确性；不得为了缓存命中绕过项目可见性判断。

## 3. SLI/SLO

按 28 天滚动窗口，计划维护期是否排除必须在上线政策中明确。

| 用户旅程/服务 | SLI | SLO |
| --- | --- | --- |
| 公开页面可用性 | 非 5xx 且返回有效 HTML | ≥ 99.9% |
| 已登录核心 API | 非 5xx/非依赖失败（不含用户 4xx） | ≥ 99.9% |
| 创建反馈 | 成功创建或安全幂等返回 | ≥ 99.95% |
| 状态迁移 | 事务成功且历史/outbox 一致 | ≥ 99.95% |
| 私密授权正确性 | 无已知未授权读取 | 100%，发现即安全事件 |
| 站内通知新鲜度 | 业务事件至站内可见 | P95 ≤ 60 秒 |
| 未读通知计数 | 与通知列表一致（无邮件通道，站内是唯一渠道） | P95 ≤ 60 秒 |
| 附件处理 | 上传完成至 clean/rejected | P95 ≤ 2 分钟 |
| 搜索新鲜度 | 可见内容更新至可搜索 | P95 ≤ 2 分钟 |

错误预算耗尽时暂停低优先级功能发布，优先修复可靠性和安全问题。

## 4. 延迟目标

在目标区域、正常负载、缓存冷热分别观测：

| 操作 | P50 | P95 | P99 |
| --- | ---: | ---: | ---: |
| 公共列表 API | ≤ 100ms | ≤ 300ms | ≤ 800ms |
| 反馈详情 API | ≤ 120ms | ≤ 350ms | ≤ 900ms |
| 搜索 API | ≤ 200ms | ≤ 700ms | ≤ 1.5s |
| 创建反馈（不等附件处理） | ≤ 250ms | ≤ 800ms | ≤ 1.5s |
| 状态迁移 | ≤ 200ms | ≤ 600ms | ≤ 1.2s |
| 后台复杂列表 | ≤ 250ms | ≤ 800ms | ≤ 1.5s |

不通过无限数据库超时“达到成功率”。API 普通读建议 3 秒超时，写 5 秒，外部调用更短且异步化；最终按实测调整。

## 5. Web 性能预算

| 指标 | 目标（P75 移动） |
| --- | --- |
| LCP | ≤ 2.5s |
| INP | ≤ 200ms |
| CLS | ≤ 0.1，项目目标 ≤ 0.05 |
| TTFB（公开 SSR） | ≤ 800ms |
| 首页首屏 JS（br/gzip） | ≤ 120 KiB，脚手架后按构建基线锁定 |
| 普通路由新增 JS | ≤ 60 KiB |
| 首屏图片 | 响应式、明确尺寸，总传输建议 ≤ 500 KiB |

- 系统字体优先；第三方脚本延迟加载并有预算；
- 图片使用 AVIF/WebP、尺寸/比例占位和非首屏懒加载；
- 长列表按需虚拟化，但需保证 SEO、键盘和返回状态；
- 骨架保留尺寸，避免 CLS；
- CI 在技术栈确定后增加体积与 Lighthouse 预算。

## 6. 可用性与降级

### 6.1 必须持续工作的核心

- 登录会话校验；
- 读取有权限的项目/反馈；
- 创建反馈（无附件也可）；
- 状态更新、历史和审计；
- 读取站内通知。

### 6.2 可降级功能

| 故障 | 降级 |
| --- | --- |
| 缓存不可用 | 回源主库，收紧实例级限流；不跳过授权 |
| 搜索不可用 | 提供项目内基础标题查询；相似项关闭 |
| 贡献榜/相似项/统计不可用 | 关闭该模块并提示，不影响提交与分诊 |
| 图片处理不可用 | 保存无附件草稿/反馈；上传保持隔离，绝不直出 |
| 分析系统不可用 | 丢弃非关键埋点或本地短缓冲；不阻塞业务 |
| 外部 Issue 集成不可用 | 本地状态继续，显示同步失败并重试 |
| 数据库写不可用 | 明确只读模式，保留本地安全草稿 |

降级状态有指标、告警、用户可理解提示和恢复验证。

## 7. 灾备与数据保护

`[提议]` 初始目标：

- 数据库 RPO ≤ 5 分钟，RTO ≤ 60 分钟；
- 对象存储 RPO ≤ 24 小时（公开派生图可重建，私密原图需复制/版本）；
- 配置和基础设施定义进入版本控制；密钥由独立安全系统备份；
- 每日全量/增量策略按数据库能力设计，至少每季度做完整恢复演练；
- 恢复测试必须验证外键、反馈状态历史、附件引用、会话撤销和私密权限，而非只确认数据库能启动；
- 恢复环境使用隔离网络、独立对象存储桶与脱敏访问；
- 删除/注销在备份中的延迟写入隐私说明和生命周期。

## 8. 可观测性

### 8.1 三大信号

- 日志：结构化、请求/Trace 关联、脱敏；
- 指标：RED（Rate/Error/Duration）、数据库、缓存、队列、对象存储、业务 SLA；
- Trace：跨 Web/API/Worker/外部 provider，采样规则不捕获正文。

### 8.2 业务指标

- 反馈提交漏斗与失败原因；
- `submitted` 最老年龄、首次响应与分诊时长；
- 各状态停留时间和过期数；
- 重复/拒绝/上线率（不能单独作为绩效）；
- 通知、附件、搜索、外部同步延迟；
- 举报处理/申诉推翻率；
- 权限拒绝和异常导出；
- 用户删除/导出请求 SLA。

### 8.3 告警

| 告警 | 条件提议 | 级别 |
| --- | --- | --- |
| 核心 API 错误率 | 5 分钟 5xx > 2% 且请求量足够 | P1 |
| 创建反馈失败 | 5 分钟成功率 < 99% | P1 |
| 权限/缓存泄露信号 | 任何确认事件 | P0 |
| 数据库不可写 | 连续 1 分钟 | P0/P1 |
| Outbox 最老事件 | > 5 分钟 | P1 |
| 附件扫描积压 | 最老 > 10 分钟 | P2 |
| 死信 | 新增任何 critical 或 10 分钟 > 10 普通 | P1/P2 |
| 磁盘/连接池 | 持续超过安全阈值 | P2 |
| 备份失败 | 任一计划备份失败 | P1 |

告警必须可行动并链接 runbook；避免按单用户正常 4xx 报警。

## 9. 可访问性与兼容性

- 目标 WCAG 2.2 AA；
- 支持最近两个稳定版 Chrome、Edge、Firefox、Safari，以及目标用户仍占显著比例的 iOS Safari/Android Chrome；
- 支持 320px 宽度、200% 浏览器缩放、键盘-only、屏幕阅读器基本路径、减少动态、高对比需求；
- JavaScript 失败时公开内容仍可阅读，登录/表单至少显示明确恢复信息；如框架支持，核心表单渐进增强；
- 不禁用页面缩放，不依赖 hover、拖拽、颜色或精细手势；
- 正式浏览器范围根据访问数据调整，停止支持前公告并保留基础可读性。

## 10. 测试层次

### 10.1 单元测试（多数）

- 状态机、权限、可见性、贡献和邀请；
- 文本清洗、游标、幂等、错误映射；
- 前端表单 schema、状态展示、筛选序列化；
- 纯逻辑覆盖边界和性质测试。

### 10.2 集成测试（关键边界）

- 真实数据库迁移、约束、事务、并发和查询；
- 缓存失效/降级、对象存储隔离、outbox/Worker；
- OpenAPI 请求响应校验；
- 不向任何第三方发送测试数据（本项目无外部投递渠道）。

### 10.3 端到端（少而关键）

1. 邀请/注册 → 加入项目 → 提交反馈 → 收到确认；
2. 运营分诊 → 回复 → 开发状态 → 关联版本上线 → 用户通知；
3. 私密反馈在访客、普通成员、项目运营和无关管理员下的权限；
4. 合并/解除重复项；
5. 举报 → 隐藏 → 申诉复核；
6. 会话过期后草稿恢复；
7. 附件扫描成功、拒绝、超时；
8. 角色撤权立即生效。

### 10.4 安全测试

- 身份枚举、CSRF、XSS、IDOR、SSRF、上传、限流、会话固定；
- 列表/搜索/计数/导出越权；
- 缓存与 SSR 私密泄露；
- 依赖/秘密/容器扫描；
- 上线前独立评审或渗透测试。

### 10.5 性能与恢复

- 关键 API 在基线和 3 倍峰值压测；
- 慢查询/锁等待、队列积压、缓存故障演练；
- 数据库备份恢复和对象引用校验；
- 浏览器性能在真实移动网络配置下测，不只跑本机开发模式。

## 11. 测试数据

- 全部使用虚构用户、项目和内容；
- 每个自动化用例有唯一前缀并自行清理，不按宽泛通配删除共享数据；
- 任何生产备份进入测试前必须经过批准和不可逆脱敏；
- 图片 fixture 自制，覆盖正常、伪 MIME、超像素、EXIF、损坏和扫描超时；
- 私密测试内容不包含真实漏洞、账号或个人信息。

## 12. CI 质量门

技术栈确定后，每次合并至少执行：

- 格式化检查、lint、严格类型检查；
- 单元测试与相关集成测试；
- OpenAPI 校验、breaking change 检测、客户端生成物漂移检查；
- 数据库迁移 up/down 或 expand/contract 验证；
- Markdown 本地链接、文档索引与敏感信息扫描；
- 依赖漏洞、许可证、秘密和容器扫描；
- Web 构建、体积预算与关键无障碍自动检查；
- 高风险路径变更触发完整 E2E/安全套件。

禁止用 `skip`、关闭 TLS/权限或跳过 hook 来获得绿色构建，除非有批准、期限和跟踪任务。

## 13. Definition of Done

每个功能完成必须同时满足：

- 用户场景、范围内/外和异常边界已按规格实现；
- 新行为有测试，Bug 修复先看到正确失败；
- 相关单元、集成、契约、端到端验证通过；
- 页面在浏览器实际走过，不只编译；
- 接口、数据库、配置和行为文档同步；
- 权限、隐私、输入/输出、附件等安全清单通过；
- 有日志/指标/审计和可执行回滚；
- 最终回复记录实际命令、环境和结果，不用“应该可以”。

## 14. 发布验收

- 预发使用与生产同拓扑/配置校验，只有规模可缩小；
- 迁移演练、回滚/前滚方案、备份和恢复证据齐全；
- 关键 E2E、权限矩阵、Web 性能和无障碍通过；
- 健康检查连续稳定，指标与告警已接入；
- 公开条款、隐私说明、社区规则、举报/申诉可用；
- 没有未接受的高危/中危安全问题；
- 灰度发布并观察错误预算；回滚不会破坏已写新数据。

## 15. 已定与待确认

已定（2026-10-23）：界面语言只有简体中文；只有响应式 Web 与运营后台；通知只有站内渠道；无邮件/第三方集成依赖，因此不需要外部 provider 的可用性目标。

待确认：容量规模、用户地区与部署区域、浏览器支持范围、SLO 与 RPO/RTO 的正式承诺、运维响应时间与预算。当前数值用于架构与任务估算，不是对外 SLA。
