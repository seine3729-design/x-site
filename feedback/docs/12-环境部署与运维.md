## 1. 环境

| 环境 | 用途 | 数据 | 外部副作用 |
| --- | --- | --- | --- |
| `development` | 本地开发与调试 | 自动生成虚构 seed，可重置 | 无（没有邮件/集成，副作用只有对象存储与数据库） |
| `test` | 自动化测试 | 每个用例隔离并自行清理 | 禁止公网调用；集成测试用 testcontainers |
| `staging` | 预发验收、迁移与恢复演练 | 虚构或不可逆脱敏数据 | 与生产隔离的桶与数据库 |
| `production` | 正式流量 | 真实数据、最小权限 | 严格审批与审计 |

每个环境的数据库、对象存储桶、Valkey 命名空间、Cookie 域和密钥完全隔离。生产密钥不得出现在本地或 CI 日志。本项目没有邮件/短信/第三方集成，因此不存在“误发给真实用户”的外部投递风险。

## 2. 部署单元

```text
edge / load balancer
└─ web            Next.js 16（(site) 与 (admin) 两个路由组，同一部署）

private network
├─ api            Go 1.27.3 cmd/api，无状态，1–2 实例
├─ worker         Go 1.27.3 cmd/worker（River：critical/files/notifications/search/maintenance）
├─ postgres       PostgreSQL 18 主库（业务 + River 队列）
├─ valkey         可选，限流与热点读
├─ object storage 隔离 / 私密派生 / 公开派生 三桶
└─ otel collector 日志、指标、链路
```

PostgreSQL、Valkey、对象存储管理端与健康详情不暴露公网。后台与用户端同一个 Next.js 部署，通过路由组和中间件隔离；是否再加独立域名或零信任入口由 `X5-1` 决定。

## 3. 配置清单

配置通过环境变量或平台 Secret 注入；仓库只保存 `.env.example`，值为非秘密示例。Go 侧用 caarlos0/env 在启动时强校验必填、格式与生产禁用项。

### 3.1 通用

| 变量 | 作用域 | 是否秘密 |
| --- | --- | --- |
| `APP_ENV` | 全部 | 否 |
| `APP_VERSION` | 全部 | 否 |
| `LOG_LEVEL` / `LOG_FORMAT` | api / worker | 否 |
| `OTEL_SERVICE_NAME` / `OTEL_EXPORTER_OTLP_ENDPOINT` / `OTEL_SDK_DISABLED` | api / worker | 否 |
| `TRUSTED_PROXIES` | api | 否（敏感配置） |

### 3.2 Go 服务

| 变量 | 作用 | 是否秘密 |
| --- | --- | --- |
| `HTTP_ADDR` | API 监听地址，默认 `:8080` | 否 |
| `DATABASE_URL` | PostgreSQL 读写连接 | 是 |
| `DATABASE_RO_URL` | 可选只读连接 | 是 |
| `DATABASE_MAX_CONNS` | 每实例连接上限 | 否 |
| `AUTO_MIGRATE` | 开发环境启动时跑 goose；production 禁止开启 | 否 |
| `VALKEY_URL` | 可选缓存与限流 | 是 |
| `WORKER_QUEUES` | Worker 消费的队列与并发，如 `critical=2,files=2,notifications=4,search=2,maintenance=1` | 否 |
| `JOB_MAX_ATTEMPTS` | 默认重试上限 | 否 |
| `SESSION_SECRET_KEYS` | 会话签名/加密密钥轮换集 | 是 |
| `CSRF_SECRET` | CSRF 机制密钥 | 是 |
| `ARGON2_PARAMS` | Argon2id 内存/时间/并行度，可随硬件升级 | 否 |
| `WEB_ORIGINS` | 用户端允许来源（Origin 校验） | 否 |
| `ADMIN_ORIGINS` | 后台允许来源；`/api/admin` 写请求必须命中 | 否 |
| `SERVICE_TOKEN` | Next.js 服务端访问 API 的服务身份 | 是 |
| `INVITE_TOKEN_TTL` | 邀请码默认有效期 | 否 |
| `REAUTH_TTL` | 后台高敏操作的近期认证时限 | 否 |
| `ENVELOPE_KEY_URI` | 敏感字段信封加密 KEK（如 TOTP 种子） | 是/引用 |
| `EGRESS_ALLOW_PRIVATE` | 是否允许出站访问内网；development 允许，production 不允许开启 | 否 |

### 3.3 对象存储与附件

| 变量 | 作用 | 是否秘密 |
| --- | --- | --- |
| `S3_ENDPOINT` / `S3_PUBLIC_ENDPOINT` / `S3_REGION` / `S3_FORCE_PATH_STYLE` | S3 兼容配置 | 否 |
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | 凭据，按桶最小权限 | 是 |
| `S3_BUCKET_QUARANTINE` | 原始隔离文件（只有 worker 可读） | 否 |
| `S3_BUCKET_PRIVATE` | 私密派生文件 | 否 |
| `S3_BUCKET_PUBLIC` | 公开内容哈希派生图 | 否 |
| `UPLOAD_MAX_BYTES` / `UPLOAD_MAX_PIXELS` / `UPLOAD_MAX_PER_FEEDBACK` | 附件限制 | 否 |
| `UPLOAD_SCAN_TIMEOUT` | 扫描时限，超时视为未通过 | 否 |

### 3.4 Next.js 前端

| 变量 | 作用 | 是否秘密 |
| --- | --- | --- |
| `NEXT_PUBLIC_APP_ENV` | 环境标识（会进客户端） | 否 |
| `NEXT_PUBLIC_SITE_URL` | 用户站规范 URL | 否 |
| `API_INTERNAL_URL` | 服务端访问 Go API 的内网地址 | 否 |
| `API_SERVICE_TOKEN` | 服务令牌，**只在服务端运行时** | 是 |
| `SESSION_COOKIE_DOMAIN` | Cookie 域策略 | 否 |
| `ADMIN_BASE_PATH` | 后台路由前缀（默认 `/admin`） | 否 |

只有 `NEXT_PUBLIC_*` 会进客户端 bundle。任何令牌、数据库或对象存储凭据都不得使用 `NEXT_PUBLIC_` 前缀。

### 3.5 生产启动必须拒绝的配置

默认或空密钥、`AUTO_MIGRATE=true`、HTTP 明文公网 URL、通配 CORS/Origin、`EGRESS_ALLOW_PRIVATE=true`、调试模式、匿名可读的对象存储桶、过宽的 `TRUSTED_PROXIES`。

## 4. 本地开发

`X0-2` 必须提供一条根命令启动下列服务，并把实际命令回填到本节：

| 服务 | 镜像/运行方式 | 说明 |
| --- | --- | --- |
| postgres | `postgres:18.x` + `pg_bigm` | 库与账号由 compose 初始化；中文检索扩展随镜像构建 |
| seaweedfs | S3 兼容 | 自动创建隔离/私密/公开三个桶 |
| valkey | `valkey/valkey:9.x` | 可选；关闭时服务降级为实例内限流 |
| api | `golang:1.27.3` + air | 源码挂载，保存即重编译 |
| worker | 同上 | River 消费，`files` 队列并发 1 |
| web | `oven/bun:1.4.x` | `bun install --frozen-lockfile && bun run dev` |
| otel（可选） | Jaeger 或等价 | `--obs` 时启动 |

要求：

- 首次从 `.env.example` 生成 `.env.local`，`change-me` 自动替换为随机值，文件权限受限且已被忽略；
- 重复启动幂等，不覆盖已有秘密；
- 端口只绑定 `127.0.0.1`，且与工作区根目录的栈不冲突（需在 `X0-2` 选定一组独立端口）；
- 提供等价能力：`up / down / logs / restart / psql / migrate / sqlc / seed / test / doctor / reset`；
- `reset` 删除数据卷前要求显式确认；
- seed 只有虚构数据：一个平台管理员、两个项目、若干成员与反馈，不含真实个人信息或参考站内容；
- 没有真实病毒扫描服务时使用确定性模拟器，**不得把未扫描附件标记为 clean**；
- 首个平台管理员只能用 `cmd/admintool` 创建，密码从标准输入读取。

当前 `feedback/` 下只有文档，**没有可运行的启动命令**；本文不声称任何服务已验证。

## 5. 健康检查

| 端点 | 语义 | 响应 |
| --- | --- | --- |
| `/health/live` | 进程存活 | 快速 200，不访问依赖 |
| `/health/ready` | 可接流量 | PostgreSQL 可用、迁移版本兼容；Valkey 不可用时按降级规则仍可 ready |

公开响应只给状态与版本摘要，不泄露连接串、依赖版本或堆栈。详细依赖状态只在私有监控暴露。

## 6. 数据库迁移

- 使用 goose，目录 `service/db/migrations`，每个迁移必须有 `-- +goose Down` 或在不可逆时写明前滚方案；
- 生产由独立 migration 步骤执行，应用进程不自动抢跑（`AUTO_MIGRATE` 在 production 禁用）；
- 每个迁移在空库与上一个生产 schema 上都测试；
- 大表变更评估锁、回填批次、磁盘与取消行为；
- 不可逆变更按 expand → backfill → switch → contract 分四步跨发布完成；
- 迁移失败立即停止发布，不让部分实例写入不兼容数据；
- River 自身的迁移随 `cmd/worker` 启动或独立步骤执行，与业务迁移分开记录。

发布顺序：备份检查 → 部署兼容旧 schema 的版本（需要时）→ 扩展迁移 → 灰度新版本 → 回填与校验 → 切换读写 → 观察一个周期 → 后续发布收紧约束。

## 7. 构建与发布

- `go.sum` 与 `bun.lock` 冻结安装；CI 构建一次，环境间晋级同一签名产物；
- Go 产物为 distroless 单二进制（`cmd/api`、`cmd/worker`）；Next.js 产出 `standalone`；
- **运行时选择**：`X0-1` 实测 Bun 是否能稳定运行 Next.js standalone；不通过则生产用 Node.js 官方镜像，工具链仍用 Bun，结论回写本节；
- 产物附版本、SBOM、依赖清单与迁移范围，不包含任何 `.env`；
- 使用短期 OIDC/工作负载身份访问发布系统；
- 生产发布需变更摘要、负责人、风险、迁移、监控与回滚方案；
- 先小流量灰度再放量，每阶段检查错误率、创建反馈成功率、授权拒绝异常、数据库、队列与 Web 指标。

## 8. 回滚

### 8.1 应用

保留至少两个已签名稳定版本，可一键切回。新版本写入的数据必须能被旧版本读取；否则用功能开关或兼容部署代替直接回滚。Worker 与 API 的事件版本保持兼容，回滚不得产生无限死信。

### 8.2 数据

优先前滚修复。只有在已验证且无新数据丢失时才执行 `goose down`。数据损坏时恢复到隔离实例比对后定向修复，不直接覆盖生产。每次回滚记录原因、影响、操作者、验证与后续任务。

### 8.3 功能开关

可关闭：相似项建议、贡献榜、议题回答、批量导出、看板重计算。不得用开关绕过授权、审计、输入清洗或附件扫描。

## 9. 备份与恢复

- PostgreSQL 连续归档/增量 + 定期全量，目标 RPO/RTO 见 `10`；
- 备份加密，访问身份与生产数据库管理员分离；
- 对象存储开启版本与生命周期；私密原图按业务价值复制；
- 配置与 IaC 版本化；密钥恢复由密钥系统独立流程管理；
- 至少每季度恢复到隔离环境并校验：用户/项目/成员、反馈状态历史、重复关系、贡献可重算、附件引用、私密权限、River 队列位置；
- 恢复环境禁用对外副作用并使用脱敏访问；
- 记录恢复开始/完成、数据点、差异与实际 RPO/RTO。

## 10. 监控与告警

仪表盘最少包含：各组件版本与实例、RPS/5xx/延迟/饱和度、PostgreSQL 连接与慢查询与备份、Valkey 命中与错误、River 队列最老任务年龄与死信、附件处理时长与拒绝率、登录异常与权限拒绝、后台高敏操作与导出、反馈创建/分诊/状态老化、站内通知延迟、Core Web Vitals。

每个 P0/P1 告警必须链接 `runbooks/` 中的文档。

## 11. 日常运维

| 周期 | 动作 |
| --- | --- |
| 每日 | 备份结果、死信、磁盘、证书、P1 告警、状态老化 |
| 每周 | `govulncheck` 与 `bun audit` 报告、异常权限/导出、存储增长、慢查询、反滥用误伤 |
| 每月 | 密钥与管理员审查、项目所有者核对、成本、SLO/错误预算、恢复抽查 |
| 每季度 | 完整恢复演练、安全事件演练、权限复核、依赖大版本评估（Go / Next.js / Bun / PostgreSQL） |

自动清理任务失败必须告警，不把“配置了生命周期”当作已经执行。

## 12. 首批 Runbook

1. API 5xx 或延迟升高；
2. PostgreSQL 不可写或连接耗尽；
3. River 队列积压与死信；
4. 附件扫描失败或恶意文件事件；
5. 私密内容缓存或权限泄露；
6. 会话或邀请码疑似泄露（恢复码已不存在，见 `adr/0011`）；
7. 对象存储不可用；
8. 发布回滚与迁移失败；
9. 备份恢复；
10. 紧急全站只读/冻结写。

模板见 [`runbooks/TEMPLATE.md`](./runbooks/TEMPLATE.md)。

## 13. 生产访问

- 使用个人身份，不共享账号；管理访问 MFA、最小权限、短时提升与审计；
- 普通运营不直接连库；紧急数据库访问需审批并告警；
- 导出生产数据默认禁止，必要时脱敏、限时、记录用途；
- 离职或角色变化即时撤权并轮换共享风险凭据。
