# 07 · 运营后台与内容治理

> 状态：草案  
> 最后核对：2026-10-23  
> 权威范围：后台页面、角色权限、分诊、审核、批量操作与审计要求

## 1. 后台目标

运营后台必须让团队完成真实闭环，而不是只有后端接口：

- 看见待处理、即将超时和阻塞中的反馈；
- 在一个工作区完成上下文阅读、分诊、回复、状态与分派；
- 管理项目动态、测试议题、发布版本和成员邀请；
- 处理举报、隐私泄露、封禁与申诉；
- 查看每个高风险动作的操作者、原因、时间和结果；
- 能预览批量操作影响并撤销可逆动作。

## 2. 后台角色

| 角色 | 作用域 | 主要能力 |
| --- | --- | --- |
| 项目运营 `project_operator` | 单/多个项目 | 动态、议题、分诊、公开回复、标签、邀请 |
| 项目维护者 `project_maintainer` | 单/多个项目 | 负责人、研发状态、发布版本、内部备注 |
| 项目所有者 `project_owner` | 项目 | 前两者 + 成员/项目设置、所有权转移 |
| 版主 `moderator` | 全站或授权项目 | 举报、隐藏、限制、申诉初审 |
| 平台管理员 `platform_admin` | 平台 | 项目、角色、全局配置、管理员与审计 |
| 安全审计员 `security_auditor` | 只读 | 安全事件和脱敏审计，不做业务修改 |

角色可由权限点组合，但首期提供固定模板。项目角色与平台角色分开，不能通过前端菜单隐藏代替服务端授权。

## 3. 权限点

命名采用 `resource.action`：

```text
overview.view
projects.view / projects.create / projects.edit / projects.archive
members.view / members.invite / members.edit / members.remove
feedback.view / feedback.view_private / feedback.triage
feedback.assign / feedback.transition / feedback.merge / feedback.export
posts.view / posts.create / posts.publish / posts.archive
topics.view / topics.manage
releases.view / releases.manage
reports.view / reports.resolve
appeals.view / appeals.resolve
users.view / users.restrict / users.suspend
invitations.view / invitations.manage
contributions.view / contributions.adjust
roles.view / roles.manage
audit.view
settings.view / settings.manage
```

导出、私密反馈、角色管理、永久封禁、贡献手调和全局设置属于高敏操作，要求重新认证、填写原因并审计。

- 一级与二级菜单都使用一致 SVG 图标；菜单名完整显示，不依赖省略号；

- 项目作用域用户在顶部看到项目切换器；全局页面清楚退出项目上下文；
- 层级数据用可展开树或缩进列表，不用难以扫描的权限矩阵卡片。

## 5. 概览

### 5.1 项目运营概览

- 待分诊数量与最老等待时长；
- 即将超过首次响应目标的反馈；
- `planned / in_progress / verifying` 中超过更新期限的反馈；
- 最近 7/30 天提交、确认、上线、关闭数量；
- 类型、状态、版本分布；
- 最新举报和附件处理失败；
- 快捷动作：发布测试任务、创建议题、创建版本。

数字必须链接到对应已筛选列表。图表提供表格替代、单位、时间范围和数据口径，不用红/绿颜色单独表达好坏。

### 5.2 平台概览

项目健康、活跃成员、异常登录、队列积压、存储增长、审核 SLA、失败任务。平台指标不得默认展示私密反馈标题或正文。

## 6. 反馈队列

### 6.1 默认视图

列表列：复选框、编号、标题、类型、状态、优先级、项目、作者、负责人、投票、评论、最后活动、等待时长。

- 默认“待分诊优先 + 最旧提交在前”；
- 筛选写入 URL：项目、类型、状态、优先级、标签、负责人、可见性、时间范围；
- 支持保存个人视图，平台级共享视图需管理权限；
- 列表更新后保持选中和滚动；资源版本变化时提示刷新，不静默覆盖。

### 6.2 反馈工作区

桌面采用双栏或详情页：

- 左/主栏：正文、上下文、附件、补充、公开评论、状态时间线；
- 右栏：状态、负责人、协作者、优先级、严重度、类型、标签、版本、可见性；
- 独立 Tab：内部备注、审计/修改记录、相似反馈；
- 固定回复区可在“公开回复/内部备注”间切换，使用明显背景和二次确认防发错；
- 所有保存显示进行中、成功、失败和冲突，失败不丢输入。

### 6.3 分诊动作

完成分诊至少检查：

1. 反馈类型与项目；
2. 可见性及是否含隐私/漏洞；
3. 是否重复；
4. 严重度与优先级；
5. 负责人/下一状态；
6. 是否需要向作者追问信息；
7. 给出公开确认或原因。

系统允许保存部分分诊草稿，但只有满足条件才能从 `submitted` 进入 `triaged`。

### 6.4 批量操作

允许：设置负责人、标签、优先级、关注提醒、导出脱敏摘要。状态批量变更只允许低风险且每项独立校验。

要求：

- 执行前显示受影响条数、不可执行条数和原因；
- 默认只对当前显式选中项，不把“本页全选”暗中扩成全部结果；
- 大批量转异步任务，显示进度、逐项结果和可重试失败；
- 导出文件短期有效、加水印/操作者信息、字段按权限脱敏；
- 可逆动作提供有限时撤销；不可逆动作要求重新认证和原因。

## 7. 重复项合并界面

- 搜索主反馈并显示编号、标题、状态、可见性和项目；
- 只能选同项目且可见性兼容的反馈；
- 对比两条正文和上下文，不自动展开私密附件；
- 预览将迁移的关注者、标签和关系；
- 明确评论默认不移动；
- 确认按钮写明“将 X 标记为 Y 的重复项”；
- 合并后显示解除入口（有权限且未发生不兼容后续操作时）。

## 8. 项目、成员与邀请

### 8.1 项目

**只有平台管理员能创建项目**（`adr/0001`）。项目运营、项目所有者和普通用户都看不到「新建项目」入口，直接请求创建接口也会被服务端拒绝。创建时必须指定首位项目所有者。

列表支持状态、可见性、加入模式和健康筛选。创建/编辑表单分为：基本资料、访问方式、反馈设置、通知与危险区。

- Slug、反馈前缀修改影响外链，需预览和二次确认；
- 暂停/归档需原因和用户可见说明；
- 删除不作为普通动作，只有无业务数据的草稿项目可物理删除；
- 项目配置变更写审计并使相关缓存失效。

### 8.2 成员

使用可展开列表展示成员与角色，不用“用户 × 权限”巨型矩阵。支持邀请、改角色、移除、转移所有权。

- 不能移除/降级最后一名所有者；
- 不能授予操作者自己没有的角色；
- 权限变更即时使服务端授权生效；
- 已移除成员对成员内容和私密反馈的访问立即失效。

### 8.3 邀请

创建时设置项目、角色、到期、最大次数和备注。明文 token 只显示一次，随后仅显示前缀/末尾、使用次数和状态。支持撤销，不支持查看完整 token。

## 9. 内容管理

### 9.1 动态

- 草稿、预览、发布、定时发布、隐藏、归档；
- 类型决定结构化辅助字段，正文使用受限 Markdown；
- 置顶显示剩余时间和项目内已占名额；
- 发布后编辑显示差异与修改摘要；
- 上线小结可选择版本并关联反馈，发布前检查私密项不会被公开引用。

### 9.2 议题

创建流程：题型 → 问题/选项 → 受众与结果可见时间 → 排期 → 预览。开放后不能改题型或增删选项；结束后只归档，不删除回答。

### 9.3 发布版本

版本列表显示关联反馈数与发布状态。发布前预览将进入 `shipped` 的反馈，逐项校验；部分失败可重试，不能把整批伪装成成功。

### 9.4 标签

项目内标签用树/列表管理，显示名称、语义、使用数和归档状态。颜色从设计 token 选择且必须有文字；归档不删除历史关联。

## 10. 治理后台

### 10.1 举报队列

列：风险级别、目标摘要、原因、项目、举报数、首次/最后举报时间、当前可见性、处理人。紧急隐私/安全项置顶但不展示敏感全文。

处理动作：不成立、隐藏、删除派生附件、警告、限时禁言/限制、永久封禁升级、转安全团队。每个动作要求规则、公开原因、内部证据和期限。

### 10.2 申诉

原处理人可补充材料但不能独立终审。复核页面展示原规则、证据摘要、用户说明与时间线；决定为维持、修改或撤销，并通知申诉人。

### 10.3 用户

显示账号状态、项目关系、近期治理事件和会话安全摘要。默认不显示邮箱等敏感字段；无“查看密码”或直接设置用户密码功能。封禁/恢复、强制下线和资料隐藏均需原因与审计。

## 11. 角色权限

按菜单树展示权限：目录/页面可展开，查看/创建/编辑/高敏动作三态勾选；支持搜索、展开/折叠全部和全选可见范围。

规则：

- 父级勾选只影响当前可见且操作者可授予的子项；
- 高敏权限单独分组并显示风险说明；
- 保存前显示新增/移除差异；
- 未保存离开时提醒；
- 不能编辑系统保底规则、自己的最后管理权限或最后一名管理员；
- 权限在服务端立即生效，菜单缓存不得延迟授权撤销。

## 12. 表单与控件规范

- 每个输入、密码、文本域、下拉和搜索框都有中文 placeholder，同时保留可见 Label；
- 同一表单的输入、下拉、日期和组合框等宽等高；
- 必填字段、帮助说明和错误位置统一；
- 复杂选项渐进展开，不在一屏放完所有配置；
- 只读与禁用视觉/语义不同，禁用时解释原因；
- 危险动作与普通保存空间分离，使用明确中文动词；
- 弹窗有标题、影响范围、取消和确认，关闭后焦点返回触发控件；
- 选择资源时支持按名称和编号搜索，并明确无查看权限的原因。

## 13. 表格与列表规范

- 表头可排序时设置排序状态，键盘可操作；
- 空状态、过滤无结果、错误和加载骨架分别设计；
- 分页总数/游标语义与 API 一致，不在前端猜页数；
- 状态、角色、标签不依赖颜色；
- 长标题优先换行，ID/时间列使用等宽数字；
- 移动端后台只保证应急处理，复杂表格转成信息卡或显式滚动；
- 导出字段、时间范围、脱敏级别和生成时间可见。

## 14. 审计与高敏操作

必须审计：登录安全事件、项目/成员/角色、可见性、反馈状态/合并、动态发布、版本上线、治理、贡献调整、邀请、导出、系统设置。

审计页支持按操作者、动作、资源、项目、时间和请求编号筛选；差异先脱敏。高敏操作要求近期重新认证，弹窗显示影响、不可逆性和回滚方式。

## 15. 后台验收场景

1. 项目运营只看到所属项目，直接输入其他项目 URL/API 仍被拒绝且不泄露数据。
2. 分诊员在同一页面完成类型、重复、优先级、负责人、公开回复和 `triaged`，作者收到一条聚合通知。
3. 私密反馈不出现在无 `feedback.view_private` 权限角色的列表、搜索、计数和导出中。
4. 合并前能预览影响，跨项目/可见性冲突被阻止，解除合并可恢复。
5. 发布版本批量上线时逐项反馈结果，失败项可重试，已成功项不重复发贡献分。
6. 角色权限按树编辑，不能移除最后管理员或授予越级权限，撤权立即生效。
7. 举报处理和申诉由不同人员复核，全部动作可按请求编号追踪。
8. 每个表单控件有中文 placeholder，输入与下拉等宽等高，键盘可完成。
9. 关键列表在空、错误、加载、无权和冲突下均有可恢复界面。

## 16. 待确认

- 后台与用户端同工程还是独立应用/域名；
- 项目运营能否查看私密反馈，版主是否默认可见；
- 优先级是否对用户公开；
- 成员自由讨论内容由谁审核；
- 首期是否需要贡献管理、分析看板和外部导出；
- 管理员二次认证采用 TOTP、Passkey 或组织身份提供商。
