# 09 · 安全、隐私与滥用防护

> 状态：安全基线草案  
> 最后核对：2026-10-23  
> 权威范围：威胁模型、身份、输入、附件、权限、隐私、滥用和安全验收

## 1. 安全目标

1. 私密反馈、内部备注、成员内容和个人信息不被跨项目或匿名访问；
2. 攻击者不能通过评论、Markdown、附件、链接或导出执行代码或窃取会话；
3. 会话、邀请、重置凭据和外部集成密钥不可从数据库明文或前端产物恢复；
4. 运营高敏动作可追责、可撤销或有明确补救；
5. 反滥用不以过度采集设备指纹、精确位置和永久 IP 历史为代价；
6. 发生依赖故障或攻击时优先保护数据与权限，允许功能降级。

## 2. 资产与信任边界

### 2.1 关键资产

- 账号凭据、会话、邀请和恢复凭据；
- 私密反馈、原始附件、内部备注与安全漏洞信息；
- 项目成员关系、权限和未发布动态/版本；
- 审计记录、贡献账与治理证据；
- 数据库、对象存储、Valkey 凭据，会话与 CSRF 密钥，服务令牌；
- 数据导出和短期下载 URL。

### 2.2 不可信输入

浏览器请求、URL、Header、Cookie、Markdown、评论、搜索词、图片、文件名、EXIF、项目配置、Webhook URL/回调、第三方响应、队列 payload、日志字段均视为不可信。

### 2.3 信任边界

```text
Internet → Edge/WAF → Web/API → Database
                         ├────→ Object Storage quarantine
                         ├────→ Worker sandbox
                         └────→ External providers
Admin network/identity → Admin UI → Admin API → privileged use cases
```

通过边界时重新校验身份、权限、格式、大小、协议与目标地址；不能因“来自 Worker/后台”就省略业务约束。

## 3. 主要威胁

| 威胁 | 场景 | 核心控制 |
| --- | --- | --- |
| IDOR/越权 | 改 URL 读取其他项目私密反馈或导出 | 项目作用域服务端授权、不可猜 ID、越权测试 |
| XSS | Markdown、文件名、搜索高亮、外链注入脚本 | 原始 HTML 禁用、白名单清洗、编码、CSP |
| CSRF | 利用登录 Cookie 发状态变更/封禁请求 | SameSite、Origin、CSRF token、重新认证 |
| SQL/查询注入 | 搜索、排序、筛选字段拼接 | 参数化 SQL、字段白名单、查询成本限制 |
| SSRF | Webhook/头像/外部集成 URL 访问内网 | 仅 HTTPS、DNS/IP 校验、阻断保留地址、禁绕过重定向 |
| 恶意文件 | 伪装图片、解码漏洞、压缩炸弹、EXIF 泄露 | 隔离、头部/解码检查、沙箱重编码、像素/资源限制 |
| 撞库/枚举 | 登录、注册、邀请、账号恢复探测账号 | 统一响应、相近耗时、分层限流、风险挑战 |
| 垃圾/骚扰 | 批量反馈、评论、举报滥用 | 账号/项目/IP 风险桶、冷却、审核、申诉 |
| 刷票/刷贡献 | 多账号、自投、反复状态切换 | 唯一约束、事件幂等、异常检测、只追加冲销 |
| 缓存泄露 | 私密响应被 CDN/SSR 缓存 | `private, no-store`、路由缓存白名单、缓存测试 |
| 供应链 | 依赖投毒、构建密钥泄露 | 锁版本、冷却期、SBOM、签名、最小 CI 权限 |
| 内部滥用 | 管理员浏览私密内容或批量导出 | 最小权限、重认证、原因、审计、告警 |

## 4. 身份与账号

### 4.1 登录方式

已采纳（`adr/0007` + `adr/0011`）：**用户名 + 密码，邀请码注册，不收集邮箱与手机号，
且没有任何账号找回途径。**

- 密码使用 Argon2id，参数入库可升级；最小长度 12，允许粘贴、密码管理器和自动填充，不设置无意义的字符组合规则；
- 登录成功轮换会话；改密、重置、封禁、强制下线都递增 `session_version`；
- 错误不区分“账号不存在”和“密码错误”，响应耗时相近；
- 连续失败触发渐进延迟与人机挑战，不用可被攻击者滥用的永久账号锁；
- **没有找回凭据**（`adr/0011`，2026-10-25）：不发恢复码、不发邮件短信、不存任何可用于
  重置密码的凭据。库里 `fb_user.recovery_code_hash` 恒为空串，已标注废弃；
- **唯一的改密路径**是 `POST /api/v1/feedback/me/password`，必须提供正确的当前密码。
  没有 `/auth/recover`，没有 `/me/recovery-code`；
- **管理员不能重置用户密码**，只能停用账号或重新发放邀请，全部审计。
  这一点现在更强了：后台连「代为重置」的接口都不存在，不是靠权限控制住的，而是没有实现；
- 安全上的取舍要写清楚：这消掉了「找回流程被滥用导致账号接管」这一整类风险
  （本来也没有可核验身份的手段），代价是忘记密码的用户永久失去账号，这是已确认的产品决定；
- 管理员自身强制 MFA（优先 Passkey/WebAuthn，TOTP 备选），其备份码只显示一次且哈希存储。

界面必须明确告知：**密码是进入账号的唯一凭据，忘记后账号不可恢复**。
注册页用一条静态提示承担这个告知义务（不是必须勾选的确认框 —— 用户要求去掉勾选，
但告知本身不能省：后果不可逆的事情藏起来是坑人）。

因为没有邮箱，也不存在「发送重置链接」这一路径，实现时不要引入；
同样不要为了「方便」加回恢复码或后台重置 —— 那需要先改 `adr/0011`。

### 4.2 会话

- Cookie：`Secure`、`HttpOnly`、`SameSite=Lax/Strict`、宿主限定、最小 Path；
- 服务端只存令牌哈希；空闲和绝对过期分开；
- 用户可查看并撤销设备会话；安全变更立即使旧会话失效；
- 管理员会话更短，高敏动作要求最近认证；
- 不把会话、CSRF、邀请或恢复 token 写日志、URL 或分析事件；
- 退出登录和撤销幂等。

### 4.3 邀请

使用至少 128 bit 随机 token，明文只在创建时显示。限制用途、项目、角色、次数和期限；核销原子；邀请链接不得自动执行加入，登录后仍显示确认项目和角色。

## 5. 授权与项目隔离

- 默认拒绝，新接口必须显式声明公开或需要的动作；
- 项目资源查询必须带 `project_id` 作用域；
- 详情、列表、搜索、计数、通知、导出、附件和批量任务使用同一授权策略；
- 用户端 DTO 不包含内部备注字段，即使值为空也不复用后台 schema；
- 平台管理员读取私密内容需支持工单/原因/审计，不默认无限浏览；
- 权限变更即时生效，缓存键包含成员版本并可主动失效；
- 后台菜单是体验层，不是安全边界；
- 自动测试覆盖横向（同角色跨项目）与纵向（低角色高权限）越权。

## 6. Web 安全

### 6.1 CSRF 与跨源

- Cookie 写请求验证 Origin + CSRF；
- CORS 使用明确来源白名单，不回显任意 Origin，不与凭据通配；
- GET/HEAD 无副作用；预取不能触发退出、加入、投票或状态变化；
- 高敏操作不能只靠 CSRF token，还要求重新认证。

### 6.2 XSS 与内容安全策略

- 用户内容保存原始 Markdown/纯文本，由服务端可信清洗器生成呈现；
- 禁止原始 HTML、`javascript:`、事件属性、SVG、iframe 和自动外部媒体；
- 搜索高亮和提及使用结构化节点，不拼字符串 HTML；
- CSP 以 nonce/hash 为主，生产不使用 `unsafe-inline`/`unsafe-eval`；
- 设置 `frame-ancestors`、`object-src 'none'`、`base-uri 'none'` 等；
- 外链使用 `noopener noreferrer`，用户确认后离站；
- 错误页和 404 也执行同样 CSP。

### 6.3 安全头

至少：HSTS（生产验证后）、`X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`、合理 Permissions-Policy、CSP、禁止后台被嵌入。

## 7. 输入、数据库与资源消耗

- 所有输入校验长度、数组数量、枚举、数字范围、Unicode 控制字符和嵌套深度；
- SQL 全参数化，排序/字段名白名单；
- 限制搜索词、正则能力和查询时间，不把用户输入交给危险正则/模板；
- 请求体、解压后体积、并发、响应大小和导出行数有限制；
- GraphQL 若未来采用必须做深度/成本限制；首期 REST；
- 批量操作异步、逐项授权，不允许一次请求锁住全表；
- 反序列化不允许任意类型/类实例化。

## 8. 文件与对象存储

### 8.1 上传

- MVP 只允许 JPEG/PNG/WebP；扩展名不作为类型依据；
- 限制单文件、总文件、像素、帧数、解码内存和处理时间；
- 原始文件进入隔离私有桶，随机服务端 key；
- 扫描、完整解码、重编码、删除 EXIF/GPS 后生成派生图；
- 扫描失败/超时不公开；处理器使用低权限隔离进程/容器；
- SVG、HTML、PDF、压缩包、视频默认拒绝；
- 文件名只作显示并转义，不拼入路径或响应 Header。

### 8.2 访问

- 私有对象存储默认禁止匿名列举；
- 公开派生图用内容哈希 key；私密图使用短期、受众绑定的授权或服务端代理；
- 签名 URL 不进日志、Referer、埋点或长期通知；
- 删除内容时同步清 CDN/派生图；失败进入重试与告警；
- 存储凭据只供服务端/Worker，最小桶/前缀权限并定期轮换。

## 9. SSRF 与外部集成

首期 SSRF 面很小：没有 Webhook、没有外部 Issue 集成、头像只接受上传文件而非远程 URL。但只要出现任何“服务端按用户输入发起请求”的功能（例如以后加入 Web Push 端点、远程图片抓取或集成），必须按以下规则实现，不得临时放宽：

针对 Webhook、Issue 系统、远程头像或任何用户配置 URL：

1. 只允许 HTTPS，生产验证证书；
2. URL 解析后校验主机、端口和协议，禁止用户名密码段；
3. DNS 解析后阻断 loopback、link-local、私网、保留、metadata 地址；
4. 连接时固定已校验 IP并验证主机名，防 DNS rebinding；
5. 每次重定向重新校验，或直接禁重定向；
6. 限制响应体、时间、连接数和内容类型；
7. 使用独立出站网络策略，无法访问数据库/控制面；
8. 错误日志不记录完整带签名 URL。

## 10. 隐私与数据最小化

### 10.1 收集原则

- 只为账号、安全和反馈复现收集必要数据；
- 地区只到足够排障的粗粒度，默认不收精确定位；
- 不采集广告设备 ID、通讯录、硬件序列号或跨站指纹；
- 页面 URL 在上传前删除 token、email、订单号等敏感查询参数；
- 自由文本旁提示不要提交密码、密钥和个人信息；
- 分析事件不含正文、标题、自由回答、附件名和完整 IP。

### 10.2 用户权利

- 查看和修改公开资料；
- 导出自己的资料、反馈、评论、关注和贡献事件；
- 注销账号并按规则匿名化/删除；
- 删除私密附件和申请移除公开署名；
- 管理通知偏好与非必要分析；
- 查看治理处置并申诉。

具体隐私告知、法定期限和数据驻留必须根据目标地区由合格人员审查；本文不是法律意见。

### 10.3 留存

留存默认值见 `03`，必须配置化、有清理任务、有失败告警并可验证。备份中的删除通过生命周期到期实现，隐私说明需告知延迟。

## 11. 日志、审计与密钥

- 普通日志和长期审计分开；
- 日志脱敏 Authorization、Cookie、token、邮箱、完整 IP、签名 URL、正文和附件；
- 审计记录高价值动作的安全摘要，不复制私密内容；
- 密钥来自部署平台 Secret/KMS，本地使用未提交的 `.env.local`；
- 数据库中 TOTP 种子等可逆敏感值信封加密；密码、邀请码、会话令牌只存不可逆哈希
  （恢复码已删除，见 `adr/0011`）；
- 每个密钥有 owner、用途、创建/轮换/撤销时间和双密钥轮换流程；
- 密钥比较使用常量时间函数；
- 密钥绝不进入前端构建变量、错误监控附件或测试快照。

## 12. 滥用防护

### 12.1 分层控制

1. 请求层：IP 粗粒度、账号、会话、项目、动作限流；
2. 产品层：新账号冷却、链接/附件门槛、重复反馈提示；
3. 行为层：异常创建/投票/举报速度、多账号关联的隐私友好风险信号；
4. 治理层：警告、降速、临时限制、隐藏、封禁、申诉；
5. 运营层：规则和误伤率看板，人工调整。

不能因共享网络简单封禁整个学校/公司/地区。风险模型不给用户不可申诉的永久处罚。

### 12.2 贡献与投票

- 用户对同一反馈一票，数据库唯一；
- 自己投票是否允许为 `[待确认]`，但不应增加贡献分；
- 状态反复切换不能重复发分，使用源事件唯一键；
- 人工加减分要求双人审批或至少重认证 + 原因 + 审计；
- 公开榜隐藏被限制账号和可疑事件，不能泄露风控原因；
- 投票不自动决定产品优先级。

### 12.3 安全漏洞反馈

提交页提供“安全/隐私问题请设为私密”的明确路径。高风险关键词只用于提示和后台升级，不把正文发送第三方 AI。安全反馈的站内通知只给最小摘要，标题与列表预览不泄露漏洞细节。

## 13. 后台安全

- 独立后台入口，生产可叠加组织身份、IP/零信任策略；
- 管理员 MFA，短会话，敏感操作近期认证；
- 角色、管理员、私密导出、永久封禁、系统设置等动作必须审计；
- 禁止管理员改自己权限绕过双人规则、删除最后管理员或清除相关审计；
- 导出默认脱敏、短期下载、标记操作者、下载也审计；
- 后台 CSP 更严格，不加载非必要第三方脚本；
- 支持紧急冻结写操作，但必须有到期、通知和解除流程。

## 14. 供应链与基础设施

- 依赖锁定、冻结安装、最小发布时间冷却和漏洞扫描；
- CI 使用短期 OIDC 凭证，不给不可信 PR 密钥；
- 产物签名、SBOM、镜像扫描、非 root 和只读文件系统；
- 数据库/缓存/对象存储不暴露公网，TLS 验证开启；
- 备份加密、恢复权限独立、定期实测恢复；
- 生产调试端点关闭，健康检查不泄露版本/依赖地址；
- 管理端与数据层采用最小网络访问规则。

## 15. 安全验收清单

上线前必须有证据：

- [ ] 横向/纵向越权测试覆盖详情、列表、搜索、计数、附件、导出和批量任务；
- [ ] CSRF、Origin、Cookie、会话轮换/撤销、登录枚举与限流测试；
- [ ] Markdown/XSS、CSP、外链和错误编码测试；
- [ ] 恶意/伪装/超大图片、EXIF、扫描超时与隔离测试；
- [ ] SSRF 覆盖 DNS rebinding、IPv4/IPv6 保留地址和重定向；
- [ ] 私密内容不进缓存、HTML 元数据、通知、日志、埋点和搜索；
- [ ] 管理员 MFA/重认证、最后管理员保护、越级授权和审计测试；
- [ ] 秘密扫描、依赖漏洞与容器扫描无未接受高危项；
- [ ] 数据导出、注销、删除、留存任务和备份生命周期实测；
- [ ] 外部渗透测试或独立安全评审完成，高危/中危处置有结论。

## 16. 事件响应

严重事件步骤：发现与分级 → 限制影响（撤会话/停集成/冻结写）→ 保存脱敏证据 → 修复 → 验证 → 通知受影响方 → 复盘和长期措施。

必须预先准备：会话全撤、密钥轮换、Webhook 停用、私密缓存清理、恶意附件隔离、只读模式、审计导出和联系链路 runbook。

## 17. 已定与待确认

已定（2026-10-23，找回部分于 2026-10-25 更新）：账号为用户名 + 密码，
**没有任何找回途径**，管理员不能重置用户密码（`adr/0011` 取代 `adr/0007` 的恢复码方案）；
不收集邮箱/手机；只有站内通知；无外部集成与 Webhook；注册需邀请码；贡献榜仅登录可见。

待确认：


- 管理员 MFA 采用 Passkey 还是 TOTP 起步；
- 部署地区与适用法规，决定隐私告知与留存期限；
- 附件限制是否沿用默认；
- 举报处理 SLA 与申诉时限；
- 私密反馈的人工支持流程（谁能在工单下访问、如何审计）。
