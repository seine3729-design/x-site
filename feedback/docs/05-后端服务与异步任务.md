# 05 · 后端服务与异步任务

> 状态：已采纳技术栈（Go 1.27.3 + Gin + pgx/sqlc + goose + River），实现待开始  
> 最后核对：2026-10-23  
> 权威范围：后端模块边界、用例、授权、事务、任务、错误和测试要求

## 1. 分层与依赖方向

```text
HTTP/Worker Adapter
        ↓
Application Use Cases   ← 身份、授权、事务、幂等、审计
        ↓
Domain                  ← 状态机、不变量、策略、领域事件
        ↓
Ports                   ← Repository、Clock、ID、Storage、Notifier
        ↓
Infrastructure Adapters ← PostgreSQL、对象存储、Valkey、River
```

领域层不依赖 HTTP 框架、ORM、数据库驱动或外部 SDK。Handler 只负责协议转换、认证上下文、输入校验和错误映射，不编写状态机。

### 1.1 Go 落地映射

| 层 | 目录 | 允许依赖 |
| --- | --- | --- |
| HTTP | `internal/http` | Gin、DTO、`internal/app` |
| Worker | `cmd/worker` + `internal/adapters/jobs` | River、`internal/app` |
| 用例 | `internal/app` | `internal/domain`、端口接口 |
| 领域 | `internal/domain` | 仅标准库 |
| 适配器 | `internal/adapters` | pgx/sqlc、valkey-go、AWS SDK v2、River |
| 平台 | `internal/platform` | 配置、slog、OTel、uuid、时钟 |

约定：

- 端口（仓储、对象存储、通知、时钟、ID 生成）定义在 `internal/app/ports`，实现放 `internal/adapters`，便于用假实现做快速单测；
- SQL 写在 `db/queries/*.sql`，由 sqlc 生成类型安全代码；不手写字符串拼接；
- 迁移在 `db/migrations`，goose 格式，必须含 `-- +goose Down`；
- 事务通过 `app.Tx(ctx, func(tx) error)` 风格封装，River 入队必须在同一 `tx` 内完成；
- ID 用标准库 `uuid.NewV7()`；时间统一 `time.Time` + UTC；
- 所有导出用例接收 `context.Context` 并尊重取消；
- 错误用 `errors.Join` / `%w` 包装，领域错误是可判别类型，由 HTTP 层映射为业务码。

## 3. 请求处理管线

Gin 中间件顺序（`internal/http`）：

1. `recovery`：panic 恢复，返回 `INTERNAL_ERROR` 并记录脱敏栈；
2. `requestid`：生成或接受可信 `X-Request-Id`，写入 `context`；
3. `otel`：Trace 与指标；
4. `realip`：按 `TRUSTED_PROXIES` 解析客户端地址；
5. `secureheaders`：安全响应头；
6. `bodylimit` + 超时 + 内容类型校验；
7. `session`：解析会话 Cookie，校验 `session_version`；
8. `csrf`：Cookie 写请求校验 Origin 与 CSRF token；
9. `ratelimit`：全局、账号与项目级配额（Valkey，不可用时降级实例内）；
10. `binding`：Gin binding + validator 校验结构与字段；
11. `authz`：项目作用域权限判定（`RequireAction`）；
12. 用例执行与事务；
13. `audit` + 统一响应包；
14. 访问日志与指标。

`/api/v1` 与 `/api/admin` 是两个 `*gin.RouterGroup`：后台组额外挂更严格的限流、重新认证检查与审计默认开启。中间件只提供机制，是否能把反馈改为 `shipped` 仍由 `feedback` 用例按项目、状态、版本和角色判断。

## 4. 身份与授权

### 4.1 身份上下文

应用层只接收最小身份：`user_id`、`session_id`、`session_version`、平台角色。项目角色从权威数据读取或短缓存，不能由客户端声明。

### 4.2 权限策略

动作使用可审计标识，例如：

```text
projects.view
projects.manage
members.manage
posts.publish
feedback.create
feedback.triage
feedback.assign
feedback.transition
feedback.view_private
comments.moderate
reports.resolve
contributions.adjust
roles.manage
audit.view
```

判定输入为 `(actor, project, action, resource)`。平台管理员拥有平台权限，但读取私密项目内容仍应有显式、可审计的支持流程，避免默认“超级管理员能看一切”。

### 4.3 防越权不变量

- 资源 `project_id` 取自数据库，不信任 URL 与请求体同时传入时的一致性；
- 更新/删除使用 `WHERE id = ? AND project_id = ?` 或同等仓储保证；
- 不能移除最后一个项目所有者或最后一个可用平台管理员；
- 操作者不能授予自己没有的权限；
- 被停用成员的既有会话在下一请求失效；
- 列表总数与导出也必须经过同一权限过滤。

## 5. 核心用例与事务

### 5.1 `CreateFeedback`

输入：项目、类型、标题、正文、类型上下文、可见性、临时附件 ID、幂等键。

事务：

1. 检查成员资格、项目状态和可见性许可；
2. 命中幂等记录时返回既有结果；
3. 锁项目编号计数器并分配编号；
4. 创建反馈和上下文；
5. 验证附件所有权/扫描状态并绑定；
6. 写首条状态历史和默认关注；
7. 写 `feedback.created` outbox；
8. 提交并保存幂等响应摘要。

相似项查询发生在提交前，不能成为创建事务的外部依赖。

### 5.2 `TransitionFeedback`

- 输入必须带当前 `version`，过期返回冲突及最新状态；
- 领域状态机检查来源/目标、角色、负责人、发布版本和说明；
- 同一事务更新快照、写状态历史、贡献事件、审计和 outbox；
- 进入同一状态的重复请求幂等返回当前资源；
- `planned` 不要求发布日期；若传日期必须明确是目标而非承诺。

### 5.3 `MergeDuplicate`

- 锁定两条反馈并按固定 ID 顺序加锁，避免死锁；
- 验证同项目、非自身、无合并环和可见性兼容；
- 原反馈转 `duplicate`，保留原编号；
- 关注者和标签去重迁移，评论默认不搬正文；
- 私密项只能建立后台关联，不能暴露给公开主项；
- 生成可逆的合并记录，解除时恢复原状态。

### 5.4 `PublishRelease`

- 发布版本号项目内唯一；
- 将选中反馈逐条转 `shipped`，每条独立幂等；
- 大批量使用任务分批处理，失败可重放；
- 上线小结发布与状态通知可以最终一致，但页面不得显示不存在的关联。

### 5.5 `RedeemInvite`

校验 token 哈希、项目、期限、撤销、次数、账号状态；锁定邀请记录，创建/恢复成员、写核销、递增次数和审计。错误提示不区分“token 不存在”与“已被猜中但不可用”的敏感细节。

## 6. 输入与内容呈现

- DTO 校验类型、长度、枚举、数组数量和字符串规范化；
- 标题去首尾空白、折叠不可见控制字符，不改变用户语义；
- Markdown 使用严格白名单，禁用原始 HTML、脚本、iframe、事件属性、危险协议与自动外部资源；
- 出站链接添加安全属性，界面明确外部站点；
- 搜索高亮在结构化 token 层实现，不能拼接 HTML；
- 错误响应不包含 SQL、路径、堆栈、内部备注或权限策略细节。

## 7. 幂等与并发

| 操作 | 幂等策略 |
| --- | --- |
| 创建反馈/评论/议题回答 | `Idempotency-Key` + 用户 + 路由范围，保存响应摘要 24 小时 |
| 投票/关注 | `PUT` 表达目标状态，唯一约束，重复调用返回当前值 |
| 状态迁移/编辑 | `version` 或 `If-Match` 乐观锁 |
| 邀请核销 | token 行锁 + 唯一核销记录 |
| Worker 事件 | `event_id`/`dedupe_key` 唯一，副作用记录供应商 ID |
| 批量操作 | 任务 ID + 每项结果，重试只处理未完成项 |

幂等记录不保存敏感原始请求体；请求指纹使用规范化后摘要。

## 8. Outbox 与异步任务

### 8.1 队列

| 队列 | 任务 | 优先级/时限 |
| --- | --- | --- |
| `critical` | 安全通知、会话吊销、私密内容紧急隐藏后续 | 高，秒级 |
| `files` | 图片扫描、解码、重编码、EXIF 清理、缩略图 | 高，分钟级 |
| `notifications` | 站内通知生成与聚合（无外部投递渠道） | 中，分钟级 |
| `search` | 建索引、删索引、相似项特征 | 中，分钟级 |
| `maintenance` | 临时文件清理、状态老化提醒、计数校准 | 低，小时级 |

队列用 River 的 `Queues` 配置声明，每个队列单独设并发上限；`files` 不能挤占 `critical`。没有 `integrations` 队列：外部集成已排除在范围外。

### 8.2 交付语义

River 提供同事务入队、重试、唯一任务与周期任务，因此不再单独实现 outbox 表；“outbox”在本文指 River 的同事务入队语义。

- 入队必须使用业务事务的同一 `pgx.Tx`，禁止事务提交后再入队；
- 至少一次消费，业务处理器必须幂等；
- 指数退避 + 抖动，区分可重试和永久错误；
- 每类任务定义最大尝试、超时、死信和人工重放；
- 任务 payload 只放 ID 与事件版本，不放完整私密正文或长期授权 URL；
- Worker 关闭时停止取新任务，给在途任务完成/续租时间；
- 队列延迟、失败率、死信数量和最老任务年龄必须监控。

### 8.3 周期任务

- 每 5 分钟：发送到期状态提醒候选（去重）；
- 每小时：清理过期上传、邀请与幂等记录；
- 每日：重算抽样计数、贡献总分、项目健康指标；
- 每周：留存清理与权限异常报告；
- 备份、密钥轮换不放在普通业务调度器中静默执行，使用运维流程。

周期仅为建议，正式数值在容量与运营 SLA 确认后配置化。

## 9. 搜索与相似项

MVP：数据库全文检索 + 标题规范化相似度。

- 索引字段：公开/成员可见标题、清洗正文摘要、项目、类型、状态、标签；
- 私密反馈单独索引或直接使用权限过滤的数据库查询；
- 相似项在已选项目范围内，对标题权重最高，并过滤用户无权查看的结果；
- 搜索故障时提交表单继续可用，只关闭相似项提示；
- 独立搜索引擎只能接收最小字段和权限标签，删除/收紧可见性事件优先处理；
- 相关性变化需离线样本评估，不能只看点击率。

## 10. 附件处理

- 上传授权有效期短、限定对象 key、大小、MIME 与单次次数；
- 对象 key 由服务端生成，不使用原文件名；
- 读取文件头并完整解码，防 MIME 欺骗、压缩炸弹和超大像素；
- 图片在隔离环境重新编码，删除 EXIF/GPS；
- 扫描器超时视为未通过，不能自动公开；
- 处理后生成固定尺寸集合，页面不请求任意动态变换参数；
- 失败保留最小诊断，用户可删除并重传；
- 所有外部对象存储调用有超时、TLS 验证和受控重试。

## 11. 通知

领域事件映射为通知意图，再根据用户偏好、可见性和聚合窗口生成通知。

- 只有站内渠道，没有邮件与第三方推送（`adr/0007`）；
- 私密反馈只在生成通知时重新验证接收者权限；
- 通知内容只含最小摘要与受保护链接，不含私密正文；
- 被提及用户必须能读取目标内容，否则不创建通知；
- 同一反馈 5 分钟内多次状态/评论可聚合，按 `dedupe_key` 去重；
- 因为无法离线触达，未读状态必须持久保存，直到用户显式已读。

## 12. 错误模型

| 业务码 | HTTP | 场景 |
| --- | ---: | --- |
| `VALIDATION_FAILED` | 422 | 字段校验失败，返回字段级问题 |
| `AUTH_REQUIRED` | 401 | 无有效会话 |
| `FORBIDDEN` | 403 | 已认证但无动作权限；私密资源可返回 404 |
| `NOT_FOUND` | 404 | 资源不存在或不可见 |
| `CONFLICT` | 409 | 版本冲突、非法状态或唯一冲突 |
| `IDEMPOTENCY_MISMATCH` | 409 | 同一幂等键用于不同请求 |
| `RATE_LIMITED` | 429 | 配额耗尽，带 `Retry-After` |
| `UPLOAD_REJECTED` | 422 | 类型、大小或扫描不通过 |
| `PROJECT_NOT_ACTIVE` | 409 | 项目暂停/归档，禁止当前写操作 |
| `INTERNAL_ERROR` | 500 | 未预期错误，只给请求编号 |
| `DEPENDENCY_UNAVAILABLE` | 503 | 必要依赖不可用，可重试 |

详细响应契约见 `08`。

## 13. 日志、指标与审计

- 日志：JSON，包含时间、级别、服务、环境、request/trace ID、路由模板、状态码、耗时和安全事件类型；
- 禁止：正文、评论、密码、Cookie、Authorization、邀请 token、完整邮箱/IP、对象存储签名地址；
- 指标：请求 RED、数据库池、事务冲突、outbox 延迟、任务失败、附件处理、登录异常、权限拒绝；
- 审计：角色/成员、可见性、状态、合并、发布、审核、贡献调整、邀请与系统设置；
- 普通用户操作日志与管理员审计分开，不把全部访问写成长期审计。
