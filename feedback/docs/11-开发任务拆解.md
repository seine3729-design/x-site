# 11 · 开发任务拆解

> 状态：P0 决策已确认，M0 可以开工  
> 最后核对：2026-10-23  
> 权威范围：里程碑、任务边界、依赖、优先级、验收与证据要求

## 1. 约定

### 1.1 编号

| 前缀 | 工作流 |
| --- | --- |
| `D` | 产品、设计、文档与决策 |
| `X` | 工程底座、契约、CI、部署与跨端集成 |
| `B` | Go 后端（API / Worker / 数据） |
| `W` | Next.js 用户端路由组 `(site)` |
| `A` | Next.js 运营后台路由组 `(admin)` |
| `Q` | 质量、安全、性能与发布 |

编号形如 `B2-3`：后端、M2 里程碑、第 3 项。任务号稳定，不因排序改变而重编号。

### 1.2 状态

`待评审 / 就绪 / 进行中 / 阻塞 / 完成 / 取消`。只有验收证据存在且 `10` 第 13 节的 Definition of Done 满足后才能标“完成”。

### 1.3 规模

- `S`：≤ 1 人天；
- `M`：2–3 人天；
- `L`：4–5 人天，必须有独立规格并切片；
- 大于 `L` 必须拆分，不用一个任务包住完整模块。

估算不含等待产品决策和外部审核。

### 1.4 技术栈（`adr/0006`）

前端 Next.js 16.4 + React 19.3 + Bun 1.4 + TypeScript 7 + Tailwind 4.3 + shadcn/ui；后端 Go 1.27.3 + Gin 1.12 + pgx/sqlc + goose + River + PostgreSQL 18 + 可选 Valkey 9。用户端与后台是同一 Next.js 工程的两个路由组。

## 2. 里程碑

| 里程碑 | 用户结果 | 出口标准 |
| --- | --- | --- |
| M0 工程底座 | 团队能在本地安全、可重复地开发 | 工程、契约、迁移、CI 可运行；用户端与后台空壳可登录；健康检查通过 |
| M1 项目与动态 | 用户凭邀请码加入项目并理解当前测试重点 | 邀请 → 注册 → 项目页 → 阅读置顶测试任务；管理员能建项目、运营能管成员与动态 |
| M2 反馈闭环 | 用户提交并跟踪一条反馈，运营完成分诊到上线 | 提交 → 分诊 → 状态 → 版本上线 → 站内通知全流程；私密权限与附件通过 |
| M3 社区参与 | 用户能讨论、投票、参与议题并看到贡献等级 | 评论/投票/关注/议题/贡献榜可用；贡献事件可审计与冲销 |

## 9. 建议的第一个纵切

M0 完成后优先做一条不依赖附件、投票和评论的纵切，用来最早验证核心价值：

1. `api/openapi.yaml`：创建反馈、反馈详情、后台分诊、状态历史；
2. 迁移：`users`、`invitations`、`projects`、`project_members`、`feedback`、`feedback_status_history`、审计最小表；
3. Go：邀请码注册、用户名登录、创建反馈、项目作用域授权、`submitted → triaged`；
4. `(site)`：项目页 + 提交表单 + 反馈详情；
5. `(admin)`：待分诊列表 + 工作区 + 官方确认；
6. Worker：站内通知；
7. E2E：成员提交后运营确认，成员看到状态变化与通知。

范围外：附件、投票、评论、议题、贡献、相似搜索。

## 13.7 已完成：运营能把已注册账号拉进项目、邀请落地页（2026-10-24）

### 后端：补上 13.3 节记录的第二条缺口

`PATCH /api/admin/feedback/projects/:id/members/:user_id` 原来要求成员行必须已存在，
所以运营没有任何办法把一个已注册账号加进「仅邀请」项目（会 404）。现在成员行不存在时
这次调用就是「添加成员」：

- 添加前先确认社区账号真的存在，否则会写出一条指向幽灵用户的成员记录；
- 账号不存在返回 404；
- 移除一个本来就不是成员的人仍然返回 404（调用方搞错了对象，不该静默成功）；
- 已有成员改角色、以及「不能移除项目所有者」的规则都不变。

契约同步：该端点的 description 写明了新语义，`openapi.yaml` 升一个 patch 版本。

验证：`./dev.sh go test ./internal/domain/feedback/ -run TestSetMemberRole -v` 五个用例全通过
（添加缺失成员、拒绝不存在的账号、移除非成员、改已有成员角色、不能移除所有者）。
做过变异检查——把逻辑还原成旧写法后该包无法通过编译（`errors` 导入不再被使用），
所以这里拿到的是「旧代码跑不了这组测试」而不是「断言失败」，证据强度比标准的红→绿略弱。

### 前台：邀请落地页 `/invite/[token]`

未登录时展示邀请码并带进注册页（`/register?invite=...`），同时把「恢复码只显示一次」
说在前面。已登录时诚实说明现状：邀请码只在注册时核销，已有账号要进「仅邀请」项目
得让运营添加。

这一页刻意不校验邀请码：校验在注册时由后端做（无效、过期、用完返回同一个提示）。
在落地页先调接口验一次，等于把「某个邀请码是否有效」变成任何人都能探测的接口。

### 这个缺口还剩两条

- **后台还没有「添加成员」的入口**：后端能力有了，但 `admin/` 的项目成员列表只能改已有成员的角色，界面上没有添加按钮。要补一个「按用户名搜索并添加」的弹窗。
