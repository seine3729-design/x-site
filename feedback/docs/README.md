## 2. 标记约定

| 标记 | 含义 | 是否可直接实现 |
| --- | --- | --- |
| `[观察]` | 从公开页面直接看到或可复现的事实 | 只能作为参考证据 |
| `[假设]` | 为形成完整方案而暂定，尚未确认 | 可用于估算，不应锁死不可逆实现 |
| `[提议]` | 有明确理由的推荐方案，等待决策 | 决策后进入 ADR |
| `[决策]` | 已在“已采纳”ADR或用户明确回复中确认 | 可以实现 |
| `[待确认]` | 会显著改变范围、成本或数据结构的问题 | 相关任务开始前必须确认 |

引用外部产品时记录访问日期、访问身份与限制。研究内容必须转述，不复制品牌名称、长段文案、图片或私有数据。

## 3. 权威源顺序

同一规则冲突时，先停止实现并按以下顺序核对：

1. 已采纳 ADR与用户最新明确决定；
2. `01` 的产品业务规则；
3. 机器可校验契约（后续的 `api/openapi.yaml`、数据库迁移）；
4. `03` 数据设计、`08` API 语义与端侧文档；
5. 任务规格与代码实现；
6. `research/` 仅为证据，不是权威需求。

接口字段以 OpenAPI 为准，数据库现状以迁移文件为准，部署配置以校验后的示例配置为准。文档与实现不一致时，不以“代码已经这样写了”为理由覆盖已确认规则。

## 4. 已确认决策（2026-10-23）

| 主题 | 决策 |
| --- | --- |
| 平台模型 | 多项目，所有业务数据带项目作用域 |
| 项目创建 | 只有平台管理员能创建项目 |
| 注册 | 必须持有效邀请码，不开放自助注册 |
| 账号 | 用户名 + 密码，不收集邮箱/手机号；**没有任何找回途径**，忘记密码即永久失去账号（`adr/0011`） |
| 通知 | 只做站内通知（没有邮箱即没有邮件通道） |
| 社区功能 | 投票、议题、贡献等级进入首发，保持非货币化 |
| 语言 | 只做简体中文，不做多语言与 RTL |
| 外部集成 | 不做 GitHub/Jira/Slack/Telegram 等集成 |
| 端 | 响应式 Web + 运营后台，不做原生 APP |
| 技术栈 | 前端 Next.js 16.4 + React 19.3 + Bun 1.4；后端 Go 1.27.3 + Gin + PostgreSQL 18 |

决策依据见 [`adr/`](./adr/)。仍需你确认：可见性矩阵（`00` 第 8.2 节）、容量与部署区域（`10` 第 2 节）。

## 5. 更新规则

- 新业务规则：更新 `01`，跨模块决策另写 ADR。
- 新表或字段：更新 `03`，实现时同步迁移。
- 新接口或字段：先更新 OpenAPI，再同步 `08` 的索引与语义。
- 页面行为变化：用户端更新 `06`，运营端更新 `07`。
- 任务状态变化：只更新 `11` 与对应 `specs/` 的证据，不在设计文档写开发流水账。
- 文档描述当前有效状态；历史和被替代理由保留在 Git 与 ADR。
