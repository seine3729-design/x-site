# 0008 · 实现位置：后端复用 service/，后台复用 admin/，feedback/ 只做 H5 前台

状态：已采纳  
日期：2026-10-23  
决策人：用户（2026-10-23：「后端不用搭建新框架了，可以在 service 这个项目里面写后端；运营后台在 admin 目录；feedback 是前台项目，需要适配 H5」）  
适用范围：代码位置、数据库、鉴权、部署、任务拆解  
取代/被取代：细化并部分取代 `adr/0002` 与 `adr/0006` 中「独立 service/ 与 web/ 工程」的部分

## 背景与问题

`adr/0006` 原计划在 `feedback/` 下新建独立的 Go 后端与 Next.js 工程（含独立 compose、数据库、CI）。但同一工作区已有成熟的 `service/`（Go 1.27.3 + Gin + pgx/sqlc + goose + River，已带会话、RBAC、审计、报文加密、对象存储）和 `admin/`（React 19.3 + TanStack + shadcn，已带 DB 驱动菜单、权限树、表格表单体系）。重复搭一套会多出两套工具链、两套本地环境和两份鉴权实现。

## 决策

| 层 | 位置 | 说明 |
| --- | --- | --- |
| 后端 | `service/`（现有工程） | 新增 `internal/domain/feedback` 业务域，表名统一 `fb_` 前缀，与短剧业务同库不同表 |
| 前台用户接口 | `/api/v1/feedback/*` | 挂在现有 `/api/v1` 加密分组内 |
| 后台接口 | `/api/admin/feedback/*` | 复用现有会话 + Origin + CSRF + RBAC + 审计中间件 |
| 运营后台 | `admin/`（现有工程） | 新增 `src/features/feedback/*` 与 `admin_menu` 的「反馈社区」目录 |
| H5 前台 | `feedback/`（Next.js 16.4 + Bun） | 只做用户端页面，移动优先 |

配套约定：

- **数据隔离靠表前缀**，不新建数据库或 schema：迁移编号延续 `service/db/migrations`（本次 `00012`），sqlc 查询加 `db/queries/feedback.sql`。
- **社区用户与后台管理员是两套身份**：社区用户在 `fb_user`，管理员仍在 `admin_user`。后台人员通过 RBAC 权限点管理反馈社区，不需要社区账号。
- **H5 前台不实现 HPKE**。浏览器只与 Next.js 同源通信，Next.js 服务端带 `X-Service-Token` 调 Go；该路径命中现有 `isInternalSSR` 豁免（`IsFromBFF && X-Bff-Proxy == ""`），允许明文。因此不需要在 `docs/10` 第 5.3 节新增加密豁免路径。
- **社区会话令牌不走 Cookie 到 Go**：Go 在登录响应体返回不透明令牌，由 Next.js 写成自己的 HttpOnly Cookie；后续请求 Next.js 以 `Authorization: Bearer` 转发。Go 侧不读 Cookie，因此 Go 侧不需要社区用户的 CSRF 机制，CSRF 由 Next.js 同源策略承担。
- 新增后台页面必须同时写 `admin_menu`（kind=page）与 `admin_permission`，否则 `checkDeclaredPermissions` 会让进程启动失败。
- 文档归属：产品与领域设计仍在 `feedback/docs/`；接口契约写进 `service/api/openapi.yaml` 并同步 `docs/07`；任务编号仍用 `feedback/docs/11`。

## 备选方案与放弃原因

| 方案 | 放弃原因 |
| --- | --- |
| 独立 Go 服务 + 独立库（原 `adr/0006`） | 重复实现会话、RBAC、审计、迁移、可观测与本地环境；运维与 CI 成本翻倍 |
| 独立运营后台工程 | 要再实现一遍登录、菜单、权限树、表格表单与设计系统 |
| 独立 PostgreSQL schema（`feedback.`） | 需要改 sqlc 搜索路径与所有查询限定前缀，收益只是命名整洁；表前缀已足够隔离 |
| 社区用户复用 `admin_user` | 把运营身份与社区身份混为一体，权限与审计语义被破坏 |
| 浏览器直连 Go `/api/v1/feedback/*` | 需要在前台实现 HPKE 客户端，或新增加密豁免，两者都比 SSR 转发成本高 |

## 正面后果

- 复用既有鉴权、审计、迁移、可观测与本地 compose，立刻可跑；
- 后台页面与现有菜单/权限体系天然打通；
- 反馈社区与短剧业务共享一次部署与一套监控；
- H5 前台不需要加密客户端，首屏与开发复杂度都更低。

## 负面后果与风险

- `service/` 与 `admin/` 承载两个产品，模块边界必须靠目录与表前缀自律维持；
- 迁移编号、`openapi.yaml`、`router.go`、`app.go`、`navigation.ts` 成为跨产品共享文件，多人协作需逐次重读再局部修改；
- 两个产品的发布被绑定在同一个后端部署上；
- 短剧业务未来若新增 `user` 表，需确认与 `fb_user` 的命名与语义不混淆。

## 安全、隐私与运维影响

- 社区用户表与管理员表分离，权限判定仍在 Go 侧按项目作用域执行；
- 社区会话存 Valkey（独立键前缀），`session_version` 变更即时失效；
- 服务令牌只存在于 Next.js 服务端运行时，不进客户端 bundle；
- 后台对反馈社区的写操作全部进审计。

## 迁移、兼容与回滚

本次为新增，不影响短剧业务。回滚 = `goose down` 到 `00011` 并移除路由注册；`fb_` 表与短剧表无外键交叉（只引用 `admin_user` 记录操作者）。若未来需要拆为独立服务，领域代码 `internal/domain/feedback` 与 `fb_` 表可整体迁出。

## 复审触发器

- 反馈社区流量或发布节奏开始明显干扰短剧业务；
- 两个产品的数据合规要求出现分歧；
- `service/` 单体体积影响构建或测试时长。
