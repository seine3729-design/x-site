# 0006 · 技术栈选型：Next.js + Bun 前端，Go 后端

状态：已采纳  
日期：2026-10-23  
决策人：用户（2026-10-23 明确指定）  
适用范围：前端、运营后台、后端、数据层、本地环境、CI  
关联任务：D0-3、X0-1、X0-2  
取代/被取代：细化 `adr/0002` 的应用形态，不取代它

## 背景与问题

`adr/0002` 只确定“Web 优先的模块化单体”，没有确定语言与框架。用户明确要求：前端 Next.js + Bun + 最新前端技术栈，后端 Go + 最新技术栈。需要把“最新”固化为可锁定、可复现的版本基线，否则每个人理解的最新都不同。

## 约束与决策驱动因素

- 公开项目、动态和反馈需要服务端渲染与可被索引的元数据；
- 反馈状态、历史、贡献和审计需要单事务强一致；
- 附件扫描、通知、搜索索引需要异步执行；
- 同一工作区已有 Go + PostgreSQL + Valkey 的工程实践，可复用团队经验与本地镜像；
- 依赖必须锁定精确版本并可被漏洞扫描覆盖。

## 决策

### 前端与运营后台

| 类别 | 选型 | 版本基线（核对于 2026-10-23） | 说明 |
| --- | --- | --- | --- |
| 框架 | Next.js（App Router） | 16.4.x | SSR/SSG、Server Components、Server Actions、Turbopack |
| UI 库 | React | 19.3.x | 与 Next.js 16.4 配套 |
| 编译优化 | React Compiler | 1.0 | 自动记忆化，减少手写 memo |
| 运行时/包管理 | Bun | 1.4.x（当前 1.4.3） | 1.4 起由 Rust 重写；用于安装、脚本、测试 |
| 语言 | TypeScript | 7.0.x | 严格模式；若 lint 工具链仍依赖 TS 6 编程 API，则并存安装 |
| 样式 | Tailwind CSS | 4.3.x | 原生 CSS 配置、容器查询 |
| 组件 | shadcn/ui（CLI v4）+ `radix-ui` 统一包 | — | 组件进仓库，可按 `06` 的 token 改造 |
| 表单 | react-hook-form + zod | — | 与服务端共享校验 schema 形状 |
| 客户端数据 | 以 Server Components / Server Actions 为主，必要处用 TanStack Query v5 | — | 不默认引入全局状态库 |
| 图表 | Recharts 3（经 shadcn charts） | — | 仅后台看板使用，按路由懒加载 |
| 图标 | Lucide | — | 统一线性 SVG，不用 Emoji 当图标 |
| 测试 | Bun 内置测试或 Vitest + Playwright | — | 单元 + E2E |

- 用户端与运营后台**同一个 Next.js 工程**，用路由组分隔（`(site)` 与 `(admin)`），共享生成的 API 类型与设计 token，但各自独立的布局、CSP 与鉴权中间件。
- 浏览器直接调用 Go API 的场景走同源路径；需要隐藏服务令牌或聚合时使用 Next.js 服务端（Route Handler / Server Action）转发。
- **运行时待实测**：Next.js 官方生产运行时是 Node.js。Bun 作为包管理器和脚本运行器已稳定；是否用 Bun 跑生产 server 必须在 `X0-1` 实测 standalone 产物后确认，失败则生产用 Node.js、开发与工具链仍用 Bun。该结论要写回 `04` 和 `12`。

### 后端

| 类别 | 选型 | 版本基线 | 说明 |
| --- | --- | --- | --- |
| 语言 | Go | 1.27.3（`go.mod` 与镜像锁定补丁版本） | 泛型方法、`encoding/json/v2`、标准库 `uuid`（含 `NewV7`）、goroutine 泄漏 profile |
| HTTP 框架 | Gin | 1.12.x | 与同工作区现有服务一致，降低切换成本 |
| 数据访问 | pgx v5 + sqlc | sqlc 1.31.x | SQL 即契约，编译期生成类型安全代码 |
| 迁移 | goose v3 | — | SQL 迁移，可嵌入二进制，CI 先迁移再发布 |
| 任务队列 | River | — | 基于 PostgreSQL，可与业务同事务入队，天然满足 Outbox |
| 缓存/限流 | Valkey 9.x + valkey-go | — | 可降级；本地缺失时退化为实例内限流 |
| 配置 | caarlos0/env v11 | — | 环境变量映射 + 启动期强校验 |
| 校验 | go-playground/validator v10 | — | 与 Gin binding 集成 |
| 日志/遥测 | `log/slog` + OpenTelemetry Go | — | 结构化日志 + Trace/Metric |
| 密码 | `golang.org/x/crypto/argon2`（Argon2id） | — | 参数可升级并记录 |
| 对象存储 | AWS SDK for Go v2（S3 兼容） | — | 本地用 SeaweedFS，桶分隔离/私密/公开 |
| 测试 | `testing` + testcontainers-go | — | 真实 PostgreSQL/Valkey 集成测试 |

### 数据与基础设施

- PostgreSQL 18.x 为唯一业务权威源，首期用主库全文检索，不引入独立搜索引擎；
- Valkey 9.x 可选，用于会话辅助、限流和热点读，故障时降级不影响授权；
- 对象存储使用 S3 兼容服务，三桶分离：隔离、私密派生、公开派生；
- 本地开发用 Docker Compose，在 `feedback/` 下独立编排，不与工作区根目录的栈共用端口与数据卷；
- 依赖全部锁定在 `go.sum` / `bun.lock`，CI 使用冻结安装。

### 目录结构

```text
feedback/
├─ api/openapi.yaml
├─ service/            # Go：cmd/api、cmd/worker、internal/{domain,app,adapters,http}
├─ web/                # Next.js 16 App Router：(site) 与 (admin) 路由组
├─ deploy/local/       # 独立 compose 与开发镜像
└─ docs/
```

## 备选方案与放弃原因

| 方案 | 放弃原因 |
| --- | --- |
| SvelteKit 前端 | 用户明确要求 Next.js；工作区已有 SvelteKit 实践但不适用于本决策 |
| 全栈 TypeScript（Next.js 直连数据库） | 失去 Go 的事务/并发实践与进程隔离；状态机、审计和 Worker 更难独立测试 |
| Go 用 chi 或标准库 `net/http` | 可行且更轻，但 Gin 与同工作区既有服务一致，团队与中间件模式可直接复用 |
| GORM / ent 替代 sqlc | 本项目有大量显式约束与状态迁移查询，SQL 可读性和执行计划控制更重要 |
| Kafka/NATS 做任务队列 | 需求规模用 River + PostgreSQL 已足够，且能与业务事务原子入队 |
| 独立 Vite 后台（双前端工程） | 增加重复的鉴权、token 生成与设计系统同步成本；路由组已能隔离 |

## 正面后果

- 公开页面有 SSR 与元数据，满足展示与检索；
- 后端在单库事务内保证状态、历史、贡献与审计一致；
- River 让异步副作用与业务写同事务入队，避免双写；
- 前后台共享类型与 token，减少契约漂移；
- 版本有明确基线，可被锁文件与漏洞扫描覆盖。

## 负面后果与风险

- 两种语言、两套工具链，CI 与本地环境更复杂；
- Bun 作为 Next.js 生产运行时未经本项目验证，存在回退到 Node.js 的可能；
- Next.js 16 的 App Router 缓存与导航语义变化较快，升级需回归测试；
- 前后台同工程要严格防止后台代码或权限逻辑进入用户端 bundle；
- Go 与 TypeScript 的校验规则需要靠 OpenAPI 保持一致，不能各写一套。

## 安全、隐私与运维影响

- Go 服务是唯一授权判定方；Next.js 不得直接连接数据库或持有对象存储长期凭据；
- 后台路由组独立中间件、更严格 CSP，不加载非必要第三方脚本；
- 服务端令牌只存在于 Next.js 服务端运行时，不进入客户端环境变量；
- Go 1.27.3 为当前安全补丁版本，需跟随安全公告升级；
- 两套依赖都纳入漏洞扫描与最小发布观察期。

## 迁移、兼容与回滚

首期无存量代码。回滚粒度：

- 生产运行时可从 Bun 回退 Node.js，不改应用代码；
- 后台可从路由组拆成独立应用，保留同一 OpenAPI 与生成类型；
- 框架大版本升级先在预发回归 SSR、缓存、鉴权与无障碍。

## 复审触发器

- Next.js 或 Bun 出现影响本项目的破坏性变更或长期未修的严重缺陷；
- 公开反馈量超过主库全文检索的相关性/性能上限；
- 任务吞吐或隔离需求超出 River + PostgreSQL；
- 团队结构变化导致 Go 维护成本不可接受。
