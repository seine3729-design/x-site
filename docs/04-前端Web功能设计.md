# 04 · 前端（Web）功能设计（apps/）

技术栈：**Bun 1.4 + SvelteKit 3.1 + Svelte 5.57（Runes）+ Vite 8 + Tailwind CSS 4.3 + TypeScript 6 + adapter-bun**。SSR 保 SEO 与首屏，`src/routes/api/*` 作为 BFF 聚合后端数据、注入站点配置、处理边缘缓存头。移动优先；界面 9 种语言（A.4）；浏览器发往 `/api/v1/*` 的请求全部报文加密（A.5）。

## A. 工程与技术方案

### A.1 现状与升级点

现有工程已是 SvelteKit 3 结构（配置在 `vite.config.ts`、`#lib` 子路径导入、`src/env.ts` 显式环境变量、`$app/env/private`），在此基础上补齐：

| 项 | 现状 | 目标 |
| --- | --- | --- |
| 版本 | kit 3.0 / svelte 5.57 / bun 1.4.2 | kit 3.1.x（CSP 哈希上报、服务端 tracing span）、bun 1.4 最新补丁 |
| CSP | 自定义头，`script-src 'unsafe-inline'` | 改用 SvelteKit 内置 `csp`（`mode: 'hash'`），去掉 `unsafe-inline`；开启 `report-to` 收集违规 |
| 限流 | 进程内 Map 令牌桶 | 多实例下改为 Valkey（`Bun.RedisClient` + Lua）共享桶；Valkey 故障降级为进程内桶 |
| 压缩 | 运行时 brotli/gzip 同步压缩 | 静态资源走构建期 `precompress`；动态 HTML 改为流式压缩或交给 CDN，避免 `brotliCompressSync` 阻塞事件循环 |
| 数据获取 | 尚未接入后端 | `+page.server.ts` load + `#lib/server/api.ts` 统一后端客户端；Remote Functions 稳定前不使用 |
| 可观测 | 无 | `src/instrumentation.server.ts` 接入 OpenTelemetry，透传 `traceparent` 到后端 |
| 类型 | TS 6.0 | 保持 TS 6（`svelte-check` 尚不支持 TS 7.0）；TS 7.1 编程 API 稳定后再评估 |

### A.3 BFF 约定

- 浏览器只访问同源 `/api/v1/*`；BFF 通过内网 + mTLS 调 `service/`，附 `BFF_SERVICE_TOKEN` 与原始客户端信息（`x-forwarded-for`、国家头、UA、设备 Cookie）。BFF 只透传 `/api/v1/*`，`/api/admin/*` 等其余 `/api/*` 由 `src/routes/api/[...path]` 直接返回 JSON 404，后台接口不能经前台域名访问（`07` 第 0.5 节）。
- 浏览器请求是端到端加密的（浏览器 ↔ Go）：`/api/v1/[...path]` 只原样转发密文与 `x-enc`、`x-enc-type` 头，不解密、不改写路径与查询串，并加 `x-bff-proxy: 1` 让后端按浏览器请求强制加密；回传给浏览器的响应头走白名单。SSR `load` 经 `#lib/server/api.ts` 内网明文调用，不加 `x-bff-proxy`。
- BFF 只做：聚合（首页一次拿全区块）、字段裁剪、站点配置注入、缓存头、会话 Cookie 读写。不持有数据库连接与业务密钥。
- 登录令牌全部放 `HttpOnly; Secure; SameSite=Lax` Cookie，浏览器 JS 读不到；`/api/v1/me/*` 写操作同时校验 `Origin` 与 CSRF 令牌（可用 `Bun.CSRF`）。
- 后端错误码在 BFF 统一映射为页面状态（401 登录墙、402 VIP 墙、404 下架、429 退避）。

#### A.3.1 会话实现（`#lib/server/session.ts`）
- Cookie 三个：`xs_at`（Access Token）、`xs_rt`（Refresh Token）都是 HttpOnly，生产环境加 `__Host-` 前缀；另有脚本可读的 `xs_li=1`，只用来让页面判断要不要请求 `/me/state`，不含任何身份信息。令牌一律不进 `localStorage`。
- 透传时 BFF 从 Cookie 取 Access Token 加到 `Authorization` 头；快过期时先用 Refresh Token 轮换。轮换是**单飞 + 30 秒内复用结果**：同一个 Refresh Token 并发只向后端换一次，否则会触发后端的重放检测、整个令牌家族被吊销。多实例部署时并发轮换仍可能撞车，建议后端给旧 Refresh Token 留一个宽限窗口。
- 游客身份**按需签发**：只有写请求才在没有会话时先要一个游客令牌，纯浏览不产生写库。
- **与 B.10 的偏差（已知、有意）**：登录、注册、登出走 SvelteKit 表单动作，由 BFF 经内网**明文**调后端，拿到令牌后写 Cookie；`/api/v1/auth/{guest,login,register,refresh,logout}` 在透传层直接返回 404。原因是浏览器到 Go 的报文端到端加密，BFF 读不到透传响应里的令牌，也就无法写 Cookie。代价是这几个接口的请求体在「浏览器 → BFF」这一段只靠 HTTPS 保护，不额外加密。
- SSR 页面不读会话：公共页面要进边缘缓存，个人数据（追剧、续播、未读数）一律由浏览器二次请求填充。

| --- | --- | --- | --- |
| 简体中文（默认） | `zh-CN` | 无 | ltr |
| English | `en` | `/en` | ltr |
| Español | `es` | `/es` | ltr |
| Tiếng Việt | `vi` | `/vi` | ltr |
| 日本語 | `ja` | `/ja` | ltr |
| 한국어 | `ko` | `/ko` | ltr |

#### A.4.1 路由与检测
- 语言只由 URL 前缀决定：`src/hooks.ts` 的 `reroute` 去掉前缀后匹配同一份路由（`/ja/d/1` 与 `/d/1` 是同一个页面组件），`/api/v1/*` 不带前缀。页面缓存键天然按语言区分，不需要 `Vary`。
- `hooks.server.ts` 把语言写入 `locals.locale`，替换 `app.html` 中的 `%lang%`、`%dir%`，并设置 `Content-Language`。
- 首次访问无前缀地址时，客户端按 `navigator.languages` 跳到对应语言（`location.replace`，只在浏览器执行，不影响边缘缓存）；用户在语言菜单选过语言（本机 `lang_pref`）后以选择为准；爬虫不跳。繁体中文没有对应文案，不匹配简体中文。
- 页头语言菜单不依赖 JS（`details` + 链接整页跳转），保留当前路径与查询串；`<head>` 输出全部语言的 `hreflang` 与 `x-default`。

#### A.4.2 文案
- 文案放 `src/lib/i18n/messages/<标签>.json`：扁平键（`模块.用途`，如 `home.intro`），占位符写 `{name}`；简体中文为基准。键名由 `zh-CN.json` 推导出的 TS 类型约束（`t('不存在的键')` 在 `svelte-check` 报错）。
- 校验（发布脚本 `bun run i18n:build`）：9 种语言键与中文一致、值非空、占位符一致、非中文不原样照抄中文。
- 用法：组件内 `const i18n = getI18n()`，`i18n.t('key', { name })`、`i18n.error(code)`（业务码 → 当前语言）、`i18n.path('/d/1')`（加语言前缀）。数字、日期、货币用 `Intl.*` 按当前语言格式化。
- 每次请求只把当前语言的文案随 layout 数据下发（服务端打包全部语言，客户端包里不含其他语言）。
- 后端 `message` 是中文兜底，界面不直接展示，一律 `i18n.error(code)`。
- RTL：阿拉伯语 `<html dir="rtl">`；样式用逻辑属性（`ms-*`/`me-*`/`ps-*`/`pe-*`/`start-*`/`end-*`），方向性图标用 `rtl:` 变体镜像；混排数字、用户名等用 `<bdi>`。
- 字体：按 `:lang()` 选择各语言字体栈（中、日、韩分别用本地字形，泰文、天城文、阿拉伯文优先 Noto 对应字体），不额外加载 Web 字体。
- 范围外：剧名、简介等内容的多语言（需要后台按语言录入，后续单独设计）。

#### A.4.3 放到 CDN 与频繁变更的优化
文案改动频繁，又要放 CDN，目标是「改完几分钟内生效、不用清 CDN、旧页面不出错、CDN 挂了也能显示」：

1. **按内容哈希命名、永久缓存**：发布产物 `i18n/web/<标签>.<hash>.json`，`Cache-Control: public, max-age=31536000, immutable`。内容不变文件名就不变；改文案只产生新文件，旧地址继续有效，不需要清理 CDN 缓存。
2. **只有清单短缓存**：`i18n/web/manifest.json`（< 1 KB）记录每种语言当前文件名与清单版本，`Cache-Control: public, max-age=60, stale-while-revalidate=600`；发布后可只清这一个地址。多 CDN 下也只有清单有不一致窗口，且窗口内拿到的旧清单指向的旧文件仍然可用。
3. **发布顺序**：CI 校验 → 生成哈希文件 → 先上传全部语言文件 → 最后上传清单（客户端不会拿到指向不存在文件的清单）。旧文件保留至少 30 天（旧页面、旧 APP 仍可能引用）。回滚 = 重新发布旧清单。
4. **BFF 读取，浏览器零额外请求**：BFF 进程内缓存清单 60 秒（条件请求），按哈希缓存文案文件（不可变，LRU 常驻）；SSR 把当前语言文案随页面数据下发，浏览器不单独请求文案，也不会先显示键名再闪成文字。CDN 不可用或校验失败时用打包进服务端的内置文案。
5. **合并而不是替换**：远程文案逐键覆盖内置文案，缺键回退内置，再回退中文；远程文件不通过校验（缺键、占位符不一致）整份不启用并告警。
6. **按命名空间拆分（按需）**：单语言超过约 30 KB，或某块文案改得特别勤时，再拆成 `common`、`play`、`me`、`vip` 等命名空间文件，页面只取用到的命名空间；改一处只换一个小文件。现在每种语言 2–4 KB，不拆。
7. **兼容旧版本**：新增键先发文案再发代码；删除键先发代码、确认旧版本（尤其 APP 最低支持版本）不再使用后再删文案。
8. **高频运营文案不进文案包**：活动、公告、广告语、套餐角标说明等由后台按语言配置、随接口下发；文案包只放界面固定文案。

> 当前状态：文案 JSON、校验与哈希产物脚本已实现（`scripts/i18n-build.ts`），线上仍用打包的内置文案；上传 CDN 与 BFF 远程读取见 `11` 任务 X0-7、W0-9。

### A.5 报文加密（浏览器侧）
- 浏览器调用 `/api/v1/*` 一律用 `#lib/crypto/api-client.ts` 的 `secureApi.json()` / `secureApi.secureFetch()`，不要直接 `fetch('/api/v1/...')`（`/api/v1/health` 等 BFF 自身接口除外）。协议见 `10` 第 5.3 节。
- 例外：签发令牌的 `/api/v1/auth/*` 不走加密客户端，由表单动作在服务端明文调用（原因见 A.3.1）。
- 统一入口 `#lib/api/client.ts`：`api.get/post/patch/del` 自动带设备标识 `X-Device-Id`（本机 `xs_did`）与 `Accept-Language`，解包 `{ code, message, data }`，非 OK 抛 `ApiError`；`reserved()` 把「文档里有、后端还没实现」的接口的 404 当空数据处理。
- 播放令牌绑定选源时用的 `X-Device-Id`，所以 hls.js 取清单与密钥必须用同一个标识：用 `deviceSecureFetch` 而不是裸的 `secureApi.secureFetch`，否则后端按「不是签给本设备」返回 403。
- 公钥首次使用时从 `/api/v1/crypto/keys` 取并缓存在内存；`ENC_KEY_UNKNOWN` 时重新取公钥、`ENC_TIME_SKEW` 时按响应 `Date` 校准时钟，各重试一次。
- 加密响应不可被浏览器或 CDN 缓存（每个响应的密钥不同）；需要复用数据时在内存里缓存，或用 ETag 条件请求拿 304。

## B. 页面功能

### 0. 全局外壳（根 layout）
- **顶部头部**：品牌名/Logo（取 `site`）、返回键、搜索入口（占位「搜索剧名」）、「我的」入口（未读角标）、在线客服外链、浅/深色切换。
- **手机底部 tabbar**：图标预设 15 项（首页、刷剧、发现、排行、我的、搜索、剧集、热门、追剧、历史、专题、分类、消息、福利、下载），后台可配，与顶部导航分开。
- **页脚**：帮助与条款、回家的路、防丢地址、版权。
- **全局浮层**：站点公告、年龄确认门、回到顶部、App 下载浮窗（播放页外）。
- **初始化**：SSR 阶段由 BFF 确保游客 Cookie（无则调用 `POST /api/v1/auth/guest`）并在 layout load 中带回 `me.state`，首屏无需客户端再发两次请求。
- **语言菜单**：页头右侧，列出 9 种语言（本族语名称），见 A.4。
- **版本检测**：按 SvelteKit 的 assets 基址轮询 `_app/version.json`（`kit.version.pollInterval`）；使用独立 CDN 时发布任务在全部哈希产物成功后最后覆盖该固定对象，且 CDN 不对它做 immutable 长缓存。站点 `version` 变化后静默刷新数据。
- **标题/面包屑映射**：首页、剧集详情、第 N 集、探索、频道、专题、搜索「词」、我的、消息、说明、回家的路、登录、注册、会员中心、我的订单。标题模板与各语言文案都在 i18n JSON 中。

### 1. 错误页
- 404「内容不见了 / 可能已下架或链接错误」；429「操作太频繁，休息一下」；5xx「服务开小差」；兜底「页面打不开」。
- SvelteKit 3 的错误边界覆盖渲染期错误，区块级组件用 `<svelte:boundary>` 隔离，单个区块出错不拖垮整页。
- 操作：去探索 / 回首页。

### 2. 首页 `/`
- 由后台「页面区块」拼装，10 类区块（轮播大图/精选大卡/海报网格/横滑列表/排行榜/专题组/标签云/广告位/公告条/自定义HTML）。
- 剧类区块三种来源：手选编号、某专题、自动选取（排序/上新/频道交集/维度取值/单标签/数量 1–60 默认 24）。
- 排行区块 2 种：周/月剧集。
- 首屏只 SSR 前 3 个区块，其余区块数据随页面下发但组件按可视区懒挂载；自定义 HTML 区块在沙箱 iframe 中渲染。
- 后台一个区块都没配时**不显示空状态**，而是用探索的热门 / 最新加周榜合成一套默认首页（轮播 + 热播榜 + 猜你喜欢），新站点开箱就有内容；接口整体不可用时才落到空状态「首页内容正在准备中 · 先去探索看看」。

### 3. 探索 `/explore`
- 两个 Tab：剧集 / 专题。筛选：板块、状态、标签、上新（不限/7/14/30/90 天）。排序：最新/最热/推荐/随机。
- 筛选条件写入 URL 查询串（可分享、可缓存）；切换筛选用 `goto(..., { keepFocus: true, noScroll: true })`，结果列表请求带 `AbortController` 取消旧请求。
- 手机筛选抽屉，确认键显示「查看 N 部」[推断]；已选条件 chip 可单删/清空。
- 列表无限滚动 + 虚拟列表（超过 200 项时启用），内插信息流广告。

### 4. 频道/标签/专题
- **频道 `/c/:slug`**：排序 + 分页（上一页/下一页/跳页）+「共 N 部」；第 8 部后插一格图片广告。
- **标签 `/tag/:slug`**：聚合列表；敏感标签需过年龄门，页面输出 `noindex`。
- **专题 `/topics`、`/topics/:slug`**：列表 + 详情（剧列表 + FAQ，FAQ 输出 `FAQPage` 结构化数据）。

### 5. 剧详情 `/d/:id`
- 信息：评分、角标、播放次数、简介（展开/收起）、集数状态。
- 操作：立即观看（有历史变「续看第 N 集」）、追剧、点赞、分享；追剧/点赞做乐观更新，失败回滚。
- 选集：未上架「敬请期待」，登录墙集标「需要登录」。
- 相关推荐；详情页横幅广告（电脑两张并排）。
- 游客 vs 登录差异提示同前版；关闭「游客互动」后游客操作需先登录。
- 卡片去向可配：手机沉浸式 + 电脑详情 / 全部沉浸式 / 全部详情。
- 输出 `TVSeries` + `Episode` 结构化数据与 OG 卡片。

### 6. 播放页 `/play/:id/:n`（最复杂）

#### 6.1 布局
- 电脑：播放器 + 控制条（播放/进度/静音/画质/倍速/弹幕/下一集/全屏）+「竖屏看，滚轮换剧」；侧边选集 + 评论。
- **竖屏视频在电脑端是「高度受限」的**：宽度 = 可用高度 × 比例，所以舞台上下留白压到 1.5rem，侧栏加宽（25 / 30rem）不会把视频挤小。控制条里**收起非必要控件的断点必须按播放器宽度量**（`Player.svelte` 用 `ResizeObserver`，窄于 380px 收起音量条），不能用 `xl:` 这类视口断点——实测视口 1280 时播放框只有 295px，音量条照样显示，整行需要 339px 塞进 263px，时间就被挤到换行。`.ctl` 同理固定 34px，不随视口放大。
- 手机：沉浸式竖屏，右侧按钮列（赞 / 评论 / 追剧 / 分享 / 选集 / 剧集详情）。

#### 6.2 播放设置面板
- 音量、画质（自动 + 各档）、倍速、从头播放、线路；提示「卡住/黑屏就换线或刷新当前线路，会接着原位置放」。

#### 6.3 快捷键 / 手势
- 快捷键：F 全屏、D 弹幕、N 下一集、I 沉浸式、←/→ 跳 5 秒、滚轮或 ↑/↓ 换一部。
- 手势：上滑换一部、左滑下一集、单击暂停、按住 2x、长按设置；边界提示「松手看《下一部》/回《上一部》」「没有更多推荐了」。
- 状态浮层：暂停/播放、±5 秒、音量、倍速、画质、静音、弹幕开关、已是第一/最后一集。
- 手势监听使用 `passive` 事件，滑动动画只改 `transform`，保持 60fps。

#### 6.4 自动播放与声音
- 默认静音自动播放，提示「点画面开声音」；iOS 提示「只能用侧边音量键调音量」[推断]。
- 不支持网页全屏时提示「横过手机看更大」；横屏片源提示「转动手机」。

#### 6.5 续播/连播/试看
- 断点续播：显示「上次看到 X」，可从头播；进度每 15 秒及暂停/切集/`visibilitychange` 时上报。
- 「跳过这一段」（片头/片尾 [推断]）。
- 自动连播下一集；整部看完倒计时「N 秒后播放《下一部》」。
- **连播倒计时的起始条件要带分集校验**：换集时 `data` 先变、`player.load()` 要等读完本机续播位置才调用，这段时间 `player.phase` 还停在上一集的 `'ended'`。只判断 `phase === 'ended'` 会让倒计时在新一集上重新冒出来（用户看到「进了下一集提示还在」），到点还会再多跳一集。判断要加 `player.episodeId === episode.id`；另外任何换集（含点「立即播放」）都要先把 `countdown` 收掉。
- 能不能看：未上架、登录墙、VIP 墙（`NEED_VIP`，非会员看 VIP 集）、试看结束、其他错误五种提示；试看时长由服务端清单控制。VIP 墙展示套餐卡片与「开通会员」，开通后回到原位置继续播放。
- 播放令牌（签名 URL）过期前 60 秒静默重新取源，不打断播放。

#### 6.6 广告
- 播放前贴片（仅电脑、可跳过）、暂停贴片、沉浸流整屏插入。

### 7. 刷剧 `/shua`
- 竖屏沉浸式连播流，从最热开始；滑动换剧；两剧间插整屏广告。复用播放页沉浸式内核。
- 同时最多 3 个 `<video>` 实例（上一条/当前/下一条），其余回收；下一条只预取清单与首个切片。
- **电脑端舞台高度按实际可用高度算**，不是写死 `100dvh - 页头高`：顶上还可能有公告条、旧浏览器提示。挂载时量 `<main>` 的 `offsetTop` 得到被占高度，写进 `--shua-h`（再留 2.5rem 余量），宽度由它按 9:16 推出。原来写死页头高时，一条公告条就能把舞台底部顶出视口，播放控制条跟着跑到屏幕外——而鼠标在这个列表上滚动是「切下一部」、页面不会动，于是控制条永远点不到。`ResizeObserver` 盯着外壳，公告条开关时跟着重算。

### 8. 排行 `/rank`
- 两榜：剧集周/月；每隔几分钟更新，取前 20。条目：热度值、累计播放、N 人关注。可被关闭。
- 版式：标题 + 计分说明 + 更新时间，榜单切换是标题下方的胶囊（当前项品牌色实心）。**前三名**为横向大卡（电脑三列、手机一列）：竖封面 + 左上 `TOP1/2/3` 金银铜标（拉丁字标不进 i18n，读屏走 `rank.position`）+ 剧名 + 评分 / 集数 / 年份 / 累计播放 + 角标 + **热度条**（按榜首归一化）+「看剧」。TOP1 用品牌色描边。**第 4 名起**是电脑两列、手机一列的紧凑列表：名次 + 小封面 + 剧名 + 集数与热度 + 描边「看剧」。
- 列表行只放集数与热度，不再并排累计播放：热度分是内部计分，和播放量数量级相近时两个数字挨着看像重复。接口（`/api/v1/rank`）不返回简介与维度标签，所以大卡用热度条占住那块空间，没有按参考站那样排简介。

### 9. 搜索 `/search`

### 13a. 会员中心 `/vip`
- **当前读模型实现**：浏览器经加密 `GET /api/v1/vip/plans` 读取已上架套餐，按 `code` 映射九语言名称、按 `price_fen` 显示人民币；套餐为空时显示未开放空态，请求失败可重试。`/me` 在登录态确认后单独经加密 `GET /api/v1/me/vip` 显示会员有效/未开通/到期日；失败不伪装成非会员，个人状态不进入 SSR 或边缘缓存。订单与渠道适配未完成前，购买 CTA 保持禁用。

## C. 共享组件

### C.1 播放器内核
- 一律用 hls.js（动态 `import()`，独立 chunk，不进首屏），经 MSE（iOS 17.1+ 为 ManagedMediaSource）播放，`<video>` 的地址是浏览器生成的临时 `blob:`，页面上看不到清单与切片地址。
- 清单与 AES-128 内容密钥走加密接口（`#lib/player/secure-hls.ts` 的自定义加载器只接管同源 `/api/` 请求），切片由 hls.js 默认加载器直接从 CDN 拉取并解密。
- 不支持 MSE 的浏览器（如 iOS 17.1 以下 Safari）不回退原生 HLS（原生播放器取密钥时无法走加密接口），提示「升级系统或浏览器，或使用 APP 观看」。
- 画质「自动」+ 各档；倍速（含临时 2x）；音量/静音/全屏；无画中画 [推断]。
- hls.js 配置：`startLevel` 依据上次测得带宽、`maxBufferLength` 移动端 15s / 桌面 30s、`backBufferLength` 10s（控制内存）。
- 错误：「所有线路都不可用」(重试)、「视频数据出错（非网速问题）」(解码错误)。

### C.2 线路选择与测速
- 线路由后端按客户端 IP（国家/省份/运营商）排序下发（`/api/v1/lines`、`/sources`），标签显示「推荐 / 本地区 / 通用 / 手选」；完整交互见 `12` 第 6 节。
- 自动：先选本区线路，卡顿自动换，提示「原线路变慢/中断，已切换到 X」「线路恢复后自动接回」。
- 手动：记本机，显示「X（手选）」，慢了只提示不自动换。
- 线路菜单标签：播放中/实测最快/地区默认/较慢/暂不可用/你在这里；「刷新当前线路」从原位置续播。
- 测速：并发 `Range` 请求（上限 3 条并行），测前暂停、测完切最快续播；失败原因分超时/被拒/服务器错/清单异常/跨域；429 退避；切集/离开自动取消。
- 诊断面板「详情与报告」：探针结果 + 当前线路 + 结论 + 事件日志（可复制）。
- 首帧、卡顿、失败、切换事件批量上报 `POST /api/v1/lines/report`；图片加载失败时按 `/api/v1/lines?kind=image` 的顺序换下一条线路。

### C.3 弹幕
- 渲染：单个 `<canvas>` 绘制（不为每条弹幕建 DOM），轨道分配避免重叠；页面不可见时暂停。
- 开关快捷键 D；发弹幕（字数上限、颜色）；按 60 秒窗口预取下一窗口。
- 受总开关、屏蔽词、先审后显、禁言约束。

### C.4 评论
- 排序最新/最热，标题「评论（N）」；空态「来抢沙发」。
- 发表（表情来自 `/api/v1/emojis`）、回复、点赞、删除本人；举报原因 7 类；待审「审核中」；手机沉浸式下评论以抽屉打开，抽屉内容懒加载。
- 位置：电脑端侧栏下半块在「选集 / 评论（N）」之间切换（侧栏已占满视口高度，两块并排会把选集挤得没法用）；手机端入口在右侧按钮列。
- 版式（参考主流短视频评论区）：头像在左，昵称小号灰字在上、正文在下，时间与「回复 / 删除 / 举报」在正文下一行，点赞爱心单独在右侧一列（图标 + 计数竖排，触摸区 44px）；回复默认折起，显示「展开 N 条回复」；回复不单独插入输入框，而是把底部输入框的提示换成「回复 某人」，列表不会因此跳动。
- 手机抽屉：`#lib/ui/Sheet.svelte`（分享面板共用），`fill` 时固定高度 76dvh，从底部滑上来、顶部抓手可下拉关闭、列表自己滚动（`overscroll-behavior: contain`）、输入框贴底并避开安全区。**高度必须写死**：内容是异步来的，内容驱动高度会让抽屉顶边一跳一跳。抓手是纯指针增强，不可聚焦、对读屏隐藏（键盘与读屏走关闭按钮与 Esc）——给它 `tabindex` 会让 `showModal()` 把焦点落在上面，全局 `:focus-visible` 的描边会铺成两条横线。
- **抽屉的两个位移属性各管一段**：跟手下拉写在 `translate`（行内样式 + `transition`），进出场动画写在 `transform`（`sheet-up` / `sheet-down`），`will-change` 要把两个都列上，否则另一下拿不到提前提层的提示。**别图省事统一成一个属性**——进出场动画的 `animation-fill-mode` 是 `both`，动画结束后会继续接管那个属性，行内的拖拽位移被它盖掉（动画的层叠来源高于行内样式），下拉关闭就直接失效了。
- 刷剧页 `/shua` 的评论入口在右侧按钮列（「赞」之后），抽屉按**当前在播的那一集**取评论；手机端另有顶部返回条（有来路退回去，直接进来的回首页）。
- **游标坑**：列表接口的 `next_cursor` 没有 `omitempty`，**没有下一页时下发的是空字符串**而不是缺省。判断「还有下一页」一律用真假值（`#lib/comment/thread.ts` 的 `nextCursor`），写成 `!== undefined` 会让无限滚动把空游标当成还有下一页，而拼地址时空游标又被丢掉，于是反复重新请求第一页——实测短评论列表 4 秒内发了 59 次请求、评论区 DOM 变动 237 次，表现为「加载时一直抖」。同理，「结果为空就重试」不能作为取表情的条件（后台没配表情或命中 304 时结果恒为空，写回状态又把 effect 自己触发一遍）。
- 实现偏差（W2-3）：列表接口是游标分页、没有总数，所以还有下一页时标题显示「评论（N+）」；后端没有取消点赞接口，点过即定住；列表接口不含待审内容，自己刚发的待审评论只在本次会话里回显；删除走 5 秒撤销提示而不是二次确认弹窗（与「清空历史」一致，接口没有还原）。
- 评论晒图（V1 及以上）：最多 3 张，选图后在浏览器压缩（长边 1600 px）、直传对象存储并显示进度，提交后整条「审核中」；图片用 `BlobImage` 显示缩略图，点开大图可键盘左右切换、Esc 关闭（`13` 第 3.8 节）。
- 所有用户内容按纯文本渲染（不使用 `{@html}`）。

### C.5 广告组件
- 12 个位置；角标「广告/推广」、「了解详情」、「N 秒后可跳过/跳过」、「关闭广告」。
- 曝光用 `IntersectionObserver`（≥ 50% 可见且 ≥ 1 秒）判定，批量随埋点上报。
- 广告素材固定宽高占位，避免布局偏移（CLS）。
- **取数期间不画骨架屏**：大多数广告位平时是空的，先摆骨架再撤掉会闪一下（用户反馈）。`AdSlot` 只在素材到位后才渲染，没有素材时整块不存在、不占位；代价是有广告时会有一次布局位移，发生在挂载后很早。
- 已接入的位置与落点（`#lib/home/AdSlot.svelte` 为公共组件）：`home_top` / `home_bottom` 首页区块上下、`home_mid` 由后台「广告位」区块编排、`footer_banner` 与 `text_link` 页脚、`detail_banner` 详情页剧集区块之前、`pause` 播放器暂停贴片（第一次暂停才挂载，之后用 `hidden` 收起——`display:none` 时 `IntersectionObserver` 不会误报曝光）、`global_popup` 全站弹窗（`#lib/shell/AdPopup.svelte`，电脑居中 / 手机底部抽屉，**取到素材才弹**，关掉后当天不再弹）、`app_download` 右下角浮窗（`#lib/shell/AdFloat.svelte`，同样取到素材才出现、可关闭）。「今天不再显示」记在本机（`#lib/shell/ad-dismiss.ts`），不含身份信息。
- 非横幅位要传 `aspect`（弹窗 3:4、浮窗 16:9），否则素材按横幅的 3:1 / 6:1 被压扁。
- **仍未接入**：`preroll`（贴片要接播放门控与「N 秒后可跳过」）、`immersive_feed`（插进刷剧流会改动条目索引）、`list_feed`（要插到列表网格内部）。后台能配、接口能返回，但前台没有落点。

### C.6 账号/游客/注册墙
- 登录弹窗/注册墙三好处：进度跨设备同步、追更提醒、游客记录自动并入。
- 注册墙漏斗曝光→点注册→成功（同人同集同日去重）：曝光与点击是 `register_wall` 的 `step=show` / `click`，成功是 `register`（点过墙的归到那一集），见 C.10；汇总只数曝光并按同设备同集同日去重。

### C.7 分享与海报
- 分享面板：复制链接、系统分享（`navigator.share`）、生成海报。
- 海报：Canvas 画「剧名 第N集」+ 二维码，可下载；二维码库按需加载。
- 实现（W3-3 的分享部分）：`#lib/share/SharePanel.svelte` 由 `#lib/drama/DramaActions.svelte` 的分享按钮打开，**电脑是居中弹窗、手机是从底部滑上来的抽屉**（同一个 `#lib/ui/Sheet.svelte`，`center` 控制电脑端形态）。面板内容：海报预览（9:16 固定占位，画好再淡入）、下载海报、复制链接、更多分享。海报在面板打开后才画。
- **抽屉滑入期间不显示转圈**：抽屉滑上来要 300ms，而封面已在本机缓存时海报只要几十毫秒就画好。原先一打开就挂转圈，于是它在滑动途中出现又消失（实测可见约 26–48ms），表现为「滑出之后闪一下」。现在转圈延迟 300ms 登场（`SPINNER_DELAY_MS`，画完即撤计时器）：常见情况下它一帧都不亮，预览区从底色直接淡入海报（实测滑入全程 0 帧占位、不透明度单调递增）；封面真要现解码时（注入 900ms 延迟实测）转圈在抽屉停稳后 +311ms 才出现并持续 617ms，长等待仍有反馈。预览容器的 `aria-busy` 始终如实反映绘制中状态，读屏不受转圈延迟影响。对应 ui-ux `loading-indicators`：不要为近乎瞬时的工作闪现指示器。
- **海报代码目前仍进详情页初始包**：`SharePanel` 里的 `import('./poster.ts')` 本意是按需加载，但同一文件的 `POSTER_WIDTH` / `POSTER_HEIGHT` / `posterFileName` 是静态导入的，Rollup 于是把 `drawPoster` 与二维码编码器并进了 `SharePanel` 所在的 chunk——实测产物 `chunks/Bi1BXUlU.js`（16.7KB，br 6.1KB）被 3 个路由节点以 `from"…"` 静态引用，`nodes/` 里没有任何动态 `import()`。要真正分包，得把尺寸常量与文件名函数挪到不依赖 Canvas / `qr.ts` 的小模块里。
- **二维码不引三方库**：`#lib/share/qr.ts` 是仓库内的最小编码器（Model 2、字节模式、等级 M、版本 1–10，上限 213 字节），照 `#lib/ui/icons.ts` 的做法把需要的表放进仓库，`apps` 保持零运行时依赖。改动二维码编码逻辑后，需用 Chrome 的 `BarcodeDetector` 回读原文验收。
- 版面坐标写死在 `#lib/share/poster.ts` 顶部（720×1280）：封面卡片 2:3、剧名在二维码上方用整幅宽、扫码提示与地址排在二维码左侧。**改任何一块都要重算后面的块**——封面原先按整幅宽算高（912px），下方只剩 236px，扫码提示直接压在剧名上。
- 海报底色取当前主题的 `--brand` / `--canvas` / `--fg`，后台换配色海报跟着变；封面取不到时按剧名画稳定渐变 + 首字（与列表占位一致）。
- 「生成海报」受 `features.share_poster` 控制，关掉时面板只剩复制链接与系统分享。
- 社交卡片图来自 `/api/v1/og/drama/:id`、`/api/v1/og/brand-logo`。

### C.8 通知 / 主题 / 公告 / 卡片
- 主题：浅/深色切换；色板、头部样式、卡片标题位置、底栏、Logo 由后台配，作为 CSS 变量在 SSR 时写入 `<html>`，避免闪烁。实现（W0-6，`docs/specs/W0-6.md`）：
  - **令牌推导**：后台只配六个种子色（主色/强调色/页面背景/卡片背景/正文/次要文字），`#lib/theme/tokens.ts` 推导出界面用的 18 个令牌（四档背景、三档文字、两档描边、品牌三态 + 品牌上的文字色、会员两态）。运营直接填的色值原样使用；推导出的令牌需保持 WCAG AA（正文 4.5:1、次要文字 3:1，品牌/会员底色上的文字自动在黑白里挑）。预设的种子色与后台预览用的那份（`admin/.../branding-utils.ts`）同名同值。
  - **注入**：`hooks.server.ts` 在 SSR 时把**两套**配色写进 `<html style>`——深色 `--d-*`、浅色 `--l-*`，另带 `--card-radius`、`--cover-ratio`、字体前缀 `--app-font-prefix`、关掉手机底栏时的 `--tabbar-h: 0rem`。`app.css` 里每个令牌都是 `var(--d-x, 内置值)`，后端不可用时自动落到内置经典红色板。两套同时在，深浅色切换只是加减 `<html class="light">`，不闪也不用再请求。
  - **深浅色**：SSR 按后台的默认深浅色给出 `class` 与 `data-scheme`（`system` 按深色出），`app.html` 里的同步内联脚本在首帧前按本机 `xs_theme` 偏好与 `prefers-color-scheme` 校正；后台关掉「允许访客切换」时注入 `data-scheme-lock`，脚本忽略本机偏好、页头也不渲染切换按钮。地址栏 `theme-color` 取当前配色的 `--d-canvas` / `--l-canvas`。SSR 输出只依赖后台配置、与 Cookie 无关，页面仍可进边缘缓存。
  - **组件消费**：封面比例 → `aspect-cover` 与 `Poster` 的占位宽高；圆角 → `rounded-card`；页头样式 → 经典 / 居中（三栏网格）/ 胶囊（悬浮圆角条）；卡片标题位置 → 标题在封面下或压在渐变遮罩上（骨架同步省掉下方两行）；底栏开关、Logo / favicon / 版权文字同样来自后台。`play_mode` 已随站点配置下发（`SiteData.layout.playMode`），播放页接入见 W1-3 / W1-5。
- 剧卡：封面、角标、集数状态、播放次数、评分、「看到第 N 集」。
- 空态 `#lib/ui/EmptyState.svelte`、骨架 `#lib/ui/Skeletons.svelte`（grid / rail / list，尺寸与真实卡片一致）、区块级错误边界 `#lib/ui/Boundary.svelte`（`<svelte:boundary>` + 可重试提示 + 控制台日志，`silent` 时不占位）。
- 图片（封面、海报、头像、广告图）统一用 `#lib/media/BlobImage.svelte`：`fetch` 取回后转临时 `blob:` 地址显示，**不加密**，组件销毁时释放地址。默认固定宽高比占位（CLS）；页头自定义 Logo 固定高 32px、按原图比例自适应宽度；首屏前 4 张 `priority`（高优先级），其余进入可视区 300px 内才加载、低优先级；`display:none` 的不加载（如手机上电脑端专用的那张）；支持多条图片线路依次回退；只接受 `image/*`（不接受 SVG）。
  - **按显示尺寸缩放**（`08` 第 5 节）：在交叉回调里拿到排版后的尺寸（不强制重排），宽 × 像素比取到 `#lib/media/image.ts` 的档位，先请求同源的 `/cdn-cgi/image/width=W,…,format=webp/<原图>`，失败再按线路试原图。缩放入口返回非 2xx（站点挂在没接 Cloudflare 的域名上时是 404，`hooks.server.ts` 对 `/cdn-cgi/*` 直接回 404）后本页停用缩放。只缩放 `IMAGE_RESIZE_ORIGINS` 登记的线路。`blurred`（模糊氛围底图，如精选卡、详情页背景）只取最小一档。
  - 同一地址的并发请求合并、最近 48 张复用（`imageCache`）；首页有轮播首图时，其余图片等它画出来再下载（`#lib/media/lead.ts`）。
- **首页轮播首图是唯一的例外**（LCP 元素）：SSR 直接输出 `<picture>` + `fetchpriority="high"`（手机竖封面、电脑横封面按 `media` 二选一），`<head>` 里放同参数的 `<link rel="preload" as="image" imagesrcset>`；它的地址（含 CDN 原图地址）会出现在 DOM 里。缩放入口失败时退回原图，原图也失败只留渐变占位。水合等它画出来再开始（最多 800 ms，`src/hooks.client.ts`）。
- 图片线路须对站点域名返回 CORS 头（缩放失败回退原图时要用），CSP `connect-src` / `img-src` 包含图片域名（缩放地址同源，`'self'` 已覆盖）。OG 分享图、favicon、PWA 图标仍用普通地址（爬虫与系统不执行 JS）。

数据只有一个字段 `drama.badge`（后台「剧资料 → 角标」，`06` 第 5 节）：取值要么是**预设 id**、要么是**自定义文案**，空串不渲染。预设表 `#lib/drama/badge.ts`、配色 `app.css` 的 `.badge-*`、渲染 `#lib/drama/Badge.svelte`。

### C.10 埋点 SDK（W4-1）

数据看板、剧集分析的数据全部来自这里（`POST /api/v1/events` → `event_raw` → 每小时汇总进 `metric_*`，`03` 第 8 节）。看板与剧集分析的窗口到「昨天」为止，**今天上报的数据明天才出现在后台页面上**。

**发送**（`#lib/analytics/`：`track.ts` 入口、`queue.ts` 攒批、`outbox.ts` 关页暂存）
- **埋点代码不进首屏包**：页面与组件一律 `import('#lib/analytics/runtime.ts')` 动态导入这一个入口（根 layout 的 `afterNavigate`、广告位、注册页、回家的路），播放器内核静态引用的只有一个很小的外壳 `playback-lazy.ts`：模块加载完之前的调用连同发生时刻、页面是否可见一起记下，加载后按原时刻重放，首帧耗时与观看时长不受加载快慢影响。只有一个入口，打包器就不会在首屏里另拆零碎的辅助文件（实测拆过一次私有字段辅助函数、一次命名空间辅助函数，各多一个首屏请求）。`playback.ts` 用 TS 的 `private` 而不是 `#` 私有字段，原因相同。
- 调用 `track(type, { drama_id?, episode_id?, props? })`；服务端渲染时什么都不做。
- 攒批：第一条入队后等 2 秒、攒满 20 条、页面隐藏（`visibilitychange` / `pagehide`）时发送；单批 ≤ 50 条；断网与 5xx 最多重试 3 次，4xx 直接丢；队列上限 300 条，满了丢最旧的。页面已隐藏时才入队的事件（结算的观看、CLS / INP）立即发。
- 走报文加密：加密客户端 + 设备标识（`X-Device-Id`，UV 与剧集观看人数都按它去重）+ `fetch` 的 `keepalive`。**不用 `sendBeacon`**：它带不了 `X-Enc` 头。
- **关页不丢、不重**：加密是异步的，页面被卸载时不一定来得及做完（实测整页跳走时做不完，关标签页时有时做得完）。所以页面一隐藏，就把还没交给浏览器的事件同步写进 `localStorage`（键 `xs_evq:<本页随机串>`，每个页面一个键，只存事件本身）；加密客户端在请求发出前同步回调 `onSend`，这一批随即从暂存里拿掉（`keepalive` 请求页面关掉也会送达）；页面回到前台时暂存作废。真没发出去的，下一次打开本站（同一台设备 10 分钟内）时补发，超过 10 分钟的丢掉——服务端按收到的时间记事件，隔太久补会记到错误的时段。例外：整页跳走后页面进了往返缓存（`pagehide.persisted`）时不暂存，避免「后退」恢复后与补发重复；这种页面被浏览器清掉时，还没发出去的会丢。实测（关掉往返缓存的无头 Chrome）：暂停后 0.5 秒整页跳走、直接关掉正在播放的标签页，观看与 CLS / LCP 各到一条，不丢不重。
- BFF 透传 `/api/v1/events` 时不为没有会话的访客签发游客身份（其他写请求会签发），否则每个首访访客都会被建一个游客账号。
- 首屏体积（`bun run budget`，同一份代码去掉本功能做基线对比）：普通页面 +0.2 KB（br），播放页与刷剧页 +0.7 KB。播放页（94.0 → 94.7 KB）与刷剧页（90.0 → 90.7 KB）基线就已达到或超过 90 KB 预算，要在 W5-1 里先给这两页减重。

**事件字典**（类型与后端白名单一一对应；`props` 只放标量，不记查询串、完整来源地址等任何用户输入）

**口径要点**
- 播放尝试结果三分类由汇总推导：成功 = `play_start`，失败 = `stage=pre` 的 `play_error`，其余为起播前流失。
- 观看只累计「真在播且页面可见」的墙钟时间：倍速不放大、缓冲等待与后台播放都不算。
- 刷剧流预加载上下两条，**没有播放意图之前不发任何带剧集编号的事件**（剧集观看人数按「该剧有过任一事件的设备」去重，预加载会虚增它）；预加载时遇到的失败与登录墙等滑到这一条再报。滑走时还没出画面算一次起播前流失，滑回来重新计一次尝试。
- 实现分工：播放器内核（`#lib/player/controller.svelte.ts`，构造时传 `analytics: 'play' | 'feed'`）在各个时刻经 `playback-lazy.ts` 通知 `#lib/analytics/playback.ts` 的 `PlaybackStats`，口径换算全在后者；`load()` 的第三个参数传 `dramaId`（播放页换剧时组件不重建，不传沿用上一次的）。选源被拒时按墙区分：登录墙记一次注册墙曝光，会员墙与分集不可播放（404）不计入播放尝试与失败。来访、浏览与 Web Vitals 在根 layout 的 `afterNavigate`（`visit.ts` 的 `navigated`），注册归因在 `funnel.ts`。

## D. PWA

只取 Service Worker 带来的加载速度与离线兜底，**不做「安装到桌面」**。

- **刻意不提供 web app manifest**：浏览器判定「可安装」的前提之一就是 manifest，没有它地址栏不会出现安装图标、也不会弹安装横幅。`register-service-worker.svelte` 另外监听 `beforeinstallprompt` 并 `preventDefault()`，万一某个浏览器仍然触发也不弹。原 `/manifest.webmanifest` 路由与 `<link rel="manifest">` 已删除。
- 生产构建才注册（`dev` 时直接跳过），缓存名带构建版本：新版激活时删旧缓存并通知页面。
- **源码在 `src/sw/index.ts`，不由 SvelteKit 构建**，而是 `scripts/build-sw.ts` 用 Bun 编译到
  `static/service-worker.js`（构建版本与产物前缀以 `__SW_VERSION__` / `__SW_ASSET_BASE__` 注入）。
  原因：SvelteKit 只要扫到自己管的 SW 入口文件、而 `paths.assets` 又非空，就直接以
  `service_worker_assets` 退出，而带内容哈希的产物要走 CDN 绝对地址（A.5、`14` 第 0 节）。
  **必须在 `vite build` 之前编译并输出到 `static/`**：adapter-bun 的静态路由表是在 `vite build` 时定下的，
  构建之后再往 `build/client/` 里塞文件，文件在磁盘上但 `/service-worker.js` 一律 404。
- 缓存策略（`src/sw/index.ts`）：
  - 产物缓存优先（内容哈希命名，可永久缓存）。产物地址可能是 CDN 绝对地址，所以收录条件是
    `response.type` 为 `basic` 或 `cors`，仍然挡 `opaque`（CDN 的 CORS 没配好时就会退化成它：
    status 恒 0、存了读不出来还占配额）；
  - 导航请求：缓存里的副本不到 10 分钟就直接用，否则先走网络（2.5 秒超时）→ 缓存副本 → `/offline`；
  - 响应头带 `no-store` 或 `private` 的一律不缓存；缓存键是完整地址（含查询串），最多留 40 个页面；
  - `/api/*` 一律走网络：加密响应每次密钥都不同，也含个人数据。
- 预缓存 `/`、`/way-home`、`/offline`。

> 曾用 `ignoreSearch` 的 stale-while-revalidate 会让带查询串的地址命中错误页面（`/explore?sort=hot` 拿到 `/explore` 的缓存），已改成完整地址作键。

## E. 性能要点（详见 `08`）

- 首屏预算：HTML ≤ 50 KB（br），首屏 JS ≤ 90 KB（br），LCP ≤ 2.0s（4G 移动端 P75），CLS ≤ 0.05，INP ≤ 200ms。
- 样式整份内联进 HTML（`inlineStyleThreshold: 160_000`，主样式表约 104 KB / br 约 14 KB），首屏没有渲染阻塞请求；`modulepreload` 由 SvelteKit 自动生成；整页只有一条 preconnect（`hooks.server.ts`）；第三方脚本（统计、广告）`defer` 且在 `requestIdleCallback` 后加载。
- 图片经站点 Cloudflare 区域的 `/cdn-cgi/image/` 按显示尺寸实时缩放（同源，见 C.8 与 `08` 第 5 节）；首页轮播首图输出 `srcset`（手机 360/540/720/1080，电脑 720/1080/1440/1920），其余由 `BlobImage` 按实测尺寸挑一档。
- SSR 页面缓存：首页/列表 `s-maxage=60, stale-while-revalidate=300`；详情 `s-maxage=120`；个人页 `private, no-store`。缓存键不含登录态，个性化数据（追剧状态、续播）由客户端二次请求填充。实现：`hooks.server.ts` 按路由 ID 查 `#lib/server/cache-policy.ts` 的登记表写 `Cache-Control`（浏览器 `max-age=0`，只让 CDN 缓存）；未登记的路由、非 200、写 Cookie 的响应一律 `private, no-store`，新增公共页面要在表中登记；load 里用 `setHeaders` 自定的不覆盖；客户端导航的 `__data.json` 由 SvelteKit 固定为 `no-store`。
- 源站动态压缩（未经 CDN 的流量）：`#lib/server/compress.ts` 用 `node:zlib` 流式压缩（Brotli 质量 5 / gzip），在线程池执行、不缓冲整页，不阻塞事件循环也不打断流式 SSR；静态资源由 adapter 预压缩。
- 首屏体积检查：`bun run build` 后执行 `bun run budget`，按 SvelteKit 构建清单统计每个页面首次访问要加载的 JS（br）与内联样式，超过 90 KB 时失败（CI 接入随 X0-3）。
- `Bun.Image` 用于 BFF 侧生成/缩放分享图，产物写对象存储，不在请求路径实时渲染。

## F. 安全要点（详见 `10`）

- CSP 哈希模式（W0-4）落地时注意：主题令牌写在 `<html>` 的 `style` **属性**上（C.8），哈希管不到行内样式属性，`style-src-attr` 要保留 `'unsafe-inline'`（或改成给 `<style>` 块算哈希，代价是多一段内联样式）。
- CSP 哈希模式 + `frame-ancestors 'none'` + `object-src 'none'`；`connect-src` 仅本站、图片与视频切片域名池；`media-src`、`img-src` 为 `'self' blob:`，`worker-src 'self' blob:`（hls.js 转封装 Worker）。
- `connect-src` 的两个域名池**随 `site-config` 下发、CSP 按请求生成**（契约 0.77.0）。`hooks.server.ts` 每次文档请求取一次站点配置（进程内缓存 30 秒），把 `media.image_bases` / `media.video_origins` 交给 `config/security-headers.ts` 生成 CSP；部署配置 `IMAGE_BASE_URLS`、`MEDIA_CONNECT_ORIGINS` 退为**补充**，与下发的池子合并去重（后台池优先），用于登记「后台把封面 / Logo 填成完整地址」那类不在线路表里的域名，以及后端不可用时兜底。只取 scheme://host:port，填错的地址忽略——CSP 里写坏值会让整条策略失效。**封面受 connect-src 约束而不是 img-src**：`BlobImage` 是 `fetch` 取图再转 `blob:`，域名不在池里生产环境一张封面都出不来；视频切片同理（清单与密钥是本站地址，不受影响）。
  - 同一个池子还用来拼**图片的相对 key**（`#lib/media/image.ts` 的 `imageSources`，`docs/12` 第 6 节）：后台上传的封面在库里是 `img/drama_cover/xxx.webp` 这种相对 key，池子为空时拼不出地址，前台直接退到渐变占位图——**不发请求、没有 404、也没有 CSP 违规**，从前端完全查不出来。这是把域名池从部署期变量改成随配置下发的直接原因（本地实测过：`apps/.env.development` 从来没配 `IMAGE_BASE_URLS`，后台上传的封面一张都显示不出来）。
  - 仍存在的局限：后台可以把封面 / Logo 填成任意完整地址，那类域名不在线路表里，只能继续在部署配置里登记。
  - 图片 / 视频线路必须对站点域名返回 CORS 头，否则即使 CSP 放行也会被浏览器拦（本地实测过：后台把 Logo 填成不带 CORS 头的第三方地址时，Logo 回退到内置标识；同一个域名下也可能是 CDN 边缘缓存里存了一份没有 CORS 头的副本，purge 即可，不必动桶的 CORS 规则）。
- favicon 等 `<link rel="icon">` 必须是普通文件地址：内联成 `data:` 会被 `img-src 'self' blob:` 拦掉（构建时用 Vite 的 `?no-inline` 强制输出文件）。
- 浏览器 `/api/v1/*` 请求报文加密（A.5），BFF 不接触明文；加密只提高抓包和批量抓取的成本，鉴权仍由会话与限流保证。
- 富文本（静态页）由后端清洗后输出；前端**不用 `{@html}` + DOMPurify，改为与自定义 HTML 区块同一套沙箱 iframe**（`#lib/home/SandboxHtml.svelte`，`sandbox="allow-scripts"`、不加 `allow-same-origin`，高度由 iframe 内 `postMessage` 回传，配色读外层 CSS 变量）。好处是不引入新依赖、SSR 不需要 jsdom，隔离强度也比在主文档里清洗更高。唯一仍用 `{@html}` 的地方是 JSON-LD（内容是转义后的 JSON，带 eslint 豁免说明）。
- 关键第三方资源加 SRI；统计代码仅超管可配，且受 CSP 约束。
- 不在 `localStorage` 存任何令牌；本机记录（搜索历史、手选线路、关页时没发出去的埋点暂存）不含身份信息。
