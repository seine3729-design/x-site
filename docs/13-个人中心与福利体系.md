# 13 · 个人中心与福利体系

本文定义用户端（Web、APP）的**个人中心**（收藏、观看历史、点赞、账号设置、会员等级、金币钱包）与**活动专区「福利中心」**（幸运转盘、每日转盘、天天奖券、评论晒图、任务金币墙、推广返利、金币商城）的业务规则、数据模型、接口要点、风控与合规、经济参数和开发计划。

- 决策依据：`adr/0005`；会员与支付见 `03` 第 12 节与 `adr/0004`；账号规则见 `adr/0001`。
- 接口完整列表在 `07`，表结构在本文第 4 节（`02` 第 5.11 节只做索引）。
- 运营后台只用中文；用户端界面文案与活动内容支持 9 种语言。

## 1. 共同原则

1. **只发给注册用户**：游客能看全部活动与规则，领取、抽奖、兑换时弹出注册 / 登录（「注册领新人礼包」）。游客的历史、收藏、点赞只存本机，登录时一次性并入（第 2.2 节）。
2. **服务端定结果**：抽奖结果、任务完成、奖励数量都由服务端判定；客户端只展示和播动画，从不提交金额、概率或结果。
3. **一本账、统一发奖**：金币变动只经过钱包服务；所有奖励经过发奖器，按「来源类型 + 来源单号 + 用户 + 序号」去重，与来源事件在同一数据库事务中完成。
4. **可追溯**：每笔金币、每次抽奖、每次兑换都有记录；后台人工调整需二次验证并审计；每晚对账。
5. **按站点时区计「每日」**：`site_config.timezone`；签到、每日任务、每日转盘、奖券期次都用该时区的日期作为周期键，不看用户设备时区（防止改时区重复领取）。
6. **内容多语言**：活动、奖品、任务、商品的名称与规则存为 `content_i18n jsonb`（`{"zh-CN": {...}, "en": {...}}`），缺语言回退简体中文；界面固定文案在文案包（`04` A.4）。
7. **加密接口**：用户端接口都在 `/api/v1/*`（报文加密，`10` 第 5.3 节）；第三方回调在 `/callback/*`（验签）。
8. **不虚构**：跑马灯、中奖名单、库存、概率只展示真实数据；不用虚假倒计时或「仅剩 1 份」制造紧迫感。
9. **可随时止损**：每个活动单独开关（`features.welfare_*`）+ 全局「暂停发奖」应急开关；预算耗尽自动停发。

## 2. 个人中心

### 2.1 页面结构（Web `/me`、APP「我的」）

| 区块 | 注册用户 | 游客 |
| --- | --- | --- |
| 资料卡 | 头像（含头像框）、昵称、等级徽章、会员状态（到期时间 / 开通）、一行简介、编辑入口 | 默认头像 +「登录 / 注册」+「注册领新人礼包」 |
| 资产条 | 金币余额（→ 钱包）、优惠券张数、成长值进度（→ 等级） | 「注册后可赚金币」 |
| 继续观看 | 最近 10 条历史（横滑） | 本机最近 10 条 |
| 常用入口 | 观看历史、我的收藏、我的点赞、我的订单、消息、邀请好友、福利中心 | 观看历史、我的收藏、我的点赞（本机） |
| 设置 | 账号设置、语言、登录设备、关于与条款、退出登录（与其他项分开，危险样式） | 语言、关于与条款 |

- 首屏只发一次 `GET /api/v1/me/overview`（资料、会员、等级、余额、未读数、优惠券数、各列表计数），`private, no-store`。
- 游客提示条：「记录只存在本设备，登录后自动同步到账号」。

### 2.2 观看历史

| 项 | 游客 | 注册用户 |
| --- | --- | --- |
| 存储 | 本机：Web IndexedDB（库 `xsite`，表 `history`）；APP drift 表 `local_history` | 服务端 `watch_history`（只存注册用户）+ 本机缓存（秒开） |
| 写入 | 每 15 秒、暂停、切集、离开时写本机，不请求服务端 | 同样节奏上报 `POST /api/v1/me/history`（Valkey 合并写、批量落库，`03` 第 6 节） |
| 容量 | 最近 300 部剧，按更新时间淘汰 | 最近 500 部剧，超出由清理任务删除 |
| 字段 | 剧 ID、分集 ID 与集号、播放位置、时长、更新时间、展示快照（剧名、封面 key、总集数） | 同左（快照由服务端补齐） |

- **并入账号**：登录或注册成功后，客户端读取本机游客数据，调用一次 `POST /api/v1/me/local-merge`（历史、收藏、点赞各 ≤ 300 条，请求体 ≤ 64 KB）。服务端按剧去重、保留更新时间较新的一条；晚于当前时间的按当前时间处理，早于 180 天的丢弃；接口幂等。成功后本机游客数据改作账号缓存。
- 并入的记录**不计入**观看时长任务与成长值（防止伪造本机记录刷任务）。
- 列表：按「今天 / 昨天 / 更早」分组；每项显示封面、剧名、「看到第 N 集 mm:ss」、进度条、继续播放；编辑模式多选删除；清空需二次确认，5 秒内可撤销。
- 设置「暂停记录观看历史」：开启后不再写入本机与服务端，续播位置只在当前会话内保留 [推断]。
- 删除：`DELETE /api/v1/me/history?drama_ids=`；清空 `DELETE /api/v1/me/history?all=1`。

### 2.3 收藏（追剧）

- 收藏即追剧：收藏的剧上新集时发站内信 / 推送；界面叫「收藏」，简体中文文案可显示为「追剧」。
- 游客收藏存本机（最多 200 部），登录时并入；注册用户存 `follow`。
- 列表排序：最近更新（默认）/ 最近收藏；角标「更新至第 N 集」「N 集未看」（最新集号与本人历史位置比较）「已完结」。
- 收藏数只计注册用户；游客收藏在并入账号时才计入。

### 2.4 点赞

- 对象：剧、分集（评论点赞不进列表）。
- 游客点赞存本机、不计入公开数，登录并入时计入（与 `02` 第 5.3 节一致）。
- 「我的点赞」：按类型筛选（剧 / 分集）、取消点赞、去播放。

### 2.5 账号设置

| 项 | 规则 |
| --- | --- |
| 头像 | 预设头像库（后台维护）或上传（V1 及以上，走第 3.8.2 节图片管线；审核通过前显示原头像） |
| 昵称 | 2–16 个字符（按用户感知字符计，兼容中日韩、泰文组合符、阿拉伯文）；去首尾空白，禁止控制字符与零宽字符；过屏蔽词（命中 block 拒绝，命中 review 进资料审核，审核期间显示原昵称）；不要求唯一；保留词（「官方」「客服」「管理员」及其他语言对应词）不可用；30 天内最多改 3 次 |
| 个人简介 | 0–80 个字符，纯文本，最多 2 个换行；过屏蔽词（block / mask / review 都生效）；禁止网址与联系方式（屏蔽词分组「引流」+ 正则：网址、QQ / 微信 / Telegram 号）；显示在用户小卡片 |
| 修改密码 | 当前密码 + 新密码（输两次）；新密码 ≥ 8 位、不在弱口令表、不同于当前密码；走认证限流桶；成功后吊销全部会话（含当前）并要求重新登录；页面提示「忘记密码无法找回」 |
| 语言 | 9 种（`04` A.4 / `05` A.6）；注册用户写入 `user.locale`，换设备登录后沿用 |
| 登录设备 | 查看并下线（已有） |

- 接口：`PATCH /api/v1/me/profile`（`avatar`、`nickname`、`bio`），`POST /api/v1/me/password`；错误按字段返回业务码（`NICKNAME_LIMITED`、`CONTENT_REJECTED` 等，第 5 节）。
- 表单：每个输入框有可见标签与字数计数；错误显示在对应字段下方并用 `aria-describedby` 关联；密码框可切换显示并支持密码管理器自动填充。
- 用户小卡片：点评论里的头像弹出（`GET /api/v1/users/:id/card`，公开、可短缓存）——头像与头像框、昵称、等级、勋章、简介；不显示用户名。

### 2.7 金币钱包

| 项 | 赠送金币 | 充值金币（`features.coin_recharge`，默认关闭） |
| --- | --- | --- |
| 来源 | 签到、任务、抽奖、奖券、返利、补偿 | 人民币 / USDT 购买金币套餐（复用 `03` 第 12 节支付） |
| 有效期 | 获得后 180 天（可配置），按批次过期 | 不过期 |
| 退款 | 不可退 | 7 天内未使用的部分可原路退回，套餐附赠的赠送金币同时扣回 |
| 使用 | 商城全部商品、兑换抽奖次数 | 商城中 `payable_with=any` 的商品；不能兑换抽奖次数 |
| 提现 / 转赠 | 不可以 | 不可以 |

- 界面不标注金币的现金价值（不显示「约 ¥x」）。
- 忘记密码重新注册：只有充值金币可凭支付凭证由客服迁移（`adr/0001`、`adr/0005`），赠送金币不迁移。

## 3. 活动专区（福利中心）

### 3.1 入口与页面

- 入口：Web `/welfare`（底栏图标预设已有「福利」）；APP 底部 Tab「福利」。APP 底栏保持 5 项：首页 / 刷剧 / 福利 / 发现 / 我的，「消息」移到「我的」与首页右上角铃铛（菜单可在后台调整，`05` B 节）。
- 页面区块（顺序与显隐由后台配置）：

| # | 区块 | 内容 |
| --- | --- | --- |
| 1 | 资产条 | 金币余额、今日已赚、等级 |
| 2 | 签到 | 7 日进度、今日奖励、签到 / 补签 |
| 3 | 每日转盘 | 剩余次数 + 入口 |
| 4 | 天天奖券 | 今日已领张数、开奖倒计时、上期中奖号码 |
| 5 | 幸运转盘 | 进行中的活动横幅（0–N 个） |
| 6 | 任务金币墙 | 新手 / 每日 / 每周 / 活动（Tab） |
| 7 | 推广返利 | 「邀请好友得金币」+ 我的邀请码 |
| 8 | 金币商城 | 精选商品横滑 + 全部入口 |
| 9 | 评论晒图 | 进行中的晒图活动 + 精选墙入口 |

- 一次请求 `GET /api/v1/welfare/home` 拿到全部区块的当前状态（个人数据，`no-store`）。
- 每个活动都有「规则」页（时间、资格、奖品与概率、上限、发放方式）和「我的记录」。
- 游客：全部区块可见，按钮文案为「登录领取」，点击弹出登录 / 注册。

### 3.2 活动平台底座

**活动配置 `activity`**：类型（`checkin` / `daily_wheel` / `lucky_wheel` / `daily_ticket` / `task_campaign` / `photo_review` / `referral`）、状态（草稿 → 已排期 → 进行中 ⇄ 已暂停 → 已结束）、起止时间、多语言内容（标题、副标题、规则、横幅图）、资格（注册时长、最低等级、仅会员、客户端、允许 / 禁止国家）、预算（每日金币预算、总预算、每人每日上限）、版本号。进行中的活动修改奖池或概率会生成新版本并审计，规则页同步更新。

**奖励类型（发奖器统一发放）**

| 类型 | 参数 | 发放到 |
| --- | --- | --- |
| `coin_bonus` | 数量 | 钱包赠送批次（带有效期） |
| `vip_days` | 天数 | `user_vip` 顺延，会员流水 `reason=reward` |
| `coupon` | 优惠券模板 | `user_coupon` |
| `chance` | 活动 + 次数 | 抽奖次数 |
| `ticket` | 张数 | 当期奖券 |
| `makeup_card` | 张数 | 补签卡 |
| `cosmetic` | 装扮 + 天数（0 = 永久） | `user_cosmetic` |
| `growth` | 成长值 | 等级 |
| `none` | — | 「谢谢参与」 |

- 发奖与来源事件（签到、抽奖、领取、兑换、返利到账）在同一事务；`reward_grant` 唯一键 `(source_type, source_id, user_id, seq)` 保证重放只发一次。
- 发金币前检查预算计数（Valkey：活动每日已发、用户每日已得）；超出时改发兜底奖励（通常为「谢谢参与」）并提示「今日奖励已发完」，记录原因。
- 配置热更新：活动与奖池在进程内 `atomic.Pointer` 缓存，`activity.version` 变化经 Pub/Sub 通知各实例。

### 3.3 每日转盘

- 每天免费 1 次；会员 +1，等级加成见第 2.6 节；次数当天有效，不累积。
- 额外次数：任务奖励；APP 激励视频广告（P4，需接入广告 SDK）。
- 8 格奖品，以小额金币为主（如 5 / 10 / 20 / 50 / 100 / 500），含优惠券、会员天卡（低概率、限量）；「谢谢参与」最多 1 格。
- 交互：点「开始」→ 服务端返回结果 → 转盘 2–3 秒减速停在结果格（只动画 `transform`）；系统开启「减少动效」时直接显示结果；结果用 `aria-live` 播报；请求进行中按钮禁用，防止重复提交。
- 我的记录可查 30 天（服务端保留 2 年）。

### 3.4 幸运转盘

- 活动制：后台按节日或专题创建，限时，可同时进行多个；奖品更丰富（会员周卡 / 月卡、大额金币、装扮、商城券）。
- 次数来源：任务奖励、邀请奖励、活动期间签到赠送、用**赠送金币**兑换（默认 200 金币 / 次，每天最多 10 次）。不能直接用现金或充值金币购买次数（第 6.2 节）。
- 保底：每 10 次（可配）至少抽中一次「中级及以上」奖品；页面显示「再抽 N 次必得」。
- 十连抽：一次请求、一个事务内完成最多 10 次，依次返回结果。
- 每个奖品显示概率与剩余数量；中奖跑马灯只显示真实记录（用户名脱敏，如 `ab***z`）。

### 3.5 抽奖引擎（每日转盘、幸运转盘共用）

| 项 | 规则 |
| --- | --- |
| 奖池 | 每个活动版本一组奖品：奖励类型与参数、权重（整数，合计 1,000,000）、档位（普通 / 中级 / 高级）、总库存、每日库存、每人上限、是否兜底 |
| 随机数 | 服务端 `crypto/rand` 生成 `[0, 1,000,000)` 的均匀随机数，按累计权重选奖；不用伪随机，不用任何客户端数据 |
| 保底 | 用户在该活动「距上次中级」的计数达到 N−1 时，本次只在中级及以上奖品中按权重重新归一后抽取 |
| 降级 | 选中奖品库存不足、达到个人上限或预算超出 → 改发兜底奖品，记录原始结果与降级原因 |
| 事务 | 扣次数（条件更新 `used < granted`）→ 选奖 → 限量奖品条件扣库存（`stock_left > 0`）→ 写抽奖记录 → 发奖 → 更新保底计数，全部在一个事务内 |
| 公示 | `GET /api/v1/activities/:id` 返回当前版本各奖品概率（保留两位小数）与剩余库存；改概率生成新版本，旧版本与其记录保留 |
| 模拟 | 后台「模拟 10 万次」：内存中执行同一算法，输出命中分布、平均每次成本（按奖品参考价值）、预计每日发放量，不写库 |

- 并发：普通奖品不扣库存，只有限量奖品行存在竞争，且抽中概率低，冲突很少。
- `lottery_draw` 按月分区，保留 2 年。

**规则（默认，站点时区）**

| 项 | 默认 |
| --- | --- |
| 期次 | 每天一期：00:00 开始领取，19:50 截止，20:00 开奖 |
| 领券途径 | 签到 +1；当日有效观看满 30 分钟 +1；完成任意 3 个每日任务 +1；有效邀请 +2；会员每日 +1；V5 及以上每日 +1；每人每天最多 10 张 |
| 号码 | 当期从 000001 起按领取顺序编号 |
| 奖项 | 一等奖 1 名（会员月卡）、二等奖 10 名（会员周卡）、三等奖 100 名（500 金币），可配置 |
| 中奖限制 | 同一用户每期最多中 1 个奖：按奖级从高到低分配，已中奖用户的其他号码跳过 |
| 发放 | 开奖后自动发放并发站内信；总张数少于奖项人数时按顺序全部中奖 |

**公开可校验的开奖（承诺—揭示）**

1. 开期：服务端生成 32 字节随机种子（加密保存），公布 `commit = SHA-256(seed)`。
2. 截止：公布总张数与 `tickets_digest = SHA-256(按号码排序、逐行「号码:用户哈希」)`，提供号码清单下载；用户哈希 = `HMAC(期次密钥, 用户 ID)` 前 8 字节，不暴露用户。
3. 开奖：公布 `seed`，按序计算 `h_k = HMAC-SHA256(seed, 期次 ID ‖ tickets_digest ‖ k)`，中奖号码 = `h_k mod 总张数 + 1`，跳过重复号码与已中奖用户，直到填满全部奖项。
4. 开奖页「校验」：浏览器用 Web Crypto 按同一算法复算，结果须与公布的中奖号码一致，且 `SHA-256(seed)` 等于开期时的 `commit`。

种子在截止前不可见，截止后号码清单固定，服务端无法事后挑选结果。

- 举报扩展到图片（`03` 第 5.3 节新增对象类型 `comment_image`）。

#### 3.8.2 用户图片管线（评论晒图、头像共用）

1. 客户端压缩：长边 ≤ 1600 px、质量 0.8（Web 用 `createImageBitmap` + Canvas，APP 用原生压缩）；原图 ≤ 10 MB。
2. `POST /api/v1/uploads/images {purpose, mime, size, sha256}` → 返回上传单号与预签名 POST（暂存桶 `xsite-ugc-staging`，10 分钟有效，策略限制大小与类型）。
3. 客户端直传对象存储（不经业务进程），再调用 `POST /api/v1/uploads/images/:id/complete`。
4. worker（`media` 队列）：按文件头识别类型（JPEG / PNG / WebP / HEIC / AVIF）；像素上限 4000 万（防解压炸弹）；解码并按方向校正；**去除全部元数据（EXIF / GPS / XMP）**；重新编码 WebP（长边 1600 px + 400 px 缩略图）；感知哈希去重与黑名单比对；二维码检测（引流广告）；机审（适配器，服务商在后台配置）→ 通过 / 拒绝 / 人工审核。
5. 通过的图片写入公开桶 `xsite-ugc`，经图片线路分发，前台用 `BlobImage` 显示（不加密，`04` C.8）；暂存桶原图处理后 24 小时内删除；被拒图片保留 30 天（申诉与审计）后删除。

图片处理建议用 libvips（支持 HEIC / AVIF、内存占用低），放在与转封装共用的媒体 worker 镜像中。

#### 3.9.1 邀请与绑定

## 5. 接口要点

完整接口列表见 `07`（「个人中心」「福利」两节）。这里只写容易做错的约定：

- 福利类接口要求注册用户（游客 401 `NEED_LOGIN`）；领取、抽奖、兑换、补签等写接口带 `Idempotency-Key`；限流桶「福利」：每用户每分钟 60 次。
- 抽奖响应：`{ draws: [{ draw_id, slot_index, downgraded, prize: { id, tier, reward_type, reward_value, name } }], chances_left, pity_left }`。客户端按 `slot_index` 对齐转盘格位，不自己计算结果。
- 本机数据并入：`POST /api/v1/me/local-merge {history: [...], favorites: [...], likes: [...]}`，每类 ≤ 300 条；响应各类实际并入的条数；重复调用结果不变。
- 奖券校验数据：`GET /api/v1/tickets/rounds/:id` 返回 `commit_hash`，截止后返回 `tickets_digest` 与 `total`，开奖后返回 `seed` 与中奖号码；`GET /api/v1/tickets/rounds/:id/numbers` 截止后分页下载号码与用户哈希。
- 金额与数量一律由服务端计算并返回；请求体中只有商品 / 活动 / 任务 ID 与数量。
- 新增业务码（同步 `07` 第 4 节，实现时同步两端文案 JSON）：`NOT_ELIGIBLE`、`LEVEL_REQUIRED`、`RISK_REVIEW`、`ACTIVITY_INACTIVE`、`NO_CHANCE`、`ALREADY_CLAIMED`、`TASK_INCOMPLETE`、`INSUFFICIENT_COINS`、`OUT_OF_STOCK`、`BUDGET_EXHAUSTED`、`LIMIT_REACHED`、`NICKNAME_LIMITED`、`INVITE_INVALID`、`CONTENT_REJECTED`、`UPLOAD_INVALID`。

## 6. 风控与合规

### 6.1 风控

| 层 | 措施 |
| --- | --- |
| 资格 | 注册满 24 小时（可配）才能领高价值奖励（会员天数、优惠券）；活动可要求等级、会员、客户端、国家 |
| 设备与网络 | 同一游客设备 ID 每天最多 3 个账号领取同一活动奖励；同一 IP 段每小时领取次数上限；APP 完整性等级为 none 的设备降低上限 |
| 上限与预算 | 每用户每日金币上限（默认 2,000，不含返利）；活动每日 / 总预算；全站每日发放预算；超出即停发并提示 |
| 行为识别 | 观看时长与真实播放事件不符、任务完成过快、领取节奏过于规律、大量新号集中绑定同一邀请人 → 标记，转人工或降级 |
| 人工审核 | 会员月卡及以上奖品、单笔返利超过阈值、命中风控规则的有效邀请 → 进审核队列，通过后才发放 |
| 名单 | 黑名单（用户、设备、IP 段，可设到期）；封禁用户的钱包冻结出账 |
| 止损 | 每个活动单独开关；全局「暂停发奖」应急开关（与挑战模式、写冻结并列，`07` 第 2 节）；每小时发放量突增告警 |
| 对账 | 每晚：钱包（第 4.2 节）、库存（已发 = 总库存 − 剩余）、返利（冻结 / 到账 / 撤回与订单状态一致） |

### 6.2 合规（上线前法务确认）

| 主题 | 设计约束 |
| --- | --- |
| 抽奖与概率玩法 | 次数只来自免费赠送或赠送金币兑换，不能直接付费购买；奖品不可提现、不可转让；公示奖品、概率与保底规则；抽奖记录保留 2 年；仅成年用户（年龄确认门） |
| 推广返利 | 只做一级；只返赠送金币，不发现金；规则页写明奖励条件与上限 |
| 虚拟币 | 金币不可提现、不可转赠、不标示现金价值；如启用充值金币，按预付与虚拟币相关规定处理退款与资金，商店包必须走内购 |
| 应用商店 | 不为评分、下载其他应用发奖励；第三方任务墙与外部支付不出现在商店包；奖励说明符合商店政策 |
| 用户内容 | 晒图先审后显、去除元数据、举报与下架流程；涉及他人肖像可举报删除 |
| 广告宣传 | 不展示虚假中奖信息与虚假库存；规则写明时间、资格、奖品、概率与发放方式 |
| 隐私 | 不新增收集邮箱、手机号、地址；邀请记录与中奖名单只显示脱敏用户名 |

## 7. 经济模型与默认参数

- **参考价值**（只用于预算、模拟与返利折算，不对用户展示）：1,000 金币 ≈ ¥1（按会员天卡 ¥3、商城售价 3,000 金币对齐）。
- **典型收入**：一个活跃用户每天约 200 金币（签到 10–80、每日任务约 150、每日转盘约 20、奖券期望值约 5），兑换一张会员天卡约需 2–3 周。
- **典型消耗**：会员天卡 3,000、幸运转盘次数 200、补签卡 300、装扮 500–5,000。
- **预算规则**：全站每日金币发放预算 ≤ 前 7 日日均广告收入 × X%（后台配置，建议从 20% 起）；每个活动预算独立设置。
- **看板关注**：每 DAU 发放成本、发放 / 消耗 / 过期比、未到期赠送金币总量（按参考价值折算的负债）、商城兑换率、活动参与率、任务完成率、邀请转化漏斗。
- **调参**：所有数值后台可调并写审计；每次只调一个参数，观察一周后再调下一个。
