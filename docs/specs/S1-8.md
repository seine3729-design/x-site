## 接口

| 接口 | 返回 |
| --- | --- |
| `GET /api/v1/hls/:token/index.m3u8` | 主清单：产物里的 `master.m3u8` 原样返回，各档清单是相对地址，播放器解析为 `/api/v1/hls/:token/v{短边}.m3u8` |
| `GET /api/v1/hls/:token/v{短边}.m3u8` | 改写后的一档清单（见下） |
| `GET /api/v1/hls/key/:episode_id/:key_ver?t=` | 16 字节 AES-128 内容密钥，`application/octet-stream` |

清单为 `application/vnd.apple.mpegurl`。三个接口都是 `Cache-Control: private, no-store`（含签名与令牌），出错时返回 JSON 错误包。

## 规则

### 只收加密请求

三个接口在 handler 里检查请求是否经过报文解密（`middleware.IsEncrypted`），明文一律 400 `ENC_REQUIRED`：不受 `API_ENCRYPTION_REQUIRED` 影响（本地开发也一样），SSR 阶段 BFF 的内网明文直连也不放行（SSR 不播放视频）。

### 令牌与观看者

- 校验播放令牌（`playtoken.Keyring.Verify`）：过期 401 `TOKEN_EXPIRED`「播放地址已过期，请重新获取」；格式错误、签名不对、不是签给本设备的（`Claims.BoundTo(X-Device-Id)`）一律 403 `FORBIDDEN`「播放地址无效，请重新获取」，不区分原因。客户端对 `/api/v1/hls/*` 的 401 / 403 都是重新选源，不走登录态刷新。
- 每次请求都重新确认分集仍可播放（剧前台可见、分集有产物），下架立即生效，否则 404。观看权限不重新判定：令牌就是选源时的授权，会员在播放中到期时本令牌内不中断（`03` 第 12.1 节）。
- 令牌不固定产物：选源后到取清单之间重新转封装完成的，按当前产物返回（旧版本密钥仍保留，旧清单里的密钥地址照常可用）。

### 清单改写

- 一档清单必须是主清单里列出的档位，否则 404（不能借此读产物目录里的其他文件）。
- 新 MPEG-TS 一档清单的每个 `.ts` 切片改写为令牌所指线路上的地址；历史 fMP4 的 `#EXT-X-MAP` init 段也继续改写。按线路的签名方式（`12` 第 3.3 节）：`hmac_token` / `cdn_vendor` 对目录前缀 `video/episodes/{集}/{任务}/s/` 签一次，`s3_presign` 逐个预签名（存储源与凭据只取一次），`none` 直接拼公开地址。有效期为线路的 `token_ttl`。
- 每个切片前的 `#EXT-X-KEY` 的 `URI` 从占位符 `xsite-key:{key_ver}` 改为 `/api/v1/hls/key/{集}/{key_ver}?t={令牌}`，`IV` 不变。
- 试看（令牌 `trial_sec > 0`）：只保留结束时间不超过 `trial_sec` 的切片（至少保留第一个），末尾 `#EXT-X-ENDLIST`。播放器播到清单结尾即停，后面的切片地址不出现在清单里；切片按内容哈希命名、不可推测。
- 线路已停用、不是视频线路，或该集产物有就绪副本但不在这条线路的存储源上（迁移、复制状态在选源后变化）时 503 `UNAVAILABLE`「线路暂不可用，请切换线路」，播放器换下一条线路。

### 内容密钥

- 令牌里的分集必须与路径一致，否则 403。`key_ver` 可以是该集任何仍在库里的版本（旧产物播放中的客户端仍会请求），没有时 404。
- 内容密钥用 `MEDIA_KEKS` 解开后直接返回（只在内存中），API 进程启动时解析 `MEDIA_KEKS`，缺失或格式错误时启动失败。
- 限流：每设备（没有设备标识时按 IP，IPv6 按 /64）每集每分钟 20 次，超出 429 + `Retry-After`。hls.js 同一个密钥地址只取一次，正常播放远低于这个数。

### 读取清单原文

- 产物有就绪副本时从副本所在存储源读（用存储源的只读凭据，出站地址经 `netguard` 校验）；没有任何就绪副本时（S1-6f 之前或没有配置主存储时写入默认存储）读默认存储 `S3_BUCKET_MEDIA`。只读清单，单个不超过 4 MiB；读不到时 503。
- 产物目录按转封装任务区分、写入后不再变化，清单原文进 Valkey 读穿缓存 1 小时（singleflight）。改写后的清单含签名与令牌，不缓存。

## 验收

- `11` 的验收：过期令牌 401、试看清单只含前 N 秒、明文请求 400，各有 HTTP 层与领域层测试。
- 清单改写单测：新 TS 切片与历史 fMP4 init 段换成线路地址、密钥地址带令牌、IV 不变、试看裁剪的边界（正好落在切片边界、短于第一个切片）、不认识的地址与格式拒绝；四种签名方式的批量签名单测。
- 真实链路：本地转封装一集样例视频写入 SeaweedFS，经选源 → 加密请求取主清单与一档清单 → 加密请求取密钥，用取回的清单与密钥让 FFmpeg 完整解码；试看清单的总时长不超过试看秒数；变异检查确认测试能发现回归。
  - 实现：`internal/app/hls_e2e_test.go`（`XSITE_E2E_HLS=1` 时运行，命令见文件头）。12 秒 MPEG-TS 样例完整播放解出 360 帧；试看 6 秒时按「结束时间不超过试看值」只保留首个 4 秒切片，解出 120 帧；预签名切片去掉签名后存储拒绝访问；目录前缀签名的每个地址都通过 `VerifyHMACToken` 且指向存在的对象；过期 401、明文 400、线路停用与产物迁走 503、下架 404、没有副本记录时读默认存储、密钥第 21 次 429。15 处变异检查都让测试失败。
- 预签名耗时（300 个切片，arm64 开发机）：逐个 `PresignGet` 约 60ms / 40MB（AWS SDK 每次解析端点都重新编译分区正则，占一半以上）；改为 `blob.Bucket.PresignGetMany`（端点只解析一次，结果与逐个一致，单测覆盖 AWS / R2 / 路径寻址 / 带路径的端点）后约 12ms / 6.7MB；`hmac_token` 约 0.2ms。短剧一集通常 30–90 个切片，暂不做「对象 + 分钟」缓存。

## 假设（需确认）

1. 过期用 401 `TOKEN_EXPIRED`，其余令牌问题用 403 `FORBIDDEN`（不新增业务码）；客户端对 `/api/v1/hls/*` 的这两类错误都重新选源。
2. 试看裁剪取「结束时间不超过试看秒数」的切片（新 profile 为 4 秒切片，最多可能早结束 4 秒），保证试看之外的内容不出现在清单里。
3. 密钥限流每设备每集每分钟 20 次（`03` 第 4.2 节只写了「有限次」）。
4. 取清单与密钥时只重新确认可见性，不重新判定观看权限。
