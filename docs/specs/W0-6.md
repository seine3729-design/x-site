# W0-6 设计系统：主题变量 SSR 注入、卡片、骨架、空态、错误边界

任务：`11` W0-6。验收：**深浅色无闪烁**。
目标：后台 `/brand` 配的品牌、配色、布局（S3-3 / A3-3 已完成）在前台真正生效——配色作为 CSS 变量在 SSR 时写进 `<html>`，首帧就是最终颜色；卡片、骨架、空态、错误边界四类基础组件按配置渲染。

## 决定

1. **令牌注入到 `<html style="…">`，不用 `<style>` 块、不用单独的 CSS 请求。**
   `docs/04` C.8 要求「作为 CSS 变量在 SSR 时写入 `<html>`」。行内 `style` 属性没有额外请求、不阻塞渲染、也不需要给 `<style>` 算 CSP 哈希。
   代价：W0-4 把 CSP 改成哈希模式时，`style-src` 要保留 `style-src-attr 'unsafe-inline'`（行内样式**属性**不受哈希保护，CSP3 由 `style-src-attr` 单独管）。写在 `docs/04` F 节里，留给 W0-4。
2. **两套配色同时注入，用 `--d-*` / `--l-*` 两组前缀。**
   行内 `style` 属性只有一个作用域，没法同时写 `:root` 与 `:root.light`。所以注入 `--d-canvas`、`--l-canvas`…，`app.css` 里 `:root { --canvas: var(--d-canvas, 内置值) }`、`:root.light { --canvas: var(--l-canvas, 内置值) }`。
   好处：深浅色切换只是加减 `<html class="light">`，两套颜色首帧就都在，切换不闪、不需要再请求；后端挂了则整组变量缺失，自动落到 `app.css` 的内置经典红（兜底可见、不是黑屏）。
   代价：HTML 多约 900 字节（br 后约 300 字节，首屏 HTML 预算 50 KB）。
3. **色板 = 6 个种子色 + 推导。** 后台只给 `primary`/`accent`/`bg`/`surface`/`text`/`muted` 六个可配色（`docs/06` 第 16 节），而界面需要 18 个令牌（四档背景、三档文字、两档描边、品牌三态、会员两态、品牌/会员上的文字色）。推导规则写在 `#lib/theme/tokens.ts`：按明度步长推背景层与 `fg-subtle`，描边用文字色加透明度，`brand-fg`/`vip-fg` 用「调整明度直到对比度 ≥ 4.5:1」，`on-brand`/`on-vip` 在黑白里挑对比度高的那个。
   为什么不让后台配 18 个：运营配不出协调的 18 个色；也不写死 5 套完整色板：改一个预设要维护 36 个值。
4. **运营直接填的色值原样使用，推导出来的保证对比度。** 运营填了 `text=#888` 配 `bg=#fff` 就是他要的效果（后台预览里看得见），前台不偷偷改；但 `fg-subtle`、`brand-fg`、`on-brand` 这些他看不见、改不着的，一律兜到 WCAG AA（正文 4.5:1、次要文字 3:1），由单测逐个预设 × 深浅色校验。
5. **预设种子色与后台预览用的同一份值**（`admin/src/features/platform/branding-utils.ts` 的 `PRESET_PALETTES`、`LIGHT_OVERRIDES`）。A3-3 当时在后台另存了一份预览色板，说明「真实色板由前台 CSS 变量定义」；如果前台另挑一套，后台预览就是在骗运营。两边同名同值，差异只在前台会多推导出 12 个令牌。
   浅色的中性色（背景 / 文字）五个预设共用一套，与后台预览一致；只有 `primary`/`accent` 按预设走。
6. **`color_scheme` 的解析分两步：服务端出默认，客户端出最终。**
   SSR 按 `dark`/`light` 决定 `<html class>`（`system` 按深色出），`data-scheme` 带上原始配置；首帧前的内联脚本再按 `localStorage` 偏好与 `prefers-color-scheme` 校正。SSR 输出只依赖后台配置、不依赖 Cookie，页面仍可进边缘缓存（`docs/04` E 节）。
   `allow_scheme_toggle=false` 时注入 `data-scheme-lock`，脚本忽略本机偏好、页面不渲染切换按钮——否则运营关了开关，老用户的 `localStorage` 还在，等于没关。
7. **`theme-color` 从注入的变量读，不再硬编码两个色值。** `app.html` 的脚本与 `#lib/stores/theme.ts` 都读 `--d-canvas` / `--l-canvas`（行内属性上的自定义属性在样式表加载前就可读），配色一改，手机地址栏颜色跟着改。
8. **`mobile_tabbar=false` 用注入 `--tabbar-h: 0rem` + 不渲染底栏两步做。** 页脚与沉浸式页面的底部留白都是 `calc(var(--tabbar-h) + …)`，把变量置零就不用改各处样式。
9. **`play_mode` 本次只下发、不消费**：它决定播放页形态，属于 W1-3 / W1-5。`SiteData.layout.playMode` 先放上去，播放页接入时直接取。
