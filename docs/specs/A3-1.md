# 框架组：静态页、前台菜单与防丢地址、页面区块

任务：`11` S3-1（区块编排）、S3-2 剩余部分（菜单、静态页、防丢地址）、A3-1（后台区块编排页面）、A3-2 剩余部分（前台菜单与防丢地址、静态页页面）。

目标：运营能在后台维护静态页、前台菜单与「回家的路」地址、拼装首页与频道页的区块，前台（Web、APP）通过 `/api/v1` 一次取到菜单与区块数据。

## 数据（新迁移，编号写入时按当时最大号加一；当前最大 00023）

- `page`（`02` 第 3.3 节）：`id, title(1–100 字), slug unique, body(清洗后的 HTML), body_format(rich/html), status(draft/published), seo_title, seo_desc, is_footer, created_at, updated_at`。
- `menu`（`02` 第 3.2 节）：`id, position(top/mobile_tabbar/mobile_drawer/footer), label(1–20 字), link_type(internal/page/channel/topic/tag/external), link_value, group_title(页脚分组), icon, tabbar_icon, badge, visible_to(all/auth/guest), device(all/mobile/desktop), new_tab, status(active/inactive), sort, created_at, updated_at`。索引 `(status, position, sort)`。
- `block`（`02` 第 3.1 节）：`id, page(home 或 channel:{term_slug}), type(carousel/feature/poster_grid/h_scroll/rank/topic_group/tag_cloud/ad/announce/custom_html), title, subtitle, item_limit(1–60，默认 24), status(active/inactive), more_link, cols_desktop(2–8), device(all/mobile/desktop), source_type(manual/topic/auto), source_json jsonb, custom_html, sort, created_at, updated_at`。索引 `(page, status, sort)`。`limit` 是 SQL 保留字，列名用 `item_limit`。

## 规则

- **静态页**：`slug` 全站唯一、与前台 `/p/:slug` 对应，校验同剧集 slug（小写字母、数字、连字符）。正文两种格式都按同一 HTML 白名单清洗后入库（复用广告的 bluemonday 策略），清洗后为空则拒绝；草稿不对前台下发（`GET /api/v1/pages/:slug` 返回 404）。删除不可恢复，删除时相关菜单项自动隐藏（见下）。
- **前台菜单**：
  - 链接类型与 `link_value`：`internal` 为站内页白名单（`home` / `shua` / `explore` / `rank` / `topic` / `search` / `me` / `way_home`）；`page` / `channel` / `topic` / `tag` 为对应记录的 slug，保存时校验存在；`external` 为 http(s) 完整地址。
  - 目标失效时自动隐藏（`06` 第 12 节）：静态页删除或改回草稿、频道取值停用或取消「设为频道」、专题草稿、标签隐藏或已合并时，下发层过滤掉该菜单项；后台列表标出「目标不可用」并说明原因，记录本身保留。
  - `tabbar_icon` 只有 `mobile_tabbar` 用；`group_title` 只有 `footer` 用；手机底栏最多 5 项（`04` 导航规范）。
  - 顺序按位置分别排（`POST /menus/reorder` 传某个位置下的全部编号）。
- **防丢地址**：`site_config.addresses` 段 `{notice, latest_url, permanent_url, backup_urls[≤3], publish_page, support_url, telegram, socials[]}`；地址只允许 http(s)。保存走 `SiteConfigService.BumpVersion`（version+1 + 清二级缓存 + Pub/Sub 广播），各实例秒级生效。
- **页面区块**：
  - 页面：`home` 或 `channel:{term_slug}`（取值必须是启用的频道）。同一页面内按 `sort` 排序。
  - 剧类区块（`carousel` / `feature` / `poster_grid` / `h_scroll`）三种来源：`manual`（`{drama_ids}`，按给定顺序，不可见的剧跳过）、`topic`（`{topic_id}`，复用专题选剧，含自动专题规则）、`auto`（`{sort, window, channel_ids[], term_code, tag_id}`，复用自动专题的选剧实现）。
  - 非剧类区块不需要来源：`rank` 要 `{rank_board}`、`ad` 要 `{ad_slot}`、`announce` 要 `{announce_kind}`、`tag_cloud` 可给 `{tag_ids}`（不给则取热门标签）、`topic_group` 给 `{topic_ids}`（不给则取列在专题列表页的专题）、`custom_html` 用 `custom_html` 正文。
  - `custom_html` 区块要 `blocks.custom_html` 权限（规则同广告：新建、改成 custom_html、修改原本就是 custom_html 的区块都要；删除只要 `blocks.edit`），保存时按白名单清洗，前台只在沙箱 iframe 渲染。
  - 前台一次返回该页面全部启用区块及其数据（S3-1 验收）。`ad` 与 `announce` 区块只给参数（slot / kind），素材由前台另调 `/api/v1/ads`、`/api/v1/announcements`：它们按设备频控、按语言定向，不能放进共享缓存的区块接口。
  - 下架的剧、停用的取值、草稿专题不出现；某个区块取数失败不影响整个接口（该区块返回空列表并记日志）。

## 切片

1. **静态页**：迁移 → 校验与清洗、仓储 → 后台 CRUD 与前台读接口 → 后台页面 `/pages`。
2. **菜单与防丢地址**：迁移 → 链接校验与「目标失效过滤」→ 后台 CRUD、排序、`GET/PUT /addresses` → 菜单与地址随 site-config 下发 → 后台页面 `/menus`。
3. **页面区块**：迁移 → 区块校验与来源解析（纯函数）→ 后台 CRUD、排序 → 前台 `GET /api/v1/home` → 后台页面 `/blocks`（选页面、类型表单、拖拽调序、预览）。
4. 契约（`openapi.yaml`，从 0.30.0 起）与 `02` / `03` / `04` / `06` / `07` / `11` 同步，随每片进行。

每片：领域层单测、HTTP 层测试（权限点、CSRF、状态码与业务码、审计）、PostgreSQL 集成测试；curl 实测；后台页面无头 Chrome 实测（含只读角色）。

## 验收

- 首页接口一次返回全部区块（S3-1）：一次请求拿到各区块的类型、标题与数据，剧类区块三种来源都有数据，`ad` / `announce` 区块给出参数。
- 菜单目标失效自动隐藏：把静态页改成草稿或停用频道取值后，前台 `site-config` 的 `menus` 段里对应项消失，后台列表标出「目标不可用」。
- 防丢地址保存后 `site_config.version` +1，各实例秒级拿到新地址。
- 没有 `blocks.custom_html` 权限的角色不能建或改自定义 HTML 区块（403）；脚本、事件属性、`javascript:` 链接被清洗。
- 后台三个页面：只有查看权限时只读并说明原因；输入框与下拉框都有占位提示、等宽等高；菜单与区块支持拖动 / 方向键 / 上移下移调序。

## 决定（建议，待确认）

1. **菜单的下发方式**：并入 `GET /api/v1/site-config` 新增 `menus` 段（`07` 第 1 节本来就写的是「白标/主题/**菜单**/功能开关/年龄门」），不新开接口。理由：每个页面都要用、变更极少，复用现成的三级缓存、ETag 与跨实例失效，前台少一次请求。代价是改菜单会让整份站点配置的 ETag 失效（设置类数据，可接受）。同时新增 `footer_pages` 段（`is_footer` 且已发布的静态页 `{slug, title}`），供页脚「帮助与条款」使用。
2. **菜单不按身份裁剪**：站点配置是共享缓存的公共数据，不能按登录态或设备裁剪，因此下发全部启用项并带上 `visible_to` 与 `device`，由前台判断显示（与公告「出现页面与频率由前台判断」一致）。
3. **区块数据的边界**：剧类、`rank`、`topic_group`、`tag_cloud` 区块内嵌数据（都是公共数据，能省请求）；`ad`、`announce` 区块只给参数。区块接口用 Valkey 读穿缓存 60 秒 + ETag，后台增删改区块后立即清除。
4. **代码位置**：新建领域包 `internal/domain/site`（`page.go`、`menu.go`、`block.go`、`home.go`），`store/pg/site.go`、`http/admin/site`、`http/public/site`。区块取数依赖内容与榜单，用接口注入（`DramaSource`、`RankBoardReader`），不反向依赖 `domain/content` / `domain/ops` 的具体类型。

## 假设

1. 静态页正文的富文本编辑器在后台按需懒加载（A3-2 验收要求），先用受限工具栏（标题、粗斜体、列表、链接、图片地址、引用、代码块）；`html` 格式用纯文本域直接写 HTML。两种格式入库都清洗。
2. 静态页与菜单都是设置类数据，删除不进回收站（与公告、广告一致）。
3. 手机底栏图标（`tabbar_icon`）与菜单图标（`icon`）填 lucide 图标名，前台按名字渲染；填错时前台按默认图标兜底。
4. 区块的「预览」在后台按契约数据渲染一个简化版（卡片占位 + 标题），不内嵌真实前台组件。
