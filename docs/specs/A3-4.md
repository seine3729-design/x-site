任务：`11` A3-4（广告位、排行干预、热搜词）与 A3-2 中的公告，以及它们依赖的后端：S3-6（广告）、S3-5（榜单）、S3-4 中的热搜词、S3-2 中的公告。资讯不做（S3-7）。
目标：运营能在后台投放广告、发公告、维护热搜词、干预榜单，前台（Web、APP）能通过 `/api/v1` 读到并上报计数。

## 数据（新迁移，编号写入时按当时最大号加一）

- `announcement`：`id, kind(topbar/popup/inbox), content(1–500 字), click_url, frequency(always/once/daily), pages text[]（空 = 全部页面）, image, start_at, end_at, status(active/inactive), created_at, updated_at`。
- `ad`：`02` 第 3.4 节的字段 + `locales text[]`（空 = 全部语言）+ `created_at, updated_at`；`html` 只存清洗后的结果；`weight` 1–100（默认 10）；`freq_cap` 0 = 不限；素材按类型必填（表约束）。
- `hotsearch`：`id, word(规范化后唯一), search_count, miss_count(搜了但片库没有的次数), pinned, pin_sort, visible, source(manual/auto), last_searched_at, created_at, updated_at`。
- `rank_override`：`board(drama_week/drama_month), drama_id, pinned, blocked, boost`，PK `(board, drama_id)`，删剧级联删除。
- `site_config` 增加 `ranking jsonb`：`{play, follow, like, finish}` 四个系数（`02` 第 3.6 节已列出该段，表里还没有这一列）。

## 规则

- **公告**：生效 = 显示中且当前时间在开始、结束之间（可不填）。前台按「出现页面」与「频率」决定显示（每人一次、每人每天一次的记录存在客户端本机）；同一页面有多条弹窗时只弹最新的一条。出现页面的取值：首页、探索、频道、标签、专题、剧详情、播放、刷剧、排行、搜索、我的。
- **广告**：
  - 投放：只取投放中、未过结束时间、端匹配的；每个位置按权重加权随机取 `n` 条（默认 1，最多 5）；频控按设备、按天（北京时间）计曝光次数，到上限后当天不再下发。
  - 计数：同一设备、同一广告、同一种事件 1 秒内只计一次；先在 Valkey 累加，worker 每分钟落库，后台显示的数字最多晚 1 分钟。
  - 自定义 HTML：新建、改成 HTML、修改原本是 HTML 的广告都要 `ads.custom_html` 权限（默认只有超级管理员），删除只要 `ads.edit`；保存时用 `bluemonday` 白名单清洗（清洗后为空则拒绝），前台只在沙箱 iframe 中渲染。新增依赖 `github.com/microcosm-cc/bluemonday` v1.0.27（固定版本）。
  - 跳转地址与素材地址只允许站内路径（`/` 开头，不能是 `//`）或 `http` / `https` 地址；素材按类型必填（图片、视频、文字、HTML 四选一），只保存该类型用得到的字段。
  - 新建、修改、停用后前台立即生效（清掉广告候选的缓存）；删除不可恢复。
- **热搜词**：搜索词规范化（全角转半角、转小写、去首尾与连续空白，≤ 50 字）后计数；热搜榜 = 置顶的词（按拖拽顺序）+ 显示中的词按搜索次数倒序，共 10 个。置顶的词一定显示（置顶时自动显示，不显示时同时取消置顶），最多置顶 10 个。删除连搜索次数一起删，之后再被搜到会重新出现。后台可筛「片库没有」（`miss_count > 0`）作为选品参考。
- **排行**：分数 = 播放 × 系数 + 追剧 × 系数 + 点赞 × 系数 + 看完 × 系数；不让上榜的剧不出现在该榜；加分直接加到分数上；置顶的剧排在最前，多部置顶之间按分数排；只算已上架、前台可见的剧。重算写入新的 Valkey 有序集合后原子 `RENAME`，读接口没有空窗。改了干预或系数要重算才生效（后台保存后可「马上重新排名」）。`features.ranks` 关闭时前台榜单接口返回 404。

## 切片

1. 公告：迁移 → 领域规则与仓储 → 后台接口与前台接口 → 后台页面。
2. 广告：迁移 → 校验、清洗、投放与频控 → 后台接口、前台接口与事件计数 → 落库任务 → 后台页面。
3. 热搜词：迁移 → 规范化与计数 → 后台接口与热搜榜接口 → 落库任务 → 后台页面。
4. 排行：迁移 → 计分与干预（纯函数）→ 重算任务与有序集合切换 → 后台接口与前台接口 → 后台页面。
5. 契约（`openapi.yaml`）、`02` / `03` / `06` / `07` / `11` 同步。

每片：领域层单测、HTTP 层测试（权限点、CSRF、状态码与业务码、审计）、PostgreSQL / Valkey 集成测试；curl 实测；后台页面无头 Chrome 实测（含只读角色）。

## 验收

- 频控按设备生效：同一设备当天曝光达到上限后不再下发该广告，换设备仍下发（S3-6）。
- 重算期间读接口无空窗：重算过程中并发读榜单始终有数据（S3-5）。
- 自定义 HTML 中的脚本、事件属性、`javascript:` 链接被清洗掉；没有 `ads.custom_html` 权限的角色不能建或改 HTML 素材（403）。
- 后台四个页面：只有查看权限时只读并说明原因；表单输入框与下拉框都有占位提示、等宽等高。

## 决定（已确认）

1. **范围**：后端（表、后台接口、前台读接口与计数、worker 任务）+ 后台四个页面；Web / APP 的展示组件不在这次。
2. **多语言**：`04` A.4.3 第 8 条要求公告、广告语按语言配置，`02` / `06` 原只有一份文案。做法：广告与公告各加「投放语言」`locales`（不选 = 全部语言），需要多语言时按语言各建一条；前台请求带 `locale`。
3. **榜单的计分数据**：计分来源做成接口；埋点（S4-1 / S4-2）与追剧、点赞（S2-3）就绪前，播放数暂用剧的热度分（初始播放量 + 真实播放量），追剧、点赞、看完按 0，因此周榜与月榜暂时相同。
4. **热搜词**：自动收录的词默认不显示，运营勾选「显示」后才进热搜榜；后台手动加的词默认显示。

## 假设

1. 频控与事件去重的设备标识：游客身份（S1-10）上线前，用客户端生成并存在本机的设备 ID（请求头 `X-Device-Id`，UUID）；没有时退化为「IP 段 + UA 摘要」。S1-10 上线后改用游客令牌中的设备 ID。
2. 广告图、公告配图先填资源路径或图片地址，图片上传随存储任务提供（与 A1-2 一致）。
3. 排行默认系数：播放 1、追剧 3、点赞 2、看完 2（可在后台改）。
4. 后台列表用页码分页；热搜词置顶的顺序、干预列表一次返回全部。
