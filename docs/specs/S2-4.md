## 机制

### Aho-Corasick 自动机（进程内常驻、原子替换）
`matcher.go` 实现一个构建后不可变的 AC 自动机：`BuildMatcher([]WordSpec) *Matcher`，`Matcher.Scan(text) []Hit`（返回全部命中，含重叠）。多模式串匹配一次扫描 O(文本长度 + 命中数)，与词表规模无关。
- **规范化**（匹配前与入库前一致）：全角空格转半角、全角 ASCII 转半角、转小写、丢弃零宽字符（U+200B–200D、U+2060、U+FEFF、U+00AD）。`normalizeText` 同时返回每个规范化字符对应的**原始 rune 下标**，所以 `Hit.Start/End` 指向原文区间（覆盖夹在中间的零宽字符），`mask` 能按原文打码。
- **原子替换**：`Service` 用 `atomic.Pointer[Matcher]` 持有当前自动机。词表变更后整体重建一个新自动机、`Store` 替换指针，读侧（`Matcher()` / `Scan`）无锁并发安全。
- **跨实例重建**：词表变更后 `Service.refresh` 先本实例重建、再经 `cache.Invalidator.Publish(BlockwordTopic)` 广播；各实例在 `app.go` 的 `invalidator.Subscribe` 回调里收到 `blockword` topic 调用 `OnInvalidate`（= 从库重载重建）。进程启动时 `app.go` 调一次 `Reload` 载入词表（失败视为启动错误）。
- 复用 S1-9 的失效总线（`SiteConfigTopic` 同一套 `xsite:invalidate` 频道），没有新增基础设施。

### 后台管理（docs/06 第 27 节）
`GET /api/admin/blockwords`（分组 / 处理办法 / 词筛选，页码分页）、`GET /api/admin/blockwords/groups`（已有分组，供筛选下拉）、`POST /api/admin/blockwords`（加词）、`DELETE /api/admin/blockwords/{id}`（删词）。
- word 入库前规范化并存规范化形式；`word` 唯一，重复加词返回 409（**改处理办法 = 先删再加**，所以没有更新接口）。
- 权限：读 `blockwords.view`、写 `blockwords.edit`（`admin.RequirePage("blockwords")`）；写操作记审计 `blockword.create` / `blockword.delete`。
- 前端 `/blockwords` 页面：列表（词、分组、处理办法徽章、加入时间）、分组与处理办法筛选、加词对话框（词 + 分组 + 处理办法下拉）、删除确认。侧栏菜单由后端 `/api/admin/me/menus` 驱动（00003 已配）。

## 验收

- `11` 的「1 万词表单次匹配 < 50µs」：`TestMatcher_Performance` 构建 1 万词自动机，对 141 字代表性文本重复匹配，实测**单次平均 2.9µs**，远低于 50µs。
- 单测：`matcher_test.go`（重叠命中、全角 / 大小写 / 零宽字符规范化、原文区间定位、确定顺序、性能）；`blockword_test.go`（创建规范化 + 409、校验、删除后重建、`OnInvalidate` 重载、列表校验）；`community_test.go`（HTTP 层权限点声明与 view/edit 边界、列表参数透传、创建 / 删除审计、未知字段 400、409 映射）。
- 集成：`store/pg`（新增 + 唯一冲突 + 分组 / 办法 / 词筛选 + ListAll + 分组去重 + 删除）。
- 后台前端：`admin` typecheck、lint（0 error）、build 通过。
- 本机真实容器端到端（admintool 建临时超管 → 登录拿会话 + CSRF）：`POST /api/admin/blockwords` 传「全角大写带空格」→ 入库规范化为 `vpn`；重复 → 409；空词 / 非法 action → 400；加 review 词 → 200；按分组列表 total=3；`DELETE` → 200 且审计落库 `blockword.create` / `blockword.delete`；DB 核对 word 规范化正确。测试数据与临时超管已清理。
- 回归：`go build ./...`、`go vet ./...`、`go test ./...` 通过。

## 假设（需确认）

2. **领域归属**：屏蔽词放 `internal/domain/moderation`、后台放 `internal/http/admin/community`（社区组），评论 / 弹幕 / 举报 / 用户随 S2-5 起进同一域与分组。
3. **匹配接入点不在本任务**：引擎暴露 `Service.Scan(text) []Hit` 与 `Matcher()`；评论 / 弹幕（S2-5）、昵称 / 简介（S2-9）、采集剧名（S4-6）调用时各自按 scope 决定哪些 action 生效（docs/03 第 5.5 节：mask / review 仅评论 / 弹幕，采集只认 block）。
4. **改处理办法 = 先删再加**（docs/06 第 27 节）：word 唯一、无更新接口；前端删除确认里提示这一点。
