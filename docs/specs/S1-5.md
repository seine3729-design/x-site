# S1-5 媒体转封装任务（历史 fMP4 Profile）

> 该规格记录历史 CMAF/fMP4 产物的兼容约定。自 S1-5b 起，新上传统一使用 MPEG-TS HLS；当前实现与验收见 `S1-5b-MPEG-TS-HLS.md`。

任务：`11` S1-5。依赖 S0-8（River，已完成）、S0-9（对象存储基础客户端）、X1-1（测试素材库）；后两项未完成，作为本任务的前两个切片一起完成。
目标：把一集的源视频转成加密的 CMAF（fMP4）HLS：2 秒切片、多码率阶梯、首帧图、AES-128 加密，上传对象存储并回写分集，任务可重试且幂等（`03` 第 9.6 节、`08` 第 2.1 节、`10` 第 7 节）。

## 范围

| 部分 | 内容 |
| --- | --- |
| S0-9 | `internal/store/blob`：S3 兼容客户端（Put / Get / Head / Delete / 按前缀删除），本地 SeaweedFS 读写通过；S1-6a 的存储源适配器在它上面实现 |
| X1-1 | `cmd/mediatool fixtures`：用 FFmpeg 生成 10 部样例源视频（不同比例、时长、码率、帧率、有无音轨、旋转元数据、HEVC 源），连同 `manifest.json` 上传到 `xsite-assets/fixtures/` |
| 转封装 | `internal/transcode`：下载源文件并计算 SHA-256 → ffprobe 探测 → 按源选码率阶梯 → 一次 FFmpeg 解码、多路 H.264 编码出 fMP4 HLS → 首帧 WebP → Go 内逐片 AES-128 加密并按内容哈希命名 → 上传 → 生成主清单与各档清单 |
| 任务 | River `media` 队列任务 `media_transcode`：最多 4 次（首次 + 重试 3 次），用尽后记 ERROR 日志（告警通道随 X4-1）；`transcode_job` 表记录状态、进度、错误 |
| 密钥 | 每次转封装生成新的 16 字节内容密钥，按分集递增 `key_ver`，用 `MEDIA_KEKS` 派生的 KEK（AES-256-GCM）包装后存 `media_key` |
| 后台接口 | `POST /api/admin/episodes/:id/transcode`、`GET /api/admin/transcode-jobs`、`GET /api/admin/transcode-jobs/:id`（权限点 `dramas.edit` / `dramas.view`） |
| 规则调整 | 「更新至 N 集」改为只算可播放（`media_status = ready`）的分集（`03` 第 3.1 节、S1-3 假设 3） |

范围外：清单重写、密钥接口、试看裁剪（S1-8）；选源与播放令牌（S1-7）；存储源 / 线路 / 副本 `media_replica` 与复制（S1-6a、S1-6f，本任务直接写 `S3_BUCKET_MEDIA` / `S3_BUCKET_ASSETS`）；HEVC / AV1 高效档、AVIF 首帧图、水印；旧产物清理（S1-6f / S4-7）；KMS 信封加密（S2-8）；后台转封装页面（A1-5）；开放平台任务查询（S4-6）。

## 产物

媒体桶 `hls/{episode_id}/{job_id}/`（`media_object.kind = hls_dir`，`key` 为该前缀）：

| 文件 | 说明 |
| --- | --- |
| `master.m3u8` | 主清单，按码率从低到高（播放器从第一档 360 起播）；`BANDWIDTH` 为 RFC 8216 定义的峰值码率，另有 `AVERAGE-BANDWIDTH`、`RESOLUTION`、`FRAME-RATE`、`CODECS`（从 init 段的 `avcC` 读取） |
| `v{短边}.m3u8` | 各档媒体清单：VOD、`EXT-X-INDEPENDENT-SEGMENTS`、`EXT-X-MAP` 指向不加密的 init 段；每个切片前一行 `#EXT-X-KEY:METHOD=AES-128,URI="xsite-key:{key_ver}",IV=0x…`（随机 IV），`URI` 是占位符，由 S1-8 改写为密钥接口地址 |
| `s/{哈希}.mp4`、`s/{哈希}.m4s` | init 段与 AES-128-CBC（PKCS#7）加密后的切片，文件名为内容 SHA-256 的前 32 位十六进制，`Cache-Control: public, max-age=31536000, immutable` |

- 清单与切片分属不同前缀：S1-6e 的目录前缀签名只覆盖 `s/`，拿到切片签名也读不到完整清单，S1-8 才能在服务端裁剪试看清单；切片名不可推测。
- 首帧图写图片桶 `posters/{episode_id}/{哈希}.webp`（不加密，`10` 第 7 节），写入 `episode.poster`。

码率阶梯（`08` 第 2.1 节，按短边，竖屏、横屏、方屏通用）：360 / 540 / 720 / 1080，码率上限 400k / 900k / 1.6M / 3.0M（x264 High、CRF 23 加码率上限，VBV 缓冲 1 秒以限制起播切片体积）。只出不超过源短边的档位，源比 360 还小时按源尺寸出一档。帧率超过 30 时减半到 30 以内；关键帧每 2 秒强制一次并关闭场景切换插帧，各档对齐。音频 AAC-LC 96 kbps，源为单声道时保持单声道。源文件的旋转元数据（手机竖拍）按显示方向计算档位，输出去掉源文件的全部元数据。

源文件按不可信输入处理：ffprobe / FFmpeg 只允许读本地文件（`-protocol_whitelist file`）、只接受常见视频容器（`-format_whitelist`，拒绝播放列表、拼接列表等能引用其他文件的格式），子进程只拿到 `PATH`，看不到 worker 环境里的凭据；内容密钥只在 Go 内存中，FFmpeg 不接触。

## 接口

| 接口 | 说明 |
| --- | --- |
| `POST /api/admin/episodes/:id/transcode` | 请求 `{ source_key?, force? }`：`source_key` 是源文件在 `MEDIA_SOURCE_BUCKET` 中的路径，不传时沿用该集上一个任务的源（重试）；返回新任务。已有排队或进行中的任务 409；分集或所属的剧不存在（含回收站）404；记审计 `episode.transcode` |
| `GET /api/admin/transcode-jobs` | `?episode_id=&drama_id=&status=&page=&page_size=`，按创建时间倒序，页码分页 |
| `GET /api/admin/transcode-jobs/:id` | 单个任务（轮询进度） |

任务字段：`id`（UUIDv7）、`episode_id`、`drama_id`、`episode_number`、`source_key`、`force`、`status`（`queued` / `running` / `succeeded` / `skipped` / `failed`）、`progress`（0–100）、`attempts`、`error`、`source_hash`、`key_ver`、`renditions`、`poster`、`duration_sec`、时间戳。

## 数据（迁移 00006）

- `media_object`：按 `12` 第 7 节建立（S1-6a 原计划建表，提前到本任务，因为本任务要回写 `video_object_id`）；`episode.video_object_id` 补外键与索引。`media_replica` 依赖存储源，仍随 S1-6a 建。
- `media_key`：按 `02` 第 6.4 节建立。
- `transcode_job`：新表；同一集同时最多一个 `queued` / `running` 任务（部分唯一索引）。
- `episode.poster`：新列，首帧图的相对 key。

## 状态与幂等

- `episode.media_status`：`pending`（没有视频）→ 入队时 `transcoding` → 成功 `ready`、最终失败 `failed`。已是 `ready` 的分集重新转封装时保持 `ready`，旧产物继续可播，成功后在一个事务里切换到新产物；失败时不影响旧产物。
- 幂等：下载源文件后算 SHA-256；分集已 `ready` 且 `source_hash` 相同、未要求 `force` 时任务记为 `skipped`，不再转码。
- 重试：每次尝试先清空本任务的输出前缀再上传，失败的尝试不留下半成品；切换产物、写密钥、刷新「更新至 N 集」在同一个事务内完成。源文件不存在、不是视频、超过 4 GiB 或 4 小时等不可恢复的错误不重试。
- 运行中的任务每 10 秒左右更新进度；超过 10 分钟没有更新的 `running` 任务（进程被杀）在下一次入队时标为失败，不会永远占住这一集。

## 配置（worker）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `MEDIA_TRANSCODE_CONCURRENCY` | `1` | 本进程同时转封装的任务数；`0` 表示不消费 `media` 队列（没有 FFmpeg 的通用 worker） |
| `MEDIA_TRANSCODE_TIMEOUT` | `1h` | 单次尝试的超时 |
| `MEDIA_X264_PRESET` | `veryfast` | x264 速度档（线上可调慢换体积） |
| `MEDIA_WORK_DIR` | 系统临时目录 | 源文件与中间产物的临时目录，每次尝试结束删除 |
| `MEDIA_SOURCE_BUCKET` | — | 源文件所在的桶（线上为私有的入库桶，不能是公开读的图片桶）；本地为 `xsite-assets`（素材在 `fixtures/`） |
| `MEDIA_KEKS` | — | 内容密钥的包装密钥 `kid:secret[,kid2:secret2]`，第一把用于新密钥；S2-8 接入 KMS 后由信封加密替代 |
| `FFMPEG_PATH` / `FFPROBE_PATH` | `ffmpeg` / `ffprobe` | — |

启用转封装（并发大于 0）时，缺少 `MEDIA_KEKS`、S3 配置，或 FFmpeg 不可用 / 缺 `libx264`、`libwebp` 编码器时 worker 启动失败。线上转封装 worker 用 `service/Dockerfile` 的 `media-worker` 目标（Debian + FFmpeg），API 镜像不变。

## 验收

- 纯逻辑（阶梯、FFmpeg 参数、清单解析与生成、峰值码率、AES-128、`avcC` 解析、密钥包装、源路径校验）有表驱动单测。
- 转封装集成测试：真实 FFmpeg 生成小视频 → 流水线 → 用 FFmpeg 按密钥解密并完整解码产出的 HLS；上传失败重试后不残留对象。
- PostgreSQL 集成测试：入队与 409、状态流转、成功切换产物、跳过、最终失败、「更新至 N 集」只算可播放的分集；迁移 00006 down / up。
- 后台接口 HTTP 测试（权限点、CSRF、状态码与业务码、审计），curl 实测；10 部样例剧经后台接口与本地 worker 全部转码成功，重复提交同一源记为 `skipped`。

## 假设（需确认）

1. 源文件来自对象存储（`MEDIA_SOURCE_BUCKET`）；FTP 扫描、开放平台推送入库在 S4-6 接入后同样写入源文件再入队。
2. `media_object` 提前到本任务建立；存储源、副本与复制仍按 S1-6a、S1-6f 实施，届时把本任务的产物登记为主存储副本。
3. 内容密钥在 S2-8 之前用环境变量提供的 KEK 包装（AES-256-GCM，AAD = `media_key|wrapped_key|{episode_id}|{key_ver}`，密文带 kid 前缀便于轮换）。
4. init 段不加密（只含编解码参数）；同一集各档共用一个内容密钥，每个切片使用独立的随机 IV。
5. 分集时长为 0（未知）时用探测结果回填；已填写的时长不覆盖。
