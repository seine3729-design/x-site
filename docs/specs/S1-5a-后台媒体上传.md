# S1-5a · 后台媒体上传组件与转码接入

## 目标

将运营后台现有的媒体路径输入替换为统一上传组件：图片压缩后按 WebP / AVIF 写入后台配置的图片主存储 `img/`，视频写入视频主存储 `video/source/` 并最终以 HLS m3u8 存储。

## 范围

- 后端：`admin_media_upload` 会话、同源流式内容上传、图片完整性校验、分集视频入既有转码队列、广告视频独立公开 HLS 转码。
- 后台：剧竖/横封面、分集封面与视频、公告配图、广告图片/封面/视频、反馈项目封面，以及静态页正文图片插入器。
- 存储源：创建会话时按用途解析 `storage_settings` 的图片或视频主 `storage_provider`，快照 endpoint、region、bucket、path style 与 `path_prefix`。会话期间始终写入该快照目标；CDN / `storage_line` 只用于后续读取分发，绝不作为写端点。
- 存储布局：
  - 图片：`img/<purpose>/<uuid>.webp|avif`
  - 分集原视频：`video/source/<uuid>.<ext>`
  - 分集 HLS：`video/episodes/<episode_id>/<job_id>/`
  - 广告 HLS：`video/assets/<upload_id>/master.m3u8`

## 范围外

- 尚未有实际上传 UI 的 apps、mobile 用户端页面；用户 UGC 图片审核链路仍由 S6-13 实现。
- 历史 URL / `hls/` / `posters/` 对象的批量迁移。
- 自定义存储源的浏览器直传和专属上传 CORS 策略。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/admin/uploads` | 创建绑定当前管理员、用途权限与创建时存储目标快照的 15 分钟上传会话 |
| PUT | `/api/admin/uploads/:id/content` | 按服务端生成 key 流式写入已固定的 provider 目标 |
| POST | `/api/admin/uploads/:id/complete` | 校验并完成图片、提交分集转码或广告视频转码 |
| GET | `/api/admin/uploads/:id` | 查询本人广告视频 HLS 转码状态 |

## 验收

1. 图片没有 URL 输入框；选择文件前可以选择 WebP / AVIF，上传后表单保存 `img/` 相对 key。
2. 分集视频没有视频路径输入；上传后分集状态进入转码，成功后得到受保护 HLS。
3. 广告视频上传后轮询到 `video/assets/.../master.m3u8` 并回填字段。
4. 上传对象写入后台「存储设置」指定主存储的 bucket/path_prefix，不经过 CDN/`storage_line`。
5. 主存储或同一 provider 连接配置在会话创建后变更时，已有会话仍使用创建时的物理目标；新会话才使用新配置。
6. 伪造 MIME、大小不一致、过期会话、越权会话和错误图片文件头均被拒绝。
7. 既有 `hls/` 对象仍能经播放接口读取。

## 生命周期与并发

- 会话写入以条件状态转移 `created → uploading` 原子领取；同一管理员并发重试不会覆盖已领取对象。
- 写入后的状态更新、对象元数据/图片文件头校验、视频入队任一步失败都补偿删除对象并记为 `failed`。
- 写入凭据只在受信任的 API 上传代理与 worker 内存中使用，不持久化到会话、更不会发送给浏览器。
- worker 每小时清理过期未完成会话；已就绪图片与分集视频只清理会话记录。广告视频的私有 `ingest/` 源在转码成功或终态失败时删除，provider 中的原视频至会话过期清理时回收；单个存储源清理失败不阻塞同批其他会话，失败记录留待重试。
