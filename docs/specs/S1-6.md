# S1-6 资源机（FTP）

任务：`11` S1-6。依赖 S1-2 / S1-2a（后台会话、权限点 `ftp.view` / `ftp.edit` 已在迁移 00003 中）。
目标：运营后台能登记资源机，并完成 `06` 第 31 节流程的前两步「①测连 → ②打开目录」；③查新剧与④入库属于采集入库 S4-6（依赖屏蔽词 S2-4），后台页面是 A1-4。存储源与线路是 S1-6a~f，不在本任务内。

## 范围

| 接口（`/api/admin` 下） | 说明 | 权限点 |
| --- | --- | --- |
| `GET /ftp` | 列表：`q` 搜名称或地址、`status`，页码分页 | `ftp.view` |
| `POST /ftp`、`PATCH /ftp/:id`、`DELETE /ftp/:id` | 新建、整体保存、删除（设置类，不进回收站） | `ftp.edit`（高敏，S2-6 起需重新验证） |
| `POST /ftp/:id/test` | 测连：解析地址 → 连接（含 TLS）→ 登录 → 读取登录目录，返回每步耗时与结果 | `ftp.view` |
| `POST /ftp/:id/list` | 打开目录：`{ path }`，留空为登录目录；返回实际路径与条目 | `ftp.view` |

写操作与测连、列目录都记审计（`ftp_server.create\|update\|delete\|test\|list`）。

范围外：扫描与入库（S4-6）、后台页面（A1-4）、资源体检与预热（S4-5）、二次验证（S2-6）。

## 规则

- **字段**：名称（1–64 字）、地址（域名或 IP，不带协议、端口、路径，存小写）、端口（默认 21）、加密 `none`（不加密）/ `explicit`（显式 TLS）/ `implicit`（隐式 TLS，默认 `explicit`）、被动模式、凭据标识 `cred_ref`、状态 `active` / `inactive`。
- **账号密码不入库**（`10` 第 1 节 S3 机密）：`cred_ref` 是引用，worker 从环境变量 `FTP_<cred_ref>_USER`、`FTP_<cred_ref>_PASSWORD` 读取，线上由密钥管理注入 worker。接口返回这两个变量名（`cred_env`），连不上时把它们发给技术配置账号密码（`06` 第 31 节）。两个变量必须成对配置，只配一个时进程启动失败。
- **cred_ref**：大写字母开头，大写字母、数字、下划线，≤ 32 位，保存前转大写；新建时留空自动生成 `R` + 6 位随机（如 `RK3J9X2`）；保存时留空保持原值（改了它就要重新配置账号密码）。多台资源机可以共用一个标识。
- **只走显式 TLS**（`10` 第 2 节、`03` 第 9.7 节）：非开发环境保存 `none` / `implicit` 返回 400，worker 连接前再校验一次；开发环境三种都允许（本地资源机常不带证书）。证书按系统根证书校验，不提供跳过校验的开关。
- **只支持被动模式**：`passive=false` 返回 400（主动模式要资源机回连 worker，穿不过 NAT 且暴露 worker 地址）。数据连接只连控制连接的同一 IP（忽略 PASV 返回的地址）。
- **出站地址校验（SSRF，`12` 第 9 节）**：worker 先解析地址，任一结果是内网、回环、链路本地、保留或组播地址时拒绝连接，之后每条连接（含数据连接）都按解析出的 IP 直连并再校验一次，避免 DNS 重绑定。`EGRESS_ALLOW_PRIVATE` 未设置时开发环境放开内网地址、其他环境禁止，production 不允许开启。保存时地址是 IP 字面量且被禁止的，直接 400。
- **由 worker 发起连接**（`03` 第 9.7 节，不暴露 API 节点 IP）：API 把测连 / 列目录作为 River 任务 `ftp_probe`（`default` 队列、只试 1 次）入队，等待结果最多 25 秒；worker 单次操作上限 15 秒。超时或 worker 未处理时 503 `UNAVAILABLE` 并撤销任务。
- **结果**：测连与列目录总是返回 200 和结果 `{ ok, elapsed_ms, steps[], path, entries[], truncated }`；失败写在出错的那一步（`resolve` / `connect` / `login` / `list`），提示为中文，服务器原始应答最多保留 200 字。资源机不存在 404、参数错误 400。
- **列目录**：路径 ≤ 1024 字节、不能含控制字符；先切换到该目录再读取，`path` 为服务器返回的实际路径。条目去掉 `.`、`..`，目录在前、按名称排序，最多 1000 条（超出时 `truncated=true`）。

## 验收

- 领域层单测（字段校验、TLS 与被动模式策略、cred_ref 生成与保留）、出站地址校验单测、FTP 客户端对内置测试服务器的测试（不加密 / 显式 TLS / 隐式 TLS、登录失败、缺凭据、目录不存在、内网拦截）。

- 迁移 00006 实测 down/up；真实请求按 `openapi.yaml` 校验全部接口；对真实 FTP 服务器（本地容器）测连与列目录成功。
- `go vet`、`go test ./...` 通过。

## 假设（需确认）

1. 文档冲突：`02` 第 4.2 节、`06` 第 31 节的加密方式有三种，`10` 第 2 节、`03` 第 9.7 节要求只走显式 TLS。按上文处理：字段保留三种，非开发环境只允许显式 TLS。
2. 文档只写了「被动模式」开关，所用 FTP 客户端不支持主动模式，主动模式也不适合 worker 出口，因此只接受 `true`，字段保留。
3. 测连 / 列目录只需 `ftp.view`：它们不改数据，`07` 的 🔐 标在资源机的增删改上；仍要求 CSRF 并记审计。
4. 账号密码按 `00` 第 4 节「`FTP_*` 资源机凭证引用」放在 worker 的环境变量（密钥管理注入），不走 S2-8 的信封加密入库。
5. `ftp_server` 比 `02` 多一个 `updated_at`，与其他表一致。
