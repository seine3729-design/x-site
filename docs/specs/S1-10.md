# S1-10 游客身份、令牌轮换与复用检测

任务：`11` S1-10。依赖 S0-5（中间件链）。
目标：`POST /api/v1/auth/guest` 签发游客身份（Access Token + Refresh Token），`POST /api/v1/auth/refresh` 轮换、`POST /api/v1/auth/logout` 登出，做到「刷新令牌轮换、旧令牌复用即判定泄露并吊销整族」。验收：令牌轮换与复用检测测试。

游客与注册用户（S2-1）共用同一套令牌结构（`docs/03` 第 2.1、2.2 节，`docs/10` 第 4 节）。本任务落地游客这一半：无状态 Access Token、服务端会话族 `user_session`、轮换与复用检测；注册用户的登录、游客数据合并、设备下线随 S2-1，复用这里的设施。

## 机制

### Access Token（无状态）
标准 JWT（JWS 紧凑格式），EdDSA / Ed25519 签名，头部 `alg=EdDSA, typ=JWT, kid`；载荷 `sub`（游客为 `guest_device_id`，注册用户为 `user_id`）、`sid`（`user_session.id`，把 Access Token 关联到会话族）、`role`（`guest` / `user`）、`iat`、`exp`。有效期 15 分钟（`AccessTTL`）。**校验只验签不查库**：短有效期限制了泄露窗口，用无状态换掉每次请求一次 DB 查询。校验固定只接受 `alg=EdDSA`，拒绝 `none` 与算法混淆（按 `kid` 取公钥后验签），并对非规范 base64、超长令牌、未知字段直接拒绝。

不选 `golang-jwt/jwt` 而在 `internal/crypto/authtoken` 手写：仓库现有 5 个 `internal/crypto/*` 包（apienc、playtoken、password 等）都是基于标准库手搓，零新依赖、对「只接受 EdDSA」有完全控制；产物仍是标准 JWT。

### 签名密钥环（kid 轮换）
`JWT_SIGNING_KEYS=kid:secret[,kid2:secret2]`：`kid` 为 1–16 位字母数字，`secret` ≥ 32 字符。每把 `secret` 经 `HKDF-SHA256(info="xsite-jwt/v1")` 派生成 32 字节 Ed25519 种子再 `NewKeyFromSeed`——多实例用同一 `secret` 得到同一密钥对，不必分发私钥文件（与 `playtoken` / `apienc` 一致）。第一把为当前签发密钥，其余用于轮换过渡期校验；轮换时新 `kid` 放第一把，旧 `kid` 保留到它签发的令牌全部过期（15 分钟）后再删。只有 API 进程签发与校验，缺失或格式错误时 API 启动失败（worker 不需要，因此在 `app.NewAPI` 解析而非 `config.validate`）。

### Refresh Token（轮换 + 复用检测，落 PG）
256 bit 随机串，`base64url` 返回给客户端；**服务端只存 SHA-256**（`user_session.refresh_hash`，唯一）。游客有效期 180 天（`GuestRefreshTTL`，`docs/10` 第 4 节；注册用户的 30 天滑动随 S2-1）。

`Refresh` 在一个事务内完成（`internal/store/pg/session.go`）：
1. 按旧令牌哈希 `SELECT ... FOR UPDATE` 锁住会话行，串行化同一令牌的并发刷新；
2. 行不存在 → `RotateNotFound`；已吊销（`revoked_at` 非空）→ 判定**复用**，吊销整个会话族（`family_id`）→ `RotateReuse`；已过期 → `RotateExpired`；
3. 否则吊销旧行（`revoke_reason=rotated`）、插入同族同主体的新行 → `RotateOK`。

对调用方，`RotateNotFound` / `RotateExpired` / `RotateReuse` 一律映射成同一个 `errs.ErrTokenExpired`（401 `TOKEN_EXPIRED`），**不区分原因**——尤其不告诉持有者「这是一次复用」，避免给盗取者线索。复用吊整族意味着：攻击者用偷到的旧令牌刷新会触发吊销，合法用户手里刚轮换出的新令牌也随之失效、被迫重新登录 / 领游客身份，泄露因此被发现并终止。

### 登出
`Logout` 按刷新令牌吊销其所在的会话族（`revoke_reason=logout`）。令牌为空或已失效时作为幂等成功处理（HTTP 返回 204）。只影响该会话族，不影响其他设备 / 会话族。

### 会话表（迁移 00023）
- `guest_device`：`id uuid` 主键、`source_channel`、`platform`（CHECK `web/ios/android`）、`attest_level`（CHECK `none/basic/strong`）、`merged_user_id bigint`（S2-1 合并后回填）、时间戳。
- `user_session`：`id uuid` 主键、`family_id uuid`（会话族）、`user_id bigint`（可空，S2-1 建外键）、`guest_device_id uuid`（外键 → `guest_device`，级联）、`refresh_hash bytea` 唯一、`ua_digest` / `ip_prefix`（仅摘要与网段前缀，不存完整 UA / IP）、`platform`、`created_at` / `last_seen_at` / `expires_at` / `revoked_at` / `revoke_reason`。约束 `CHECK((user_id IS NULL) <> (guest_device_id IS NULL))` 保证主体恰好一个。索引：`(user_id, revoked_at)`、`(guest_device_id)`、`(family_id)`、`(expires_at)`。迁移带 `-- +goose Down`。

## 接口与数据

契约见 `service/api/openapi.yaml`（0.31.0）：`POST /api/v1/auth/guest`（`GuestAuthRequest`，请求体可空）、`POST /api/v1/auth/refresh`（`RefreshRequest`）、`POST /api/v1/auth/logout`。三者都在 `/api/v1` 分组、走报文加密中间件（`docs/10` 第 5.3 节），响应 `Cache-Control: private, no-store`（含令牌）。成功返回 `AuthTokens`：`access_token`、`refresh_token`、`token_type=Bearer`、`expires_in=900`、`device_id`（游客设备 ID）、`role`。游客签发按客户端 IP 前缀（IPv4 /24、IPv6 /48）每分钟 30 次，超出 429 + `Retry-After`（计数器故障时放行，仿选源 / 选线上报）。`docs/07` 已列三接口，`docs/03` 第 2.1 / 2.2 节记录了设计与本任务落地点。

## 假设（需确认）

1. 游客 Refresh Token 有效期取 180 天（`docs/10` 第 4 节「游客令牌 180 天」）；`docs/03` 第 2.2 节的「30 天滑动」属注册用户，二者不冲突，已在 `docs/03` 注明。
2. Access Token 无状态：校验不查 `user_session`，因此登出 / 吊族只让 **Refresh** 立即失效，已签发的 Access Token 最多再活 15 分钟。需要「立即踢下线」时由前端在收到 401 后停止刷新即可；更强的即时吊销（会话版本写进 Valkey 并在身份中间件核对）随 S2-1 评估。
3. 本任务刻意不接身份中间件与 `PublicPlay.Identify`：S1-10 的范围是签发与轮换（`docs/11` 行），跨接口消费是 S2-1 引入「身份中间件」时的统一改造，`identity.Service.ResolveAccess` 已为其就绪，避免现在越界改动 `play` 包。
