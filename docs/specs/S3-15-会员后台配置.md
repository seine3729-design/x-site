# S3-15 会员后台配置

进度：切片 1（套餐菜单权限、sqlc 查询、领域/PG/HTTP 接线、admin 页面和 apps 读模型）已完成；TanStack 路由树已自动生成 `/vip/plans`。本轮未运行全量构建或浏览器验收；development 模拟订单不需要支付 KEK，支付渠道凭据配置仍待独立 `PAYMENT_KEKS` 授权。

## 目标

运营后台提供两类独立配置：

1. **会员套餐**：固定五种卡的价格、划线价、USDT 价、角标、推荐、允许客户端/渠道、排序和上下架。
2. **支付渠道**：渠道启停、客户端范围、国家白/黑名单、非机密配置和只写不读的渠道凭据。

订单、退款、补单、会员发放/扣回/迁移、对账结果另随 S3-11 后续写路径和 A3-5 其它页面接入，不混入本切片。

## 路由、权限与菜单

| 页面 | 前端路由 | API | 权限 | 敏感性 |
| --- | --- | --- | --- | --- |
| 会员套餐 | `/vip/plans` | `/api/admin/vip/plans` | `vip_plans.view` / `vip_plans.edit` | 常规运营写操作，审计 |
| 支付渠道 | `/payment/channels` | `/api/admin/payment/channels` | `payment_channels.view` / `payment_channels.edit` | `payment_channels.edit` 必须标记 sensitive，要求 5 分钟 reauth，审计 |

迁移必须同时新增 `admin_menu`、`admin_permission`、`admin/src/config/navigation.ts` 页面登记；菜单由 `/api/admin/me/menus` 动态下发，不能只写 React 路由。

## 套餐配置规则

- 套餐 `code` 固定为 `day`、`week`、`month`、`quarter`、`year`，后台不能增删或改编码；名称由 apps/mobile 的 i18n JSON 按 code 渲染。
- `duration_days` 默认 1/7/30/90/365，可在安全范围内修改；人民币金额使用 `price_fen` / `list_price_fen`，USDT 使用 `price_micro_usdt`，均为整数最小单位。
- 上架必须有正的人民币与 USDT 价格、至少一个允许客户端和允许渠道；`list_price_fen` 为 0 或不小于 `price_fen`。
- 已有订单将持有 `product_snapshot`，改价或下架不影响既有订单、会员权益或回调入账。
- 每次保存清除 `xsite:vip:plans:<client>` 缓存；套餐接口至多缓存 60 秒，但后台保存后应立即失效。

## 支付渠道配置规则

- 渠道固定为 `alipay`、`wechat`、`usdt`、`iap_apple`、`iap_google`；后台只编辑配置，不允许新增自定义渠道。
- 普通响应仅下发 `enabled`、客户端/地区范围、非机密 `config` 和 `configured` 状态；不得返回 `credential_enc`、明文私钥、APIv3 密钥、证书或任何可逆提示。
- 凭据输入为“只写不读”：编辑时留空表示保持现有密文；前端只显示“已配置 / 未配置”，必要时显示由后端安全计算的非机密标识。
- 支付凭据使用独立 `PAYMENT_KEKS`：`kid:secret[,kid2:secret2]`，HKDF info 固定为 `xsite-payment-kek/v1`；AAD 分别绑定 `payment_channel|credential_enc|<channel>` 和回调原文记录，禁止复用 `STORAGE_KEKS`。
- 未完成相应 S3-12～S3-14 适配器的渠道不得启用；即使凭据已配置，也不向 apps 暴露可支付渠道。

## 前端交互

### admin

- 套餐页为固定五行配置表：代码/时长/价格/客户端/渠道/推荐/上架，编辑采用带中文 placeholder 的 react-hook-form + zod 表单；只读角色保持可见但控件禁用并标识原因。
- 支付渠道页每渠道独立卡片，非机密开关与范围单独保存；凭据在独立敏感表单中保存，提交期间禁用按钮并显示结果。标签显式关联控件，输入和下拉等宽等高。
- 写操作经 `admin/src/lib/http.ts`，利用现有 CSRF、Cookie、`REAUTH_REQUIRED` 自动重验和 TanStack Query 精确失效；不直接 `fetch`。

### apps

- `/vip` 已接入真实 `GET /api/v1/vip/plans`，按 `code` 走九语言文案、按 `price_fen` 显示人民币；无上架套餐显示空态，读取失败提供重试。
- `/me` 已在登录态后单独请求 `GET /api/v1/me/vip`，显示有效/未开通/到期日；失败不会伪装成非会员，且不进入 SSR/边缘缓存。
- 支付 CTA 在订单与渠道适配完成前保持禁用，不能根据 `vip_plan.channels` 误导用户为“可支付”。
