# S2-6 后台二次验证

任务：`11` S2-6。依赖 S1-2（后台会话登录、RBAC、审计、CSRF）。
目标：后台二次验证——TOTP、Passkey（WebAuthn）、`/api/admin/login/mfa`、高敏操作重新验证、IP 网段变化重新验证。验收：超管无二次验证无法登录。

S2-6 较大（3 人天，含登录强制、重新验证、Passkey、前端）。按增量纵切推进，分 7 个切片，7 个切片均已完成并端到端验证。

## 切片划分

1. **TOTP 自助绑定（已完成，端到端已验证）**：登录管理员自助绑定 TOTP。`setup` 生成种子并暂存、`verify` 校验一次性码后信封加密落库启用。
2. **登录强制校验（已完成，端到端已验证）**：`admin.Service.Login` 密码通过后，若账号已启用二次验证，返回 `mfa_required=true` + 一次性 `mfa_ticket`（Valkey 暂存）；`POST /api/admin/login/mfa` 用 ticket + 验证码换会话。前端登录页已搭好 `mfa_required` 分支（`features/auth/sign-in.tsx`）。
3. **高敏操作重新验证（已完成，端到端已验证）**：高敏写操作要求 5 分钟内重新验证过二次因子。按 `admin_permission.sensitive`（00003 已标注：存储源 / 线路 / FTP / 配置 / API 密钥 / 域名 / 管理员 / 角色 / 角色权限的 edit + SEO 统计代码）在 `RequirePage` / `RequirePermission` 里数据驱动地判定，不在各子包逐路由布线；`POST /api/admin/reauth` 校验 TOTP 后标记会话。只对已绑定二次验证的账号生效。
4. **IP 网段变化重新验证（已完成，端到端已验证）**：把重新验证标记从「存在即可」升级为记下重新验证时的 IP 网段（`privacy.IPPrefix`，IPv4 /16、IPv6 /32）。门槛比较当前请求网段与标记网段，不同即视为需重新验证——一个标记同时覆盖「5 分钟窗口」与「IP 段变化」两个触发条件，无需改会话结构、无需改 `Authenticate`。
5. **Passkey / WebAuthn（已完成，加密 E2E 已验证）**：`admin_passkey` 表（迁移 00046）+ 自助注册 / 登录断言 / 重验断言 / 列表 / 删除（`go-webauthn/webauthn`），前端 `@simplewebauthn/browser`。
6. **管理员页「重置二次验证」（已完成，端到端已验证）**：清除目标管理员的 TOTP + Passkey 并强制下线。
7. **超管强制开启（已完成，端到端已验证）**：超级管理员未绑定二次验证时，除开启二次验证相关接口外一律 403（满足本任务验收标准）。

## 机制（TOTP 绑定）

- **为什么分 setup / verify 两步**：绑定需要用户在认证器里确认时间同步正确，避免绑了却因时钟漂移登不进。setup 只生成 + 暂存（不写库），verify 用一次性码确认后才启用。原始种子只在 setup 响应里给前端一次，verify 不回传种子（从 Valkey 暂存取），减少种子在请求间往返。
- **为什么单独一个 `MFAService`**：扩展 `admin.Service` 会改 `NewService` 签名，牵动既有登录测试与所有调用方。独立 Service 只注入它自己需要的 `MFARepo` / `TOTPPendingStore` / `*envelope.Keyring`。
- **为什么 base64 承载在 text 列**：信封密文是二进制，而 `totp_secret_enc` 自 00002 就是 `text`。改成 `bytea` 要迁移且牵动其他读写；在 pg 层做 base64 编解码把差异隔离在一处，领域层拿到的始终是 `[]byte` 明密文。
- **密钥不可用时**：`ADMIN_TOTP_KEKS` 未配置（开发常见）→ keyring 为 nil → setup/verify 返回 503，不 panic、不阻止其他功能；production 启动校验强制要求。
