# S1-7 选源鉴权

任务：`11` S1-7。依赖 S1-4（前台可见性）、S1-5（分集可播放状态与媒体对象）、S1-6b/d（线路、地区规则、健康分与选线算法）均已完成。
目标：`GET /api/v1/episodes/:id/sources?line_id=` 按分集的观看权限判定能不能看、看多少，按客户端地区排好候选视频线路，并为每条线路签发播放令牌（清单地址）。清单与密钥接口是 S1-8。

## 范围

| 内容 | 落点 |
| --- | --- |
| 播放令牌签发与校验（HMAC-SHA256，`kid` 轮换） | `internal/crypto/playtoken` |
| 观看权限判定、选源编排 | `internal/domain/play` |
| 选源用的选线（复用 S1-6d 的打分，加上手选线路；按产物副本过滤由 S1-6f 补在同一文件） | `internal/domain/storage/sources.go` |
| 可播放分集查询 | `db/queries/play.sql`、`internal/store/pg/play.go` |
| 接口、选源限流 | `internal/http/public/play` |
| 配置 `PLAY_TOKEN_KEYS` | `internal/config/play.go`、`.env.example`、`compose.yaml` |

范围外：清单重写、试看裁剪、密钥接口（S1-8，令牌在那里校验）；游客身份与登录（S1-10、S2-1）；会员判定（S3-10）；通用限流中间件与多键限流（S0-7）；风控降级（S5-3）；媒体副本的登记与复制（S1-6f，选源只读取就绪副本）；GeoIP 数据（S1-6c，未接入前地区为 `XX`）。

## 规则

### 能不能看（`03` 第 4.1 节）

先确认分集存在且可播放：剧前台可见（不在回收站、已上架、定时已到点）且分集转封装完成（`media_status = ready` 且有视频对象），否则 404 `NOT_FOUND`。

| 分集 `access` | 观看者 | 结果 |
| --- | --- | --- |
| `free` | 任何人 | 完整播放 |
| `login` | 已登录 | 完整播放 |
| `login` | 游客，`trial_sec > 0` | 试看 `trial_sec` 秒 |
| `login` | 游客，`trial_sec = 0` | 401 `NEED_LOGIN`（登录墙） |
| `vip` | 会员（`user_vip.expire_at > now`） | 完整播放 |
| `vip` | 非会员（游客一律视为非会员），`trial_sec > 0` | 试看 `trial_sec` 秒 |
| `vip` | 非会员，`trial_sec = 0` | 402 `NEED_VIP`（VIP 墙） |

- 会员每次选源实时判定；令牌最长 10 分钟，会员在播放中到期时本令牌内不中断（`03` 第 12.1 节）。
- 试看秒数写进令牌，S1-8 据此只下发前 N 秒的切片清单；响应的 `trial_sec` 告诉前台这是试看，到点后按 `access` 显示登录墙或 VIP 墙。

### 候选线路（`12` 第 4.3 节）

- 候选 = 该集当前产物（`episode.video_object_id`）有就绪副本（`media_replica.status = ready`，S1-6f）的存储源上的视频线路，镜像还没复制完的存储源不下发；产物还没有就绪副本时（如 S1-6f 之前转封装的产物没有副本记录）不按副本过滤。按 S1-6d 的算法打分（匹配精度 + 加分 + 优先级 × 10 + 健康分 × 0.3 − 观察中 50），同分按 `weight` 加权随机（种子 = 设备 + 当前 10 分钟），取前 N 条（存储设置的候选数量，默认 3）。与 `GET /api/v1/lines` 用同一套代码，后台选线预览的顺序与实际下发一致。
- 手选线路 `line_id`：在候选中（含超出 N 条的）且健康分 ≥ 30 时放到第一位并标 `manual=true`，总数仍为 N；否则忽略（前台据「第一条不是手选」提示「手选线路暂不可用，已切回自动」）。`recommended` 始终标在算法排第一的线路上。
- 没有任何可用视频线路时 503 `UNAVAILABLE`「暂无可用线路」。

### 播放令牌（`10` 第 4 节）

- 形如 `<kid>.<base64url(载荷)>.<base64url(HMAC-SHA256)>`。载荷 `{"e":分集,"l":线路,"d":设备哈希,"t":试看秒数,"x":过期时间}`，有效期 10 分钟；HMAC 覆盖 `kid` 与载荷，密钥 = HKDF-SHA256(secret, `xsite-play-token/v1`)。
- 密钥来自 `PLAY_TOKEN_KEYS=kid:secret[,kid2:secret2]`：第一把签发，全部用于校验；轮换时新密钥放第一把，旧密钥保留 10 分钟以上再删。只有 API 进程签发与校验，不下发给 CDN。缺失或格式错误时 API 启动失败。
- 设备哈希 = SHA-256(设备标识) 前 16 字节，令牌里不出现设备标识原文；没有设备标识时不绑定设备。不绑定 IP 网段：手机在 Wi-Fi 与蜂窝网络之间切换时 IP 会变，绑定会让播放中断（`03` 第 4.1 节写的 `ip_prefix` 为可选项）。
- 清单地址 `/api/v1/hls/<令牌>/index.m3u8`，同源加密接口（S1-8）。令牌不写日志（访问日志只记路由模板）。

### 观看者身份

- 选源对游客开放（免费分集游客可直接看），在代码里显式标注为公开接口。
- S1-10 / S2-1 之前没有用户端登录态：观看者一律是游客，设备标识取请求头 `X-Device-Id`（APP 发送；Web 的 BFF 不透传该头，W1-1 接入游客 Cookie 后由身份中间件提供）。格式不对（不是 1–64 位字母、数字、`-`、`_`）时 400。
- 会员查询是接口（S3-10 实现），在此之前没有人是会员：`vip` 分集对所有人按试看或 402 处理。

### 限流与缓存

- 选源桶 `s:{设备}`（没有设备标识时按 IP）每分钟 60 次（`03` 第 1.1 节），超出 429 `RATE_LIMITED` + `Retry-After`（到下一分钟的秒数）。S0-7 接入通用限流前用固定窗口计数（Valkey），Valkey 不可用时放行。
- `Cache-Control: private, no-store`（含签名，不可共享缓存）。

## 接口与数据

契约写在 `service/api/openapi.yaml`（0.20.0），新增业务码 `NEED_VIP`（402，`07` 第 4 节已登记，九种语言文案已有）；`07` 第 1 节「播放」同步。无迁移。

## 验收

- 观看权限判定的表驱动单测覆盖免费 / 登录 / 试看 / VIP 四类分集与游客、注册用户、会员三类观看者；非会员看无试看的 VIP 集 402 `NEED_VIP`。
- 播放令牌：签发 → 校验往返、篡改任一字节失败、过期、旧密钥签发的令牌在轮换后仍可校验、未知 `kid` 失败、设备绑定。
- 手选线路：在候选中置顶、超出 N 条时挤掉最后一条、不健康或不在候选中时忽略。
- PostgreSQL 集成测试：草稿 / 下架 / 定时未到点 / 回收站中的剧、未转封装的分集都查不到。
- HTTP 层：状态码与业务码、`Cache-Control`、限流 429 与 `Retry-After`、参数校验。
- 真实请求：本地栈上造一部剧与视频线路，按 `openapi.yaml` 校验响应，并用同一把密钥解开返回的令牌核对内容。

## 假设（需确认）

1. `03` 第 4.1 节写的「HMAC-SHA256(line_key, payload)」改为服务端专用的 `PLAY_TOKEN_KEYS`：令牌只由本服务（S1-8）校验，不需要线路密钥；`presign` / `none` 线路本来也没有线路密钥。线路密钥（`LINE_SIGN_KEYS`）只用于 S1-8 给切片签名。
2. 令牌比 `12` 第 4.4 节示例多一段 `kid` 前缀，用于密钥轮换。
3. `login` 分集的 `trial_sec > 0` 时游客可试看（`03` 第 4.1 节「`trial_sec>0`：未登录返回试看令牌」），不是直接 401。
4. 产物还没有就绪副本时不按副本过滤（S1-6f 的约定：它之前转封装的老内容没有副本记录，不能因此播不了）。
