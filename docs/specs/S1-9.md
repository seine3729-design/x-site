# S1-9 站点配置的 version 机制与 Pub/Sub 失效

任务：`11` S1-9。依赖 S0-4（缓存设施）。
目标：`GET /api/v1/site-config`（ETag 条件请求）+ `site.version` 机制 + Pub/Sub 失效，做到「改配置后 5 秒内各实例生效」。

读接口与 `site_config` 单行表（含 `version`、迁移 00001）在示例纵切里已有；`version +1` 的仓储方法 `BumpVersion`（查询 `BumpSiteConfigVersion`）由并行开发的 S4-4 先行加入。本任务补齐**仍然缺失的 Pub/Sub 跨实例失效**，并把「version+1 + 清缓存 + 广播」收敛到领域服务一处。

## 范围

| 内容 | 落点 |
| --- | --- |
| Pub/Sub 失效总线（发布 / 订阅，断线重连） | `internal/store/cache/invalidation.go` |
| 站点配置三级缓存 + 版本变更失效 + 广播 | `internal/domain/platform/siteconfig.go` |
| 订阅循环装配（收到广播清本实例本地缓存） | `internal/app/app.go` |

范围外：通用进程内 LRU（`otter`，S0-4，本任务只给站点配置一个专用的进程内一级缓存）；后台分段保存的写接口与校验、白标各段的具体字段（S3-3）；缓存管理页「清缓存」的扫描 / 删除与手动触发（S4-4，另有同学在做）；CDN 边缘缓存清理（S4-4）；线路表 / 屏蔽词等其它随 `site.version` 失效的进程内状态（各自任务接入时复用本总线）。

## 机制

### 三级缓存（读）
`SiteConfigService.Get`：进程内一级缓存（`atomic.Pointer`，兜底 TTL 3 秒）→ Valkey 读穿缓存（兜底 TTL 30 秒，`singleflight`）→ PG。ETag 由 `version` 派生（`W/"site-<version>"`），版本不变客户端拿 304。

### version 变更（写）
`SiteConfigService.BumpVersion`：`repo.BumpVersion`（`version +1`）→ 清本进程一级缓存 + 删 Valkey 二级缓存键 → `Invalidator.Publish("site_config")`。返回新版本。广播失败只记日志、不影响写入（各实例靠一级兜底 TTL 生效）。S3-3 白标写入各段后调用它；S4-4 手动清「站点设置」也应调用它（目前直接调仓储 `BumpVersion`，只清 Valkey 不广播，各实例靠 3 秒兜底 TTL 生效）。

### Pub/Sub 失效（跨实例）
`cache.Invalidator` 用 Valkey Pub/Sub：`Publish(topic)` 向约定频道（`xsite:invalidate`）发一条 topic 字符串；`Subscribe(onTopic)` 开后台 goroutine 循环 `Receive`，断线自动重连（漏掉的消息由一级兜底 TTL 补上），返回 `stop`。`app.go` 仿 `watchGeoIP`：订阅循环收到 `site_config` 就调 `SiteConfigService.OnInvalidate`（清本实例的本地与 Valkey 缓存），`stop` 存在 `API` 上、`Close` 时先停订阅再关 Valkey。各实例各自订阅、不经 River（River 只有一个消费者拿到；这里要广播到每个实例）。

Valkey 是所有实例共享的二级缓存，删一次即全局生效；Pub/Sub 的作用是清各实例**独立**的进程内一级缓存，这正是「各实例生效」里的「各实例」。

## 接口与数据

读接口 `GET /api/v1/site-config` 的契约（`service/api/openapi.yaml`）、行为与 `docs/07`、`docs/03` 第 9.1 节一致，本任务**不改契约、不加接口、不加迁移、不加环境变量**。频道名 `xsite:invalidate` 是进程间约定的常量。

## 验收

- `11` 的验收「改配置后 5 秒内各实例生效」：两实例共用真实 Valkey + 同一份数据，实例 A `BumpVersion` 后实例 B 在约 8ms 读到新版本（`siteconfig_pubsub_test.go`，断言 < 1 秒，远小于一级兜底 TTL 3 秒，证明走的是广播而非等 TTL）。
- `cache.Invalidator` 的 Pub/Sub 收发、按 topic 分发、`stop` 后不再收消息（真实 Valkey 集成测试）。
- 领域层单测：一级缓存命中 / 过期回源、`BumpVersion` 做到 version+1 + 清缓存 + 广播（广播失败不影响写入、repo 出错不失效也不广播）、`OnInvalidate` 清本地缓存。
- HTTP 层 ETag / 304 / 错误映射回归（原有 `handlers_test.go` 不变、仍通过）。

## 假设（需确认）

1. 进程内一级缓存兜底 TTL 取 3 秒：广播即时失效为主，3 秒兜底确保广播不可用时也满足「5 秒内」。
2. S1-9 只给站点配置做进程内一级缓存，不引入通用 LRU（S0-4）；因此本总线目前只服务站点配置，线路表 / 屏蔽词等以后各自接入。
3. S4-4 的手动清「站点设置」暂时不走广播（直接调仓储 `BumpVersion`），各实例靠兜底 TTL 生效；需要即时跨实例失效时改调 `SiteConfigService.BumpVersion`。
