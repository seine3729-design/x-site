# S2-1 用户注册 / 登录、会话、设备下线、改密吊销全部

任务：`11` S2-1。依赖 S1-10（游客身份与会话族）。
目标：用户名 + 密码注册 / 登录（Argon2id），复用 S1-10 的无状态 Access Token 与会话族为注册用户签发令牌；身份中间件统一鉴权；「我的设备」列表与下线；改密吊销该用户全部会话。验收：合并去重测试（见下「范围边界」）、改密吊销全部会话。

注册用户与游客共用同一套令牌结构（`docs/03` 第 2.2 节、`docs/10` 第 4 节）。S1-10 已落地游客半边（无状态 Access、`user_session` 轮换与复用检测）；本任务落地注册用户半边并引入身份中间件。账号只有用户名 + 密码，不收集邮箱 / 手机号，也不提供找回密码（`adr/0001`）。

## 范围边界（重要，先说清）

`docs/11` 的 S2-1 一行写了「游客数据合并」且验收含「合并去重测试」，但 `POST /api/v1/me/local-merge` 要写入的 `watch_history`/`follow`/`like` 三张表由 **S2-3** 建，且 `docs/13` 第 10.4 节把该接口明确划给 **S2-10**。两处文档与依赖关系冲突，取舍如下（已在 `docs/11` S2-1 行注明）：

- **本任务做**：`user` 表 + 回填 S1-10 预留的两个外键（账号侧地基）；注册 / 登录 / 改密 / 会话列表 / 设备下线；身份中间件。
- **本任务不做**：历史 / 收藏 / 点赞三张表（S2-3）、`POST /api/v1/me/local-merge` 的去重落库与 `guest_device.merged_user_id` 回填（随 S2-3 建表后、按 `docs/13` 归 S2-10）。因此验收「合并去重测试」随 S2-10。
- 需产品确认：若希望 S2-1 一次性建表并做完整 local-merge，再调整切分。

同样留给后续：登录失败计数 / 人机验证挑战 / 相近耗时的完整防撞库（S2-2，本任务登录已用 `Equalize` 做到相近耗时、统一提示，注册仅按 IP 粗限流）；`/me/profile`、history、follow、like、notifications（S2-3 / S2-9）；后台封禁即时踢下线（S2-7）。

## 机制

### user 表（迁移 00025）
字段见 `docs/02` 第 5.1 节：`id`（bigint identity）、`username`（唯一，`CHECK username = lower(username) AND ~ '^[a-z0-9_]{3,32}$'`）、`nickname`、`password_hash`、`avatar`、`bio`、资料审核三态、`nickname_changed_at timestamptz[]`、`locale`、`history_paused`、`status`(normal/muted/banned)、`verified_at`、`created_at`、`deleted_at`。并回填 S1-10（00023）预留的外键：`user_session.user_id → "user"(id) ON DELETE CASCADE`、`guest_device.merged_user_id → "user"(id) ON DELETE SET NULL`。`user` 是 SQL 保留字，查询一律用 `"user"`。迁移带 `-- +goose Down`。

### 注册 / 登录（`domain/user`）
- 注册：校验用户名（规范化小写）、密码（8–128、非纯数字、不在常见弱口令表、不等于用户名）、昵称（≤40，可空），必须带 `ack_no_recovery=true`（否则 400）；`hasher.Hash` 后建用户，用户名唯一冲突 → 409 CONFLICT；成功即 `identity.IssueForUser` 签发令牌。
- 登录：按规范化用户名取用户；不存在时 `hasher.Equalize` 做等代价空算 + 统一 `NEED_LOGIN`（防枚举，提示与耗时相近）；密码错同样统一提示；`status=banned` → 403；`needsRehash` 时透明重哈希；成功 `IssueForUser`。
- 密码哈希复用 app 的全局 `password.Hasher`（Argon2id，与后台、反馈社区同一实例）。

### 令牌与会话（复用 / 扩展 S1-10 的 `identity`）
- 新增 `IssueForUser(userID, in)`：建会话族（`UserID`），签发 `sub=user_id`、`role=user`，Refresh 用新增的 `UserRefreshTTL = 30 天`（游客仍 180 天）。
- `Refresh` 轮换按旧行主体选续期 TTL：注册用户续 30 天、游客续 180 天（`RotateInput` 带 `GuestExpiresAt` / `UserExpiresAt`，PG 层按 `old.user_id` 是否为空选）。复用检测与吊整族逻辑不变（S1-10）。
- 会话管理：`ListSessions`（我的设备，按 `last_seen_at` 倒序）、`RevokeSession`（设备下线，`RevokeSessionByID` 带 `user_id` 作用域防越权，命中 0 行 → `ErrNotFound`）、`RevokeAllSessions`（改密 / 封禁）。

### 身份中间件（`http/middleware/identity.go`）
- `SetIdentity(resolver)`：解析 `Authorization: Bearer <access>`。无令牌 → 匿名放行；令牌无效 / 过期 → 中止并返回对应错误（401 `TOKEN_EXPIRED` / `NEED_LOGIN`），客户端据此刷新 / 登录。校验走 `identity.Service.ResolveAccess`（无状态，只验签）。
- `RequireUser()`：要求 `role=user`，否则 401（`/api/v1/me/*` 用它；游客令牌也被挡）。
- `CurrentAccess(c)` / `BearerToken(c)` 供 handler 取身份。中间件不引用 `respond` 包（`respond` 依赖 `middleware`，会循环），错误用 `errs` + `gin.H` 自行构造，响应格式与 `respond` 一致。

### 改密吊销全部会话
`user.Service.ChangePassword`：校验旧密码 → 更新哈希 → `identity.RevokeAllSessions(userID)`。Access Token 无状态，吊销只让 Refresh 族立即作废（客户端续期失败、需重新登录）；已签发的 Access 最多再活 15 分钟（见「假设」2）。

## 接口与数据

契约见 `service/api/openapi.yaml`（S2-1 条目标为 0.35.0，顶层 version 已被并行任务推进到更高）：`POST /api/v1/auth/register`、`POST /api/v1/auth/login`、`POST /api/v1/me/password`、`GET /api/v1/me/sessions`、`DELETE /api/v1/me/sessions/{id}`。auth 两个接口公开（走报文加密）；`/me/*` 经身份中间件要求注册用户（请求头 `Authorization: Bearer`）。响应均 `Cache-Control: private, no-store`。`docs/07` 的注册 / 登录 / me 行已同步。

- `11` 的「改密吊销全部会话」：本机真实容器端到端 `curl`——改密 204 → 旧 refresh 刷新 401 `TOKEN_EXPIRED`（全部会话吊销）→ 新密码登录 200 → 旧密码登录 401；`identity` 单测与 `user_session` PG 集成测试覆盖 `RevokeAllForUser`。
- `11` 的「合并去重测试」：随 S2-10（见「范围边界」）。
- 单测：`domain/user`（注册 / 登录 / 改密 / 校验 / 防枚举、重复用户名 409）、`domain/identity`（`IssueForUser`、注册用户 30 天 TTL、会话列表 / 下线含防越权 / 吊销全部）、`http/public/auth`（注册 / 登录错误映射与注册限流）、`http/public/me`（鉴权边界：无令牌 / 游客 / 过期 / 无效都 401；current 标记；改密与下线错误映射）。
- 集成：`store/pg` 的 `TestUserRepo`（创建、唯一冲突、按名 / ID 查询、改密、软删不可见）、`TestSessionRepo_UserSessions`（列表、设备下线 `user_id` 作用域防越权、吊销全部）。
- 端到端 `curl`：注册 `role=user` → 我的设备（1 个、current）→ 第二设备登录 → 2 个设备 → 下线一台 → 改密链路（上）→ 防枚举（未知用户与错密码同 code 同 message）→ 重复用户名 409 → 未登录与游客令牌访问 `/me/sessions` 均 401。
- 回归：`service` 全量 `go build ./...`、`go vet ./...` 通过；`go test ./...` 中本任务相关包（`domain/user`、`domain/identity`、`http`、`http/middleware`、`http/public/auth`、`http/public/me`、`store/pg` 的 user/session 测试）全绿。

## 假设（需确认）

1. **用户名规范化为小写、字符集 `[a-z0-9_]`、3–32 位**（与后台 `admin_user` 一致，`docs/03` 第 2.3 节）。`docs` 未明确用户端用户名的大小写与字符集，这里取保守集；放宽（如允许连字符）不是破坏性变更。保留词拒绝若干（admin/root/official 等）。
2. **banned 的即时性**：Access Token 无状态，封禁 / 改密只吊销 Refresh 族，已签发的 Access 最多再活 15 分钟。`docs/03` 第 2.2 节「banned 立即吊销会话」在无状态取向下按「吊销 refresh 族 + 15 分钟窗口」实现；需要严格即时时，可在 `/me/*` 等敏感接口每请求查 `user.status`（随 S2-7 用户管理评估）。
3. **常见弱口令表**内置约 30 个最高频弱口令 + 规则（纯数字、等于用户名拒绝）；更系统的字典与撞库防护随 S2-2。
4. **游客数据合并**只做账号侧地基（见「范围边界」）。
