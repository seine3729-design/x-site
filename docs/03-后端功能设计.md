# 03 · 后端功能设计（service/）

技术栈：**Go 1.27.3 + Gin 1.12 + pgx v5/sqlc + PostgreSQL 18 + Valkey 9 + River**。后端是平台唯一的数据与业务权威源，对三类调用方提供接口：

- **用户端 API** `/api/v1/*`：供前端 Web（BFF 透传）与 APP 调用，**报文全程加密**（`10` 第 5.3 节）。
- **运营后台 API** `/api/admin/*`：供 `admin/` 调用，独立域名、强鉴权 + 二次验证 + 审计。
- **开放平台 API** `/open-api/*`：供外部采集程序调用，API Key + HMAC 签名。

> 路径前缀与命名规则见 `07` 第 0.5 节：用户端 `/api/v1/` 之后的部分沿用参考站已验证命名（参考站为 `/api/<同名路径>`）；`/api/admin/*`、`/open-api/*` 为建议命名。完整索引见 `07-接口清单.md`，性能、容灾、加密细节分别见 `08`、`09`、`10`。

## 0. 工程结构与运行形态

### 0.1 目录布局

```
service/
├─ cmd/
│  ├─ api/            # HTTP 进程：用户端/后台/开放平台三套路由（可按端口或 Host 拆分部署）
│  ├─ worker/         # River 任务进程：体检、预热、转封装、汇总、榜单、推送
│  └─ keytool/        # 离线工具：签发域名清单、轮换 JWT 密钥、生成 API Key（不部署到线上）
├─ internal/
│  ├─ app/            # 依赖装配（手写构造函数注入，不用反射式 DI）
│  ├─ config/         # caarlos0/env 加载 + 启动期校验
│  ├─ http/
│  │  ├─ middleware/  # requestid/recover/realip/ratelimit/auth/sign/audit/cachehdr/...
│  │  ├─ public/      # /api/v1/* handler
│  │  ├─ admin/       # /api/admin/* handler
│  │  └─ open/        # /open-api/* handler
│  ├─ domain/         # 按业务域：content/play/community/account/billing(会员与支付)/growth/ops(运营：公告、广告、热搜词、榜单干预)/metrics/platform/resource(资源机、体检、预热)
│  │                  #   福利体系（`13`）：wallet/level/reward/activity/task/referral/mall/ugc
│  │  └─ <域>/        # service.go（业务规则）· repo.go（接口）· model.go
│  ├─ store/
│  │  ├─ pg/          # sqlc 生成代码 + 事务封装
│  │  ├─ cache/       # valkey-go 封装：读穿缓存、singleflight、客户端缓存
│  │  └─ blob/        # 对象存储、FTP
│  ├─ crypto/         # apienc（接口报文加密，HPKE）、信封加密、盲索引、签名、密码哈希

│  └─ observe/        # slog、OTel、指标
├─ db/
│  ├─ migrations/     # goose SQL
│  └─ queries/        # sqlc 查询 *.sql
├─ api/openapi.yaml   # 接口契约（生成 TS/Dart 客户端类型）
└─ sqlc.yaml
```

### 0.2 分层约定

- **handler**：只做绑定、校验、调用 service、组装响应。禁止直接访问 `store`。
- **service**：业务规则与事务边界；依赖 repo 接口，便于测试替身。
- **repo**：sqlc 生成的查询 + 少量手写动态查询（筛选/排序用白名单拼接，参数一律占位符）。
- **事务**：`pgx.BeginTxFunc` 包装；需要入队的任务在同一事务内 `river.InsertTx`，保证「数据写成功 ⇔ 任务入队成功」。
- **错误**：领域错误定义为哨兵值（`ErrNotFound`、`ErrNeedLogin`、`ErrForbidden`…），中间件统一映射为 HTTP 状态 + 业务码（见 `07` 第 4 节），堆栈只进日志不回客户端。
- **JSON**：Go 1.27 中 `encoding/json` 已由 v2 实现；新代码直接用 `encoding/json/v2`，注意 v2 默认更严格（重复键报错、大小写敏感），DTO 字段统一写 `json` tag。Gin 渲染层替换为 v2 编码器。
- **ID**：表主键 `bigint identity`（内部关联、索引紧凑）；对外暴露的会话、设备、任务等用 UUIDv7（标准库 `uuid.NewV7()`，或 PG 18 `uuidv7()`）。
- **多语言**：响应里的 `message` 是中文兜底文案（后台与日志排障用），Web / APP 一律按 `code` 显示当前语言（`04` A.4、`05` A.6）；新增业务码时同步两端文案 JSON。客户端带 `Accept-Language`，内容多语言（剧名、简介）启用前后端不按它做区分。
- **报文加密**：`/api/v1/*` 的 handler 读写的都是明文，加解密只在 `apienc` 中间件；handler 需要确认请求经过加密时用 `middleware.IsEncrypted(c)`。

### 0.3 进程与部署

| 进程 | 职责 | 扩缩容依据 |
| --- | --- | --- |
| `api` | 处理 HTTP；无状态，会话与限流在 Valkey | CPU、P99 延迟 |
| `worker` | River 消费者，按队列划分：`default`/`media`（转封装、用户图片处理）/`metrics`/`push`/`pay`（订单关闭、查单、链上监听、对账）/`welfare`（任务事件、金币过期、返利到账、奖券开奖、钱包对账） | 队列积压、任务时长 |

- 镜像：多阶段构建，`CGO_ENABLED=0`，`-trimpath -ldflags="-s -w"`，distroless 基础镜像，非 root 运行。
- 运行参数：Go 1.25 起 `GOMAXPROCS` 自动感知容器 CPU 配额；设置 `GOMEMLIMIT` 为容器内存的 85–90%；开启 PGO（用线上 CPU profile 生成 `default.pgo` 放到 `cmd/api/`）。
- 优雅停机：收到 SIGTERM 后先摘除健康检查，再 `Shutdown(ctx)` 等待在途请求（上限 20s），worker 走 River 的 `Stop` 软停。

## 1. 中间件链

请求按以下顺序经过中间件（Gin `Use` 顺序即执行顺序）：

| # | 中间件 | 职责 |
| --- | --- | --- |
| 1 | `recover` | 捕获 panic，返回 500，上报错误与堆栈 |
| 2 | `requestid` | 采用上游 `x-request-id`（仅信任边缘/BFF），否则生成 UUIDv7；写入 ctx、日志、响应头 |
| 3 | `edgeauth` | 校验回源密钥 `x-edge-secret`（常量时间比较）或 mTLS 客户端证书；不通过直接 403，防止绕过 CDN 直连源站 |
| 4 | `realip` | 只从可信代理链取客户端 IP 与国家头；Gin 设置 `SetTrustedProxies` 为 CDN/BFF 网段 |
| 5 | `otel` | Trace span、HTTP 指标（按路由模板聚合，不按原始路径） |
| 6 | `bodylimit` | 默认 1 MiB，上传接口单独放宽；拒绝超长头 |
| 7 | `ratelimit` | Valkey 令牌桶，按「设备 → 会话 → IP」多键限流，见 1.1 |
| 8 | `uaguard` | 写接口无 `User-Agent` 拒绝；已知自动化 UA 进 bot 桶 |
| 9 | `sign` | APP 与开放平台请求签名校验（时间窗 ±300s + nonce 去重），见 `10` 第 5 节 |
| 9a | `apienc` | 用户端 `/api/v1/*` 报文解密 / 响应加密（HPKE，`10` 第 5.3 节）；解密前的协议错误返回明文 `ENC_*`；加密响应改写为 `Cache-Control: no-store`。挂在 `/api/v1` 路由组上，后台与开放平台不经过 |
| 10 | `auth` | 解析游客/用户/管理员/API Key 身份，写入 ctx |
| 11 | `rbac` | 后台按角色与菜单分组判定「可改」 |
| 12 | `audit` | 后台写操作记录前后差异（在 handler 返回后异步落库） |
| 13 | `cachehdr` | 按路由声明设置 `Cache-Control`、`ETag`、`Vary` |
| 14 | `secureheaders` | HSTS、`X-Content-Type-Options`、`Referrer-Policy` 等 |

### 1.1 限流模型

- 算法：Valkey Lua 脚本实现 GCRA/令牌桶，单次往返；Valkey 不可用时降级为进程内桶（宁可放宽也不全站拒绝）。
- 维度与默认配额：

| 桶 | 键 | 默认 | 说明 |
| --- | --- | --- | --- |
| 读 | `r:{device或ip}` | 120/min | 列表、详情 |
| 写 | `w:{user或device}` | 30/min | 评论、点赞、上报 |
| 选源 | `s:{device}` | 60/min | 防批量解析播放地址 |
| 认证 | `a:{ip}` + `a:{username}` | 10/min | 登录、注册、修改密码；失败累计触发验证挑战 |
| 支付 | `p:{user}` | 10/min | 下单；同一用户未支付订单最多 3 笔 |
| 福利 | `g:{user}` | 60/min | 签到、抽奖、领取、兑换、并入本机数据；另有按设备 / IP 的发放上限（`13` 第 6.1 节） |
| 上传 | `u:{user}` | 20/min | 申请图片上传 |
| Bot | `b:{ip}` | 20/min | 自动化 UA |
| 开放平台 | `o:{api_key}` | 按 Key 配置 | — |

- 响应：429 + `Retry-After` + `RateLimit-Policy`/`RateLimit` 头（IETF 草案格式），便于客户端退避。
- 已实现部分（`internal/http/router.go`）：recover → requestid → edgeauth → 访问日志 → secureheaders → bodylimit，`/api/v1` 组上再挂 `apienc`；`/api/admin` 组挂在根路由上（不嵌套在 `/api/v1` 下，因此不经过 `apienc`），依次为 Origin 白名单 → 会话（`auth`）→ CSRF → `audit`，业务模块的路由分组再挂 `rbac`（`internal/http/admin`）；其余按本表顺序陆续接入。

## 2. 身份与鉴权模块

### 2.1 游客身份
- `POST /api/v1/auth/guest`：签发设备级游客身份。Web 由 BFF 写入 `HttpOnly; Secure; SameSite=Lax` Cookie；APP 存 Keychain/Keystore。
- 设备 ID 为服务端生成的 UUIDv7，不使用硬件标识（IMEI/IDFA 等），降低隐私面。
- APP 首次签发时可携带平台完整性证明（Play Integrity token / App Attest assertion），校验通过的设备获得更高的限流额度与「可信设备」标记（见 `10` 第 6 节）。
- 令牌（S1-10 已实现）：游客与注册用户共用同一套令牌结构（见 §2.2「令牌」）——`POST /api/v1/auth/guest` 新建 `guest_device` 与一个会话族，返回无状态 Access Token（JWT/JWS，EdDSA/Ed25519，头部带 `kid`，`sub` 为游客设备 ID、`role=guest`，15 分钟）与 Refresh Token（256 bit 随机串，服务端只存 SHA-256，游客 **180 天**，`10` 第 4 节）；`POST /api/v1/auth/refresh` 轮换、`POST /api/v1/auth/logout` 吊销当前会话族（幂等）。会话落 `user_session`（游客行用 `guest_device_id`，迁移 00023）。签名密钥由 `JWT_SIGNING_KEYS` 注入（`kid:secret`，HKDF-SHA256 派生 Ed25519 种子），只有 API 进程签发与校验；校验固定只接受 `alg=EdDSA`，拒绝 `none` 与算法混淆。游客签发按客户端 IP 前缀每分钟 30 次。APP 完整性证明与 Access Token 的跨接口消费（身份中间件）随 S2-1 / S5-1。

### 2.2 用户会话
- **注册**：用户名（唯一，3–32 位）、密码（≥ 8 位，校验常见弱口令表）。不收集邮箱和手机号。可被「开放注册」开关关闭。注册请求必须带「已知晓忘记密码无法找回」的确认（`ack_no_recovery=true`），否则 400。
- **登录**：用户名 + 密码。游客的历史、收藏、点赞只存本机，登录或注册成功后由客户端调用 `POST /api/v1/me/local-merge` 一次性并入（去重、在一个事务内完成，`13` 第 2.2 节）；游客设备 ID 记录到 `guest_device.merged_user_id`。
- **密码存储**：Argon2id（`m=64MiB, t=3, p=2`，参数随硬件评估上调），哈希串内含参数，登录成功时若参数过旧则透明重哈希。
- **令牌**：
  - Access Token：JWT，EdDSA（Ed25519）签名，15 分钟，含 `sub/sid/role/kid`，不含敏感信息。
  - Refresh Token：256 bit 随机串，服务端只存 SHA-256；注册用户 30 天滑动有效、游客 180 天（`10` 第 4 节）；**每次刷新轮换**，旧令牌被再次使用即判定泄露，吊销该会话族（游客身份与轮换 / 复用检测在 S1-10 已实现）。
  - 会话表 `user_session` 记录设备、UA 摘要、最近活跃；用户可在「我的」查看并下线设备。
- **不提供找回密码**（`adr/0001`）：没有恢复码、邮件、短信，后台也没有重设用户密码的接口；忘记密码只能重新注册，原用户名不释放、数据不迁移。VIP 用户可凭支付凭证由客服迁移剩余会员天数（第 12.6 节）。
- **修改密码**：已登录且提供当前密码；成功后吊销该用户全部会话（S2-1 已实现：`POST /api/v1/me/password`，连同注册 / 登录、身份中间件、「我的设备」列表与下线 `GET/DELETE /api/v1/me/sessions[/:id]`，详见 `docs/specs/S2-1.md`；游客数据的去重并入 `local-merge` 依赖 `watch_history`/`follow`/`like` 表，随 S2-3 建表、S2-10 落地）。
- **防枚举**：登录时用户名不存在与密码错误返回相同提示与相近耗时；注册时「用户名已存在」无法避免，注册接口单独限流。
- **状态**：`banned` 立即吊销会话；`muted` 禁止发评论/弹幕。
- **防撞库**：同用户名或同 IP 连续失败 5 次后要求通过人机验证（自建 PoW 挑战或第三方验证），失败计数存 Valkey。（S2-2 已实现：失败按用户名 5 次 / IP 前缀 20 次计数（滑动 15 分钟）触发；`GET /api/v1/auth/challenge` 下发自建 PoW 挑战（`SHA-256(nonce:solution)` 前 18 bit 为 0，nonce 一次性、2 分钟有效），登录带 `challenge` 答案通过后仍正常校验密码、不锁定，成功清用户名计数；详见 `docs/specs/S2-2.md`。）

### 2.3 后台会话
- `POST /api/admin/login`：账号密码 + **TOTP 或 Passkey（WebAuthn）二次验证**，超级管理员强制开启。二次验证在 S2-6 接入，此前只校验密码（`mfa_required` 恒为 `false`），后台入口不能对公网开放。
- 用户名不区分大小写（库中存小写）。用户名不存在与密码错误返回相同的 401 `NEED_LOGIN`「用户名或密码错误」；用户名不存在时也做一次同等代价的 Argon2id 计算，耗时相近。账号停用时（密码正确）返回 403。
- 防暴力破解：失败次数按用户名、按 IP（IPv6 按所在 /64）分别计数（Valkey，最后一次失败后 15 分钟清零）；同一用户名连续失败 5 次、同一 IP 失败 20 次后锁定到计数过期，期间返回 429 `RATE_LIMITED` + `Retry-After` 且不再校验密码；登录成功清除该用户名的计数。每次尝试写 `admin_login_log`（IP 只存 /16 网段，UA 只存摘要）。
- 会话为服务端会话：256 bit 随机令牌放在 `HttpOnly; SameSite=Strict; Path=/` Cookie（开发环境名为 `xs_admin`；其余环境为 `__Host-xs_admin` 并带 `Secure`），不设过期时间，作用域仅后台域名。Valkey 中以令牌的 SHA-256 为键，只存管理员 ID、会话版本、CSRF 令牌、UA 摘要与创建时间；空闲 2 小时过期（每次请求重置）、绝对时长 7 天，UA 摘要变化即作废。每次请求都读一次账号、角色与权限点：停用账号或角色、改角色、改权限立即生效，会话版本与账号不一致（被重置密码或强制下线）时作废。
- 写操作要求 CSRF 令牌与 `Origin` 校验：令牌随会话生成，由登录与 `GET /api/admin/me` 返回，前端只存内存，写请求放在 `X-CSRF-Token` 头，服务端与会话中的值做常量时间比较；带 `Origin` 的写请求（含登录）必须来自 `ADMIN_ORIGINS`。
- 高敏操作（导入配置、改线路、生成 API Key、改管理员）要求 5 分钟内重新验证二次因子；IP 网段变化时要求重新验证（`10` 第 6.3 节）。两者在 S2-6 接入。
- 首个超级管理员只能用命令行创建：`admintool create-admin -username <名> -role superadmin`（`-role` 为角色编码），密码从标准输入读取（`11` 第 9.3 节）；之后在后台「管理员」页管理。
- 重置其他管理员的密码、强制下线：账号的 `session_version` 加一，该管理员的全部会话立即作废（会话中记录创建时的版本）。这只适用于后台管理员；用户端账号不提供任何重设密码的途径（`adr/0001`）。
- 可选：后台入口只对公司出口 IP / 零信任网关开放。

### 2.4 开放平台鉴权
- 请求头：`Authorization: ApiKey <key_id>`，`X-Timestamp`、`X-Nonce`、`X-Signature`（HMAC-SHA256，签名串见 `10` 第 5 节）。
- 后台只存 `prefix` 与密钥的 HMAC 哈希；完整密钥仅生成时返回一次。
- Scope：`push_content`、`read_metrics`；停用即时失效；可绑定来源 IP 段。

### 2.5 权限（后台，可配置，`adr/0006`）

- **权限点**：每个后台页面有「查看」`<页面>.view`；有写操作的页面另有「修改」`<页面>.edit`；需要单独授权的操作是独立权限点：`seo.analytics_code`（统计代码，高敏）、`blocks.custom_html`、`ads.custom_html`。权限点目录在 `admin_permission`，由迁移定义，后台只能授予不能新建；标 `sensitive` 的为高敏（改线路、存储源、FTP、配置导入、API Key、域名、管理员、角色与权限），S2-6 起操作需 5 分钟内重新验证二次因子。会员支付、福利等页面的权限点随对应任务的迁移加入。
- **判定**：后端路由用 `RequirePage("<页面>")`（GET/HEAD/OPTIONS 要 `.view`，写要 `.edit`）或 `RequirePermission("<权限点>", …)`（满足任一即可）声明，不满足时 403 `FORBIDDEN`。启动时校验路由声明的权限点都在目录中，缺失则拒绝启动。每个请求读一次账号、角色与权限点，修改立即生效。前端只做显示控制。
- **角色**：超级管理员是唯一的内置角色，也是唯一的超级角色，拥有全部权限点（含以后新增的），不能改权限、停用或删除；其余角色由管理员新建，新角色没有任何权限；有成员的角色不能删除；停用角色后成员不能登录、已有会话立即失效。迁移 00005 删除了 00003 预置的运营 / 审核员 / 只读三个角色（已有成员的改为自定义角色保留，回滚时恢复）。
- **防越权**：非超级管理员不能修改自己的账号与自己所属角色的权限，只能授予或收回自己拥有的权限点；只有超级管理员能授予超级管理员角色或操作超级管理员账号；修改管理员角色与状态时在事务内加锁检查，至少保留一个可用的超级管理员。授予某页面的任一权限点时自动补上该页面的「查看」。
- **以后新增的权限点**：会员支付（S3-15）与福利（S6-8）后台接口落地时随迁移加入。其中订单退款补单、会员发放扣回迁移、支付渠道与凭据、奖池概率与库存、等级权益、发放预算、金币人工调整标为高敏（金币调整超阈值另需第二位超管复核）；授予哪些角色由超级管理员在「角色权限」中决定。

- **后台菜单**：存 `admin_menu`，最多两级：一级菜单是目录、页面或外链，二级菜单是目录下的页面或外链，目录只能是一级。`GET /api/admin/me/menus` 返回当前管理员的两级侧栏：只含可见的菜单，页面还需有「查看」权限，外链对所有管理员显示，没有可见二级菜单的目录不返回。`GET /api/admin/permissions` 按同样的结构返回权限树（一级页面直接带权限点，目录下是二级页面）。默认菜单（迁移 00005）：「运营数据看板」「剧集分析」两个一级页面，之后是内容 / 框架 / 白标 / 运营 / 社区 / 系统 / 权限七个目录。

## 3. 内容服务模块

### 3.1 片库读写
- 剧/分集/标签/维度/专题的 CRUD（后台）与只读查询（前台）。不做演员（迁移 00010 已删除演员表）。后台部分在 `domain/content`（规则）+ `store/pg/content.go`（事务与 SQL）+ `http/admin/content`（接口，挂在后台会话分组上，按页面声明权限点）。
- **可见性规则**：前台只返回 `status=published 且 (publish_at 为空或 ≤ now)`；草稿、下架、定时未到不返回。后台列表的 `scheduled` 筛选即「已上架但定时未到点」。
- **上架时间**：保存或批量上架为 `published` 且没有 `publish_at` 时写入当前时间（「最新」排序用）；`publish_at` 在未来即定时上架。保存剧资料时 `hot_score` 同步为 `view_base + view_count`，真实播放量变化后的刷新由定时任务负责（S3-5）。
- 「更新至 N 集 / 全 N 集」：取已上架剧的最大可见集号与 `is_finished`；可见集号只算可播放（`media_status = ready`，转封装完成）的分集。该值在分集增删改与转封装切换产物的同一事务内写入 `drama.latest_episode` 冗余列（先锁住剧，串行化同一部剧的并发修改），避免列表页聚合查询。
- 删除进回收站（30 天可还原，S4-7）：只写 `deleted_at`，分集与关联保留；回收站中的剧及其分集在后台视为不存在（404）。手选专题整体替换时，回收站中的剧保留在专题里，还原后回到原位置。
- **关联**：标签、维度取值各自整体替换（事务内先锁剧）；单选维度最多一个取值，多选改单选前要求没有剧选了多个取值。标签不删除只合并：源标签记 `merged_into_id`，它的剧挂到目标标签，原先并入它的标签也改指目标；已合并的标签不能再被选用。
- **slug**：`a-z0-9-`，不以连字符开头或结尾，≤ 64；标签、维度、取值、专题留空时生成「前缀-6 位随机」（`t-`、`f-`、`v-`、`s-`），碰巧冲突时换一个重试；剧的 slug 可以留空。唯一键冲突按约束名映射为 409 并说明是哪一项。

### 3.2 前台内容读接口

| 接口 | 说明 | 缓存 |
| --- | --- | --- |
| 首页编排 | 按 `block(page=home)` 渲染区块，自动区块按来源规则选剧 | 整页 JSON 缓存 60s + SWR 300s |
| 频道 `/c/:slug` | 维度取值落地页，列表 + 排序 + 分页；取值停用则 404 | 60s |
| 标签 `/tag/:slug` | 标签聚合；敏感标签需过年龄门且输出 `noindex` | 60s |
| 剧详情 `/d/:id` | 资料 + 分集（含 access/试看）+ 相关推荐 + 下一部 | 120s，按剧 ID 精确失效 |
| 探索 `/explore` | 两个 Tab（剧集 / 专题）+ 分面筛选 + 排序 | 30s，按规范化查询串做键 |
| 专题 `/topics`、`/topics/:slug` | 列表 + 详情（剧 + FAQ） | 300s |

- **排序枚举**：`latest` / `hot`（真实播放 + 初始播放量）/ `recommend`（`sort_weight`）/ `random`。
- **上新窗口**：`all` / `7d` / `14d` / `30d` / `90d`。
- **分页**：列表默认游标分页（`cursor` = 排序键 + id 的编码），避免深 OFFSET；频道页保留页码跳转时限制最大页数（如 100 页）。
- `random` 排序不用 `ORDER BY random()`，而是每 10 分钟预生成随机序列表，按游标读取。

### 3.3 搜索
- `GET /api/v1/search?q=&sort=&cursor=&limit=`（S3-4，`specs/S3-4.md`）：结果只有剧集（不做资讯），游标分页 + `total`，只含前台可见的剧。排序 `latest`/`hot`/`recommend`，**默认 `hot`**——MVP 没有相关性打分，热度是最合理的代理；不支持 `random`。读穿缓存 60 秒（键含规范化后的词、排序与游标），响应带 `ETag`、共享缓存 60 秒。
- `GET /api/v1/search/suggest?q=&limit=`：剧名联想，最多 10 条，**剧名以搜索词开头的排在前面**、其余按热度（别名命中排在前缀命中之后）；读穿缓存 5 分钟，`ETag` + 共享缓存 300 秒。`features.search_suggest` 关闭时整个接口 404（前台据此隐藏实时联想）。联想**不计入**热搜：输入过程中的半截词会污染选品依据。
- 实现：MVP 用 PostgreSQL + `pg_bigm`（中文二元切分）建 GIN 索引，搜索复用前台剧列表那一套查询（`PublicDramaFilter.Pattern`），只多一个「剧名或别名命中」的条件；量大后同步到 Meilisearch，由 River 任务增量写索引，相关性排序届时再做。
  - 大小写不敏感：搜索词统一经 `internal/textnorm.Search` 转小写，SQL 按 `lower(title)` / `lower(aliases_text(aliases))` 匹配，并为这两个表达式单独建了 pg_bigm 索引（迁移 00035）。**`ILIKE` 用不上 pg_bigm 索引**（实测关掉 `enable_seqscan` 仍是顺序扫描），所以不能图省事写 `ILIKE`。
  - `%` 与 `_` 由领域层转义，不会被当成通配符。
- 热搜（`domain/ops.HotsearchService`，`specs/A3-4.md`）：搜索接口每次搜索调用 `Record(q, 结果数)`（只在第一页调，翻页不重复；命中缓存也调，因为用户确实搜了这一次；调用失败只记日志，不影响搜索结果。由 app 层把 `HotsearchService` 作为 `content.SearchRecorder` 注入，内容域不依赖运营域）。词经 `NormalizeSearch` 规范化（全角转半角、去控制与格式字符、转小写、合并空白，超过 50 字不计）后在 Valkey Hash 里累加搜索次数与「片库没有」次数（Lua 一次完成，一小时内最多收 2 万个不同的词，防刷）；worker 每小时一次 River 周期任务 `hotsearch_flush` 用与广告相同的「改名到任务编号名下 → 写库 → 删除」方式落库，新词自动收录、默认不显示。「搜得多但片库没有」的词供后台热搜模块选品。
- 热搜榜 `GET /api/v1/search/hot`：显示中的词，置顶的按后台顺序在前，其余按搜索次数倒序，共 10 个；Valkey 读穿缓存 5 分钟，后台改动与每次落库后立即清除；响应带 `ETag`，共享缓存 60 秒。置顶的词一定显示，最多置顶 10 个（事务内咨询锁串行检查）。
- 输入防护：`q` 长度 ≤ 50，去除控制字符；联想接口单独限流。

### 3.4 推荐与榜单
- 相关推荐：同标签 / 同维度召回 + 热度排序；结果按剧 ID 缓存 30 分钟 [推断]。
- 榜单 2 类：剧集周榜 `drama_week`、月榜 `drama_month`（`domain/ops.RankService`，`specs/A3-4.md`）。
- 计分 = 播放 × `play` + 追剧 × `follow` + 点赞 × `like` + 看完 × `finish` + 运营加分，系数在 `site_config.ranking`（默认 1 / 3 / 2 / 2），分数保留两位小数；只算前台可见的剧（不在回收站、已上架、定时已到点）。埋点（S4-1 / S4-2）与追剧、点赞（S2-3）就绪前，播放 = 剧的热度（初始播放量 + 真实播放量），其余按 0，周榜与月榜相同；就绪后换成按统计窗口汇总的 `RankSource` 实现。
- 运营干预（`rank_override`，`02` 第 3.8 节）：置顶的排在最前、多部置顶之间按分数；不让上榜的去掉（只影响该榜）；加分直接加到分数上，负数为减分。其余按分数倒序，同分按剧集编号升序。
- 重新排名：worker 的 River 周期任务 `rank_recompute`（`metrics` 队列，每 5 分钟）两张榜各算前 100 名。后台「马上重新排名」把同一任务入队并最多等 5 秒（每 200 毫秒查一次任务状态）：算完返回 `done=true`，否则 `done=false`、任务稍后完成，任务失败 503。不设唯一约束：River 的唯一约束必须包含运行中的任务，正在算时再点会被跳过，漏掉刚保存的改动。
- 存储：Valkey 有序集合 `xsite:rank:<board>`（成员为剧集编号，分数为名次位置，避免置顶与浮点分数混排）+ Hash `…:heat`（热度值）+ `…:at`（计算时间）。重算先写 `…:tmp:<随机>` 临时键，再由一个 Lua 脚本把两个键 `RENAME` 过去、去掉过期时间并写入计算时间；读侧用 Lua 一次取名次、热度与时间，没有空窗。结果为空时清空榜单。
- 前台 `GET /api/v1/rank`：取线上榜单前 30 名，按顺序查剧卡片、去掉排名后下架的剧，重新连续编号后取前 20；组装结果缓存 30 秒，每次重算后清除；响应带 `ETag`，共享缓存 60 秒。榜单从没算过（新环境、Valkey 被清空）时当场算一次并写入，同一时刻同一张榜只算一次（singleflight）。`features.ranks` 明确为 false 时 404。
- 后台（`http/admin/ops`，权限点 `ranks.view` / `ranks.edit`）：人工调整按榜整体保存，页面同时给出线上榜单与按当前系数、调整现算的预览；保存调整或系数只影响下一次重新排名。审计 `rank.update`、`rank.recompute`、`ranking_config.update`。

## 4. 播放服务模块（核心）

### 4.1 选源鉴权 `GET /api/v1/episodes/:id/sources?line_id=`
- 鉴权按分集 `access`：
  - `free`：直接返回。
  - `login`：未登录返回 401 + 业务码 `NEED_LOGIN`，前台展示登录墙。
  - `vip`：`user_vip.expire_at > now()` 才返回完整清单；非会员有 `trial_sec` 时按试看返回，否则 402 + 业务码 `NEED_VIP`，前台展示 VIP 墙。游客一律视为非会员。
  - `trial_sec>0`：未登录返回试看令牌，令牌内写入可播秒数，服务端生成只含前 N 秒切片的清单（试看限制在服务端生效，不依赖前端计时）。
- 出参：`region` + 候选线路数组 `{line_id, name, region_tag, recommended, manual, url, expires_at}`，`url` 为签名后的清单地址（`12` 第 4.4 节）。
- **播放令牌**（`internal/crypto/playtoken`，S1-7）：`token = kid + "." + base64url(payload) + "." + base64url(HMAC-SHA256(key[kid], kid + "." + payload段))`，payload 含分集、线路、设备哈希（SHA-256 前 16 字节，令牌里不出现设备标识原文）、试看秒数与过期时间；10 分钟有效，续播时前端在过期前 60 秒重新取源。密钥是服务端专用的 `PLAY_TOKEN_KEYS`（第一把签发、全部校验，kid 用于轮换）：令牌只由本服务的清单与密钥接口（S1-8）校验，不交给 CDN，线路密钥 `LINE_SIGN_KEYS` 只用于切片签名。不绑定 IP 网段：手机在 Wi-Fi 与蜂窝网络之间切换时 IP 会变，绑定会让播放中断。
- **观看者身份**：选源对游客开放，身份经 `Authorization: Bearer` 的 Access Token 解析（注册用户 role=user、游客 role=guest、无令牌按未登录/游客处理，S1-10 / S2-1 已接入），设备标识取 `X-Device-Id`（APP 发送；Web 的游客 Cookie 随 W1-1 接入）；会员由 S3-10 的 billing 服务按 `user_vip.expire_at > now()` 实时判定（`specs/S1-7.md`）。清单 / 密钥接口不重判身份，以播放令牌为准（会员在令牌有效期内到期不中断）。
- **限流**：选源桶 `s:{device}`（没有设备标识时按 IP，IPv6 按 /64）每分钟 60 次，超出 429 + `Retry-After`；S0-7 接入通用限流前用 Valkey 固定窗口计数，Valkey 不可用时放行。
- 地区判定：按客户端 IP 解析国家/省份/运营商（GeoIP，不落库），匹配线路地区规则并结合健康分排序；完整算法见 `12` 第 4 节。
- 缓存：选源结果不可共享缓存（`Cache-Control: private, no-store`）；线路配置在进程内缓存，随 `site.version` 失效。

### 4.2 清单与密钥 `/api/v1/hls/*`（S1-8，`specs/S1-8.md`）
- 只处理**清单（.m3u8）与密钥**，不代理切片；两者都只能经加密接口获取（`apienc`），明文请求一律 400 `ENC_REQUIRED`：在 handler 里检查，不受 `API_ENCRYPTION_REQUIRED` 影响，SSR 内网直连也不放行。Web 播放器用 hls.js 自定义加载器取回后经 MSE 播放（`<video>` 为 `blob:` 地址），APP 经本机回环代理（`05` C.3）。
- 令牌（第 4.1 节）：过期 401 `TOKEN_EXPIRED`；格式错误、签名不对、不是签给本设备的（`X-Device-Id` 的哈希不符）403 `FORBIDDEN`，不区分原因；客户端对这两类错误都重新选源，不走登录态刷新。每次请求都重新确认分集可播放（下架立即 404）；观看权限以令牌为准、不重新判定（会员在令牌有效期内到期不中断）。
  - 清单：`/api/v1/hls/:token/index.m3u8` 原样返回产物的 `master.m3u8`，各档是相对地址 `v{短边}.m3u8`、经同一接口获取（只能取主清单列出的档位）。新 MPEG-TS 产物的一档清单只包含 `.ts` 切片；历史 fMP4 的 `EXT-X-MAP` 与 `.m4s` 继续兼容。所有需访问的对象都改写为令牌所指线路上的签名地址（`12` 第 3.3 节：`hmac_token` / `cdn_vendor` 对目录前缀 `s/` 签一次，`s3_presign` 批量预签名，`none` 公开地址；有效期为线路的 `token_ttl`），`#EXT-X-KEY` 的 `URI` 重写为带令牌的密钥地址（IV 不变）；试看令牌只保留结束时间不超过 `trial_sec` 的切片（至少一个）并以 `EXT-X-ENDLIST` 结尾。线路停用 / 删除 / 不是视频线路、产物有就绪副本但不在该线路的存储源上、读不到清单或签不出地址时 503 `UNAVAILABLE`，播放器换下一条线路。
  - 清单原文：从产物就绪副本所在的存储源读（只读凭据、出站地址校验，令牌所指线路的存储源优先），没有副本记录的产物读默认存储 `S3_BUCKET_MEDIA`；单个不超过 4 MiB，Valkey 读穿缓存 1 小时（产物目录按任务区分、写入后不变）。改写后的清单含签名与令牌，不缓存。
  - 密钥：`GET /api/v1/hls/key/:episode_id/:key_ver?t=` 校验令牌（分集须与路径一致）、限流（每设备每集每分钟 20 次，超出 429 + `Retry-After`），`key_ver` 可以是该集任何仍在库里的版本；用 `MEDIA_KEKS` 解开后返回 16 字节 AES-128 密钥，`Cache-Control: no-store`。
- 切片由 CDN 直接回源对象存储，边缘验签，业务进程不承载视频流量。
- `video_process=text_to_image` 的历史线路：清单重写时附带还原参数，由客户端播放器的加载器处理（尚未实现，S1-8 范围外）；新入库内容统一走标准 MPEG-TS HLS。
- 线路侧（CDN / 存储源）对切片与测速文件支持 `Range` 与 CORS（`Access-Control-Expose-Headers: Content-Length, Content-Range`）供测速；清单与密钥是同源加密接口，不涉及。

### 4.3 线路列表 `GET /api/v1/lines?kind=video|image`
- 按客户端 IP 返回当前地区的线路列表（含测速探针地址）与 `smart_routing` 开关；存储源、线路、规则在后台配置（`12`）。
- 客户端质量上报 `POST /api/v1/lines/report` 参与健康分计算。
- 任何存储/线路变更令 `site.version` +1。
- 配置切换窗口返回业务码 `LINE_UPDATING`，前台提示「线路更新中，请稍后重试」。

### 4.4 测速配合
- 测速探针地址指向每条线路的固定小文件（如 256 KB），可被 CDN 缓存。
- 测速与选源单独限流，返回 `Retry-After`。

## 7. 增长服务模块

运营四项（公告、广告、热搜词、榜单干预，`specs/A3-4.md`）的代码在 `domain/ops`（规则、下发与计数）+ `store/pg/ops.go` + `http/admin/ops`（后台接口）+ `http/public/ops`（前台接口）；热搜词与榜单的规则见第 3.3、3.4 节。

### 7.1 广告投放
- `GET /api/v1/ads?slots=&n=&device=&locale=`：候选（投放中、未结束）在 Valkey 读穿缓存 1 分钟，后台增删改后立即删除。每次请求按位置、端（`all` 投给两端；不带 `device` 只给 `all`）、投放语言（没带或不支持按 `zh-CN`）、结束时间筛选，去掉该设备当天曝光已到 `freq_cap` 的，每个位置按权重不放回地随机取 `n` 条（1–5）。频控计数读不到时照常投放（只记日志）。响应 `private, no-store`。
- `POST /api/v1/ads/event`：`{ad_id, kind: impression|click}`，返回 204；不在投放中的广告不计数。同设备、同广告、同事件 1 秒内只计一次（`SET NX PX 1000`）；计数 `HINCRBY` 进待落库的 Hash，有频控的广告的曝光同时计入「北京日期 + 设备」的 Hash（25 小时过期）。
- 设备标识：请求头 `X-Device-Id`（UUID），没有或格式不对时用「IP 网段 + UA 摘要」；只把摘要写进 Valkey 键。游客身份（S1-10）上线后改用游客令牌中的设备 ID。
- 落库：worker 每分钟一次 River 周期任务 `ad_count_flush`（`metrics` 队列），用 Lua 把待落库的 Hash 原子改名为「任务编号」名下再读出，一条 `UPDATE … FROM unnest(…)` 加到累计上，成功后删除；写库失败时那一份留在任务编号名下，River 重试同一任务时再写，新到的计数留给下一轮。后台显示的数字最多晚 1 分钟。
- 自定义 HTML 素材：新建、改成 HTML、修改原本是 HTML 的广告都要 `ads.custom_html`（默认只有超管），删除只要 `ads.edit`。保存时用 `bluemonday` 清洗（UGC 策略 + 少量排版用的内联样式；去掉脚本、样式表、iframe、表单、事件属性与 `javascript:` 等协议，站外链接加 `target=_blank` 与 `noopener`），清洗后为空则拒绝保存；前台只在沙箱 iframe 中渲染。

### 7.2 分享与 OG 卡片
- `GET /api/v1/og/drama/:id`：剧分享卡片图。生成后写入对象存储并由 CDN 缓存（键含剧 `updated_at`），不在每次请求时渲染。
- `GET /api/v1/og/brand-logo?scheme=`：按深浅色返回品牌卡片。
- 分享海报由客户端生成，可被 `share_poster` 开关关闭。

### 7.3 公告
- `GET /api/v1/announcements?locale=`：返回当前显示中的顶部滚动条与弹窗（新的在前）。站内信（`inbox`）暂不启用，后台不能新建。
- 显示中 = 启用，且当前时间在开始、结束之间（不填表示不限），且「投放语言」为空或包含 `locale`（没带或不支持的语言按 `zh-CN`）。
- 「出现页面」「频率」由前台判断：每人一次、每人每天一次的记录存在客户端本机；同一页面有多条弹窗时只弹第一条（最新的）。
- 缓存：候选（启用、未结束）在 Valkey 读穿缓存 1 分钟，后台增删改后立即删除；起止时间与语言每次请求重新判断。响应带 `ETag`，`Cache-Control: public, max-age=0, s-maxage=30, stale-while-revalidate=60`（加密响应由中间件改为 `no-store`）。

## 8. 数据与埋点服务

### 8.1 采集 `POST /api/v1/events`
- 批量上报（最多 50 条/次，APP 本地队列）；服务端只做校验与入队，立即返回 204。Web 用加密客户端 + `fetch` 的 `keepalive`，**不用 `sendBeacon`**：`/api/v1/*` 必须报文加密，sendBeacon 带不了 `X-Enc` 头。加密是异步的，页面卸载（直接关标签页、整页跳走）时不一定来得及做完，前台把还没发出去的事件暂存本机、下次打开时补发（10 分钟内，`04` C.10）；补发的事件按服务端收到的时间记，最多晚 10 分钟。
- 写入路径：handler → 内存环形缓冲（按实例）→ 每 1 秒或 1000 条批量 `COPY` 进 `event_raw`（按天分区）；进程退出前刷盘。
- 事件内容同前版：访客、播放尝试（首帧、三分类结果、中断）、播放问题（换线、解码失败、卡顿）、观看（有效秒数 ≥ 10s 才算有效）、广告、注册墙、Web 性能指标（`web_vitals`）；APP 补充设备型号、系统版本、渠道包、推送到达/点击；容灾补充「域名切换事件」（见 `09`）。各事件的触发时机与 `props` 以 `04` C.10 事件字典为准（后端白名单在 `domain/analytics/model.go`，单测按字典逐项核对；前台类型在 `#lib/analytics/queue.ts`，增删类型两边一起改）；「有效秒数 ≥ 10s」由客户端按每集累计判定，满 10 秒才开始上报 `watch`，汇总直接求和。
- 防伪造：事件带设备 ID 与会话签名；异常速率的设备进入观察名单，看板默认剔除。

### 8.2 汇总任务
- 每日凌晨 3 点（北京时间）River 周期任务定稿昨日数据，写 `metric_daily / metric_drama_daily / metric_episode_daily`。
- 小时级预聚合：`metric_hourly` 物化，看板实时卡片读它，不扫原始表。
- `watch_since` 口径与「不与上一段比」标记保持不变。
- 注册墙曝光 `reg_wall_views` 只数 `register_wall` 的 `step=show`（没带 step 的老数据按曝光算），同设备同集同日去重（`04` C.6 漏斗口径）；点击另由 `step=click` 记录、不计入曝光。
- 冷数据：`event_raw` 保留 90 天，之后导出 Parquet 到对象存储并删除分区。

### 8.3 数据上报暂停 [推断]
- 一键暂停/恢复前台上报（经 `site_config.features` 下发），前台播放照常。

## 9. 平台服务模块

### 9.1 白标配置
- 读：`GET /api/v1/site-config` 返回全量配置 + `version`，带 `ETag`（由 `version` 派生）；BFF 与 APP 用 `If-None-Match` 条件请求。读走三级缓存（进程内一级短 TTL → Valkey 读穿缓存 → PG）。
- 写：后台分段保存，任一变更 `version +1`，并经 Pub/Sub 通知各实例清本地缓存（S1-9：`platform.SiteConfigService.BumpVersion` 统一 version+1 + 清本地与 Valkey + 广播；`cache.Invalidator` 走 Valkey Pub/Sub，各实例订阅后清各自的进程内一级缓存。实测改配置后另一实例约 8ms 生效，广播不可用时靠一级缓存 3 秒兜底 TTL，仍满足「5 秒内生效」）。后台分段保存的页面与校验是 S3-3 白标，写入各段后调用 `BumpVersion`。

### 9.1a 站点编排（静态页、前台菜单、页面区块，`specs/A3-1.md`）

代码在 `domain/site`（规则与下发）+ `store/pg/site.go` + `http/admin/site`（后台接口）+ `http/public/site`（前台接口）。三者都是设置类数据，删除不进回收站。

- **静态页**（`page` 表，迁移 00024，S3-2）：后台增删改查（搜标题或 slug、按状态筛选），前台 `GET /api/v1/pages/:slug` 只下发已发布的页（草稿与不存在都是 404），按 slug 读穿缓存 5 分钟、后台保存后立即清除，响应带 `ETag`、共享缓存 300 秒。
  - `slug` 全站唯一（`a-z0-9-`，与剧集同一套规则，由 `content.ValidSlug` 校验），唯一键冲突映射为 409。
  - 正文两种格式（`rich` 富文本、`html` 直接写）都按同一白名单清洗后入库：`internal/htmlsan` 的策略与广告的自定义 HTML 共用（bluemonday UGC + 少量排版用内联样式，站外链接加 `target=_blank` 与 `noopener`），清洗后为空则拒绝保存。
  - `is_footer` 且已发布的页随站点配置的 `footer_pages` 段下发给前台页脚（另有 5 分钟缓存，保存后一并清除）。
- **前台菜单**与**防丢地址**（`menu` 表 + `site_config.addresses`，S3-2）：随 `GET /api/v1/site-config` 下发；菜单的链接目标失效（静态页删除或改回草稿、频道取值停用等）时下发层过滤。保存地址段走 `SiteConfigService.BumpVersion`。
- **页面区块**（`block` 表，迁移 00028，S3-1）：后台按页面编排（首页 + 启用的频道页，`GET /api/admin/blocks/pages` 给下拉），前台 `GET /api/v1/home?page=` 一次返回该页面全部启用区块及其数据。
  - 10 种类型。剧类（轮播大图、精选大卡、海报网格、横滑列表）三种来源：手选编号（按给定顺序，保存时校验剧存在且不在回收站，下发时过滤不可见的）、用某个专题（专题是自动专题时沿用它的规则，条数用区块的 `item_limit`；专题被删或改回草稿时该区块暂时没有内容）、按规则自动选（复用 `content.PublicService.PickDramas`，与自动专题同一套规则引擎）。
  - 排行榜区块的剧由运营域的榜单服务给（app 层把 `ops.RankService.PublicBoard` 适配成 `site.RankBoardReader`，避免站点编排域依赖运营域；榜单与广告位的可选值在 `domain/site` 里写死，一致性由 `TestBlockEnumsMatchOps` 守着）。
  - 广告位与公告条区块只下发 `ad_slot` / `announce_kind`：素材要按设备频控，不能进共享缓存，前台另调 `/api/v1/ads`、`/api/v1/announcements`。
  - 整页读穿缓存 `site:home:{page}` 1 分钟（后台增删改、重排后立即清除；TTL 兜底的是剧集上下架等别的模块的改动），响应带 `ETag`、共享缓存 60 秒。列表类区块取不到内容时整块不下发（前台少一个空块）；单个区块取数失败只记日志并跳过，整页仍然 200（`04` 第 1 节）。
  - 自定义 HTML 走 `internal/htmlsan` 同一套白名单，清洗后为空则拒绝保存；新建、修改（含把原本是 HTML 的区块改成别的类型）要 `blocks.custom_html`，删除只要 `blocks.edit`。

### 9.2 缓存服务
- 三级：进程内 LRU（`otter` 等高性能缓存，秒级 TTL）→ Valkey（分钟级）→ PG。（通用 LRU 随 S0-4；S1-9 已先给站点配置单独实现了进程内一级缓存 + Pub/Sub 跨实例失效，见 9.1。）
- 防击穿：同键并发回源用 `singleflight` 合并；防雪崩：TTL 加 ±10% 随机抖动；防穿透：不存在的 ID 缓存空值 30s。
- 清缓存范围：`site_config`（version+1）、`home`、`list`、`drama:{id}`、`play:{id}`、`topic`、`search`、`rank`、`all`；同时调用 CDN 清理接口按标签/前缀清边缘缓存。
- 后台展示暂存量、站点版本、键前缀。

### 9.3 配置导出/导入
- 导出：菜单/静态页/区块/维度/广告素材 + 格式版本号，打包为 JSON 并附 SHA-256 摘要与签名。
- 导入：校验签名与格式版本 → 自动先做一次导出备份 → 在单事务内覆盖写入 → `version+1`。

### 9.4 资源体检任务
- River 任务按剧分片，并发探测（每资源机限并发，避免压垮源站），结果枚举 `ok/not_found/forbidden/server_error/unopenable/unreachable`。
- 最多展示 200 条；清空只清体检表。

### 9.5 资源预热任务
- 预拉清单与前 N 个切片到 CDN 边缘；参数同前（范围、模式、每清晰度片数、并发、是否含未上架）。
- 同时只允许一轮（River 唯一任务）；进度写 Valkey，后台轮询或 SSE 订阅。

### 9.6 媒体转封装任务（S1-5b，`docs/specs/S1-5b-MPEG-TS-HLS.md`）
- 触发：后台 `POST /api/admin/episodes/:id/transcode`（源文件为 `MEDIA_SOURCE_BUCKET` 中的对象；采集入库 S4-6 接入后同样入队）。任务行 `transcode_job` 与 River 任务 `media_transcode`（`media` 队列）在同一事务内写入；同一集同时最多一个排队或进行中的任务。
- 流程（`internal/transcode`）：下载源文件并算 SHA-256 → ffprobe 探测（按旋转元数据换算显示尺寸）→ 按短边选 360/480/720 码率阶梯（`08` 第 2.1 节，不放大）→ 一次解码、多路 H.264 + AAC-LC 编码出 MPEG-TS HLS（固定 4 秒切片、强制关键帧、闭 GOP、重复 SPS/PPS）→ 首帧 WebP → Go 内逐片 AES-128-CBC 加密（每片随机 IV，同一集各档共用一个新生成的内容密钥）→ `.ts` 切片按内容哈希命名后上传 → 生成各档清单与主清单。源无音轨时补本地生成的静音 AAC；HEVC / AV1 高效档按需再加。
- 产物：媒体桶 `video/episodes/{episode_id}/{job_id}/`（`master.m3u8`、`v{短边}.m3u8`、`s/` 下的切片）；清单中密钥地址是占位符 `xsite-key:{key_ver}`，由 S1-8 改写；首帧图写图片桶 `img/posters/<hash>.webp`。
- 切换：一个事务内写 `media_object`、`media_key`（KEK 包装后的内容密钥）、把分集切换到新产物（`video_object_id`、`key_ver`、`renditions`、`poster`、`source_hash`，`media_status = ready`）并刷新「更新至 N 集」。已是 `ready` 的分集重新转封装时旧产物在切换前继续可播。
- 幂等与重试：源文件哈希与当前产物相同且未要求强制时记为 `skipped`；每次尝试先清空本任务的产物目录；最多 4 次（首次 + 重试 3 次），源文件不存在、不是视频、超出限制（4 GiB、4 小时）不重试；最终失败记 ERROR 日志（`alert=true`，告警通道随 X4-1）。运行中每分钟至少更新一次进度，超过 10 分钟没有更新的任务在下一次提交时标为失败。
- 安全：源文件按不可信输入处理（FFmpeg 只读本地文件、只接受常见视频容器、子进程看不到 worker 的环境变量）；内容密钥只在 Go 内存中，不写盘、不经过 FFmpeg。
- 部署：只有 `MEDIA_TRANSCODE_CONCURRENCY > 0` 的 worker 消费 `media` 队列，线上用 `service/Dockerfile` 的 `media-worker` 镜像（Debian + FFmpeg）；配置见 `11` 第 9.4 节。

### 9.6a 后台媒体上传（S1-5a）
- API：`POST /api/admin/uploads` 按用途选择后台「存储设置」中的图片/视频主存储并创建绑定当前管理员、provider、用途和 15 分钟 TTL 的上传会话；会话同时快照该 provider 的 endpoint、region、bucket、path style 与 `path_prefix`，所以后续修改同一 provider 的物理连接配置只影响新会话。`PUT /:id/content` 先原子 `created → uploading` 领取唯一写入权，再以精确 `Content-Length` 同源流式写入该快照目标；`POST /:id/complete` 再验对象元数据和图片文件头；`GET /:id` 轮询广告视频转码。上传内容路径单独放宽到 4 GiB，其他接口仍为默认 1 MiB；处理器按会话登记的大小流式转发，不缓冲整个文件。
- 大文件上传的两处时限（否则大视频在上传末尾被掐断，浏览器侧看到的是 502）：
  - **服务端超时按路由放宽**：全局 `ReadTimeout 15s` / `WriteTimeout 30s` 是按几十 KB 的 JSON 定的，覆盖的是**整个请求**，几百 MB 的视频根本读不完。`middleware.LongRequest` 用 `http.ResponseController` 把上传内容与上传完成两个路径的截止时间推到 2 小时、视频分片推到 15 分钟（请求体上限 64 MiB，handler 再按片长逐字节核对）、把 SSE（`text/event-stream`）推到 15 分钟，其余路由仍按全局值，慢速攻击的防护不变。完成请求的请求体只有几十字节，但暂存对象缺失时它的处理时间与文件大小成正比，同样会撞上 30 秒写超时。
  - **浏览器侧超时**：`admin/src/lib/http.ts` 的默认超时是 15 秒，而视频的完成请求在退回复制时耗时与文件大小成正比。`mediaUploadApi.complete` 因此要求调用方显式传超时，视频用 5 分钟。漏传会让几十 MB 的分集在文件已经传完之后才报「网络异常或请求超时」，而服务端日志里只看到一条 `context canceled`。图片优化接口同理：它要等两次外部服务往返，前端给 120 秒、服务端按 `middleware.LongRequest` 的 `externalDeadline`（3 分钟）放宽连接期限，请求体上限单独放到 25 MiB（收的是没压过的原图）。
  - **边缘层**：`deploy/prod/nginx` 的后台 location 关闭请求体缓冲并把 `proxy_send_timeout` 提到 1 小时；`client_max_body_size` 必须与 4 GiB 上限一致，给小了会在边缘层直接 413。
- 整段上传写入对象存储用 **S3 分片上传**（`blob.PutStream`）：顺序读请求体、按 8 MiB 切片、最多 4 片并发传，失败时 `AbortMultipartUpload` 清掉已传分片。比「整个文件先落盘再单次 PUT」省掉一倍时间（那样的耗时是「收完 + 再传完」之和），顺序读 + 有界并发也让上传速度自然受下游存储限制而形成背压，不会把几 GiB 堆在内存或磁盘里。小于一个分片的对象仍走单次 PUT。
- **视频分片并行上传**（契约 0.83.0，迁移 00055，后台视频上传组件默认使用）：建会话时声明 `multipart: true`，服务端在私有入库桶上开启 S3 分片上传（`blob.MultipartStore`），会话记下 `part_size`（`upload.VideoPartSize` = 5 MiB）与 `multipart_upload_id`。浏览器按片号 6 路并发 `PUT /:id/parts/:number`，每片 `Content-Length` 必须等于推算出的片长（除最后一片外都是 5 MiB）；`TouchPart` 条件更新原子置 `uploading` 并把过期时间从当时起顺延 15 分钟（会话时长约束的是「停传多久算放弃」）。handler 把整片读进内存再 `UploadPart`（SDK 重试要能从头重读；全进程 `PartSlots` 限 24 个名额 ≈ 120 MiB），同一片重传以最后一次为准。`complete` 先 `ListParts` 核对片号 1…N 齐全且逐片长度正确，缺片返回 400（提示缺哪几片）且不改会话、补传后可再完成；齐了再 `CompleteMultipartUpload`，之后与整段上传走同一路径（`stageVideo` 再 `Head` 一次 → 入队）。分片会话拒绝整段 PUT（两条路写同一个暂存 key 会互相覆盖）；不声明 `multipart` 的请求仍是整段上传。
  - **为什么分片**：整段 PUT 在生产链路上撞三道墙 —— ① Cloudflare Free / Pro 的请求体上限 100 MB（超过直接 413，更大的视频根本传不上去）；② Traefik v3 的 entrypoint 默认 `respondingTimeouts.readTimeout` 为 60 秒，覆盖读完整个请求体（Dokploy 的 Traefik 没有改这项时，一个请求 60 秒读不完就被掐断）；③ 一个请求只用一条「边缘 → 源站」连接，跨区回源时单条连接的吞吐就是上限。实测：同一台机器到 Cloudflare 边缘单连接上行 1.46 MB/s，而后台整段上传只有约 0.25 MB/s（30 MB 两分钟）；本地按「每条连接 256 KiB/s」限速复现，整段 PUT 31.2 MB 用 120.2 秒，6 路分片 20.4 秒（1.53 MB/s，含合并）。
  - **观测**：每片一行 `后台视频分片已写入`，`read_ms` 是读请求体的耗时（浏览器 → 源站）、`store_ms` 是写入耗时（源站 → 入库桶）；合并一行 `后台视频分片已合并`（`merge_ms`、`since_create_ms`）。上传慢时按这两段判断卡在哪里。分片请求调用 `admin.SkipAudit` 不单独记审计（4 GiB 约 820 片），建会话与完成仍各记一条。
  - **清理**：过期会话里开启过分片上传、却没走到 `uploaded` 的（停传或中途失败），清理任务 `AbortMultipart` 释放残片（R2 / S3 对未完成分片计费）；已合并的返回 `ErrNotFound`，按已清理处理。SeaweedFS 的 `ListParts` 会把同一片号的每次重传都列出来（S3 / R2 只列最后一次），`blob.ListParts` 按片号去重成 S3 语义。
  - **发布顺序**：先发 service 再发 admin —— 新页面会发 `multipart` 字段，旧 service 的 JSON 绑定拒绝未知字段。
- 图片压缩走**服务端**（`POST /api/admin/images/optimize?purpose=`，`internal/imageopt`）：浏览器把原图交给它，它调 Tinify（`IMAGE_TINIFY_API_KEY`）压缩、按需转 WebP 并把最长边限制到 `IMAGE_MAX_SIDE`（默认 2400），回传结果字节；调用方再走原来的三步上传，上传管线不变。API Key 只在服务端，不下发浏览器（Tinify 也不支持浏览器直连的 CORS）。实测 1.27 MB 的 PNG 压到 20.9 KB。
  - **为什么不在浏览器压**：canvas 要先解码再有损编码，对已经优化过的 JPEG 几乎必然「又掉画质又涨体积」—— 这正是上一版固定 0.92 质量时运营报的「压缩后比原图还大」。
  - **降级**：没配 Key、本月额度用尽（Tinify 免费 500 次/月，一张需要转格式或缩尺寸的图消耗 2 次）或这张图它不认时接口回 503/400，浏览器退回 canvas 兜底。兜底不再固定一个质量值，而是沿 0.9 / 0.82 / 0.72 的阶梯取第一个确实小于原图的结果；原图是不超尺寸的 WebP 且仍更小时按原文件上传。界面上的压缩摘要会标出这次是服务端压的还是浏览器兜底压的。
  - 服务端校验 WebP 文件头（RIFF/WEBP，仍兼容历史 AVIF 对象），最终写入 `img/<purpose>/<uuid>.webp`。AVIF 的 canvas 编码主流桌面浏览器不支持，前台 AVIF 由 CDN 实时转（见 `08`）。
- 图片预览：`GET /api/admin/images/preview?key=` 把 `img/` 下的对象 key 同源代理成可直接 `<img src>` 的图片（从当前图片主存储读，带 ETag 与 `private, max-age=86400`）。只要已登录的后台会话、不绑定页面权限点（这些对象本身就是 `public, immutable` 的公开读图片，而图片字段散落在剧集、广告、公告、静态页、白标多个模块）；**key 必须在 `img/` 前缀之下**，`..`、绝对路径、反斜杠、查询串一律拒绝 —— 放开前缀就等于把私有视频源与 HLS 产物也变成可下载。后台的上传组件、手填图片字段与各列表页的缩略图都用它。
- 视频：源文件只接受 MP4/MOV/WebM/MKV，最大 4 GiB，**只写私有 `MEDIA_SOURCE_BUCKET` 的 `ingest/`**，不写主存储。分集视频提交既有加密 MPEG-TS HLS 任务；广告视频由 `admin_video_transcode` 任务复用码率阶梯和 MPEG-TS 打包，但不写分集内容密钥，最终写 `video/assets/<upload_id>/master.m3u8`。
  - **为什么不写主存储**：源文件是 `private, no-store`、不进 CDN，唯一的读者是转码 worker（`transcode_job.source_key` 就是暂存 key），主存储里那一份没有任何代码路径会读。为它多付一次完整上行，在跨公网的主存储上会直接把上传拖垮：实测 30 MB 切 4 片并发传 Cloudflare R2，单个 `UploadPart` 在途超过两分钟被对端断连，重试用尽后整个请求 500（`request send failed: EOF`，日志里没有状态码）；改成只写私有入库桶后同样的 30 MB 用 **0.2 秒**。
  - 完成阶段只 `Head` 核对暂存对象的大小与类型；只有更早版本留下的会话（源文件写在主存储）才退回复制一次。`Init` 仍然选取并快照视频主存储的 provider（`provider_id` 决定 `ingest/` 下的前缀，转码产物最终也要写它）。
- 清理：写入后的状态更新、格式校验或入队失败会立即删除刚写入的对象并标记会话 failed；worker 每小时按快照目标扫描过期会话，删除未完成图片/私有广告视频源与控制面记录。源已设为 disabled / readonly 时仍可尝试清理；单个源失败不会中断同批其他会话，失败记录保留待重试。已就绪图片只删会话记录，分集原视频保留给既有转封装重试；广告视频的 provider 源文件最多保留到会话过期清理，私有 `ingest/` 暂存由转码 worker 成功或终态失败时先行删除。
- 安全：上传会话只允许创建者写入或读取；用途决定现有 `*.edit` 权限；写入凭据仅在受信任的 API 上传代理与 worker 内存中使用，不向浏览器发放；完成、队列和失败均审计，错误消息不暴露本地文件路径。

### 9.7 采集入库
- 来源：开放平台推送 / FTP 扫描 / CSV 导入；规则同前（屏蔽词拒收、去重、草稿入库、预览不写库、记录批次）。
- 授权测试采集器（S4-6 第一切片）：仅 development 环境的 `cmd/collectortool` 接受人工核验的 catalog manifest，先校验权利基础/引用、精确下载域名和各域名的 `robots_url`，再以固定 User-Agent、HTTPS、`netguard`、无重定向、限大小/MIME/基础文件头的约束流式抓取素材。封面写图片主存储的 `img/collector/<run_id>/`，原视频写视频主存储的 `video/source/collector/<run_id>/`；报告保留物理存储目标快照，`cleanup` 只能删除本 run 的 collector 前缀。该切片不创建剧/分集、不发布、不触发 HLS 转码，真实来源必须有明确授权或开放许可；详情见 `docs/specs/S4-6-授权测试采集器.md` 与 `adr/0009`。
- FTP 连接只走显式 TLS（FTPS），凭证从密钥管理取，连接由 worker 出口发起（不暴露 API 节点 IP）。

### 9.7a 资源机（S1-6，`specs/S1-6.md`）
- 后台登记资源机（`domain/resource` + `store/pg/resource.go` + `http/admin/resource`）；账号密码不入库，`cred_ref` 对应 worker 的环境变量 `FTP_<cred_ref>_USER` / `FTP_<cred_ref>_PASSWORD`，只配一个时进程启动失败。
- 测连与打开目录：API 把 River 任务 `ftp_probe`（`default` 队列，只试 1 次，任务超时 20 秒）入队后每 200 毫秒查一次结果，最多等 25 秒，超时或调用方离开时撤销任务并返回 503 `UNAVAILABLE`；worker 用 `store/blob/ftpclient` 执行，结果写入任务 output。任务参数是发起时的资源机配置，不含账号密码。
- 连接顺序：解析地址（`internal/netguard` 校验全部 IP，被禁止的地址不连）→ 连接（显式 TLS 先 `AUTH TLS` 再发 `NOOP` 完成握手，证书按系统根证书校验）→ 登录 → 进入目录并读取（MLSD，不支持时 LIST）。每条连接（含数据连接）按 IP 直连并再校验一次；数据连接只连控制连接的对端 IP；连接的读写截止时间是整个操作的截止时间（15 秒），任务被撤销时立即中断。
- 非开发环境只允许显式 TLS，只支持被动模式；失败原因转成中文写在失败的那一步，原始错误只进 worker 日志。

### 9.8 审计
- 记录 `action/target/diff_before/diff_after/admin/ip/request_id`；密码、密钥字段在写入前脱敏。
- 审计中间件挂在 `/api/admin` 登录后的分组上：写请求返回 2xx 后异步落库（队列满或进程退出时改为同步写，不丢记录）。handler 用 `SetAudit` 补充动作（如 `drama.update`）、对象与前后差异，未补充时动作为「方法 + 路由模板」；字段名含 `password`、`secret`、`token`、`credential`、`private_key`、`api_key`、`access_key` 或以 `_enc`、`_hash` 结尾的值写入前替换为 `***`。
- 每条记录带 `prev_hash`，形成哈希链；每日把当日链尾哈希写入只追加存储，用于事后校验审计未被篡改（S4-7）。

### 9.9 推送服务（APP 新增）
- 设备推送令牌表 `push_token`（平台、通道、令牌密文、最后活跃）。
- 通道：APNs（HTTP/2，Token 鉴权）、FCM HTTP v1、国内厂商通道（华为/小米/OPPO/vivo/荣耀，或聚合服务）。
- River `push` 队列按通道限速；失效令牌回执后自动清理。

## 12. 会员与支付模块（`domain/billing`，`adr/0004`）

> 订单接口按 `adr/0005` 泛化为 `/api/v1/pay/orders`，可购买的商品类型：会员套餐 `vip_plan`；充值金币开关开启后增加 `coin_package`（`13` 第 2.7 节）。会员也可在金币商城用金币兑换（`13` 第 3.10 节）。

### 12.1 套餐与会员权益
- 套餐五种：`day`/`week`/`month`/`quarter`/`year`，默认 1/7/30/90/365 天；价格分人民币（分）与 USDT（10⁻⁶）两套，后台配置（`vip_plan`）。S3-10 先写入五种**下架**的默认套餐，不猜测价格或开放购买；由后续后台套餐页配置价格、渠道、上下架。
- `GET /api/v1/vip/plans` 的 S3-10 策略 A 仅按当前客户端过滤已上架套餐，结果按客户端缓存 60 秒；`payment_channel` 落地后（S3-11 / S3-15）再与渠道的国家/地区开关取交集，恢复「客户端 × 国家」缓存。
- 权益：观看 `access=vip` 分集（第 4.1 节）；`site_config.vip` 可配会员免广告、会员最高画质 [推断]。
- 判定：`user_vip.expire_at > now()`，读 Valkey 缓存（键 `xsite:vip:{uid}`，TTL 5 分钟），会员变动后删除缓存；选源接口每次实时判定，播放令牌最长 10 分钟，会员在播放中到期时本令牌内不中断。
- 只有注册用户能购买；游客下单返回 401 `NEED_LOGIN`。

### 12.2 下单 `POST /api/v1/pay/orders`
- **development 模拟**：仅 `APP_ENV=development` 可创建 mock 订单并调用 `POST /api/v1/pay/orders/:order_no/mock-complete`；模拟不读取凭据、不调用第三方，也不写回调留痕，但会经过真实订单状态机、会员行锁、流水和缓存失效。production 不注册该完成路径，并在没有真实渠道适配器时拒绝下单。
- 入参 `{product: {type: vip_plan|coin_package, id}, channel, client, coupon_id?, return_path?}`，带 `Idempotency-Key`；校验商品上架、渠道对该客户端与地区开放、未支付订单 ≤ 3、优惠券可用（下单时锁定，订单关闭或超时释放）。
- 订单号为随机 16 字节 base32（不可推测），`expire_at` = 现在 + 30 分钟；金额取商品当前价减优惠后写入 `product_snapshot`，之后改价不影响已下单。
- 返回 `pay_action`：

| 渠道 / 客户端 | `pay_action.type` | 内容 |
| --- | --- | --- |
| 支付宝 · Web 电脑 | `redirect` | 电脑网站支付页地址 |
| 支付宝 · Web 手机 | `redirect` | 手机网站支付页地址 |
| 支付宝 · APP 官网包 | `app_sdk` | 支付宝 APP 支付 orderStr |
| 微信 · Web 电脑 | `qrcode` | Native 支付 `code_url`（前台生成二维码） |
| 微信 · Web 手机（外部浏览器） | `redirect` | H5 支付 `h5_url` |
| 微信 · 微信内置浏览器 | `jsapi` | JSAPI 调起参数（需公众号 openid） |
| 微信 · APP 官网包 | `app_sdk` | APP 支付参数（OpenSDK） |
| USDT | `crypto` | `network`、本单收款地址、精确金额、二维码内容、到期时间 |
| 应用商店包 | `iap` | 商店商品 ID（`05` C.9） |

### 12.3 到账
- **只认服务端结果**：前台从支付页返回或轮询到「已支付」之前，一律显示「支付确认中」；`return_url` 不作为到账依据。
- **支付宝**：异步通知 `POST /callback/pay/alipay`（RSA2 验签，核对 `app_id`、`out_trade_no`、`total_amount`、`trade_status=TRADE_SUCCESS/TRADE_FINISHED`），处理完返回 `success`；未收到通知时由任务调用 `alipay.trade.query` 主动查单。
- **微信支付**：APIv3 通知 `POST /callback/pay/wechat`（平台证书 / 公钥验签，APIv3 密钥 AES-256-GCM 解密 `resource`，核对 `mchid`、`out_trade_no`、`amount.total`、`trade_state=SUCCESS`），按规范返回 200/204；同样有主动查单兜底。
- **USDT**：默认 TRC-20。每单从 `usdt_address` 取一个未用过的派生地址（服务端只持有扩展公钥，私钥离线保管、离线签名归集）；River `pay` 队列周期任务按地址拉取链上 USDT 合约的 Transfer 事件（TronGrid / 自建节点，ERC-20 用以太坊节点），到达确认数（TRC-20 ≥ 20 块，ERC-20 ≥ 12 块）后入账。少付不到账，订单有效期内可补足；多付按到账处理，差额记录人工处理。可切换为「固定地址 + 唯一尾数金额」模式。
- **入账事务**：同一事务内 `pay_order.status=paid`（唯一约束 `(channel, channel_trade_no)` 保证幂等）→ 按商品发放（会员：`user_vip.expire_at = max(expire_at, now()) + duration_days` 并写 `vip_ledger`；金币套餐：写充值金币批次与附赠的赠送金币）→ 优惠券标记已用 → 入队成长值、推广返利、任务事件与站内信任务；事务外删除 `vip:{uid}` 缓存。
- 回调路径 `/callback/pay/*` 不在 `/api/v1` 下：不经过 `apienc`、不要求会话，必须验签；原文写 `pay_notify_log`（摘要 + 加密原文）。
- 订单超时：River 周期任务每分钟关闭到期的 `pending` 订单（关闭前再查一次单）；关闭后到账照常发放并标记 `late=true` 告警复核。

### 12.4 查询与对账
- `GET /api/v1/pay/orders/:order_no`：只能查本人订单，前台每 2 秒轮询，最长 5 分钟。
- 每日 04:00（北京时间）对账任务：下载支付宝 / 微信对账单、汇总链上到账，与 `pay_order` 比对，结果写 `pay_reconcile_daily`，有差异告警。

### 12.5 退款与人工处理（后台）
- 退款：原路退回（支付宝 / 微信退款接口；USDT 由财务离线转账后登记交易哈希），按订单天数扣回会员（不足则扣到当前时间），写 `vip_ledger(reason=refund)`；同时扣回成长值、撤回或扣回推广返利；金币套餐只退未使用的充值金币并扣回附赠金币。
- 补单：凭渠道流水号查询渠道确认已支付后，后台补记到账。
- 发放 / 扣回：活动赠送或补偿，必须填写原因。
- 以上操作仅超管，需 5 分钟内二次验证，全部审计。

### 12.6 会员迁移（忘记密码的付费用户）[推断]
- 用户重新注册新账号后，凭原订单号 / 支付宝或微信交易号 / USDT 交易哈希联系客服；后台核验订单归属后，把原账号剩余天数迁到新账号（一对 `migrate_out` / `migrate_in` 流水），原账号不恢复、其他数据不迁移。
- 同一订单只能迁移一次；操作需二次验证并审计。

### 12.7 渠道与安全
- 渠道配置在 `payment_channel`：开关、允许的客户端、允许 / 禁止的国家（GeoIP，复用 `12` 第 4.2 节的解析结果）。加密货币支付在部分司法辖区被禁止，USDT 默认只对允许列表中的国家开放。
- 凭据（支付宝应用私钥、微信商户私钥与 APIv3 密钥、证书）信封加密存储，后台只写不读，只在支付服务内存中解密；USDT 不在线上保存任何私钥。
- 金额、币种、商户号、订单号逐项核对；回调重放由唯一约束挡住；金额不一致的通知不入账并告警。

完整业务规则、表结构、风控与开发计划见 `13`；这里只列后端实现约定。

- **只有钱包能改余额**：其他域通过钱包服务的方法入账或扣减，传入业务类型与业务单号；钱包在同一事务内写批次与流水，余额有 `CHECK` 约束不能为负。
- **发奖与来源同事务**：签到、抽奖、领取、兑换、返利到账都在一个数据库事务内写来源记录并调用发奖器；外部效果（站内信、推送）通过事务内入队的 River 任务完成。
- **服务端随机**：抽奖用 `crypto/rand`；天天奖券用承诺—揭示（`13` 第 3.6 节）。
- **配置热更新**：活动、奖池、任务、商品、等级配置进程内缓存（`atomic.Pointer`），版本变化经 Pub/Sub 通知。
- **事件**：业务写操作入队 `task.event`（带事件 ID），`welfare` 队列处理并按事件 ID 幂等。
- **应急**：全局「暂停发奖」开关（与挑战模式、写冻结等应急开关并列，`07` 第 2 节），开启后所有发奖返回 `BUDGET_EXHAUSTED` 类提示，抽奖与领取暂停。
