# 02 · 数据模型设计

> 目标库 PostgreSQL 18（PG 19 GA 后再评估）。字段名用 snake_case，与接口 DTO 对齐。`[推断]` 表示参考站未明示、据功能推导的字段。
> 时间统一存 UTC（`timestamptz`），看板口径按北京时间换算。软删除统一 `deleted_at`（进回收站），30 天后物理清理。
>
> **约定**
> - 主键：`bigint generated always as identity`；对外暴露的会话、设备、任务、批次用 `uuid`（UUIDv7，PG 18 `uuidv7()` 或 Go 1.27.3 `uuid.NewV7()`），按时间有序，索引局部性好。
> - 访问：全部查询写在 `service/db/queries/*.sql`，由 sqlc 生成 Go 代码；迁移用 goose。
> - 加密字段：后缀 `_enc` 表示 AES-256-GCM 信封加密密文（`v{ver}:base64`），后缀 `_bidx` 表示 HMAC 盲索引，详见 `10` 第 3 节。
> - 枚举：用 `text` + `CHECK` 约束，而不是 PG `enum` 类型，便于增加取值时不锁表。
> - 注释：全部业务表与字段的中文说明已用 `COMMENT ON` 落库（迁移 `00054_schema_comments.sql`），`psql \d+ <表>` 或任意数据库客户端都能直接看到。**新建表或新增列时在同一个迁移里写上 `COMMENT ON`**，不要只写在迁移文件的行内注释里 —— 行内注释进不了 `pg_description`。goose 与 River 自建表（`goose_db_version`、`river_*`）不注释。

## 2. 内容域

### 2.1 drama 剧集
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigserial PK | 剧编号 `#ID`，全站引用 |
| title | text | 剧名 |
| aliases | text[] | 别名（搜索/去重用） |
| slug | text unique | 网址别名 [推断] |
| summary | text | 简介 |
| cover_portrait | text | 竖封面相对 key（后台上传生成的 `img/...`） |
| cover_landscape | text | 横封面相对 key（后台上传生成的 `img/...`） |
| badge | text | 角标（如 HOT，可空） |
| score | numeric(2,1) | 评分（运营填，如 9.9） |
| year | int | 年份 |
| status | enum | `draft` / `published` / `offline`（定时未到点归 `scheduled` 视图态） |
| publish_at | timestamptz | 定时上架时间（可空/清除） |
| is_finished | bool | 是否完结 |
| sort_weight | int | 「推荐」排序权重，越大越靠前 |
| view_base | bigint | 初始播放量，热度排序时与真实播放量相加 |
| view_count | bigint | 真实播放量 |
| hot_score | bigint | 冗余：热度分，定时由 `view_base + view_count` 刷新（第 8 节） |
| latest_episode | int | 冗余：前台可见的最大集号（「更新至 N 集」），分集变更时刷新 |
| seo_title | text | SEO 标题 |
| seo_desc | text | SEO 描述 |
| source | text | 来源标识（采集批次） |
| created_at / updated_at / deleted_at | timestamptz | — |

状态机：`draft ──上架──► published ──下架──► offline`；`published` 且 `publish_at>now` 在前台不可见（定时）。
索引：三种排序的复合索引与 `title`、`aliases` 的 pg_bigm 索引，见第 8 节。`slug` 可空（前台按 `/d/:id` 访问），填写时唯一。

> 迁移 `00004_content.sql`（S1-1）。可选文本字段一律 `NOT NULL DEFAULT ''`，「可空」指可以留空字符串；`score`、`year`、`publish_at` 用 NULL 表示未填。

### 2.2 episode 分集
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigserial PK | 分集 ID |
| drama_id | bigint FK | 所属剧 |
| number | int | 集号（第几集） |
| title | text | 标题（可空） |
| video_object_id | bigint FK（可空） | 当前使用的视频对象（`media_object`，`12` 第 7 节），转封装完成时写入；被引用的媒体对象不能删除 |
| cover | text | 本集封面相对 key（后台上传生成的 `img/...`） |
| poster | text | 首帧图（WebP，图片存储中的相对 key），转封装生成，播放器出画面前显示（`08` 第 2.1 节） |
| duration_sec | int | 时长（秒）；为 0（未知）时转封装用探测结果回填，已填写的不覆盖 |
| access | enum | `free` / `login`（登录可看）/ `vip`（VIP 会员可看，非会员按 `trial_sec` 试看） |
| trial_sec | int | 可试看秒数（0=不试看） |
| media_status | enum | `pending`（没有视频）/ `transcoding`（第一次转封装中）/ `ready`（可播放）/ `failed`（转封装失败、没有可播放的视频）。已是 `ready` 的分集重新转封装时保持 `ready` |
| renditions | jsonb | 当前产物的码率阶梯 `[{name, width, height, bitrate, peak_bitrate, codecs}]`（从低到高；码率为 bps，`codecs` 为 RFC 6381 编码） |
| key_ver | int | 当前产物使用的 HLS 内容密钥版本（密钥本身在 `media_key`） |
| source_hash | text | 当前产物的源文件 SHA-256，转封装任务幂等键 |
| created_at / updated_at | timestamptz | — |

唯一约束：`(drama_id, number)`，集号大于 0。「更新至 N 集」= 已上架剧中可播放（`media_status = ready`）分集的最大集号（冗余在 `drama.latest_episode`）。`key_ver = 0` 表示尚未生成密钥。分集直接删除，不进回收站；剧被物理删除时分集级联删除（转封装任务与内容密钥随之删除，媒体对象只解除关联，待清理任务删除文件）。迁移 `00007_media.sql`（S1-5）补外键与 `poster`。

### 2.3 tag 标签 / drama_tag
- `tag`：`id, name, slug unique, is_hidden(bool 敏感标签:确认年龄后可见且不被搜索引擎收录), status(active/hidden), merged_into_id(合并目标，软合并), created_at`。
- `drama_tag`：`drama_id, tag_id`，PK 两列。

### 2.4 taxonomy 筛选维度 / taxonomy_term 取值 / drama_term
- `taxonomy`：`id, name, slug unique, multi_select(bool 可多选), show_in_explore(bool), status(active/inactive), sort`。
- `taxonomy_term`：`id, taxonomy_id, name, slug, status(active/inactive), is_channel(bool 有独立频道页), code(区块/专题引用用), sort`。`slug` 在维度内唯一；设为频道的取值 `slug` 全站唯一（频道页 `/c/:slug`）；`code` 填写时全站唯一。删除维度时取值级联删除。
- `drama_term`：`drama_id, term_id`，PK 两列（多选维度追加、单选维度替换，由业务层保证单选维度只有一个取值）。

### 2.5 topic 专题 / topic_drama
- `topic`：`id, title, slug unique, summary, status(draft/published), source_type(manual 手选 / auto 规则), rule_json(自动规则), faq_json(问答对), list_in_index(bool 列在专题列表页), created_at`。
  - `rule_json`：`{ "term_codes": [取值编号], "tag_id": 标签 ID 或 null, "sort": "latest|hot|recommend", "window": "all|7d|14d|30d|90d", "limit": 1–60 }`（同时满足全部取值与标签，S1-4 执行）；`{}` 按默认规则（最新、不限、24 部）解释。`faq_json`：`[{ "question", "answer" }]`，纯文本。
- `topic_drama`：`topic_id, drama_id, sort`（手选保存时整份替换）。

### 3.2 menu 前台菜单
`id, position(enum top/mobile_tabbar/mobile_drawer/footer), label(1–20 字), link_type(enum internal/page/channel/topic/tag/external), link_value, group_title(页脚分组，只有 footer 用), icon, tabbar_icon(只有 mobile_tabbar 用), badge, visible_to(enum all/auth/guest), device(all/mobile/desktop), new_tab(bool), status(active/inactive), sort, created_at, updated_at`。索引 `menu_position_sort_idx (position, sort, id)`。

`link_value` 按类型：`internal` 为站内页白名单（`home`/`shua`/`explore`/`rank`/`topic`/`search`/`me`/`way_home`）、`page`/`channel`/`topic`/`tag` 为对应记录的 slug（保存时校验存在）、`external` 为 http(s) 完整地址。新建与改位置时排在该位置的末尾，顺序由后台拖拽调整。菜单随 `GET /api/v1/site-config` 的 `menus` 段下发：只下发启用且链接目标当前可见的项（静态页改回草稿、频道取值停用等自动消失），`visible_to` 与 `device` 原样下发由前台判断（站点配置是共享缓存的公共数据，不能按身份裁剪）。手机底栏最多 5 项（只算启用的）。设置类数据，删除不进回收站。迁移 `00027_menu.sql`（S3-2，`docs/specs/A3-1.md`）。「后台菜单」是另一张表 `admin_menu`（`adr/0006`），不要混用。

### 3.3 page 静态页
`id, title(1–100 字), slug unique, body(清洗后的 HTML), body_format(enum rich/html), status(enum draft/published), seo_title, seo_desc, is_footer(bool), created_at, updated_at`。前台地址 `/p/:slug`，只下发已发布的页；正文两种格式都按同一白名单清洗后入库（与广告的自定义 HTML 共用 `internal/htmlsan`，清洗后为空则拒绝保存）。`is_footer` 的已发布页随站点配置的 `footer_pages` 段下发给前台页脚。部分索引 `page_footer_idx … WHERE status = 'published' AND is_footer`。设置类数据，删除不进回收站；删除或改回草稿后，指向它的前台菜单项自动隐藏（`06` 第 12 节）。迁移 `00024_page.sql`（S3-2，`docs/specs/A3-1.md`）。

### 3.5 announcement 公告
`id, kind(enum topbar/popup/inbox，站内信暂不启用), content(1–500 字), click_url(站内路径或 http(s) 地址), frequency(enum always/once/daily), pages text[]（出现页面 home/explore/channel/tag/topic/drama/play/shua/rank/search/me，空 = 全部页面）, locales text[]（投放语言，空 = 全部语言）, image(弹窗配图), start_at, end_at（晚于开始时间）, status(active/inactive), created_at, updated_at`。设置类数据，删除不进回收站。迁移 `00015_announcement.sql`（S3-2）。

### 3.6 site_config 站点配置（单行，分段 JSON）
一行多列 `jsonb`，对应后台「白标/SEO/功能/年龄门/地址/播放/评论/榜单」各段，并维护全局 `version`：
`site`(site_name/slogan/copyright/support_url/logo_light/favicon)、`theme`(preset/color_scheme/allow_scheme_toggle/colors/radius/cover_ratio/font)、`layout`(header_style/card_style/play_mode/mobile_tabbar)、`seo`(title_templates/desc_templates 按页面 + og_image/robots_allow/robots_extra/sitemap/structured_data/verifications)、`analytics`(head_snippet/body_snippet)、`age_gate`(enabled/title/**desc**/deny_text/confirm_text/deny_url/remember_days)、`features`(comments/danmaku/register/guest_interaction/ranks/share_poster/pwa/search_suggest)、`addresses`(notice/socials/telegram/latest_url/backup_urls[]/publish_page/permanent_url)、`player`(smart_routing)、`comment_policy`(pre_moderation)、`ranking`(play/follow/like/finish 系数)、`version`(int)。

`ranking` 是榜单计分系数（每项 0–1000、两位小数，默认 1 / 3 / 2 / 2），只给后台与重新排名任务读、不下发前台，修改时不改 `version`。迁移 `00021_ranking.sql`（S3-5）。

### 3.7 hotsearch 热搜词
`id, word(规范化后的搜索词，唯一，1–50 字), search_count, miss_count(搜了但片库没有结果的次数), pinned, pin_sort(置顶顺序，从 1 开始；未置顶为 0), visible, source(enum manual/auto), last_searched_at(最近一次有搜索的落库时间), created_at, updated_at`。CHECK「置顶的一定显示」。规范化：全角转半角、去掉控制与格式字符、转小写、合并空白。搜索次数先在 Valkey 累加，worker 每小时落库（`updated_at` 只在后台修改时更新）；自动收录（auto）的词默认不显示，后台手动加（manual）的默认显示；最多置顶 10 个。索引 `hotsearch_list_idx`（后台列表）与部分索引 `hotsearch_board_idx … WHERE visible`（热搜榜）。删除连搜索次数一起删、不进回收站。迁移 `00020_hotsearch.sql`（S3-4，`docs/specs/A3-4.md`）。

### 3.8 rank_override 排行人工调整
`board(enum drama_week/drama_month), drama_id FK drama(ON DELETE CASCADE), pinned(置顶), blocked(不让上榜，只影响该榜), boost(加分，-1000000000 到 1000000000，负数为减分), updated_at`，主键 `(board, drama_id)`，索引 `(drama_id)`。CHECK「置顶与不让上榜互斥」「三项至少调了一项」。后台按榜整体保存（每榜最多 100 行，目标剧必须存在且不在回收站），要重新排名才生效；剧之后下架或进回收站时不上榜、调整保留，彻底删除时一起删除。线上榜单不在库里：worker 每 5 分钟算一次，写进 Valkey 有序集合后原子替换（`03` 第 3.4 节）。设置类数据，不进回收站。迁移 `00021_ranking.sql`（S3-5，`docs/specs/A3-4.md`）。

## 4. 资源与任务域

### 4.1 存储源与线路
已拆分为 `storage_provider`（S3 / R2 / 自定义存储源）、`storage_line`（访问线路）、`storage_line_rule`（地区规则）、`media_object` / `media_replica`（媒体对象与副本）、`storage_settings`、`geoip_release`，字段定义见 `12` 第 7 节。`episode.video_path` 改为 `episode.video_object_id`。

### 4.1a transcode_job 转封装任务（S1-5）

### 4.1b admin_media_upload 后台媒体上传会话

`id uuid, admin_id FK, provider_id FK, provider_endpoint, provider_region, provider_bucket, provider_path_style, provider_path_prefix, purpose, kind(image/video), mime, image_format(webp/avif/空), size_bytes, source_key unique, output_key, episode_id FK 可空, transcode_job_id FK 可空, status(created/uploading/uploaded/queued/running/ready/failed), progress, attempts, error, expires_at, created_at, updated_at, part_size bigint default 0, multipart_upload_id text default ''`（迁移 `00038_admin_media_upload.sql`、`00040_admin_media_upload_lifecycle.sql`、`00042_admin_media_upload_provider.sql`、`00044_admin_media_upload_target_snapshot.sql`、`00055_admin_media_upload_multipart.sql`）。

## 8. 关键索引与性能建议

- 热度/推荐排序：`drama` 增加冗余列 `hot_score bigint`（定时由 `view_base+view_count` 刷新）与 `latest_episode int`，建 `(status, hot_score desc, id desc)`、`(status, sort_weight desc, id desc)`、`(status, publish_at desc, id desc)` 复合索引，配合游标分页：`WHERE status = $1 AND (hot_score, id) < ($2, $3) ORDER BY hot_score DESC, id DESC`（`id` 与排序列同为降序，行比较才能直接作为索引条件）。
- 中文搜索：`pg_bigm` 扩展，对 `title`、`aliases` 建 `gin (... gin_bigm_ops)`；`aliases` 是数组，索引建在 `aliases_text(aliases)` 上（迁移中定义的 IMMUTABLE 函数，把别名拼成一个字符串），查询必须写成 `aliases_text(aliases) LIKE likequery($1)` 才能用上索引；`likequery` 由 pg_bigm 提供，会转义 `%`、`_`。数据量上来后迁 Meilisearch。
  - 前台搜索（S3-4）要大小写不敏感，另有两条索引：`gin (lower(title) gin_bigm_ops)` 与 `gin (lower(aliases_text(aliases)) gin_bigm_ops)`（迁移 `00035_drama_search_lower.sql`），查询写成 `lower(title) LIKE $1`。**`ILIKE` 用不上 pg_bigm 索引**（实测强制关闭 `enable_seqscan` 后仍是顺序扫描），所以走小写列而不是 `ILIKE`；后台剧集搜索仍用原来的两条（按用户输入原样匹配）。
- 关联表反向查询：`drama_tag(tag_id, drama_id)`、`drama_term(term_id, drama_id)`、`topic_drama(drama_id)`，同时避免删除剧、标签、取值时级联扫描全表。
- 计数热点：播放、点赞、评论数先在 Valkey 累加，每分钟批量回写，避免热点行锁。
- 维护：大表定期 `REINDEX CONCURRENTLY`；PG 18 起统计信息在 `pg_upgrade` 后保留，大版本升级后无需长时间 ANALYZE。
