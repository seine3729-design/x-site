# 0007 接口路径前缀：前台 /api/v1，后台 /api/admin
状态：已采纳
日期：2026-10-22

## 背景
- 用户端接口原为 `/api/*`，后台为 `/admin-api/*`。两套前缀风格不一致，看路径不能直接判断是前台还是后台接口，也没有成文的路径规范。
- 前台路径不带版本号。APP 旧版本会长期存在，以后出现不兼容改动时只能在原路径上做兼容分支。

## 决策
- 前台（Web、APP）接口统一 `/api/v1/*`，后台接口统一 `/api/admin/*`。`/api/` 下只允许这两个命名空间（以后的 `/api/v2/` 除外）。开放平台 `/open-api/*`、支付回调 `/callback/pay/*`、部署探针 `/internal/*` 不变。完整规则见 `07` 第 0.5 节。
- 只有前台带版本号：兼容改动留在 `v1`，不兼容改动新开 `/api/v2/...` 并行，旧版 APP 都低于最低支持版本后下线 `v1`。后台与后端同时发布、没有旧客户端，不带版本号。
- 后端是两个独立的路由分组：`/api/v1` 挂报文加密；`/api/admin` 挂在根路由上（Origin 白名单 + 会话 + CSRF + 审计 + RBAC），不经过报文加密。
- Web BFF 只透传 `/api/v1/*`，前台域名下其余 `/api/*`（含 `/api/admin/*`）返回 JSON 404。BFF 原先透传全部 `/api/*`，后台移到 `/api/admin` 后如果不收窄，前台域名就能带着服务令牌把后台登录请求转发到后端。
- 探活也在命名空间内：Go 与 BFF 各自的 `/api/v1/health`。
- 尚未上线，直接切换、不保留旧路径（契约 0.6.0）。`service/internal/http/router_test.go` 校验所有路由都在约定前缀下。

## 备选方案与放弃原因
- 保留 `/admin-api/*`：后台路径与前台不在同一套层级规则下；前台无版本号的问题也没有解决。
- 后台也带版本号（`/api/admin/v1/*`）：后台只有一个与后端同时发布的调用方，版本号用不上，只让路径变长。
- 网关把旧路径改写或重定向到新路径做兼容：路径与查询串参与报文加密的 AAD，改写后解密失败；要兼容只能在后端同时挂新旧两套路由，而目前没有已发布的客户端，不需要。

## 影响
- 三端调用路径、`service/api/openapi.yaml`（0.6.0）、`docs/` 与项目技能同步修改；`compose.yaml` 健康检查改为 `/api/v1/health`。
- 后台会话 Cookie 仍为 `Path=/`（`__Host-` 前缀要求），后台独占域名不变。
- 未调用 `SetAudit` 的审计动作记为「方法 + 路由模板」，此后带新前缀。
- 网关按前缀回源：前台与 APP 接口域名只转发 `/api/v1/*`，后台域名只转发 `/api/admin/*`。
- `0001`–`0006` 保留当时的路径写法，按此对应：`/api/<路径>` → `/api/v1/<路径>`，`/admin-api/<路径>` → `/api/admin/<路径>`。
