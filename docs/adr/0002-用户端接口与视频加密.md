# 0002 用户端接口报文加密、视频加密播放、图片 blob 显示

状态：已采纳
日期：2026-10-21

## 背景

要求 Web 与 APP 调用的接口加密，视频加密并在页面上表现为 `blob:` 地址（不暴露清单与切片地址）；运营后台不在此列。此前 `10` 第 5.3 节只把报文加密作为敏感接口的可选项。

## 决策

- **接口**：全部用户端接口 `/api/*` 强制报文加密，协议为 HPKE（RFC 9180）base 模式，套件 DHKEM(X25519, HKDF-SHA256) + HKDF-SHA256 + AES-256-GCM。每个请求单独封装，响应用本次请求导出的密钥加密。服务端用 Go 标准库 `crypto/hpke`；Web 用 Web Crypto；APP 用 `cryptography` 包。三端用 RFC 9180 官方向量和同一份互通样本校验。
- **豁免**：`/api/health`、`/api/crypto/keys`；SSR 阶段 BFF 经内网 mTLS 直连后端时允许明文；`/admin-api/*`、`/open-api/*`、支付回调不加密。
- **视频**：切片保持 HLS AES-128（CDN 直出）；清单与内容密钥只通过加密接口获取。Web 用 hls.js（MSE / ManagedMediaSource）播放，`<video>` 地址为浏览器生成的 `blob:`。APP 原生播放器经本机回环代理取清单与密钥。
- **图片**：不加密（加解密拖慢加载）；Web 端用 `fetch` 取回后转临时 `blob:` 地址显示，图片照常走 CDN 与浏览器缓存。

## 备选方案与放弃原因

- 只依赖 TLS：无法对抗装了根证书的抓包代理与批量抓取。
- 自定义对称密钥写在前端：密钥一旦泄露，所有历史流量都能解；HPKE 每个请求独立。
- 图片也加密：每张图多一次解密，列表页明显变慢，收益有限。
- 整个请求（含路径）隧道化：会破坏路由、限流、日志与缓存；改为路径与查询串明文但用 AAD 绑定防篡改。

## 影响

- 加密响应一律 `Cache-Control: no-store`，用户端 JSON 接口不能再由 CDN 缓存；靠后端 Valkey/进程内缓存与 ETag 304 弥补。SSR 页面、视频切片、图片的 CDN 缓存不受影响。
- 不支持 MSE 的旧浏览器（如 iOS 17.1 以下 Safari）不能在网页播放，提示升级或使用 APP。
- 新增配置 `API_ENC_KEYS`、`API_ENCRYPTION_REQUIRED`（production 不能关闭）；正式 APP 构建期预置公钥 `--dart-define=API_ENC_KEYS`。
- 这一层提高抓包与批量抓取的成本，不能替代鉴权：客户端代码总能被逆向。
