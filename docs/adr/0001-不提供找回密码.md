# 0001 不提供找回密码（移除恢复码）

状态：已采纳
日期：2026-10-21

## 背景

平台只用「用户名 + 密码」注册，不收集邮箱、手机号。此前的方案用一次性恢复码找回密码，丢失恢复码时由客服人工核验后在后台重设密码。

## 决策

- 不提供任何找回密码的途径：没有恢复码、没有邮件/短信、后台也不能重设用户密码。
- 忘记密码只能重新注册新账号；原账号的用户名不释放，数据不迁移。
- 已登录用户仍可凭当前密码修改密码，成功后吊销全部会话。
- 唯一的人工例外是付费权益迁移：用户凭支付凭证联系客服，核验后把剩余会员天数与充值金币转到新账号（不恢复原账号，赠送金币、等级与其他数据不迁移，见 `0004`、`0005`）。

## 备选方案与放弃原因

- 恢复码：用户普遍不保存，实际仍要走人工；还要维护生成、展示、重新生成、作废整套流程。
- 后台人工重设密码：没有可验证的身份信息，核验只能靠「记得的观看记录」之类，容易被社会工程利用。

## 影响

- 注册页、登录页必须明确提示「忘记密码无法找回」，注册时勾选知晓。
- 删除 `user.recovery_code_*` 字段、`/api/auth/recover`、`/api/me/recovery-code`、后台「重设密码 / 作废恢复码」。
- 防撞库（限流、失败计数、人机验证、统一错误提示）保持不变。
