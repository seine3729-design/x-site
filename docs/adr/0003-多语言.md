# 0003 多语言：9 种语言，JSON 文案经 CDN 不可变发布

状态：已采纳
日期：2026-10-21

## 背景

用户端（Web、APP）需要支持简体中文、英语、西班牙语、越南语、日语、韩语、泰语、印地语、阿拉伯语；运营后台只用中文。文案后续放到 CDN，并且会频繁修改。

## 决策

- 文案用 JSON（扁平键，`{name}` 占位符），简体中文为基准语言。Web 与 APP 各一套文件、格式相同。
- Web 用 URL 前缀区分语言（中文无前缀，其他如 `/en/…`），一份路由由 `reroute` 去前缀匹配；页面缓存键天然按语言区分。阿拉伯语 `dir="rtl"`。
- APP 跟随系统语言，可手动切换；文案作为资源打包，运行时加载，不编译进 Dart 代码。
- CDN 发布：每个语言文件按内容哈希命名、永久缓存；只有很小的 `manifest.json` 短缓存。客户端始终保留内置文案兜底。
- 后端错误响应的 `message` 保持中文兜底，界面一律按业务码 `code` 显示当前语言。

## 备选方案与放弃原因

- TypeScript / Dart 代码形式的文案：改文案就要发版，不能放 CDN 热更新。
- Flutter gen-l10n（ARB 编译）：类型安全，但同样无法远程更新；改为运行时 JSON + 测试校验键名。
- Cookie / Accept-Language 决定 Web 语言：边缘缓存要按 Cookie 区分，命中率低，且搜索引擎只能看到一种语言。
- 覆盖式同名文件 + 清 CDN 缓存：清理有延迟、多 CDN 难以同时生效，旧页面可能拿到不匹配的新文案。

## 影响

- JSON 没有类型检查：键齐全、非空、占位符一致由单元测试与发布脚本校验，键名由 TS 类型（Web）和源码扫描测试（APP）兜住。
- 运营类高频文案（活动、公告、广告语）不进文案包，放后台配置。
- 内容本身（剧名、简介）的多语言不在本次范围。
