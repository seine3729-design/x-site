# 0009 授权测试采集边界

状态：已采纳
日期：2026-10-25

## 背景

短剧封面、文案和视频常受版权、访问规则和来源服务条款约束。将一个“爬虫”设计成可输入任意网址的下载器，会同时带来未授权复制、SSRF、重定向到内网、令牌泄露、超大媒体耗尽资源和误发布等风险。项目已具备主存储、媒体转码和后台导入能力，但没有授权来源、robots 或远端下载边界。

## 决策

- 测试采集只接受人工核验的 catalog manifest，不做任意网页 HTML 发现、站点遍历或选择器抓取。
- 每份 manifest 必须包含权利基础（`owned`、`licensed`、`public_domain` 或 `cc_by`）和可追溯引用；`licensed` 还必须声明未过期时间。robots 允许不能代替版权或合同授权。
- 下载域名采用精确 allowlist；每个域名必须有同主机 `robots_url`，并以固定 User-Agent 判断目标路径是否可抓取。无法读取、无法解析或包含当前实现不支持的通配规则时失败关闭。
- 仅允许 HTTPS，所有连接复用 `internal/netguard` 的解析、保留地址拒绝和 DNS 重绑定防护；禁止重定向、代理绕过、登录墙/付费墙/验证码绕过和受限资源绕过。
- 素材下载必须流式、带请求超时和间隔、可信 `Content-Length`、图片 15 MiB/视频 4 GiB 限额、MIME 与基础文件头复核。封面仅 WebP/AVIF，视频仅 MP4/MOV/WebM/MKV。
- 测试阶段只将封面与原视频写入后台配置的图片/视频主 `storage_provider`，分别位于 `img/collector/<run_id>/` 和 `video/source/collector/<run_id>/`；不走 CDN/`storage_line`，不创建剧集/分集，不触发 HLS 转码，更不自动发布。
- 每次 stage 生成权限为 `0600` 的本地报告，保存对象键和物理目标快照。cleanup 只能删除该报告中同一 run 的 collector 前缀对象；发生中途失败时先补偿删除，补偿失败则保留恢复报告。
- `collectortool` 仅允许在 `APP_ENV=development` 运行。正式入库、开放平台推送、FTP 扫描和后台批次审批作为 S4-6 后续切片另行实现。

## 备选方案与放弃原因

1. **任意 URL 爬虫**：难以判断授权、robots 和服务条款，且会扩大 SSRF 与资源消耗面。
2. **浏览器自动化绕过动态页面限制**：容易规避访问控制，无法成为合规测试数据来源。
3. **直接写 CDN 或 storage_line**：线路是读取分发入口，不保证写认证、回源一致性或凭据安全。
4. **立即自动建剧并上架**：来源文案和媒体即便下载成功仍需人工审核、屏蔽词/去重和内容确认；自动发布会把测试采集风险直接暴露给用户。

## 影响

- 新增 `internal/collector` 与 `cmd/collectortool`，复用 `netguard`、`uploadstore` 和现有主存储策略。
- 不新增依赖、数据库迁移、公开 API 或后台菜单；因此第一切片不要求前端页面。
- 后续接入正式内容域时必须保留同一授权 manifest、对象来源追溯和 cleanup 语义，并将视频通过既有 `media_transcode` 链路转为 HLS。
