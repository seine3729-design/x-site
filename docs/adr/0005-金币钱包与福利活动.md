# 0005 金币钱包、会员等级与福利活动

状态：已采纳（设计），待实现
日期：2026-10-21

## 背景

个人中心要增加收藏、观看历史、点赞、账号设置、会员等级、金币钱包；另设活动专区：幸运转盘、每日转盘、天天奖券、评论晒图、任务金币墙、推广返利、金币商城。这些功能都会发放和消耗「有价值的东西」（金币、会员天数、优惠券），设计不当会出现超发、刷量、对账不平，或触碰抽奖、传销、虚拟货币方面的法规。完整设计见 `13`。

## 决策

1. **金币先只能「赚」，不能「买」**：MVP 的金币全部来自任务、签到、活动、返利（赠送金币，有有效期），只能在金币商城使用，不能提现、不能转赠。钱包从一开始就分「赠送 / 充值」两个子余额，充值金币由开关 `features.coin_recharge` 控制，默认关闭，启用前需单独评审。
2. **一本账**：所有金币变动只经过钱包服务，每笔业务一条交易头（`coin_txn`，业务键唯一 → 幂等）+ 若干流水行；余额不能为负；每晚核对「流水合计 = 余额 = 批次余量合计」。
3. **统一发奖**：签到、转盘、奖券、任务、返利、商城、后台补发都通过同一个发奖器（`reward_grant`），按「来源 + 来源单号 + 用户」去重。
4. **抽奖只用免费机会**：转盘与奖券的次数来自每日赠送、任务、等级 / 会员加成，或用赠送金币兑换；不能直接用钱或充值金币购买。奖品没有现金价值、不能提现。概率在规则页公示，服务端用 `crypto/rand` 定结果，客户端只播动画。天天奖券用「承诺—揭示」开奖，用户可自行校验。
5. **推广返利只做一级**，返利发赠送金币（有冻结期，退款撤回），不发现金。
6. **只发给注册用户**：游客能看活动、看规则，领取时引导注册。游客的观看历史、收藏、点赞只存本机，登录或注册时一次性并入账号。
7. **会员等级 = 成长值等级**（V0–V7），对全部注册用户生效；开通会员、付费、签到、观看累积成长值。MVP 不做等级降级。
8. **「每日」按站点时区**（`site_config.timezone`，默认 `Asia/Shanghai`）切换，不按用户设备时区，防止改时区重复领取。
9. **不做实物奖品与实物商城**（需要收集地址、手机号，违背数据最小化原则）。

## 备选方案与放弃原因

- 金币可充值（付费虚拟币）：要处理预付资金、退款、商店内购抽成与审核；再与抽奖叠加，会被视为赌博类玩法。在没有「金币解锁单集」等明确消费场景之前收益很小。
- 每种活动各自发奖、各自记账：重复实现幂等与风控，对账无法统一。
- 多级分销返利：存在传销认定风险；一级返利已能覆盖拉新需求。
- 现金返利 / 金币提现：需要打款、实名、反洗钱与税务处理，超出当前范围。
- 游客数据存服务端：游客写入量大，且 `adr/0001` 后游客身份随设备丢失，存服务端意义不大。

## 影响

- 新增 `domain/wallet`、`level`、`reward`、`activity`、`task`、`referral`、`mall`，以及用户图片上传与审核（评论晒图、头像）。
- `pay_order` 泛化为可购买多种商品（会员套餐；启用后可买金币套餐），下单接口由 `/api/vip/orders` 改为 `/api/pay/orders`（尚未实现，直接改）。
- `adr/0001` 的人工迁移例外扩展为「会员剩余天数 + 充值金币」；赠送金币不迁移。
- 应用商店包：不能为评分、安装其他应用发放奖励，第三方任务墙只在 Web 与官网包开放；如启用充值金币，商店包必须走内购。
- 上线前需要法务确认抽奖、返利、虚拟币相关规则在目标运营地的适用性（`13` 第 6 节）。
