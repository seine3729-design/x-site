## 0. 两条上线路径（互斥，别同时起）

| 路径 | 文件 | 状态 |
| --- | --- | --- |
| **Dokploy**（主） | `apps/docker-compose.yml` + Dokploy 的 Traefik | 前台已就绪，本文描述这一条 |
| 自建 nginx + certbot + GitHub Actions（备） | `deploy/prod/`、`.github/workflows/deploy.yml`、[`deploy/prod/README.md`](../deploy/prod/README.md) | 整栈可用，但和 Dokploy 抢同一个域名与 80/443 |

两条路都要独占宿主机的 80/443 和 `duanju66.cc`。**用 Dokploy 就不要在同一台机器上起 `deploy/prod` 那一套。**
`deploy/prod/README.md` 仍然值得读：边缘层、压缩链路、R2 的设计原理和实测数据都在那里，Dokploy 这一条沿用同样的结论。

整条链路：

```
本机                GitHub                  服务器（Dokploy）
────                ──────                  ─────────────────
git push ─────────► main 分支
                      │                     Dokploy 收到 webhook
                      ├─ ci.yml  PR 闸门     ├─ 拉代码
                      │                      ├─ docker compose build（构建 apps 镜像）
                      └─ webhook ───────────►├─ assets 一次性容器：build/client/_app/immutable → R2
                                             ├─ apps 容器启动（SSR + BFF）
                                             └─ Traefik 自动发现标签，签/续 Let's Encrypt 证书
```

请求怎么分流：

```
浏览器 ──┬─ /_app/immutable/*  ───────────────────────→ cdn.duanju66.cc ─→ R2（桶 duanju666）
         └─ 页面、/api/v1、/service-worker.js、/icons/ ─→ Traefik ─→ apps:3001 ─→ service:8080
```

**带内容哈希的产物由浏览器直接从 CDN 取**，页面里写的就是 `https://cdn.duanju66.cc/apps/_app/immutable/...`。
这个地址在**构建期**由 `CDN_ASSET_PREFIX` 决定，一个值同时管三处，所以换 CDN 域名必须重新构建：

| 用在哪 | 怎么用 |
| --- | --- |
| SvelteKit `paths.assets` | 写进 HTML 与客户端脚本的产物地址 |
| `apps/config/security-headers.ts` | 生产 CSP 的 `script-src` / `style-src` / `font-src` / `img-src` / `connect-src` 白名单 |
| `apps/scripts/build-sw.ts` | 注入 Service Worker，让它认得出哪些请求是产物 |

> **CSP 的坑**：来源表达式里带路径时，不以 `/` 结尾就是**精确匹配那一个路径**（CSP3 §6.6.2.6）。
> `https://cdn.duanju66.cc/apps` 只会匹配 `/apps` 本身，产物一个都放不过去 —— `cdnExpression()` 因此会补上末尾斜杠。

### Service Worker 为什么不在 `src/service-worker/`

SvelteKit 只要扫到**自己管的** Service Worker 入口文件，而 `paths.assets` 又非空，就直接以
`service_worker_assets` 退出（`node_modules/@sveltejs/kit/src/exports/vite/build/service-worker.js`）。
产物要走 CDN 绝对地址，就只能让 SW 脱离 SvelteKit 的管辖：

- 源码在 `apps/src/sw/index.ts`，由 `apps/scripts/build-sw.ts` 用 Bun 编译，构建版本与产物前缀以
  `__SW_VERSION__` / `__SW_ASSET_BASE__` 注入。
- **必须在 `vite build` 之前编译、输出到 `static/`**。adapter-bun 的静态路由表是在 `vite build` 时定下的，
  构建之后再往 `build/client/` 里塞文件，文件在磁盘上但 `/service-worker.js` 一律 404
  （实测踩过：页面完全正常、只有 SW 装不上，排查方向很容易跑偏）。
- 资源缓存的收录条件从「只认 `basic`」放宽到「`basic` 或 `cors`」，仍然挡 `opaque`（CDN 的 CORS 没配好时
  就会退化成它：status 恒 0、存了读不出来还占配额）。`feedback/public/sw.js` 早就是这个写法。
- `/service-worker.js`、`/icons/`、`_app/version.json` 刻意**不**上 CDN：SW 必须同源才有 `/` 作用域，
  `version.json` 是客户端轮询新版本用的、不能长缓存。

### 2.1 推之前必须确认的三件事

**(1) 忽略规则是否够用。** 这个仓库里躺着 1.5 GB 的依赖和构建产物，漏一条就会把几百兆推上去。核对方式——在工作区**之外**建一个 git 目录做干跑：

```bash
cd ~/Desktop/x-site
D=/tmp/gitprobe/.git; rm -rf /tmp/gitprobe; mkdir -p /tmp/gitprobe
git --git-dir=$D --work-tree=$PWD init -q
git --git-dir=$D --work-tree=$PWD add -A
git --git-dir=$D --work-tree=$PWD diff --cached --name-only | wc -l       # 期望 1600 上下
git --git-dir=$D --work-tree=$PWD diff --cached --name-only -z \
  | xargs -0 du -ch | tail -1                                            # 期望 20 MB 以内
git --git-dir=$D --work-tree=$PWD diff --cached --name-only \
  | grep -E 'node_modules|/dist/|\.next/|\.svelte-kit|/build/|\.env$'     # 期望没有输出
```

> - `service/.gitignore` 加了 `/worker`、`/_uiseed` 等 `go build` 留下的裸二进制。**刻意没有 `/api`**：gitignore 分不清同名的文件和目录，写上会把契约目录 `service/api/`（`openapi.yaml` 在里面）一起忽略掉。

## 3. 服务器与 Dokploy

### 3.1 系统基础

```bash
# 时间必须准：证书校验、JWT 过期、TOTP 二次验证都看系统时间
sudo timedatectl set-timezone UTC
timedatectl   # 确认 "System clock synchronized: yes"

# 8 GB 内存建议配 4 GB swap：转封装峰值会吃内存，宁可变慢不要被 OOM 杀掉
sudo fallocate -l 4G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### 3.2 安装 Dokploy

Dokploy 的安装脚本会装好 Docker、Traefik 和面板本身，面板在 `http://<服务器IP>:3000`。
首次打开**立刻创建管理员账号**——在那之前谁先访问谁就是管理员。

装完确认三件事：

```bash
docker ps --filter name=dokploy --format '{{.Names}}\t{{.Status}}'   # 面板与 Traefik 都在
docker network inspect dokploy-network -f '{{.Name}} {{.Driver}}'     # 编排文件依赖这张网络
docker compose version                                                # 必须是 v2.x
```

### 3.3 防火墙

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow from <你的办公 IP> to any port 3000 proto tcp   # Dokploy 面板不要对全网开
sudo ufw enable
```

**不要**放开 5432 / 6379。

> Docker 会直接写 iptables，`-p 0.0.0.0:xx` 的端口映射能绕过 ufw。本项目的编排只用 `expose`，由 Traefik 统一对外，所以不受影响。新增端口映射时留意这一点。

### 3.4 Dokploy 的全局设置

- **Traefik → 确认 entrypoints 是 `web`(80) 与 `websecure`(443)，证书解析器名字是 `letsencrypt`**。编排文件里的标签按这三个名字写的，改过名就要同步改标签。
- **Registry**：不需要。Dokploy 在服务器上直接 `docker compose build`，不经镜像仓库。
- HTTP/3 默认没开。要开得在 Dokploy 的 Traefik 配置里加 `http3` 并放通 443/udp，本文不覆盖。

## 4. DNS 与 Cloudflare

### 4.1 DNS 记录

| 记录 | 类型 | 值 | 代理 |
| --- | --- | --- | --- |
| `duanju66.cc` | A | 服务器 IP | **代理（橙云）** |
| `www` | A | 服务器 IP | **代理（橙云）** |
| `admin` | A | 服务器 IP | 直连（灰云）或代理都行 |
| `feedback` | A | 服务器 IP | 直连或代理都行 |
| `cdn` | — | R2 自定义域，已存在 | Cloudflare 自动管理 |

### 4.2 代理模式下要改的三处

1. **SSL/TLS → Overview → 加密模式选 `Full (strict)`**。源站上 Traefik 签的 Let's Encrypt 证书正好满足。选 Flexible 会让 Cloudflare 用 HTTP 回源，源站的 HTTPS 跳转会把请求打成死循环。
2. **`APPS_XFF_DEPTH=2`**（Dokploy 的环境变量）。Cloudflare 把真实客户端 IP 放在 `X-Forwarded-For` 的第一段，Traefik 再把 Cloudflare 边缘 IP 追加在后面，所以要从右数第 2 个。见第 6.2 节。
3. **Caching → Cache Rules 加两条**：
   - `URI Path starts with /_app/immutable/` 或 `/icons/` → Eligible for cache，Edge TTL「Use cache-control header」（源站已给 `immutable` 一年）。
   - 确认**没有**任何规则把 HTML 设成可缓存。SSR 页面随登录用户变化，缓存串号会把别人的页面发出去。Cloudflare 默认不缓存 HTML，这条是防止后来有人加了 "Cache Everything"。

ACME 挑战不受代理影响：Cloudflare 不会把 `/.well-known/acme-challenge/` 强制跳 HTTPS。

### 4.3 R2 一次性设置

在**本机**跑（需要 aws cli；没装就用 `docker run --rm -v "$PWD":/w -w /w amazon/aws-cli` 代替 `aws`）：

```bash
cd ~/Desktop/x-site/deploy/prod
R2_ENDPOINT=https://<账户ID>.r2.cloudflarestorage.com \
R2_BUCKET=duanju666 \
AWS_ACCESS_KEY_ID=... AWS_SECRET_ACCESS_KEY=... \
APPS_DOMAIN=duanju66.cc APPS_ALIASES=www.duanju66.cc \
ADMIN_DOMAIN=admin.duanju66.cc FEEDBACK_DOMAIN=feedback.duanju66.cc \
CDN_DOMAIN=cdn.duanju66.cc \
  ./scripts/r2-setup.sh
```

脚本设 CORS 白名单 + 生命周期（`admin/`、`feedback/` 前缀下的对象 90 天过期；未完成的分片上传 1 天后中止）。

**CORS 这一步必须做，不是优化项**：三个前端的入口脚本都是 `<script type="module">`，而模块脚本一律按 CORS 模式取（这是规范行为，不是可选项）。R2 不回 `Access-Control-Allow-Origin` 的话，页面在控制台报跨域、一行脚本都跑不起来。字体同理。脚本已经把 `APPS_DOMAIN`、`APPS_ALIASES`、后台与反馈社区的域名、以及 CDN 域名自己都列进白名单了。

> `put-bucket-cors` 是**整体替换**。加域名时改 `scripts/r2-setup.sh` 重跑，不要在控制台手改——下次跑脚本又会被覆盖回去。

生命周期规则已经覆盖 `apps/`、`admin/`、`feedback/` 三个前缀（各 90 天过期）。发布时不删远端旧对象，靠这条清理 —— 90 天远大于「还有用户的页面在引用上一版 chunk」的时间窗。

## 5. 在 Dokploy 上建前台服务

### 5.1 建服务

1. New Project → New Service → **Compose**，Compose Type 选 `Docker Compose`
2. Provider：GitHub（装 Dokploy 的 GitHub App）或 Git
3. Repository：`<账号>/x-site`，Branch：`main`
4. **Compose Path：`./apps/docker-compose.yml`**
5. Save

编排文件里有两个服务，Dokploy 会按 `depends_on` 的顺序跑：

| 服务 | 作用 | 生命周期 |
| --- | --- | --- |
| `assets` | 把 `build/client/_app/immutable` 推到 R2 | 一次性（`restart: "no"`），失败就不放流量进来 |
| `apps` | Bun SSR + BFF，监听 3001 | 常驻 |

`assets` 和 `apps` 共用同一个镜像和同一段 `build`，所以**上传的产物与正在运行的那一版必然是同一次构建**。两次独立构建的内容哈希对不上时，页面会去 CDN 取一个不存在的文件名，而且只在生产复现——这就是为什么不把上传放到 CI 里另做一次构建。

### 5.2 环境变量（Environment 标签页）

| 变量 | 必填 | 填什么 |
| --- | --- | --- |
| `SERVICE_INTERNAL_URL` | 是 | Go 后端的内网地址，例如 `http://xsite-service-abc123:8080`。后端必须在同一张 `dokploy-network` 上；实际容器名在后端服务详情页能看到 |
| `BFF_SERVICE_TOKEN` | 是 | 回源服务令牌，与 `service` 的同名变量完全一致（≥ 32 字符） |
| `R2_ENDPOINT` | 是 | `https://<账户ID>.r2.cloudflarestorage.com` |
| `R2_BUCKET` | 是 | `duanju666` |
| `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` | 是 | R2 访问密钥，权限按「只能读写这一个桶」最小化 |
| `EDGE_SHARED_SECRET` | 建议 | 设上之后才校验 `x-edge-secret`，否则任何人都能伪造地区头 |
| `APPS_XFF_DEPTH` | 否 | 默认 `2`（Cloudflare 橙云 + Traefik）。前面没有 Cloudflare 时改 `1` |
| `CDN_HOST` | 否 | 默认 `cdn.duanju66.cc` |
| `CDN_ASSETS_PREFIX` | 否 | 默认 `apps`。它既是 R2 的对象键前缀、也拼进构建参数 `CDN_ASSET_PREFIX`，编排里是同一个变量，不会配歪 |
| `IMAGE_BASE_URLS` / `MEDIA_CONNECT_ORIGINS` | 否 | 图片与视频线路域名池，默认都是 `https://cdn.duanju66.cc`。生产 CSP 的 `img-src` / `connect-src` 从这里生成 |
| `APPS_DOMAIN` / `APPS_WWW_DOMAIN` | 否 | 默认 `duanju66.cc` / `www.duanju66.cc` |

**`RATE_LIMIT_*`、`APP_ENV`、`CDN_ASSET_PREFIX` 在这里设了不生效**：`apps/scripts/with-env.ts` 会用镜像里 `.env.production` 的同名值覆盖容器环境变量。要改配额就改那个文件再重新构建。

### 5.3 域名：标签还是 Dokploy Domains，二选一

编排文件里已经带了完整的 Traefik 标签（HTTPS、`www` → 主域名 301、80 → 443、`x-edge-secret` 注入）。**不要再在 Dokploy 的 Domains 标签页加域名**，两边都配会生成重复的 router。

要改用 Dokploy Domains 就把编排里的 `labels:` 段删掉，再在界面上加 `duanju66.cc`（服务选 `apps`、端口 3001）。那样会少掉 `www` 跳转与 `x-edge-secret` 注入，得自己补。

### 5.4 Deploy

点 Deploy。首次 10–20 分钟（`bun install` + `vite build` 无缓存），之后 3–6 分钟。

证书：Traefik 在第一个请求到来时按 HTTP-01 挑战签发，大约 10–30 秒。这期间 `curl` 会因为证书不受信而失败，是预期的。

## 6. 验收

```bash
# 服务器上
docker ps --filter label=com.docker.compose.project --format '{{.Names}}\t{{.Status}}' | grep apps
# apps 是 healthy；assets 已 Exited (0)

docker logs <assets 容器> | tail -3      # 期望「CDN：新增 N，已存在 M，失败 0」
```

```bash
# 本机：外部可访问性
curl -sI https://duanju66.cc/api/v1/health            # 200
curl -sI https://www.duanju66.cc/                     # 301 → https://duanju66.cc/
curl -sI http://duanju66.cc/                          # 301 → https

# 页面里引用的产物地址必须是 CDN 绝对地址，一条同源相对地址都不该剩
curl -s https://duanju66.cc/ | grep -coE '(src|href)="/_app/immutable/'          # 期望 0
ASSET=$(curl -s https://duanju66.cc/ | grep -oE 'https://cdn\.duanju66\.cc/apps/_app/immutable/entry/app\.[^"]+\.js' | head -1)
echo "${ASSET}"                                                                   # 不该为空

# 产物在 CDN 上能取到，带 CORS 头与一年 immutable
curl -sI -H 'Origin: https://duanju66.cc' "${ASSET}" \
  | grep -iE 'HTTP/|access-control-allow-origin|cache-control|content-encoding'

# Service Worker 必须由站点域名发出（同源才有 / 作用域），且不缓存
curl -sI https://duanju66.cc/service-worker.js | grep -iE 'HTTP/|content-type|cache-control'

# CSP 里的 CDN 来源必须以斜杠结尾，否则产物全被拦
curl -sI https://duanju66.cc/ | grep -i '^content-security-policy' | tr ';' '\n' | grep script-src
```

浏览器里再确认三件事才算真的通了：开发者工具的网络面板里 `/_app/immutable/*` 的域名是 `cdn.duanju66.cc`；
控制台没有跨域与 CSP 报错；Application → Service Workers 里是 activated，Cache Storage 的 `sv-static-*`
里存着 CDN 地址的条目。

### 本地按生产拓扑实测过的点（2026-10-27）

用真实镜像 + 本地后端 + 一个假 CDN（nginx，带 CORS 头）起了一套，再用无头 Chrome 走完首页。

| 验证项 | 结果 |
| --- | --- |
| 产物从哪来 | 首页发起的 37 条产物请求**全部**打到 CDN，源站 0 条；HTML 里同源相对地址 0 条 |
| CSP | 无任何违规；`script-src 'self' 'unsafe-inline' https://cdn.…/apps/`（末尾斜杠在） |
| 页面可用 | 标题、52 个剧卡、1965 字正文，已水合，控制台无错误，全程无 4xx/5xx |
| Service Worker | 在 `https://<站点>/service-worker.js`、scope `/`、状态 activated |
| 跨源资源缓存 | `sv-static-<版本>` 里 38/38 条都是 CDN 地址，`cache.match()` 读回 `type=cors status=200`（不是 opaque） |
| 离线兜底 | 预缓存 3 个页面（`/`、`/way-home`、`/offline`），`/offline` 在缓存里可读 |
| 同源回退 | `CDN_ASSET_PREFIX` 留空重建一次：产物走相对地址、CSP 里没有 CDN、SW 缓存 38/38 条同源资源（`type=basic`），同样 11/11 通过 |
| `assets` 上传 | 81 个产物 → `apps/_app/immutable/...`，Content-Type 正确，`.br`/`.gz`/`.map` 一个都没传 |
| 重复发布 | 第二次「新增 0，已存在 81」——文件名带内容哈希，已存在即同一份内容，不重传 |
| `XFF_DEPTH=2` | `X-Forwarded-For: 203.0.113.9, 10.1.2.3` → 后端收到 `203.0.113.9` |
| 地区头闸门 | 带正确 `x-edge-secret` + `CF-IPCountry: JP` → `country:"JP"`；错的或没带 → `LOCAL` |

## 7. 日常：从改代码到上线

```bash
git switch -c feat/xxx
# ... 改代码，本地用 ./dev.sh 验证 ...
git push -u origin feat/xxx
# GitHub 上开 PR → ci.yml 按改动路径跑对应的端 → 评审 → 合入 main
# Dokploy 收到 webhook，自动构建并发布
```

| 改了什么 | 要注意 |
| --- | --- |
| 只改前端样式/文案 | 没有额外动作。注意 `apps` 与 `feedback` 的首屏预算在 CI 里是硬闸门 |
| 新增数据库迁移 | 必须写 `-- +goose Down`。Dokploy 上迁移还没接进发布流程，目前要手动跑 `admintool migrate`（第 9 节） |
| 改接口 | 同步 `service/api/openapi.yaml` 与 `docs/07`（仓库红线） |
| 新增后端必填环境变量 | **先在 Dokploy 的 Environment 里加好，再合入代码**。顺序反了新容器起不来 |
| 换 CDN 域名 | 改 Dokploy 的 `CDN_HOST`，再改 `feedback/public/sw.js` 的 `ASSET_ORIGINS`（并把 `VERSION` 加一）、`feedback/src/app/layout.tsx` 与 `admin/index.html` 的 `preconnect`、`IMAGE_BASE_URLS`，最后重跑 `r2-setup.sh` 更新 CORS |
| 后台新增图片线路 | 同步 `IMAGE_BASE_URLS` / `MEDIA_CONNECT_ORIGINS`，否则生产 CSP 会把封面和视频拦掉 |

### 回滚

Dokploy 的 Deployments 列表里选上一次成功的部署 → Redeploy，它会按那个提交重新构建。

两件要注意的：

- **迁移不会自动回滚。** `admintool migrate` 只升不降。新版本加了列、旧版本不认识时，优先前滚修复。
- **旧的静态产物还在 R2 上**（上传不删远端对象），所以回滚之后老页面引用的 chunk 仍然取得到。

## 8. 运维常用命令

```bash
# 容器与日志（Dokploy 的容器名带项目前缀，先 docker ps 看一眼）
docker ps --format '{{.Names}}\t{{.Status}}'
docker logs -f --tail 100 <apps 容器>
# 这一版的产物前缀与 SW 版本（构建期注入，排查「页面取错域名」时第一步看它）
docker exec <apps 容器> sh -c 'cat .env.production.local; grep -o "sv-static-[0-9]*" build/client/service-worker.js | head -1'

# 手动重跑一次产物上传（不重新构建）
docker compose -f /etc/dokploy/compose/<项目>/code/apps/docker-compose.yml run --rm assets

# 手动跑迁移（后端服务所在的编排里）
docker compose run --rm --entrypoint /app/admintool service migrate

# 建首个超级管理员（后台没有注册入口）。密码从标准输入读，不进命令行参数与 shell 历史
read -rs -p "密码（8–128 位）: " PW && echo
printf '%s\n' "${PW}" | docker compose run --rm -T \
  --entrypoint /app/admintool service create-admin -username root -role superadmin
unset PW

# 手动备份（没有自动备份，见第 9 节）
docker exec -t <postgres 容器> pg_dump -U postgres -Fc xsite > ~/backup-$(date +%F).dump
```

账号初始状态是 `unused`，首次登录后变 `active`。角色编码 `superadmin` 是唯一内置角色，其余角色在后台新建。

## 9. 排查速查表

| 现象 | 先看什么 |
| --- | --- |
| 部署卡在 `assets` | R2 四个变量是否齐、密钥是否还有效。日志里会直接写「缺少环境变量 X」或「上传失败 <键>」 |
| 整站 503、Traefik 报 no available server | 容器没进 `dokploy-network`。确认编排里每个服务都有 `networks: [dokploy-network]`，并且没开 Isolated Deployments |
| 页面能开但脚本全 404 | 页面里的地址和 R2 上的实际前缀对不上。对比 `docker exec <apps> cat .env.production.local` 与 `docker logs <assets>` 里的上传前缀 |
| 控制台报跨域、脚本一个都不执行 | R2 CORS 白名单里没有站点域名，重跑 `r2-setup.sh`（模块脚本一律按 CORS 模式取，没有 ACAO 就全挂） |
| 控制台报 CSP 拦住了 `cdn.…` 上的脚本 | CSP 里的 CDN 来源没以 `/` 结尾（带路径时不以斜杠结尾是精确匹配）。正常值形如 `https://cdn.duanju66.cc/apps/` |
| 页面正常但 Service Worker 装不上 | `curl -I https://duanju66.cc/service-worker.js`：404 说明它没进 adapter 的静态路由表 —— `scripts/build-sw.ts` 必须在 `vite build` **之前**跑并输出到 `static/` |
| SW 缓存里的产物读不出来（status 0） | 响应是 `opaque`，即 CDN 没回 CORS 头。同上，重跑 `r2-setup.sh` |
| 每个页面请求 500，日志写 `XFF_DEPTH is 2, but only found 1 addresses` | 站点没走 Cloudflare 代理却留着 `APPS_XFF_DEPTH=2`，改成 `1` |
| 限流把正常用户拦住、日志里 IP 全一样 | 反了：站点在 Cloudflare 后面但 `APPS_XFF_DEPTH=1` |
| 浏览器报证书不受信 | Traefik 还没签下来。看 Dokploy 的 Traefik 日志；Cloudflare SSL 模式必须是 Full (strict) |
| 后台登录后立刻掉登录态 | 后端的 `ADMIN_ORIGINS` 和实际域名不一致（production 只允许 https） |
| 封面或视频出不来 | `IMAGE_BASE_URLS` / `MEDIA_CONNECT_ORIGINS` 没跟着后台线路表更新，被 CSP 拦了 |
| 产物还是 gzip、没有 Brotli | `/_app/immutable/*` 由 Cloudflare 边缘压（`.br` 刻意不上传），看它的 Brotli 开关；HTML 与 `/icons/`、`/service-worker.js` 由 `apps` 自己处理（`src/lib/server/compress.ts` + adapter 的预压缩文件） |
| 后台资源预热进度条不动 | SSE 被缓冲。Traefik 默认不缓冲，检查有没有人给 `/api/admin/` 加了 buffering 中间件 |

## 10. 安全红线与当前缺口

红线（`docs/10`、`security-checklist`）：

- 密钥只存在 Dokploy 的 Environment 里，不提交、不进镜像、不贴进聊天或工单。
- 每个密钥字段独立生成（`deploy/prod/scripts/gen-secrets.sh` 可以直接用来生成 14 个字段），不要一个值填到所有字段。
- 不放开 5432 / 6379 到公网；Dokploy 面板的 3000 端口只对自己的 IP 开。
- 存储源凭据由后台页面录入、信封加密入库、只写不读；不要塞进环境变量。
- R2 密钥若曾经明文出现在任何可留存的地方，立即轮换。
- **产物域名是脚本来源，等同于代码执行权**。CDN 只放带内容哈希的构建产物，R2 的那对密钥按「只能读写这一个桶」最小化；CSP 的 CDN 来源要带路径前缀（`…/apps/`）而不是整个域名放开 —— 这个桶还放着后台可上传的媒体文件。

当前缺口，上线前要知道：

- **只有 `apps/` 有 Dokploy 编排。** `service/`（含 PostgreSQL、Valkey、worker、media-worker）、`admin/`、`feedback/` 还得各自建编排，或者继续用 `deploy/prod` 那一套（但不能和 Dokploy 同机）。
- **迁移没接进发布流程。** `deploy/prod/scripts/deploy.sh` 里「拉镜像 → 迁移 → 起服务」的顺序在 Dokploy 上没有对应物，目前要手动跑 `admintool migrate`。
- **静态产物的压缩降档。** 构建期压好的 Brotli 11 文件用不上了（实测 `app.*.js` 6062 → 1727 字节），`.br` 刻意不上传（在 R2 上是独立对象键，CDN 不会按 `Accept-Encoding` 在不同键之间选），压缩由 Cloudflare 边缘做、档位更低。要拿回来得让 `upload-assets.ts` 同时上传 `.br`（Bun 的 S3 客户端有 `contentEncoding` 选项，可以把 `Content-Encoding: br` 写在对象上），代价是要为「客户端不接受 br」留一条回退路径。
- **换 CDN 域名要重新构建。** `CDN_ASSET_PREFIX` 是构建期写进 HTML、CSP 与 Service Worker 的，改运行期环境变量不生效。
- **没有自动备份。** PostgreSQL 的连续归档与定期全量要按 `docs/09` 单独配（`docs/11` X5-4）。现在只有第 8 节的手动 `pg_dump`。
- **单副本，发布有秒级中断。** 要无缝发布得先上多副本 + 真正的负载均衡；注意 `apps` 的限流是进程内令牌桶（`src/lib/server/rate-limit.ts`），多副本时配额按副本翻倍。
- **没有多 CDN 与 GSLB**（`docs/11` X5-1），也没有回源 mTLS。
- **后端没有 `/metrics`**，`docs/11` 要求的仪表盘还没有数据源。
- **HTTP/3 没开。** Dokploy 的 Traefik 默认只有 HTTP/1.1 与 HTTP/2。
