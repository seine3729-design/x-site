## 0. 两条上线路径（互斥，别同时起）

| 路径 | 文件 | 状态 |
| --- | --- | --- |
| **Dokploy**（主） | `apps/docker-compose.yml` + Dokploy 的 Traefik | 前台已就绪，本文描述这一条 |
| 自建 nginx + certbot + GitHub Actions（备） | `deploy/prod/`、`.github/workflows/deploy.yml`、[`deploy/prod/README.md`](../deploy/prod/README.md) | 整栈可用，但和 Dokploy 抢同一个域名与 80/443 |

两条路都要独占宿主机的 80/443 和 `duanju66.cc`。**用 Dokploy 就不要在同一台机器上起 `deploy/prod` 那一套。**
`deploy/prod/README.md` 仍然值得读：边缘层、压缩链路、R2 的设计原理和实测数据都在那里，Dokploy 这一条沿用同样的结论。

整条链路：

```
本机                GitHub                  服务器（Dokploy）
────                ──────                  ─────────────────
git push ─────────► main 分支
                      │                     Dokploy 收到 webhook
                      ├─ ci.yml  PR 闸门     ├─ 拉代码
                      │                      ├─ docker compose build（构建 apps 镜像）
                      └─ webhook ───────────►├─ assets 一次性容器：build/client/_app/immutable → R2
                                             ├─ apps 容器启动（SSR + BFF）
                                             └─ Traefik 自动发现标签，签/续 Let's Encrypt 证书
```

请求怎么分流：

```
浏览器 ──┬─ /_app/immutable/*  ───────────────────────→ cdn.duanju66.cc ─→ R2（桶 duanju666）
         └─ 页面、/api/v1、/service-worker.js、/icons/ ─→ Traefik ─→ apps:3001 ─→ service:8080
```

**带内容哈希的产物由浏览器直接从 CDN 取**，页面里写的就是 `https://cdn.duanju66.cc/apps/_app/immutable/...`。
这个地址在**构建期**由 `CDN_ASSET_PREFIX` 决定，一个值同时管三处，所以换 CDN 域名必须重新构建：

| 用在哪 | 怎么用 |
| --- | --- |
| SvelteKit `paths.assets` | 写进 HTML 与客户端脚本的产物地址 |
| `apps/config/security-headers.ts` | 生产 CSP 的 `script-src` / `style-src` / `font-src` / `img-src` / `connect-src` 白名单 |
| `apps/scripts/build-sw.ts` | 注入 Service Worker，让它认得出哪些请求是产物 |

> **CSP 的坑**：来源表达式里带路径时，不以 `/` 结尾就是**精确匹配那一个路径**（CSP3 §6.6.2.6）。
> `https://cdn.duanju66.cc/apps` 只会匹配 `/apps` 本身，产物一个都放不过去 —— `cdnExpression()` 因此会补上末尾斜杠。

### Service Worker 为什么不在 `src/service-worker/`

SvelteKit 只要扫到**自己管的** Service Worker 入口文件，而 `paths.assets` 又非空，就直接以
`service_worker_assets` 退出（`node_modules/@sveltejs/kit/src/exports/vite/build/service-worker.js`）。
产物要走 CDN 绝对地址，就只能让 SW 脱离 SvelteKit 的管辖：

- 源码在 `apps/src/sw/index.ts`，由 `apps/scripts/build-sw.ts` 用 Bun 编译，构建版本与产物前缀以
  `__SW_VERSION__` / `__SW_ASSET_BASE__` 注入。
- **必须在 `vite build` 之前编译、输出到 `static/`**。adapter-bun 的静态路由表是在 `vite build` 时定下的，
  构建之后再往 `build/client/` 里塞文件，文件在磁盘上但 `/service-worker.js` 一律 404
  （实测踩过：页面完全正常、只有 SW 装不上，排查方向很容易跑偏）。
- 资源缓存的收录条件从「只认 `basic`」放宽到「`basic` 或 `cors`」，仍然挡 `opaque`（CDN 的 CORS 没配好时
  就会退化成它：status 恒 0、存了读不出来还占配额）。`feedback/public/sw.js` 早就是这个写法。
- `/service-worker.js`、`/icons/`、`_app/version.json` 刻意**不**上 CDN：SW 必须同源才有 `/` 作用域，
  `version.json` 是客户端轮询新版本用的、不能长缓存。

## 2. 把仓库推上 GitHub

工作区现在还不是 git 仓库，这一步从零开始。

### 2.1 推之前必须确认的三件事

**(1) 忽略规则是否够用。** 这个仓库里躺着 1.5 GB 的依赖和构建产物，漏一条就会把几百兆推上去。核对方式——在工作区**之外**建一个 git 目录做干跑：

```bash
cd ~/Desktop/x-site
D=/tmp/gitprobe/.git; rm -rf /tmp/gitprobe; mkdir -p /tmp/gitprobe
git --git-dir=$D --work-tree=$PWD init -q
git --git-dir=$D --work-tree=$PWD add -A
git --git-dir=$D --work-tree=$PWD diff --cached --name-only | wc -l       # 期望 1600 上下
git --git-dir=$D --work-tree=$PWD diff --cached --name-only -z \
  | xargs -0 du -ch | tail -1                                            # 期望 20 MB 以内
git --git-dir=$D --work-tree=$PWD diff --cached --name-only \
  | grep -E 'node_modules|/dist/|\.next/|\.svelte-kit|/build/|\.env$'     # 期望没有输出
rm -rf /tmp/gitprobe
```

实测：**1600 上下个文件、18 MB**。被挡在外面的：各端 `node_modules`（合计 1.1 GB）、`feedback/.next`（159 MB）、`mobile/build`（78 MB）、`service/tmp`（107 MB）、`admin/dist`、`apps/build`、`apps/.svelte-kit`、根目录 `.env`、`.local/`、`semantic-review/`、`__pycache__/`，以及所有 `.br` / `.gz` 预压缩产物。

> 为这次上传补过的忽略规则，换环境时注意别丢：
> - `admin/.gitignore` **原来根本不存在** —— 不加会提交 `admin/node_modules`（380 MB）。
> - `service/.gitignore` 加了 `/worker`、`/_uiseed` 等 `go build` 留下的裸二进制。**刻意没有 `/api`**：gitignore 分不清同名的文件和目录，写上会把契约目录 `service/api/`（`openapi.yaml` 在里面）一起忽略掉。
> - 根 `.gitignore` 加了 `semantic-review/`、`__pycache__/`。

**(2) 有没有密钥混在里面。** 扫一遍源码与配置（跳过 `docs/`，那里引用关键词本身会自己命中）：

```bash
grep -rIl --exclude-dir=node_modules --exclude-dir=.git --exclude-dir=docs \
  -e 'PRIVATE KEY-----' -e 'AKIA' -e 'cfat_' \
  service apps admin feedback mobile deploy .github *.yaml *.sh 2>/dev/null
```

预期没有输出。`.env.example`、`deploy/prod/.env.example` 里只有占位值，是故意提交的；`${XXX:?...}` 是变量引用不是值；真正的 `.env` 已被忽略。

**(3) 行尾与大文件。** 仓库里没有需要 Git LFS 的文件（最大的是 808 KB 的图标数据集）。

### 2.3 分支保护（不是可选项）

`ci.yml` 监听 `branches-ignore: [main]` 与 `pull_request`，而 Dokploy 是「推 main 即发布」。
**这意味着直接推 main 会跳过全部检查直接上线。** 唯一的闸门是分支保护，必须配：

Settings → Branches → Add rule，`main`：

- ☑ Require a pull request before merging
- ☑ Require status checks to pass before merging → 勾上 `service`、`apps`、`admin`、`feedback`
  （检查名第一次开 PR 跑过之后才会出现在列表里，先建 rule 再回来补）
- ☑ Require branches to be up to date before merging
- ☑ Do not allow bypassing the above settings

## 3. 服务器与 Dokploy

### 3.1 系统基础

```bash
# 时间必须准：证书校验、JWT 过期、TOTP 二次验证都看系统时间
sudo timedatectl set-timezone UTC
timedatectl   # 确认 "System clock synchronized: yes"

# 8 GB 内存建议配 4 GB swap：转封装峰值会吃内存，宁可变慢不要被 OOM 杀掉
sudo fallocate -l 4G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### 3.2 安装 Dokploy

Dokploy 的安装脚本会装好 Docker、Traefik 和面板本身，面板在 `http://<服务器IP>:3000`。
首次打开**立刻创建管理员账号**——在那之前谁先访问谁就是管理员。

装完确认三件事：

```bash
docker ps --filter name=dokploy --format '{{.Names}}\t{{.Status}}'   # 面板与 Traefik 都在
docker network inspect dokploy-network -f '{{.Name}} {{.Driver}}'     # 编排文件依赖这张网络
docker compose version                                                # 必须是 v2.x
```

### 3.3 防火墙

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow from <你的办公 IP> to any port 3000 proto tcp   # Dokploy 面板不要对全网开
sudo ufw enable
```

**不要**放开 5432 / 6379。

> Docker 会直接写 iptables，`-p 0.0.0.0:xx` 的端口映射能绕过 ufw。本项目的编排只用 `expose`，由 Traefik 统一对外，所以不受影响。新增端口映射时留意这一点。

### 3.4 Dokploy 的全局设置

- **Traefik → 确认 entrypoints 是 `web`(80) 与 `websecure`(443)，证书解析器名字是 `letsencrypt`**。编排文件里的标签按这三个名字写的，改过名就要同步改标签。
- **Registry**：不需要。Dokploy 在服务器上直接 `docker compose build`，不经镜像仓库。
- HTTP/3 默认没开。要开得在 Dokploy 的 Traefik 配置里加 `http3` 并放通 443/udp，本文不覆盖。

## 4. DNS 与 Cloudflare

### 4.1 DNS 记录

| 记录 | 类型 | 值 | 代理 |
| --- | --- | --- | --- |
| `duanju66.cc` | A | 服务器 IP | **代理（橙云）** |
| `www` | A | 服务器 IP | **代理（橙云）** |
| `admin` | A | 服务器 IP | 直连（灰云）或代理都行 |
| `feedback` | A | 服务器 IP | 直连或代理都行 |
| `cdn` | — | R2 自定义域，已存在 | Cloudflare 自动管理 |

### 4.2 代理模式下要改的三处

1. **SSL/TLS → Overview → 加密模式选 `Full (strict)`**。源站上 Traefik 签的 Let's Encrypt 证书正好满足。选 Flexible 会让 Cloudflare 用 HTTP 回源，源站的 HTTPS 跳转会把请求打成死循环。
2. **`APPS_XFF_DEPTH=2`**（Dokploy 的环境变量）。Cloudflare 把真实客户端 IP 放在 `X-Forwarded-For` 的第一段，Traefik 再把 Cloudflare 边缘 IP 追加在后面，所以要从右数第 2 个。见第 6.2 节。
3. **Caching → Cache Rules 加两条**：
   - `URI Path starts with /_app/immutable/` 或 `/icons/` → Eligible for cache，Edge TTL「Use cache-control header」（源站已给 `immutable` 一年）。
   - 确认**没有**任何规则把 HTML 设成可缓存。SSR 页面随登录用户变化，缓存串号会把别人的页面发出去。Cloudflare 默认不缓存 HTML，这条是防止后来有人加了 "Cache Everything"。

ACME 挑战不受代理影响：Cloudflare 不会把 `/.well-known/acme-challenge/` 强制跳 HTTPS。

### 4.3 R2 一次性设置

在**本机**跑（需要 aws cli；没装就用 `docker run --rm -v "$PWD":/w -w /w amazon/aws-cli` 代替 `aws`）：

```bash
cd ~/Desktop/x-site/deploy/prod
R2_ENDPOINT=https://<账户ID>.r2.cloudflarestorage.com \
R2_BUCKET=duanju666 \
AWS_ACCESS_KEY_ID=... AWS_SECRET_ACCESS_KEY=... \
APPS_DOMAIN=duanju66.cc APPS_ALIASES=www.duanju66.cc \
ADMIN_DOMAIN=admin.duanju66.cc FEEDBACK_DOMAIN=feedback.duanju66.cc \
CDN_DOMAIN=cdn.duanju66.cc \
  ./scripts/r2-setup.sh
```

脚本设 CORS 白名单 + 生命周期（`admin/`、`feedback/` 前缀下的对象 90 天过期；未完成的分片上传 1 天后中止）。

**CORS 这一步必须做，不是优化项**：三个前端的入口脚本都是 `<script type="module">`，而模块脚本一律按 CORS 模式取（这是规范行为，不是可选项）。R2 不回 `Access-Control-Allow-Origin` 的话，页面在控制台报跨域、一行脚本都跑不起来。字体同理。脚本已经把 `APPS_DOMAIN`、`APPS_ALIASES`、后台与反馈社区的域名、以及 CDN 域名自己都列进白名单了。

> `put-bucket-cors` 是**整体替换**。加域名时改 `scripts/r2-setup.sh` 重跑，不要在控制台手改——下次跑脚本又会被覆盖回去。

生命周期规则已经覆盖 `apps/`、`admin/`、`feedback/` 三个前缀（各 90 天过期）。发布时不删远端旧对象，靠这条清理 —— 90 天远大于「还有用户的页面在引用上一版 chunk」的时间窗。

## 5. 在 Dokploy 上建四个服务

四份编排，每份在 Dokploy 里是一个 Compose 服务：

| 顺序 | Compose Path | 域名 | 里面有什么 |
| --- | --- | --- | --- |
| ① | `./service/docker-compose.yml` | 无（只提供两条按域名+路径的接口入口） | postgres、valkey、migrate、service、worker、media-worker |
| ② | `./apps/docker-compose.yml` | `duanju66.cc`、`www.duanju66.cc` | assets（一次性）、apps |
| ③ | `./admin/docker-compose.yml` | `admin.duanju66.cc` | assets（一次性）、admin |
| ④ | `./feedback/docker-compose.yml` | `feedback.duanju66.cc` | assets（一次性）、feedback |

**①必须先部署**：另外三份都要通过 `dokploy-network` 访问它。它给自己挂了固定的网络别名 **`xsite-service`**，所以另外三端的 `SERVICE_INTERNAL_URL` 一律是 `http://xsite-service:8080`，不用去查 Dokploy 生成的容器名（这也是默认值，通常不用填）。

每份的建法都一样：New Project → New Service → **Compose**，Compose Type 选 `Docker Compose`，Provider 选 GitHub（装 Dokploy 的 GitHub App）或 Git，Repository 填 `<账号>/x-site`，Branch `main`，填上表里的 Compose Path，Save，然后在 Environment 标签页填变量再 Deploy。

### 5.0 请求最终怎么分流

```
duanju66.cc           ┬─ /_app/immutable/*  ──────────────→ cdn.duanju66.cc ─→ R2
                      └─ 其余 ────────────→ Traefik ─→ apps:3001 ─────┐
admin.duanju66.cc     ┬─ /assets/*         ──────────────→ cdn.duanju66.cc ─→ R2
                      ├─ /api/admin/*      ─→ Traefik ──────────────┐ │
                      └─ 其余（index.html）─→ Traefik ─→ admin:8080  │ │
feedback.duanju66.cc  ┬─ /_next/static/*   ──────────────→ cdn.duanju66.cc ─→ R2
                      ├─ /open-api/feedback ─→ Traefik ─────────────┤ │
                      └─ 其余 ────────────→ Traefik ─→ feedback:3002┤ │
                                                                    ▼ ▼
                                                      xsite-service:8080（service）
```

`/api/admin/*` 与 `/open-api/feedback` 这两条路由的标签挂在 **service 容器**上，不在 admin / feedback 的编排里 —— Traefik 的 Docker provider 只能把标签挂在要回源的那个容器上。它们的 `priority=100`，比 admin / feedback 容器上的兜底路由（`priority=10`）高，所以先被挑走。

### 5.1 ① 后端（`./service/docker-compose.yml`）

| 服务 | 作用 | 生命周期 |
| --- | --- | --- |
| `postgres` | PG 18 + pg_bigm（从 `deploy/local/postgres/` 构建，本地与生产同一个 Dockerfile） | 常驻，数据在 `pgdata` 卷 |
| `valkey` | 会话、限流计数、待落库的计数与榜单本体 | 常驻，`appendonly yes`，数据在 `valkeydata` 卷 |
| `migrate` | `admintool migrate`（嵌入式 goose，只升不降） | 一次性，失败就停住、service 不起 |
| `service` | Go API，8080 | 常驻 |
| `worker` | 通用异步任务（不消费媒体队列） | 常驻 |
| `media-worker` | 转封装（带 FFmpeg 的镜像） | 常驻 |

**首次空数据卷会自动完成两步**：

```text
官方 PostgreSQL entrypoint
  → 镜像内 /docker-entrypoint-initdb.d/01-init.sh
      → 创建 xsite、xsite_app、xsite_ro、5 个扩展和权限
  → migrate（嵌入式 Goose）
      → 创建全部业务表、索引与初始数据
  → service / worker / media-worker 启动
```

`01-init.sh` 是镜像的一部分，**只在 `pgdata` 卷首次为空时运行一次**；它不建业务表，表结构仍由 `migrate` 创建。production 禁用 `AUTO_MIGRATE`（启动校验会拒），所以 `service` / `worker` 都 `depends_on` `migrate` 的 `service_completed_successfully`。

`migrate` 容器只接收 `DATABASE_URL`，不加载 API / worker 的完整配置；它不需要也不应被 Valkey、BFF、S3、报文加密、后台 TOTP 等运行时配置阻断。API / worker 仍保留完整严格校验：迁移成功不代表可以遗漏它们的生产必填变量。

> **已有卷不要删除。** 修改 `POSTGRES_PASSWORD`、`XSITE_*` 或 `VALKEY_PASSWORD` 的 Environment 后，重建容器不会自动更新卷里的 PostgreSQL 角色、数据库或密码；必须先备份，再显式执行 `ALTER ROLE` / 权限变更。不要为了重跑初始化删生产 `pgdata`。
>
> `01-init.sh` 使用非幂等的 `CREATE ROLE` / `CREATE DATABASE`，只适合空卷首次启动；不要把它直接拿去对已有库重复执行。

一个要知道的细节：compose 只在镜像或配置变了的时候重建一次性容器。只改了环境变量没改代码时它可能不重跑，手动来一次：

```bash
docker compose -f <编排路径> up -d --force-recreate --no-deps migrate
```

必填变量（密钥用 `deploy/prod/scripts/gen-secrets.sh` 生成，14 个字段每个都要独立随机值）：

| 变量 | 说明 |
| --- | --- |
| `POSTGRES_PASSWORD` / `XSITE_APP_PASSWORD` / `XSITE_RO_PASSWORD` / `VALKEY_PASSWORD` | 数据层口令。连接串由编排自己拼，不用手写。每个独立生成，且必须使用 URI 安全字符（推荐十六进制） |
| `BFF_SERVICE_TOKEN` | 与 apps / feedback 的同名变量完全一致 |
| `EDGE_SHARED_SECRET` | 与 apps 一致；Traefik 用它注入 `x-edge-secret`，直连源站会被 403 |
| `API_ENC_KEYS`、`ADMIN_TOTP_KEKS`、`JWT_SIGNING_KEYS`、`PLAY_TOKEN_KEYS`、`MEDIA_KEKS`、`STORAGE_KEKS`、`LINE_SIGN_KEYS`、`CONFIG_BACKUP_KEYS` | 各类签名/加密密钥，格式 `kid:secret`，缺任何一项 production 启动失败 |
| `S3_ENDPOINT` / `S3_ACCESS_KEY` / `S3_SECRET_KEY` / `S3_BUCKET_MEDIA` / `S3_BUCKET_ASSETS` / `MEDIA_SOURCE_BUCKET` | 媒体主存储（`docs/12`）。`MEDIA_SOURCE_BUCKET` 不能等于公开读的 `S3_BUCKET_ASSETS`，启动校验会拒 |

固定的非密钥值直接填：`XSITE_DB=xsite`、`XSITE_APP_USER=xsite_app`、`XSITE_RO_USER=xsite_ro`。

数据库/Valkey 口令不要写进仓库或聊天。请在**自己的安全终端**运行下面命令，输出的四行直接逐项粘到 Dokploy 的 Environment（命令只用十六进制，能安全嵌进当前 compose 自动拼出的连接 URI）：

```bash
cd ~/Desktop/x-site/deploy/prod
./scripts/gen-secrets.sh | grep -E '^(POSTGRES_PASSWORD|XSITE_APP_PASSWORD|XSITE_RO_PASSWORD|VALKEY_PASSWORD)='
```

`gen-secrets.sh` 每次执行都会生成新的随机值；只执行一次、妥善粘贴保存，不要把输出发进聊天、工单、CI 日志或提交。

可选：`ADMIN_DOMAIN` / `FEEDBACK_DOMAIN`（默认 `admin.duanju66.cc` / `feedback.duanju66.cc`，决定上面两条路由与 `ADMIN_ORIGINS`）、`PG_PORT`（默认 `55432`，只绑 `127.0.0.1`，便于 psql 与 pg_dump；刻意不是 5432，Dokploy 自己的面板库可能占着）、`MEDIA_TRANSCODE_CONCURRENCY`、`IMAGE_TINIFY_API_KEY`、`PG_SHARED_BUFFERS` 等调优项。

**GeoIP（可选）**：首次部署不要设置 `GEOIP_XDB_PATH`（或将其留空），地区会按未知处理，只有 `region_scope=global` 的兜底线路会命中；功能不挂，但按地区多线路调度不生效。只有 `geoip` 卷中已有有效的 ip2region xdb 文件时，才设置 `GEOIP_XDB_PATH=/data/geoip/ip2region.xdb`。配置了非空路径但文件缺失或损坏时，API 与 worker 会拒绝启动，避免误以为地区判断正在工作。

service 挂载该卷为只读，不能直接 `docker cp` 到 service 容器。先在服务器上把文件写入同一个命名卷，再设置环境变量并重新部署：

```bash
SERVICE_CONTAINER=<service 容器名>
GEOIP_VOLUME=$(docker inspect "${SERVICE_CONTAINER}" --format '{{range .Mounts}}{{if eq .Destination "/data/geoip"}}{{.Name}}{{end}}{{end}}')
test -n "${GEOIP_VOLUME}" || { echo '没有找到 /data/geoip 命名卷' >&2; exit 1; }
docker run --rm -i -v "${GEOIP_VOLUME}:/data" alpine:3.22 \
  sh -c 'cat > /data/ip2region.xdb' < ip2region.xdb
```

### 5.2 ② 前台（`./apps/docker-compose.yml`）

两个服务：`assets`（把 `build/client/_app/immutable` 推 R2）→ `apps`（Bun SSR + BFF，3001）。
两者共用同一个 `image` 与同一段 `build`，所以**上传的产物与正在运行的那一版必然是同一次构建**。两次独立构建的内容哈希对不上时，页面会去 CDN 取一个不存在的文件名，而且只在生产复现 —— 这就是为什么不把上传放到 CI 里另做一次构建。

| 变量 | 必填 | 填什么 |
| --- | --- | --- |
| `BFF_SERVICE_TOKEN` | 是 | 与 service 一致（≥ 32 字符） |
| `R2_ENDPOINT` / `R2_BUCKET` / `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` | 是 | R2 访问密钥，权限按「只能读写这一个桶」最小化 |
| `SERVICE_INTERNAL_URL` | 否 | 默认 `http://xsite-service:8080` |
| `EDGE_SHARED_SECRET` | 建议 | 设上之后才校验 `x-edge-secret`，否则任何人都能伪造地区头 |
| `APPS_XFF_DEPTH` | 否 | 默认 `2`（Cloudflare 橙云 + Traefik）。前面没有 Cloudflare 时改 `1` |
| `CDN_HOST` / `CDN_ASSETS_PREFIX` | 否 | 默认 `cdn.duanju66.cc` / `apps`。同一个值既是 R2 对象键前缀、也拼进构建参数 `CDN_ASSET_PREFIX` |
| `IMAGE_BASE_URLS` / `MEDIA_CONNECT_ORIGINS` | 否 | 图片与视频线路域名池，默认都是 `https://cdn.duanju66.cc`。生产 CSP 的 `img-src` / `connect-src` 从这里生成 |
| `APPS_DOMAIN` / `APPS_WWW_DOMAIN` | 否 | 默认 `duanju66.cc` / `www.duanju66.cc` |

**`RATE_LIMIT_*`、`APP_ENV`、`CDN_ASSET_PREFIX` 在这里设了不生效**：`apps/scripts/with-env.ts` 会用镜像里 `.env.production`（以及构建期写入的 `.env.production.local`）的同名值覆盖容器环境变量。要改配额就改那个文件再重新构建。

### 5.3 ③ 运营后台（`./admin/docker-compose.yml`）

两个服务：`assets`（把 `dist/assets` 推 R2）→ `admin`（alpine + nginx + `ngx_brotli`，8080）。

**`index.html` 必须由 `admin.duanju66.cc` 自己发，不能搬到 CDN**：后台会话是 HttpOnly Cookie，后端还要校验 Origin 白名单与 CSRF（`docs/03` 第 2.3 节），页面和 `/api/admin` 必须同源。只有带内容哈希的 `assets/` 走 CDN。

自己带一层 nginx（而不是把产物交给别的东西发）是为了 `brotli_static`：构建期 `scripts/precompress.mjs` 把 `.js` / `.css` **以及 `index.html`** 压成了 Brotli 11，这一层能把它们原样送出去。基础镜像用 alpine + `nginx-mod-http-brotli` 而不是官方 nginx 镜像 —— 官方镜像没有 brotli 模块。配置见 `admin/nginx.conf`。

| 变量 | 必填 | 填什么 |
| --- | --- | --- |
| `R2_ENDPOINT` / `R2_BUCKET` / `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` | 是 | 同上，三端共用一对密钥即可 |
| `CDN_HOST` / `CDN_ASSETS_PREFIX` | 否 | 默认 `cdn.duanju66.cc` / `admin`，拼成构建参数 `ADMIN_ASSET_BASE`（末尾要带斜杠，Vite 的要求） |
| `ADMIN_DOMAIN` | 否 | 默认 `admin.duanju66.cc` |

后台不需要 `BFF_SERVICE_TOKEN`：它是纯静态 SPA，浏览器直接打 `/api/admin/*`，由 Traefik 转给 service 并在那一跳注入 `x-edge-secret`。

### 5.4 ④ 反馈社区（`./feedback/docker-compose.yml`）

两个服务：`assets`（把 `.next/static` 推 R2）→ `feedback`（Next.js standalone，3002）。

浏览器只与这个域名同源通信：Next.js 的服务端带 `X-Service-Token` 转发到 Go（`feedback/docs/adr/0008`），所以客户端拿不到后端地址也拿不到服务令牌。`/open-api/feedback` 是唯一例外 —— 它是站外网页里的 JS 直接提交的，在 Go 侧免回源鉴权、改用 `X-Api-Key` + Key 上的 Origin 白名单（`adr/0009`），所以 service 上只放了这**一个精确路径**，没放 `/open-api/` 前缀。

| 变量 | 必填 | 填什么 |
| --- | --- | --- |
| `BFF_SERVICE_TOKEN` | 是 | 与 service 一致（≥ 32 字符）。它命中 Go 侧的 `isInternalSSR` 明文豁免，所以这一端不需要报文加密客户端 |
| `R2_ENDPOINT` / `R2_BUCKET` / `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` | 是 | 同上 |
| `SERVICE_INTERNAL_URL` | 否 | 默认 `http://xsite-service:8080` |
| `CDN_HOST` / `CDN_ASSETS_PREFIX` | 否 | 默认 `cdn.duanju66.cc` / `feedback`，拼成构建参数 `NEXT_ASSET_PREFIX` |
| `FEEDBACK_DOMAIN` | 否 | 默认 `feedback.duanju66.cc` |

HTML 的压缩是 Next.js 自己的 `compress: true`（只有 gzip）。Traefik 看到带 `Content-Encoding` 的响应不会再处理，所以**加 compress 中间件也没用**；想让 HTML 拿到 Brotli 只有「关掉 `next.config.ts` 的 compress 再加中间件」这一条路，那是 `feedback/` 自己的取舍（`feedback/docs/06` 第 11 节），别在编排里单方面改。

### 5.5 域名：标签还是 Dokploy Domains，二选一

四份编排都带了完整的 Traefik 标签（HTTPS、80 → 443、`apps` 还有 `www` 跳转、service 上的两条接口路由、`x-edge-secret` 注入）。**不要再在 Dokploy 的 Domains 标签页加同一个域名**，两边都配会生成重复的 router。

要改用 Dokploy Domains，就把对应编排里的 `labels:` 段删掉再在界面上加域名（apps → 服务 `apps` 端口 3001；admin → `admin`/8080；feedback → `feedback`/3002）。但 **service 那份的标签删不掉** —— `/api/admin/*` 与 `/open-api/feedback` 是按路径分流的，Dokploy 的界面只能按域名配。

### 5.6 Deploy 与首次证书

按 ①②③④ 的顺序点 Deploy。首次耗时：service 6–10 分钟（Go 构建 + postgres 要编译 pg_bigm），apps 10–20 分钟，admin 与 feedback 各 4–8 分钟；之后都是 3–6 分钟。

证书：Traefik 在第一个请求到来时按 HTTP-01 挑战签发，大约 10–30 秒。这期间 `curl` 会因为证书不受信而失败，是预期的。

### 回滚

Dokploy 的 Deployments 列表里选上一次成功的部署 → Redeploy，它会按那个提交重新构建。

两件要注意的：

- **迁移不会自动回滚。** `admintool migrate` 只升不降。新版本加了列、旧版本不认识时，优先前滚修复。
- **旧的静态产物还在 R2 上**（上传不删远端对象），所以回滚之后老页面引用的 chunk 仍然取得到。

## 9. 排查速查表

| 现象 | 先看什么 |
| --- | --- |
| `migrate` 退出 1，postgres / valkey 已 healthy | 先看 `docker logs <migrate 容器>` 的 `错误：` 行。`读取迁移配置失败` = `DATABASE_URL` 没生成；`连接数据库失败` = 账号/密码/数据库与已有 `pgdata` 不一致；`执行迁移失败` = 某条 Goose SQL 失败。迁移容器现在只依赖 `DATABASE_URL`，BFF / Valkey / S3 / API 密钥不再会阻断它 |
| 部署卡在 `assets` | R2 四个变量是否齐、密钥是否还有效。日志里会直接写「缺少环境变量 X」或「上传失败 <键>」 |
| 整站 503、Traefik 报 no available server | 容器没进 `dokploy-network`。确认编排里每个服务都有 `networks: [dokploy-network]`，并且没开 Isolated Deployments |
| 页面能开但脚本全 404 | 页面里的地址和 R2 上的实际前缀对不上。对比 `docker exec <apps> cat .env.production.local` 与 `docker logs <assets>` 里的上传前缀 |
| 控制台报跨域、脚本一个都不执行 | R2 CORS 白名单里没有站点域名，重跑 `r2-setup.sh`（模块脚本一律按 CORS 模式取，没有 ACAO 就全挂） |
| 控制台报 CSP 拦住了 `cdn.…` 上的脚本 | CSP 里的 CDN 来源没以 `/` 结尾（带路径时不以斜杠结尾是精确匹配）。正常值形如 `https://cdn.duanju66.cc/apps/` |
| 页面正常但 Service Worker 装不上 | `curl -I https://duanju66.cc/service-worker.js`：404 说明它没进 adapter 的静态路由表 —— `scripts/build-sw.ts` 必须在 `vite build` **之前**跑并输出到 `static/` |
| SW 缓存里的产物读不出来（status 0） | 响应是 `opaque`，即 CDN 没回 CORS 头。同上，重跑 `r2-setup.sh` |
| 每个页面请求 500，日志写 `XFF_DEPTH is 2, but only found 1 addresses` | 站点没走 Cloudflare 代理却留着 `APPS_XFF_DEPTH=2`，改成 `1` |
| 限流把正常用户拦住、日志里 IP 全一样 | 反了：站点在 Cloudflare 后面但 `APPS_XFF_DEPTH=1` |
| 浏览器报证书不受信 | Traefik 还没签下来。看 Dokploy 的 Traefik 日志；Cloudflare SSL 模式必须是 Full (strict) |
| 后台登录后立刻掉登录态 | 后端的 `ADMIN_ORIGINS` 和实际域名不一致（production 只允许 https） |
| 封面或视频出不来 | `IMAGE_BASE_URLS` / `MEDIA_CONNECT_ORIGINS` 没跟着后台线路表更新，被 CSP 拦了 |
| 产物还是 gzip、没有 Brotli | `/_app/immutable/*` 由 Cloudflare 边缘压（`.br` 刻意不上传），看它的 Brotli 开关；HTML 与 `/icons/`、`/service-worker.js` 由 `apps` 自己处理（`src/lib/server/compress.ts` + adapter 的预压缩文件） |
| 后台资源预热进度条不动 | SSE 被缓冲。Traefik 默认不缓冲，检查有没有人给 `/api/admin/` 加了 buffering 中间件 |

## 10. 安全红线与当前缺口

红线（`docs/10`、`security-checklist`）：

- 密钥只存在 Dokploy 的 Environment 里，不提交、不进镜像、不贴进聊天或工单。
- 每个密钥字段独立生成（`deploy/prod/scripts/gen-secrets.sh` 可以直接用来生成 14 个字段），不要一个值填到所有字段。
- 不放开 5432 / 6379 到公网；Dokploy 面板的 3000 端口只对自己的 IP 开。
- 存储源凭据由后台页面录入、信封加密入库、只写不读；不要塞进环境变量。
- R2 密钥若曾经明文出现在任何可留存的地方，立即轮换。
- **产物域名是脚本来源，等同于代码执行权**。CDN 只放带内容哈希的构建产物，R2 的那对密钥按「只能读写这一个桶」最小化；CSP 的 CDN 来源要带路径前缀（`…/apps/`）而不是整个域名放开 —— 这个桶还放着后台可上传的媒体文件。

当前缺口，上线前要知道：

- **只有 `apps/` 有 Dokploy 编排。** `service/`（含 PostgreSQL、Valkey、worker、media-worker）、`admin/`、`feedback/` 还得各自建编排，或者继续用 `deploy/prod` 那一套（但不能和 Dokploy 同机）。
- **迁移没接进发布流程。** `deploy/prod/scripts/deploy.sh` 里「拉镜像 → 迁移 → 起服务」的顺序在 Dokploy 上没有对应物，目前要手动跑 `admintool migrate`。
- **静态产物的压缩降档。** 构建期压好的 Brotli 11 文件用不上了（实测 `app.*.js` 6062 → 1727 字节），`.br` 刻意不上传（在 R2 上是独立对象键，CDN 不会按 `Accept-Encoding` 在不同键之间选），压缩由 Cloudflare 边缘做、档位更低。要拿回来得让 `upload-assets.ts` 同时上传 `.br`（Bun 的 S3 客户端有 `contentEncoding` 选项，可以把 `Content-Encoding: br` 写在对象上），代价是要为「客户端不接受 br」留一条回退路径。
- **换 CDN 域名要重新构建。** `CDN_ASSET_PREFIX` 是构建期写进 HTML、CSP 与 Service Worker 的，改运行期环境变量不生效。
- **没有自动备份。** PostgreSQL 的连续归档与定期全量要按 `docs/09` 单独配（`docs/11` X5-4）。现在只有第 8 节的手动 `pg_dump`。
- **单副本，发布有秒级中断。** 要无缝发布得先上多副本 + 真正的负载均衡；注意 `apps` 的限流是进程内令牌桶（`src/lib/server/rate-limit.ts`），多副本时配额按副本翻倍。
- **没有多 CDN 与 GSLB**（`docs/11` X5-1），也没有回源 mTLS。
- **后端没有 `/metrics`**，`docs/11` 要求的仪表盘还没有数据源。
- **HTTP/3 没开。** Dokploy 的 Traefik 默认只有 HTTP/1.1 与 HTTP/2。
