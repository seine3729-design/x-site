# 10 · 数据安全与加密方案

本文定义数据分级、传输与存储加密、密钥管理、接口签名、媒体保护和各端安全要求。所有加密使用经过审计的标准库或成熟库，不自创算法。

## 1. 数据分级

| 级别 | 数据 | 存储要求 | 日志要求 |
| --- | --- | --- | --- |
| S3 机密 | 密码哈希、各类密钥（含接口报文加密私钥种子）、Refresh Token 哈希、API Key 哈希、FTP 凭证、存储源凭据、TOTP 种子、支付渠道凭据（应用私钥、商户私钥、APIv3 密钥） | 只存哈希或经 KMS 信封加密；密钥不入库 | 禁止出现 |
| S2 支付 | 订单与渠道流水号、支付回调原文、USDT 收款地址与交易哈希 | 回调原文信封加密，保留 180 天；订单表常规存储 | 只记订单号与结果，不记原文 |
| S2 个人敏感 | 登录 IP、推送令牌、设备完整性结果 | 字段级加密；查询用盲索引 | 脱敏（IP 只留前两段） |
| S1 内部 | 观看历史、关注、点赞、评论、埋点原始数据、金币流水、抽奖与兑换记录、邀请关系 | 磁盘加密；按最小权限访问 | 可记录 ID，不记录内容全文 |
| S2 用户图片原图 | 晒图与头像的原始上传（可能含 GPS 等元数据） | 只在暂存桶，处理后 24 小时内删除；对外只发布去除元数据的处理结果 | 不记录元数据内容 |
| S0 公开 | 剧集资料、封面、公开计数 | 常规 | 常规 |

- 数据最小化：不采集邮箱、手机号、硬件标识（IMEI、IDFA）、精确位置；设备 ID 由服务端生成；客户端 IP 只用于实时选线与限流，不落库（只记前缀与解析后的地区）。
- 保留期：`event_raw` 90 天后转匿名聚合；已注销用户 30 天后物理删除个人字段；登录日志 180 天。

## 2. 传输加密

| 链路 | 要求 |
| --- | --- |
| 用户 ↔ CDN | TLS 1.3 优先（最低 1.2），HSTS（`max-age=31536000; includeSubDomains; preload`），可开 ECH；HTTP/3 |
| CDN ↔ 源站 | TLS + mTLS 客户端证书（或回源共享密钥），只放行 CDN 网段 |
| BFF ↔ service | 内网 mTLS + 服务令牌 |
| service ↔ PG/Valkey | TLS（`sslmode=verify-full` / `rediss://`），证书校验开启 |
| worker ↔ FTP 资源机 | 只用 FTPS 显式 TLS（数据连接 `PROT P`），证书按系统根证书校验、不提供跳过开关；连接前解析并校验目标 IP（`12` 第 9 节）。开发环境另允许不加密与隐式 TLS（本地资源机）；账号密码只注入 worker（`FTP_<凭据标识>_USER/PASSWORD`），不入库 |
| 浏览器 ↔ Go（经 BFF 透传） | TLS + 报文加密（第 5.3 节），BFF 只转发密文 |
| APP ↔ API | TLS + 证书公钥锁定（第 6.2 节）+ 请求签名（第 5 节）+ 报文加密（第 5.3 节） |
| 支付渠道 ↔ 回调 | TLS + 渠道签名验签（第 7.1 节） |

- Go 1.24 起 `crypto/tls` 在未指定曲线时默认启用 **X25519MLKEM768** 混合后量子密钥交换，Go 服务端保持默认即可。
- 证书私钥由 CDN/证书管理托管，源站内部证书由私有 CA 签发，90 天轮换。

## 3. 存储加密

### 3.1 基础层
- 云盘/数据库卷、对象存储（SSE-KMS）、备份文件全部加密；备份另用独立密钥加密后再上传到第二家对象存储。
- Valkey 不存 S3 级数据；会话只存不透明 ID 到用户的映射。

### 3.2 字段级信封加密（S2）
- 算法：AES-256-GCM，每条记录随机 96 bit nonce；关联数据（AAD）= `表名|列名|主键`，防止密文被挪到其他行使用。
- 结构：数据密钥（DEK）加密字段；DEK 由 KMS 中的主密钥（KEK）加密后存表 `crypto_key`（带版本）。实现采用 Tink Go 的 `aead` + KMS 封装，密钥集支持多版本并存。
- 存储格式：`v{key_ver}:{base64(nonce|ciphertext|tag)}`。
- 轮换：KEK 每年轮换；DEK 每 90 天新建版本，新数据用新版本，旧数据由后台任务逐步重加密。
- 查询：推送令牌等需要精确查找的字段另存**盲索引** `HMAC-SHA256(index_key, normalize(value))`，索引密钥与加密密钥分开管理。

### 3.3 密码与令牌
- 用户/管理员密码：Argon2id（`m=64MiB, t=3, p=2`，盐 16 字节），哈希串含参数，旧参数登录时透明升级。
- Refresh Token、API Key：只存 `SHA-256`（API Key 用 HMAC-SHA256 + 服务端密钥）。
- 不提供找回密码（`adr/0001`），因此没有恢复码、密码重置令牌。
- TOTP 种子：信封加密存储。

## 4. 身份令牌

| 令牌 | 形式 | 有效期 | 说明 |
| --- | --- | --- | --- |
| 用户 Access Token | JWT，EdDSA（Ed25519），头部带 `kid` | 15 分钟 | 只含 `sub/sid/role/exp/iat`；不放任何个人数据 |
| 用户 Refresh Token | 256 bit 随机串 | 30 天滑动 | 每次刷新轮换，旧令牌复用即吊销整个会话族 |
| 游客令牌 | 同 Access/Refresh 结构，`role=guest` | 180 天 | — |
| 后台会话 | 不透明 ID（Valkey） | 空闲 2 小时 / 绝对 7 天 | HttpOnly + Secure + SameSite=Strict + CSRF |
| 播放令牌 | HMAC-SHA256 签名的紧凑串 `kid.载荷.签名`（`internal/crypto/playtoken`） | 10 分钟 | 绑定分集、线路、设备哈希、试看秒数；不绑定 IP 网段（手机换网不中断播放） |

- 签名密钥轮换：每 90 天新增 `kid`，旧 `kid` 保留到最长令牌过期后删除；JWKS 只对内部服务开放。
- 校验时固定允许的算法（只接受 `EdDSA`），拒绝 `none` 与算法混淆。

## 5. 接口签名与报文加密

### 5.1 APP 请求签名
- 设备首次注册时，服务端在校验完整性证明后下发设备签名密钥 `device_secret`（32 字节），APP 存安全存储。
- 每个请求附带：

```
X-Device-Id:  <设备 UUID>
X-Timestamp:  <Unix 秒>
X-Nonce:      <16 字节随机 base64url>
X-Signature:  base64url(HMAC-SHA256(device_secret, canonical))

canonical = METHOD \n PATH \n SORTED_QUERY \n X-Timestamp \n X-Nonce \n SHA256(body)
```

- 服务端校验：时间窗 ±300s；`nonce` 在 Valkey 中 `SET NX EX 600` 去重；签名用常量时间比较。
- 签名的目的是提高批量伪造请求的成本、防重放，不作为唯一身份依据（密钥终究存在端上）。

### 5.2 开放平台签名
- 同样的签名串，密钥为 API Key 对应的签名密钥；可绑定来源 IP。

### 5.3 报文加密（用户端接口，必选，`adr/0002`）

**范围**：浏览器与 APP 发往 `/api/v1/*` 的全部请求。豁免：`/api/v1/health`、`/api/v1/crypto/keys`；SSR 阶段 BFF 经内网 mTLS 直连（带服务令牌、不带 `X-Bff-Proxy`）。`/api/admin/*`、`/open-api/*`、`/callback/*` 不在此列。`API_ENCRYPTION_REQUIRED` 未设置时 development 允许明文（方便 curl），其他环境强制，production 不允许关闭。

**算法**：HPKE（RFC 9180）base 模式，DHKEM(X25519, HKDF-SHA256) + HKDF-SHA256 + AES-256-GCM，`info = "xsite-api/v1"`。服务端 Go 标准库 `crypto/hpke`；Web 用 Web Crypto；APP 用 `cryptography`。三端测试使用 RFC 9180 官方向量与同一份互通样本（`service/internal/crypto/apienc/testdata/interop_v1.json`，Web、APP 各有相同副本）。

**一次请求**：
```
客户端：enc, ctx = SetupBaseS(服务端公钥, info)          # 每个请求新的临时密钥
       aad = "xsite-api/v1\n" + METHOD + "\n" + 路径?查询串 + "\n" + 时间戳
       tag = ctx.Seal(aad, "")                          # 序号 0：没有请求体也能校验路径与时间
       body = ctx.Seal(aad, 明文 JSON)                    # 序号 1：有请求体时
       X-Enc: 1.<kid>.<时间戳>.<base64url(enc)>.<base64url(tag)>
服务端：ctx = SetupBaseR(enc, 私钥[kid], info)；校验时间戳 ±300 秒 → Open(tag) → Open(body)
响应：  key = ctx.Export("xsite-api/v1 response", 32)
       响应体 = nonce(12) ‖ AES-256-GCM(key, nonce, 明文, aad = "xsite-api/v1 response")
       Content-Type: application/vnd.xsite.enc；X-Enc-Type: 原始类型；Cache-Control: no-store
```

- **不加密的部分**：方法、路径、查询串、HTTP 状态码（路由、限流、日志、CDN 回源需要）。它们由 AAD 绑定，改动即校验失败；敏感参数一律放请求体。
- **错误**：解密前的失败返回明文 `ENC_REQUIRED` / `ENC_INVALID` / `ENC_KEY_UNKNOWN` / `ENC_TIME_SKEW`；解密成功后 handler 的所有响应（含业务错误）都加密。客户端遇到 `ENC_KEY_UNKNOWN` 刷新公钥、`ENC_TIME_SKEW` 按响应 `Date` 校准时钟，各重试一次。
- **密钥**：`API_ENC_KEYS=kid:secret[,kid2:secret2]`，私钥由 secret 经 HPKE `DeriveKeyPair` 派生（多实例同一 secret 得到同一私钥）。第一把为当前密钥，其余只用于过渡期解密。
- **公钥分发**：Web 运行时从 `/api/v1/crypto/keys` 获取（同源，无法抵御能改写页面的中间人，Web 侧主要防抓包与批量抓取）；APP 正式包构建期预置当前与下一把公钥（`--dart-define=API_ENC_KEYS`），不在线获取。
- **轮换**（90 天）：新密钥先作为第二把上线并写入新版 APP → 新版覆盖到最低支持版本后调到第一把 → 旧密钥保留到最长请求窗口与旧版 APP 淘汰后删除。
- **缓存**：每个响应的密钥不同，加密响应不能被 CDN 或浏览器缓存；ETag 条件请求仍然有效（304 无响应体）。缓存收益由后端 Valkey / 进程内缓存承担（`08` 第 3 节）。
- **定位**：这一层提高抓包、篡改与批量抓取的成本；客户端代码可被逆向，鉴权、限流、风控仍是主要防线，不能因为「加密了」而放松。
- **性能**：服务端每请求一次 X25519 解封装 + AES-GCM，约数十微秒；浏览器 Web Crypto 每请求约 1 ms 内。响应无法再走 gzip/br 压缩（压缩后再加密存在 BREACH 类风险，暂不做）。

## 6. 端侧安全

### 6.1 Web（apps）
- 令牌只在 HttpOnly Cookie；不在 `localStorage`/`sessionStorage` 存身份信息。
- CSP 哈希模式、`frame-ancestors 'none'`、`object-src 'none'`、`base-uri 'self'`；关键第三方资源 SRI。
- 用户内容按纯文本渲染；富文本后端白名单清洗 + 前端 DOMPurify；自定义 HTML 只进沙箱 iframe。
- 写接口校验 `Origin` + CSRF 令牌。
- `/api/v1/*` 只用 `#lib/crypto/api-client.ts` 发送（第 5.3 节）；CSP `media-src` / `img-src` / `worker-src` 允许 `blob:`（视频 MSE、图片 blob 显示、hls.js Worker），`connect-src` 仅本站与媒体域名池。

### 6.2 APP（mobile）
- **证书公钥锁定**：锁定 SPKI 哈希，至少 2 个（当前证书 + 备用密钥或 CA 中间证书），带过期时间；iOS 用 ATS `NSPinnedDomains`，Android 用 Network Security Config `<pin-set>`。使用 `native_dio_adapter` 时需实测锁定在 Cronet/URLSession 下是否生效，不生效的平台改用 `IOHttpClientAdapter` 并在证书回调中校验。锁定集可随签名配置更新。
- **存储**：令牌、`device_secret` 存 Keychain（`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`）/ Android Keystore 支持的加密存储；drift 数据库不存 S2/S3 数据。
- **报文加密公钥**：构建期预置（第 5.3 节），与证书公钥锁定一起防中间人；`ENV=development` 之外不在线获取公钥。
- **播放回环代理**：只监听 `127.0.0.1`，随机端口 + 每会话随机令牌，离开播放页即关闭（`05` C.3）。
- **完整性**：Play Integrity（Android）与 App Attest（iOS）证明由服务端验证；RASP 检测 root/越狱、调试、Hook、模拟器、重签名，按策略「上报 / 降级 / 阻断」。
- **代码**：`--obfuscate --split-debug-info`、R8；不在包内硬编码任何服务端密钥（签名密钥运行时下发）。
- **隐私**：后台切换时遮挡敏感页面快照（「我的」页）；剪贴板只在用户操作时读写。

### 6.3 后台（admin）
- 二次验证（TOTP/Passkey），高敏操作重新验证；会话绑定 UA 摘要，IP 段变化时要求重新验证。
- 独立域名 + 访问控制；严格 CSP；`X-Robots-Tag: noindex`。
- 导出数据（看板、用户列表）默认脱敏，导出操作记审计。

## 7. 媒体内容保护

| 层级 | 措施 | 适用 |
| --- | --- | --- |
| L1 | 签名 URL（清单与切片），短有效期，边缘验签 | 全部内容 |
| L2 | HLS AES-128 加密，按集生成密钥（`key_ver` 支持轮换）；密钥接口校验播放令牌（分集与路径一致、设备哈希一致）、每设备每集每分钟 20 次、`no-store`（S1-8） | 默认开启 |
| L2+ | 清单与密钥只经报文加密接口下发（第 5.3 节；接口自己检查，明文一律 400 `ENC_REQUIRED`，不受 `API_ENCRYPTION_REQUIRED` 影响、SSR 直连也不放行）；Web 用 hls.js + MSE 播放，`<video>` 地址为临时 `blob:`；APP 经本机回环代理 | 默认开启 |
| L3 | 商用 DRM（Widevine / FairPlay，CMAF `cbcs`） | 有版权方要求时 |

- 密钥存储：内容密钥用 KMS 信封加密后存库（`media_key`），只在使用方内存中解密。每次转封装生成一把新的 16 字节密钥（`crypto/rand`），同一集各档共用、每个切片随机 IV；密钥不写盘、不经过 FFmpeg（加密在 Go 内完成，S1-5）。S2-8 接入 KMS 之前，包装密钥（KEK）由 `MEDIA_KEKS=kid:secret[,…]` 提供：KEK = HKDF-SHA256(secret)，AES-256-GCM，AAD 绑定分集与版本，密文带 kid 便于轮换（新 KEK 放第一把，旧的留到密文重新包装完）。重新包装用 `admintool rewrap-media-keys`（`14` 第 8 节）：只换外层密文、内容密钥不变，已有 HLS 产物不用重新转封装；本地库导入线上后的旧密钥也这样换成线上 KEK。
- 转封装产物：新上传为 MPEG-TS HLS，`s/` 下每个 `.ts` 切片均经 AES-128-CBC 加密并按密文哈希命名；清单与切片分属不同前缀，切片的目录前缀签名读不到原始清单（`12` 第 5 节）。历史 fMP4 的未加密 init 段仅为兼容已有产物保留。
- 试看：服务端只返回试看范围内的切片清单，客户端无法通过修改参数看到后续内容；VIP 集对非会员同样只返回试看清单。
- 图片：**不加密**（加解密拖慢列表加载）；Web 端 `fetch` 后转临时 `blob:` 地址显示，不在 DOM 中暴露 CDN 原地址，只是增加盗链成本，不是访问控制。真正需要保护的图片用签名 URL（L1）。
- 水印 [推断]：如版权方要求，可在转封装时加可见水印，或在播放器层叠加含会话标识的浮层。

### 7.1 支付安全（`03` 第 12 节）

- 到账只认服务端结果：渠道异步通知验签（支付宝 RSA2、微信 APIv3 平台证书 / 公钥）或主动查单、链上确认；前端跳转回来的参数一律不作为依据。
- 逐项核对商户号 / AppID、订单号、金额、币种、交易状态；`(channel, channel_trade_no)` 唯一约束保证重复通知只入账一次；金额不一致不入账并告警。
- 订单号随机不可推测；查单接口只允许本人；下单限流且未支付订单 ≤ 3。
- 凭据信封加密，后台只写不读；退款、补单、发放、迁移、改渠道凭据仅超管，需二次验证并审计。
- USDT：服务端只持有扩展公钥派生收款地址，私钥离线保管、离线签名归集；确认数达到阈值才入账；地址不复用。
- 回调原文信封加密保留 180 天，日志只记订单号与处理结果；每日对账发现差异告警。

### 7.2 福利与金币安全（`13` 第 6 节）

- 余额：只有钱包服务能改；`CHECK` 约束余额不为负；每笔业务一行流水；每晚对账，不一致冻结该账户出账并告警。
- 发奖：与来源事件同事务，`reward_grant` 唯一键去重；客户端不提交金额、概率与结果。
- 随机：抽奖用 `crypto/rand`；天天奖券承诺—揭示，种子加密保存、开奖后公开。
- 人工调整：超管 + 二次验证 + 原因；超过阈值需第二位超管复核；全部审计。
- 用户图片：直传到暂存桶（预签名 POST 限制类型与大小）；按文件头识别类型、像素上限防解压炸弹；去除全部元数据；不接受 SVG；未审核图片不可公开访问。
- 后台媒体上传：上传会话绑定管理员、用途权限、对象 key、MIME、精确大小与 15 分钟 TTL；浏览器只走后台同源 Cookie + CSRF 的流式接口，绝不获得存储凭据。图片完成时二次校验 WebP / AVIF 文件头；视频源仅在私有 `video/source/`，FFmpeg 子进程不继承数据库或存储凭据；审计只记会话、用途与状态，不记文件内容。
- 刷量：设备 / IP / 账号上限、预算、行为规则、审核队列、黑名单、全局暂停发奖。

## 8. 密钥管理

| 密钥 | 存放 | 轮换 |
| --- | --- | --- |
| KEK（字段加密主密钥） | 云 KMS / Vault Transit | 1 年 |
| DEK | 库内（KEK 加密） | 90 天 |
| 盲索引密钥 | KMS 托管 | 不轮换（轮换需重建索引，按需执行） |
| JWT 签名密钥 | 密钥管理下发到 service 内存 | 90 天 |
| 接口报文加密私钥（HPKE X25519，`API_ENC_KEYS`） | 密钥管理下发到 service 内存；公钥预置进 APP | 90 天，新旧并行，见第 5.3 节 |
| 支付渠道凭据 | 库内信封加密（`payment_channel.credential_enc`） | 按渠道要求（证书到期前更换） |
| USDT 收款私钥 | 离线设备，双人保管；线上只有扩展公钥 | 按需 |
| 媒体签名密钥 | 密钥管理 → service 与 CDN 边缘 | 90 天，双密钥并行过渡 |
| 播放令牌签名密钥（`PLAY_TOKEN_KEYS`） | 密钥管理下发到 service 内存；只有 API 进程签发与校验，不给 CDN 边缘 | 90 天：新密钥放第一把签发，旧密钥保留到它签发的令牌全部过期（10 分钟）后删除 |
| HLS 内容密钥 | 库内 `media_key`（KEK 包装；S2-8 前 KEK 来自 `MEDIA_KEKS`，由密钥管理注入 worker 与 API） | 每次转封装换新；KEK 1 年 |
| 域名清单签名私钥 | 离线设备（不联网），双人保管 | 1 年，客户端预置下一把公钥 |
| 回源 mTLS 证书 | 私有 CA | 90 天 |

- 应用通过工作负载身份（云 IAM / Vault Kubernetes auth）获取密钥，不使用长期静态凭证。
- 所有密钥使用与轮换记录写入审计，不记录密钥内容。

## 9. 日志与审计

- 日志字段白名单输出；请求体默认不记录；`Authorization`、`Cookie`、`X-Signature`、`X-Enc` 头一律剔除；支付回调原文不进日志。
- 金币人工调整、奖池与概率修改、返利释放与撤回、风控审核结果全部进审计哈希链。
- 后台审计日志带哈希链（`03` 第 9.8 节），每日链尾哈希写入只追加存储。
- 日志存储加密，访问需审批并留痕。

## 10. 供应链与开发安全

- 锁文件 + 冷却期（Bun `minimumReleaseAge`、pnpm 11 默认 1 天）+ 漏洞扫描（`govulncheck`、`bun audit`、`osv-scanner`）。
- CI：fork PR 不使用写权限的缓存与密钥；发布用 OIDC 短期凭证；产物 cosign 签名 + SBOM。
- 静态检查：Go `gosec`、`staticcheck`；前端 Oxlint/ESLint 安全规则；密钥扫描（gitleaks）在提交前与 CI 中各跑一次。
- 每年一次外部渗透测试；关键接口（登录、选源、密钥、报文加密、支付回调、后台）变更需安全评审。

## 11. 事件响应

| 事件 | 动作 |
| --- | --- |
| 疑似密钥泄露 | 立即轮换对应密钥，吊销相关令牌/会话，排查访问日志 |
| 数据库疑似被访问 | 隔离实例、保留快照取证、轮换 DEK 与数据库凭证、评估通知义务 |
| 依赖被投毒 | 锁定版本回退、全量重建产物、轮换 CI 中可能暴露的凭证 |
| 管理员账号异常 | 强制下线、冻结账号、复核审计日志中的写操作 |
