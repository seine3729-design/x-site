# 07 · 接口清单（API 索引）

三类接口按路径前缀区分（规则见 0.5）：前台（用户端）`/api/v1/*`（Web BFF + APP，**全部报文加密**）、运营后台 `/api/admin/*`（独立域名，不加密）、开放平台 `/open-api/*`（签名，不加密）；另有支付渠道回调 `/callback/pay/*`。
用户端 `/api/v1/` 之后的路径沿用参考站已验证命名（参考站为 `/api/<同名路径>`）；后台/开放平台为建议命名。业务规则见 `03`，签名与加密见 `10`，域名切换见 `09`。
契约以 `service/api/openapi.yaml` 为准，由它生成 admin（TypeScript）与 mobile（Dart）的类型。

## 0. 通用约定

### 0.1 响应包
- 成功：`{ "code": "OK", "message": "ok", "data": ... }`；失败：`{ "code": "<业务码>", "message": "...", "request_id": "..." }`。`code` 始终是字符串
- `message` 是中文兜底文案；Web / APP 按 `code` 显示当前界面语言（9 种），后台直接显示中文。
- 用户端接口下文描述的都是**解密后的明文**；网络上的报文格式见 0.4。
- 分页（游标）：`{ "list": [...], "next_cursor": "..." | null, "total": 123 }`；页码分页 `?page=&page_size=`（返回 `{ list, total, page, page_size }`）只用于前台频道页与后台列表（表格要显示总页数并跳页，第 2 节）。
- 时间 ISO 8601（UTC）；ID：内部实体用数字，会话/设备/任务用 UUIDv7 字符串。
- JSON 字段 snake_case；未知字段客户端忽略，服务端拒绝（`encoding/json/v2` 严格模式）。

### 0.2 请求头

| 头 | 端 | 说明 |
| --- | --- | --- |
| `X-Request-Id` | 全部 | 可选，客户端生成 UUIDv7 便于排查；服务端始终在响应回显 |
| `X-Device-Id` | Web、APP | 设备 UUID（客户端首次启动时生成并存在本机），用于广告频控与事件去重、选线种子；没有或不是 UUID 时服务端按「IP 网段 + UA 摘要」区分设备，只保存摘要。游客身份（S1-10）上线后改用游客令牌中的设备 ID。Web 经 BFF 转发时需把它加入转发白名单（W3-3 接入时） |
| `X-App-Version` / `X-Platform` / `X-Channel` | APP | 版本、平台、渠道包 |
| `X-Timestamp` / `X-Nonce` / `X-Signature` | APP、开放平台 | 请求签名（`10` 第 5 节） |
| `Authorization` | APP：`Bearer <access>`；开放平台：`ApiKey <key_id>` | Web 不用此头，走 HttpOnly Cookie |
| `X-CSRF-Token` | Web 写接口、后台写接口 | 双提交校验 |
| `X-Enc` | Web、APP（`/api/v1/*`） | 报文加密头 `1.<kid>.<unix秒>.<enc>.<tag>`，见 0.4 |
| `X-Enc-Type` | Web、APP（有请求体时） | 请求体原始类型，默认 `application/json` |
| `Accept-Language` | Web、APP | 当前界面语言（`zh-CN`/`en`/`es`/`vi`/`ja`/`ko`/`th`/`hi`/`ar`）；内容多语言启用前后端不区分 |
| `If-None-Match` | 全部 | 配置、详情等支持 ETag 条件请求 |
| `Accept-Encoding` | 全部 | `br, gzip, zstd` |

### 0.3 响应头
- `X-Request-Id`；限流 `RateLimit-Policy` / `RateLimit` / `Retry-After`；缓存 `Cache-Control` / `ETag` / `Vary`。
- 个人数据接口一律 `Cache-Control: private, no-store`。
- 加密响应：`Content-Type: application/vnd.xsite.enc`，`X-Enc-Type` 为原始类型，`Cache-Control: no-store`（每个响应的密钥不同，任何缓存都不能复用）；HTTP 状态码照常（401、404 等的响应体同样加密）；304/204 无响应体。

### 0.4 报文加密（`10` 第 5.3 节）
| 项 | 约定 |
| --- | --- |
| 算法 | HPKE（RFC 9180）base 模式：DHKEM(X25519, HKDF-SHA256) + HKDF-SHA256 + AES-256-GCM，`info = "xsite-api/v1"` |
| 公钥 | `GET /api/v1/crypto/keys`（明文）；正式 APP 构建期预置 |
| 请求 | 每个请求一次封装；`tag = Seal(aad, "")`，请求体 = `Seal(aad, 明文)`；`aad = "xsite-api/v1\n" + METHOD + "\n" + 路径?查询串 + "\n" + 时间戳` |
| 响应 | 密钥 = `Export("xsite-api/v1 response", 32)`，响应体 = `nonce(12) ‖ AES-256-GCM(明文, aad="xsite-api/v1 response")` |
| 明文 | 路径与查询串不加密（路由、限流、日志需要），由 AAD 防篡改；敏感参数放请求体 |
| 豁免 | `/api/v1/health`、`/api/v1/crypto/keys`；SSR 阶段 BFF 内网直连；`/api/admin/*`、`/open-api/*`、`/callback/*` |
| 协议错误 | 解密前发生，明文返回：`ENC_REQUIRED`、`ENC_INVALID`、`ENC_KEY_UNKNOWN`（刷新公钥重试一次）、`ENC_TIME_SKEW`（按 `Date` 校准时钟重试一次） |

### 0.5 路径规范（`adr/0007`）

| 前缀 | 调用方 | 鉴权 | 报文加密 | 版本 |
| --- | --- | --- | --- | --- |
| `/api/v1/*` | 前台：Web（浏览器经 BFF 透传、SSR 内网直连）、APP | 游客 / 用户身份 | 是（豁免见 0.4） | 路径带主版本号 |
| `/api/admin/*` | 运营后台 `admin/`（独立域名） | 会话 Cookie + Origin + CSRF + 权限点 + 审计（第 2 节） | 否 | 不带版本号 |
| `/open-api/*` | 开放平台调用方（S4-6） | API Key + 签名（第 3 节）；`/open-api/feedback` 例外，见第 6 节 | 否 | S4-6 接入时确定 |
| `/callback/pay/*` | 支付渠道 | 验签 | 否 | — |
| `/internal/*` | 部署探针（`/internal/ready`） | 不对外暴露 | 否 | — |

- **区分前后台**：前台接口一律以 `/api/v1/` 开头，后台接口一律以 `/api/admin/` 开头。`/api/` 下只允许这两个命名空间（以后的 `/api/v2/` 除外），新接口不能直接挂在 `/api/` 下；探活也在命名空间内（`/api/v1/health`）。
- **版本**：加字段、加接口等兼容改动留在 `v1`；删字段、改类型或语义等不兼容改动新开 `/api/v2/...` 与 `v1` 并行，旧版 APP 都低于最低支持版本（`GET /api/v1/app/version`）后再下线 `v1`。后台与后端同时发布、没有旧客户端，不带版本号；破坏性变更直接改，并在 `openapi.yaml` 的版本说明中记录。
- **命名**：资源用名词复数，多个单词用连字符（`/api/admin/admin-menus`、`/api/v1/me/local-merge`）；单个资源用 `/:id`；动作用资源下的动词子路径（`POST /api/admin/storage/lines/:id/test`）；查询参数与 JSON 字段用 snake_case（`?line_id=`、`page_size`）。
- **隔离**：后端 `/api/v1` 与 `/api/admin` 是两个独立的路由分组，后台分组不嵌套在 `/api/v1` 下，因此不经过报文加密。Web BFF 只透传 `/api/v1/*`，前台域名下的 `/api/admin/*` 与其他 `/api/*` 一律返回 404；网关按前缀回源：前台与 APP 接口域名只转发 `/api/v1/*`，后台域名只转发 `/api/admin/*`。
- **不改写**：路径与查询串参与报文加密的 AAD（0.4），BFF、网关、CDN 不能改写或重定向 `/api/v1/*` 的请求目标；调用方直接请求带 `/api/v1` 的完整路径。

### 站点与内容读取（建议命名，参考站走 SSR loader）

内容读接口（S1-4）只返回前台可见的内容（已上架、定时已到点、不在回收站），不可见时统一 404 `NOT_FOUND`；响应不含 `status`、`view_base`、`hot_score`、`media_status` 等后台字段，播放次数为 `play_count`。剧卡片里的 `badge`（角标）是**预设 id 或自定义文案**：预设 id 为 `hot`、`new`、`exclusive`、`trending`、`preview`、`free`、`finished`、`vip`，由客户端渲染配套样式、文案按用户的界面语言取（契约 0.66.0，`04` C.9、`06` 第 5 节）；其他取值按自定义文案原样显示，空串表示没有角标。排序为 `latest`（默认）/ `hot` / `recommend` / `random`（随机按 10 分钟稳定的种子打乱，只用于游标分页）；上新窗口 `all` / `7d` / `14d` / `30d` / `90d`；游标分页 `{ list, next_cursor, total }`，`cursor` 不透明、`limit` 1–60（默认 24），游标与本次 `sort` 不一致时 400。每个接口带 `ETag`（支持 `If-None-Match` → 304）与 `Cache-Control: public, max-age=0, s-maxage=<下表秒数>, stale-while-revalidate=300`；加密响应被强制为 `no-store`，`s-maxage` 只对 BFF 明文直连生效。

## 2. 运营后台 API `/api/admin/*`（建议命名）

统一需后台会话（HttpOnly Cookie）+ CSRF + 角色鉴权 + 审计。资源 REST 风格：`GET` 列表 / `POST` 创建 / `PATCH :id` / `DELETE :id`，批量 `POST :resource/bulk`。高敏操作标 🔐，需 5 分钟内重新验证二次因子。

- 会话 Cookie 开发环境为 `xs_admin`，其余环境为 `__Host-xs_admin`（`HttpOnly; Secure; SameSite=Strict`）；前端请求一律 `credentials: 'include'`。
- 写请求带 `Origin` 时必须在服务端 `ADMIN_ORIGINS` 中；登录后的写请求还要带 `X-CSRF-Token`（登录或 `/api/admin/me` 返回的 `csrf_token`）。不满足时 403 `FORBIDDEN`。
- 每个接口按权限点判定（`03` 第 2.5 节、`adr/0006`）：页面接口读要 `<页面>.view`、写要 `<页面>.edit`，无权限 403 `FORBIDDEN`。成功的写请求记审计。
- 登录失败统一 401 `NEED_LOGIN`「用户名或密码错误」；连续失败被锁定时 429 `RATE_LIMITED` + `Retry-After`；会话失效 401 `NEED_LOGIN`。
- 列表用页码分页（`?page=1&page_size=20`，`page_size` ≤ 100），数量少的配置类列表（维度与取值、分集、管理员、角色、菜单）一次返回全部。`PATCH :id` 是整体保存：未传的可选字段按新建时的默认值保存；新建与保存都返回保存后的完整记录（权限管理接口只返回 `id`）。
- 唯一键冲突返回 409 `CONFLICT`，`message` 说明是哪一项（如「slug 已被使用」）；引用的记录不存在（如给剧选的标签）返回 400。

## 5. 限流与缓存默认值

- 限流（每分钟）：页面 300、读 120、写 30、选源 60、认证 10、Bot 20；开放平台按 Key 配置。写接口无 `User-Agent` 直接拒。
- 缓存：加密响应一律 `no-store`，用户端 JSON 接口不能由 CDN 缓存，靠后端缓存（`03` 第 9.2 节）与 ETag 304；`03` 第 3.2 节的 `s-maxage` 只对 SSR 阶段 BFF 明文直连生效（BFF 进程内缓存与页面边缘缓存）。站点配置变更 `version+1` 作废旧缓存；个人数据与选源 `private, no-store`。
- 限流另有支付桶：下单每用户每分钟 10 次，未支付订单 ≤ 3；福利桶：每用户每分钟 60 次；上传桶：每用户每分钟 20 次。
- 福利、个人中心接口都是个人数据：`private, no-store`；`/api/v1/users/:id/card` 例外，可 `private, max-age=60`。

## 6. 反馈社区接口（另一产品，文档在 `feedback/docs`）

反馈社区与短剧平台共用这一个后端，但是独立产品：表前缀 `fb_`（迁移 `00012`），领域代码在 `service/internal/domain/feedback`，决策见 `feedback/docs/adr/0008`。本文件不重复它的端点清单。

| 内容 | 位置 |
| --- | --- |
| 接口契约（权威） | `service/api/openapi.yaml`（0.17.0 起，路径与 schema 前缀 `Fb`） |
| 开放提交接口的鉴权决策 | `feedback/docs/adr/0009-开放提交接口鉴权.md` |
| 接口语义与端点索引 | `feedback/docs/08-API契约与集成.md` |
| 后台页面与权限点 | `feedback/docs/07-运营后台与内容治理.md` |
| 数据模型 | `feedback/docs/03-领域模型与数据设计.md` |

与本文件第 0 节约定的差异（都写在 `feedback/docs/adr/0008`）：

- 前台 `/api/v1/feedback/*` 的会话走 `Authorization: Bearer`，不用 Cookie，因此没有社区用户的 CSRF 机制；H5 前台（`feedback/`，Next.js）经自身服务端带 `X-Service-Token` 转发，命中 `isInternalSSR` 豁免走明文，前台不实现 HPKE，也没有新增报文加密豁免路径。
- 后台 `/api/admin/feedback/*` 与本平台后台完全一致：Origin 白名单 + HttpOnly 会话 + CSRF + RBAC + 审计，权限点为 `fb_projects`、`fb_issues`、`fb_posts`、`fb_invites`、`fb_users`、`fb_topics`、`fb_api_keys` 的 `.view` / `.edit`。
- 前台列表用页码分页（`list/total/page/page_size`），不用本文件第 0.1 节的游标分页。
- **`POST /open-api/feedback` 不用第 3 节的签名方案**，改为 `X-Api-Key` + 密钥上的 `Origin` 白名单 + 配额（`feedback/docs/adr/0009`）。原因：这个接口要在站外网页的前端 JS 里直接调用，浏览器藏不住签名密钥。该路径免回源鉴权（登记在 `http.NewRouter` 的 `EdgeAuth.Exempt`），只能写入一条反馈、不提供任何读接口。第 3 节的服务端对服务端推送接口（S4-6）仍用签名。
