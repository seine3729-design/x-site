# 09 · 高可用与抗封锁方案

「防封禁」在本项目中指：**服务在单点故障、网络劫持、恶意流量和误拦截下仍可被正常用户访问**。本文覆盖域名、DNS、CDN、源站、客户端切换、防爬防盗链与灾备。

## 0. 范围与合规边界

**覆盖的风险**

| 风险 | 表现 |
| --- | --- |
| 单域名不可用 | 域名过期、注册商/DNS 服务商故障、被个别网络误拦截 |
| DNS 劫持/污染 | 本地 DNS 返回错误地址，用户打开仿冒页或连接失败 |
| 运营商劫持 | HTTP 页面被插入广告或脚本 |
| CDN 故障 | 单家 CDN 区域性故障或回源异常 |
| DDoS / CC 攻击 | 带宽打满、接口被刷 |
| 爬虫与盗链 | 播放地址被批量解析、切片被外站盗用，流量成本上升 |
| 应用被篡改 | 二次打包、注入广告或窃取数据 |
| 账号滥用 | 撞库、刷评论、刷量 |

**不纳入本方案的做法**（违反平台规则，一旦发现通常是永久封禁，风险远大于收益）：
- 对应用商店审核、搜索引擎、社交平台安全检测展示与真实用户不同的内容。
- 使用企业证书、「超级签」等方式向公众分发 iOS 应用。
- 冒用其他品牌、仿冒其他站点的域名或界面。

**合规是最稳的防封手段**：按运营地要求完成网站备案/许可、内容版权授权、未成年人保护和用户实名等义务（例如在中国大陆提供网络视听服务，需要相应许可与 ICP 备案，发布评论/弹幕前需完成真实身份认证）。`01` 第 6 节的相关开关按运营地配置。

## 1. 架构原则

1. **没有单点**：域名、DNS、CDN、证书、对象存储、数据库、运维账号都至少两套，并分属不同供应商。
2. **入口与源站分离**：用户只接触 CDN 入口；源站 IP 不对外公开。
3. **客户端自愈**：APP 与 Web 在入口不可用时能自动或半自动找到可用入口。
4. **清单可验证**：任何下发给客户端的「可用地址列表」都带签名，防止被劫持替换。
5. **可观测**：每次切换、每类失败都上报，问题在用户大面积感知前被发现。

## 2. 域名体系

### 2.1 域名角色

| 角色 | 数量建议 | 用途 | 公开方式 |
| --- | --- | --- | --- |
| Web 主入口 | 1 | 用户日常访问、SEO | 公开 |
| Web 备用入口 | 2–3 | 主入口不可用时使用 | 回家的路、APP 内 |
| 永久导航 | 1 | 长期不变的「找到我们」地址，托管在独立供应商 | 页脚、APP 内、社媒 |
| API 域名池 | 3–5 | APP 接口访问 | 只在 APP 与签名清单中 |
| 媒体域名池 | 每家 CDN 1–2 个 | 切片、封面（即存储线路，后台配置，见 `12`） | 只在选源结果中 |
| 后台域名 | 1 | 运营后台 | 不公开，叠加访问控制 |
| 支付回调域名 | 1 + 备用 1 | 支付宝、微信异步通知（`/callback/pay/*`），在商户平台登记，不随入口域名轮换；只放行回调路径 | 不公开；更换需同步修改渠道后台配置 |

### 2.2 管理规范

- 分散在 ≥ 2 家注册商、≥ 2 个顶级域；全部开启自动续费 + 注册商锁 + DNSSEC。
- 每个域名单独签发证书（ACME 自动化，准备两家 CA 作为后备），单张证书出问题只影响一个域名。
- 证书到期前 21 天告警；CAA 记录限定允许签发的 CA。
- 所有入口强制 HTTPS + HSTS；主入口提交 HSTS preload。
- 后台「域名与证书」模块（`06` 第 38 节）统一维护域名状态与健康度。

## 3. DNS 层

- **多 DNS 服务商**：主备两家权威 DNS，同步同一份区域数据（通过 API 或 IaC 推送），任一家故障不影响解析。
- **TTL**：入口记录 300s，便于快速切换；NS 记录保持默认。
- **防劫持**：
  - 全站 HTTPS + HSTS，劫持后的连接会因证书不匹配被浏览器拒绝，不会静默进入仿冒页。
  - APP 内对 API 域名优先使用 **DoH / HTTPDNS** 解析（按地区配置 2 家以上服务商），解析失败或超时（800ms）回退系统 DNS；结果按 TTL 缓存。用 IP 直连时，TLS 的 SNI 与证书校验仍按原域名进行。
  - 支持 ECH（RFC 9849）的 CDN 可开启 Encrypted Client Hello，减少连接元数据暴露；它依赖客户端与网络环境，只作为增益项。
- **监控**：多地区拨测各入口的解析结果，结果与预期 IP 段不符即告警。

## 4. 客户端入口切换协议

### 4.1 签名域名清单

后端提供 `GET /api/v1/app/domains`（同时以静态 JSON 形式发布到 ≥ 2 个独立对象存储/静态托管），内容：

```json
{
  "v": 42,
  "issued_at": "2026-10-21T08:00:00Z",
  "expires_at": "2026-11-20T08:00:00Z",
  "api":  [{ "host": "a1.example.net", "weight": 60, "region": "cn" },
           { "host": "a2.example.org", "weight": 40, "region": "*" }],
  "web":  [{ "host": "www.example.com", "role": "primary" },
           { "host": "m.example.net",   "role": "backup" }],
  "nav":  "https://go.example.dev",
  "sig":  "base64(Ed25519 签名)"
}
```

- 签名私钥只在离线签发工具（`service/cmd/keytool`）中使用；客户端内置 2 把公钥（当前 + 下一把），支持密钥轮换。
- 客户端校验：签名有效、`v` 不小于本地版本、未过期；任一不满足则丢弃，继续用本地版本。
- 包内置一份种子清单（构建时注入），保证首次安装离线可用。

### 4.2 APP 切换流程

```
启动 → 使用「上次成功域名」直接发请求（不阻塞首屏）
     ├─ 成功 → 记录延迟，后台静默刷新签名清单
     └─ 失败（DNS 失败 / 连接超时 3s / TLS 失败 / 连续 3 次 5xx）
           → 从清单中按权重取 2 个候选并行探测 /api/v1/health（各 2s）
           → 取最先成功者，持久化为当前域名，重放失败请求
           → 全部失败：指数退避（2s, 4s, 8s… 上限 60s），并尝试从静态托管拉取新清单
           → 仍失败：展示「回家的路」离线页（含永久导航地址）
```

- 熔断：单域名失败 3 次进入 5 分钟冷却。
- 证书锁定校验失败（疑似中间人）：不重试该网络路径上的同一域名，切换候选并上报 `pin_mismatch` 事件。
- 每次切换上报 `{from, to, reason, network_type, carrier, region}`，用于后台健康看板。

### 4.3 Web 侧

- 浏览器无法在不同源之间自动迁移会话；Web 的策略是**让用户能找到新入口**：
  - Service Worker 预缓存「回家的路」页面和最近一次校验通过的签名清单，主入口打不开时离线展示备用地址与永久导航。
  - 页面在后台低频探测备用入口（`/api/v1/health`，`no-cors` + 超时），在回家的路页显示可用性。
  - 页脚、APP 内、社媒固定展示永久导航地址。
- 多入口的 SEO：各入口 `rel="canonical"` 指向主入口，避免重复内容稀释权重。

## 5. CDN 与源站

### 5.1 多 CDN

- 至少 2 家 CDN 同时在线，按地区设置主备；用 DNS 权重或 GSLB 调度，健康检查失败自动摘除。
- 两家 CDN 的缓存规则、回源鉴权、安全规则用同一份 IaC 定义，避免配置漂移。
- 媒体线路与 CDN 一一对应，选源接口按线路健康度排序返回（`03` 第 4 节）。

### 5.2 源站保护

- 源站只接受 CDN 回源：安全组只放行 CDN 回源 IP 段 + 回源鉴权（mTLS 客户端证书或 `x-edge-secret`，后端中间件常量时间校验）。
- 源站 IP 不出现在任何公开 DNS 记录、错误页中；出站请求（FTP 资源机、推送、Webhook）走独立出口 IP。
- 历史上曾暴露过的源站 IP 直接更换。
- 源站与数据库在私有网络，数据库不开放公网。

### 5.3 DDoS 与 CC

- 带宽型攻击由 CDN/高防清洗；源站侧只承受回源流量。
- CC 攻击分层处理：
  1. 边缘 WAF：按 IP/ASN/国家/UA/JA4 指纹限速，命中规则返回挑战页。
  2. BFF/后端：Valkey 多维度限流（`03` 第 1.1 节）。
  3. 业务：登录、注册、评论、选源接口按设备和账号额外限流，异常时触发人机验证。
- 应急开关：后台一键开启「全站挑战模式」或关闭评论/弹幕等写功能，读功能和播放照常。

## 6. 防爬与防盗链

| 层 | 手段 |
| --- | --- |
| 播放地址 | 短期签名 URL（10 分钟，绑定设备哈希，可选绑定 IP 前缀）；切片边缘验签 |
| 内容加密 | HLS AES-128，按集密钥，密钥接口需播放令牌并限流（`10` 第 7 节） |
| 接口 | 用户端接口报文加密（HPKE，`10` 第 5.3 节），抓包代理看不到明文、改不了参数；APP 另有请求签名 + 设备完整性证明 + 预置公钥；Web 依赖 HttpOnly 会话 + 限流 + 行为特征 |
| 视频 | 清单与密钥只经加密接口下发，网页 `<video>` 为 `blob:` 地址，页面上拿不到清单与切片地址 |
| 图片 | 不加密；网页以临时 `blob:` 地址显示，DOM 中不出现 CDN 原地址（增加批量盗图成本，不是访问控制） |
| 行为识别 | 同设备短时间内跨大量剧集选源、无播放事件的选源、请求节奏过于规律 → 降级额度或要求人机验证 |
| 枚举防护 | 公开接口不返回可连续遍历的内部字段；列表深分页受限 |
| Referer/Origin | 媒体域名校验 Referer 白名单（辅助手段，可被伪造，不单独依赖） |

## 7. 应用防篡改

- 代码混淆（Dart `--obfuscate`、R8）、RASP（检测 root/越狱、调试器、Hook 框架、模拟器、二次签名）。
- 服务端校验 Play Integrity / App Attest 结果，被篡改或签名不符的客户端只能访问公开内容，不能写入、不能取高清源。
- 官网公布 APK 签名指纹，引导用户只从官方渠道安装。

## 8. 数据与服务灾备

| 项 | 目标 | 方案 |
| --- | --- | --- |
| 数据库 | RPO ≤ 1 分钟，RTO ≤ 15 分钟 | 同城流复制 + 异地异步副本；WAL 持续归档到另一家对象存储；每日全量备份加密 |
| 对象存储 | 关键数据跨供应商 | 切片与封面跨区域复制；原片冷备到第二家 |
| Valkey | 可丢失 | 只放缓存与可重建数据；会话丢失仅导致重新登录 |
| 配置 | 可快速重建 | 站点配置定期导出（`03` 第 9.3 节）；基础设施全部 IaC |
| 运维账号 | 防单点 | 云账号、注册商、DNS、CDN 均开启 MFA，至少两名管理员持有恢复凭证 |

- 每季度做一次演练：切换 DNS 服务商、摘除一家 CDN、数据库主备切换、从备份恢复到新环境。

## 9. 运维手册（摘要）

| 场景 | 处理 |
| --- | --- |
| 某入口在部分地区打不开 | 看健康看板确认范围 → 降低该域名权重或停用 → 签发新清单 → 观察切换率回落 |
| 某 CDN 区域故障 | GSLB 自动摘除；手动把该线路优先级降到最低；通知运营公告 |
| 遭遇 CC | 开启挑战模式 → 分析特征下发 WAF 规则 → 恢复 |
| 源站 IP 疑似泄露 | 更换源站 IP，更新 CDN 回源配置，排查泄露途径 |
| 证书即将到期且自动续签失败 | 切换备用 CA 签发，检查 CAA 与 DNS 验证记录 |
