# 06 · 运营后台功能设计（admin/）

技术栈：**React 19.3 + React Compiler 1.0 + Vite 8（Rolldown）+ TypeScript 7 + TanStack Router v1 / Query v5 / Table v8 / Virtual v3 + shadcn（CLI v4）+ Tailwind CSS 4.3 + Recharts 3 + Zustand 5 + react-hook-form 7 + zod 4**。保留现有骨架的通用组件（DataTable、表单、布局、命令面板），业务模块按本文档重建。

布局：左侧两级菜单（一级菜单默认是「运营数据看板」「剧集分析」两个页面和内容/框架/白标/运营/社区/系统/权限七个可展开的目录，福利目录随 A6-1 加入；侧栏收起时目录改为弹出菜单）+ 顶栏（面包屑、命令面板「跳转到…」拼音搜索、打开前台、深浅色、登出、收起侧栏）。侧栏由后端按「后台菜单」配置与当前角色权限下发（第 33c 节），只显示有查看权限的页面。侧栏宽 16rem（收起后为图标栏），二级菜单名称 9 个字以内完整显示，更长的省略显示、悬停看全名；一级、二级菜单都带图标，没有设置图标时按类型显示默认图标（目录 `Folder`、页面 `Circle`、外链 `Link`）。表单中每个输入框与下拉框都有占位提示，同一表单内的下拉框与输入框等宽、等高。

时间选择统一用 `components/date-picker` 的 `DatePicker`，**不用原生 `<input type="date|datetime-local|month">`**（原生控件各浏览器长相与语言都不一致，后台只用中文）。它的值是字符串、格式与所替代的原生 input 完全一致：`mode='date'` → `yyyy-MM-dd`，`mode='datetime'` → `yyyy-MM-ddTHH:mm`（本地时间），`mode='month'` → `yyyy-MM`；空串表示未选择。面板内自带「清除」与「今天 / 现在 / 本月」，`datetime` 模式右侧是时、分两列；范围筛选用 `min` / `max` 互相约束。表单里用 `features/content/components/fields` 的 `DateField`（运营模块另有 `DateTimeField`），工具栏里直接用 `DatePicker` 并传 `className='h-9 …'`。

弹窗（`Dialog` / `AlertDialog`，含命令面板）统一最大高度 `100dvh - 4rem`：内容超出时由弹窗正文区（`data-slot="dialog-body"` / `alert-dialog-body"`）自己滚动，右上角关闭按钮固定不动；内容不超高时弹窗仍按内容高度显示，不被拉满。各页面不要再单独写 `max-h-[90vh] overflow-y-auto`。弹窗里的下拉框会 portal 到弹窗内容元素上，所以该元素刻意不加 `overflow-hidden`，否则下拉面板会被裁掉。

登录页（`/login`）桌面为左右分栏：左侧是固定深色的品牌面板（站名、一句话定位、安全机制说明），右侧是账号密码表单与二次验证步骤；窄屏（< `lg`）隐藏品牌面板，只保留紧凑品牌行与表单。两种布局都显示提示「仅限授权人员 · 所有操作记入审计日志」。

> 后台**只用中文**，不接入用户端的多语言；`/api/admin/*` 不做报文加密（独立私有域名 + HttpOnly 会话 + CSRF + 二次验证已覆盖）。用户端的多语言与报文加密见 `04` A.4–A.5、`10` 第 5.3 节。

### 0.3 鉴权与请求层改造

现状问题：访问令牌存在 JS 可读的 Cookie（`JT_TRACK_ACCESS`）并以 `Authorization: Bearer` 发送，XSS 时可被直接窃取；`code === 1000` 时用 `window.location.href` 硬跳转。

目标：
- 会话改为后端下发的 `HttpOnly; Secure; SameSite=Strict` Cookie，前端不接触令牌；请求统一 `credentials: 'include'`。
- 写请求带 CSRF 令牌（登录后由 `/api/admin/me` 返回，存内存，不落盘）。
- 登录流程：账号密码 → 二次验证（TOTP 用现有 `input-otp`，或 Passkey）→ 进入后台；高敏操作弹窗重新验证。
- 请求封装职责：超时（默认 15s，`AbortSignal.timeout`）、统一错误映射（401 → 跳登录并带 `redirect`；403 → 403 页；429 → 按 `Retry-After` 提示）、`x-request-id` 回显到错误提示中便于排查。
- `auth-store` 只保存用户资料与权限列表，不保存令牌。
- 权限判定只用于显示控制，真正的权限校验在后端。

### 0.4 部署与访问控制

- 后台部署在独立私有域名（不出现在用户端任何页面、sitemap、robots 中），可叠加 IP 白名单或零信任网关。
- 静态资源走 CDN，`index.html` `no-cache`，带哈希的资源 `immutable`。
- 响应头：严格 CSP（`script-src 'self'`）、`frame-ancestors 'none'`、`Referrer-Policy: no-referrer`、`X-Robots-Tag: noindex`。

### 0.5 性能要点

- 路由级代码分割（`autoCodeSplitting`），首屏 JS ≤ 200 KB（br）；图表、富文本编辑器、CSV 解析、拖拽排序按路由懒加载。
- DataTable 统一服务端分页/筛选/排序，超过 100 行启用虚拟滚动；筛选条件同步到 URL 查询串（`use-table-url-state` 已有）。
- TanStack Query：列表 `staleTime` 30s，字典类（标签、维度、线路）`staleTime` 10 分钟；写操作后精确 `invalidateQueries`，常用写操作做乐观更新。
- 看板数据由后端预聚合，前端只渲染；大图表用 Canvas 渲染或抽样。
- CSV 导入预览在 Web Worker 中解析，避免卡住主线程。

### 0.6 迁移步骤

1. 依赖升级与工具链切换（React 19.3、Vite 8、plugin-react v6、Compiler、TS 7），`tsc -b` 与构建通过。
2. 合并 Radix 包、移除 Tremor/Clerk/crypto-js，替换图表组件。

## 一、概览组

### 1. 运营数据看板（`/admin`）
- **用途**：全站数据看板，按 9 板块叙事：①来访与来源 ②是否真看剧 ③看得深不深 ④留存 ⑤谁会注册 ⑥片库质量 ⑦收益 ⑧播放体验 ⑨福利（发放与消耗、成本、参与、邀请漏斗，详情见第 48 节经济看板）。
- **操作**：重算昨天的数字（手动汇总/重跑昨日定稿）、复制数据给 Agent 分析（打包数据+口径+提示词给 AI，生成给领导的摘要）、切换时间范围、点每部剧进单剧分析。
- **口径**：窗口=到昨天整天（北京时间）+等长前段对比；凌晨 3 点定稿；`watch_since` 后才计真实观看秒数；口径变更指标标「不与上一段比」；结果三态 ✓/!/✕。
- 指标清单见 `03` 第 10 节。

### 2. 剧集分析列表（`/admin/analytics/dramas`）
- **列**：每天看的人、开始看的人、平均看到第几集、看到第 3 集(%)、看完全剧。
- **筛选**：全部/要处理/好看但看的人少/新上架。**排序**：点列头。
- **操作**：进单剧分析、复制全部剧数据给 Agent。
- **阈值**：前 3 集留存 ≥~60%「好看」、≤bad「留不住人」、样本<min_sample 不下结论。

### 3. 单剧分析（`/admin/analytics/dramas/:id`）
- 指标：开始看的人、平均看到第几集、前 3 集留存、完播、追剧、评论、举报；每集留存曲线（每 100 人剩多少）、与全站均值对比、流失拐点（drop_peak_sec/drop_episode）、来源（含刷剧入口）、端占比、上架天数、热度排名。
- 操作：生成运营建议、跳对应集流失秒数、进剧集设置、复制该剧数据给 Agent。

## 二、内容组

### 4. 剧集列表（`/admin/dramas`）
- 搜剧名/别名 + 分页；筛选：上架状态、标签、维度取值。
- 状态：`已上架/草稿/已下架` + 「定时未到点」。
- 新建：剧名+简介→草稿。
- 批量：上架、下架、转草稿、打标签、加入专题（手选型）、设维度取值（多选追加/单选替换）。
- 规则：删除→回收站（30 天）；每剧有 `#ID`。搜索、筛选、排序与页码写在地址栏（刷新、分享后保持，换条件回到第 1 页）；多选只在当前页内。集数列显示「更新至 N 集 / 全 N 集」，只算可播放的分集，没有时为「暂无可播分集」。

### 5. 剧集编辑（`/admin/dramas/:id`，重点）
- **剧资料**：剧名、状态、角标（可空，见下）、评分、简介、竖封面（上传组件）、已完结；更多：别名、年份、横封面、排序值（推荐排序，越大越前）、初始播放量（热度排序与真实相加）、SEO 标题/描述、定时上架（可清除）。
- **角标**：下拉选预设（热播 / 新剧 / 独家 / 爆款 / 预告 / 限免 / 完结 / 会员，选项里直接显示前台的配色小样）或选「自定义文案」自己填（≤ 16 字）。选预设存的是预设 id，前台有配套配色与图标、文案按用户的界面语言显示（9 种语言，`04` C.9）；自定义文案只显示填写的这一种语言。老数据里手填的「热播」「独播」「HOT」等写法会被识别成对应预设，再保存时统一成预设 id。
- **标签**：搜标签、只看已选、多选。
- **维度取值**：搜取值、不限、按维度多选/单选、停用取值提示。
- **分集**：搜集号/标题；新增字段=集号、标题（可空）、封面上传、时长（秒）；每集设「谁能看」（免费/登录可看/VIP）与「可试看秒数」（不超过时长）。视频通过独立上传按钮选择文件，按服务端给的 5 MiB 分片 6 路并发上传到私有入库桶（单片失败按 1/2/4/8 秒退避自动重试，最多 5 次；会话过期、片长不符这类 4xx 不重试、直接提示原因），传完自动提交 HLS 转封装；列表显示没有视频 / 转封装中 / 可播放 / 转封装失败。
- **分集的两段进度**：上传与转码各 0–100%，必须都能看到 —— 大视频上传要几分钟、转码更久，只给一个「处理中」运营无法判断是在走还是卡住了。上传阶段显示「正在分片上传 x（n 片，最多 6 路并行，单片失败自动重试）」、百分比 + 「已传 x / 共 y · 速度 · 预计剩余」（速度样本不足 1 秒时只显示字节数，避免数字乱跳；进度 = 已确认送达的分片 + 在传分片的字节，某片失败重传时如实回退）；上传完成后按该集的转封装任务（`GET /api/admin/transcode-jobs/:id`，每 2 秒）显示「正在转码为 HLS… n%」，结束时提示完成、沿用旧产物（`skipped`）或失败原因。关掉上传弹窗后，分集列表自己按任务进度（每 3 秒）在「转封装中」后面显示百分比，并在有分集在转码时自动刷新列表。
- 操作：分别保存剧资料/标签、新增/删除分集、后台试播单集（第 37 节）、放回收站、看数据。
- 规则：封面只使用上传组件生成的 `img/` 相对 key；图片选择后在浏览器统一压缩为 WebP、质量 0.92、最长边 2400 px（0.92 在封面这类图上肉眼看不出与原图的差别；更低的质量会在渐变与文字边缘出现可见块状噪点。AVIF 的 canvas 编码主流浏览器不支持，前台 AVIF 由 CDN 实时转，见 `08`）。**原图已经是不超尺寸的 WebP 且比重编码结果更小时直接上传原文件**（不再编码一次，真正无损）。上传器显示「原图 x → WebP y（省 z%）」，压完反而变大时如实显示「大 z%」，运营据此判断要不要换图。定时上架需状态=已上架且到点。各分区有未保存的修改时，离开页面或切换分区前提醒。搜标签、列出维度取值要有「标签」「筛选维度」的查看权限，没有时对应选择禁用并说明原因（维度取值分区只列出本剧已选的取值）。

### 6. 演员（不做）
- 不提供演员管理，剧集也不维护演员表（`11` S1-3a）。保留本节编号，以免后续章节的引用错位。

### 7. 标签（`/admin/tags`）
- 搜名称/slug；字段：名称、slug、隐藏（敏感标签：过年龄门才显示、不被收录）。状态正常/隐藏。
- 操作：新建、保存、并入别的标签（合并，显示「已并入 #ID」）。

### 8. 批量导入（`/admin/import`）
- CSV 批量导入**剧**。CSV 列：剧名、别名、简介、标签 —— **不含分集**：这四列里推不出集号也推不出视频来源，分集靠资源机扫描（第 31 节）或开放平台推送带入。页面上要把这点写明，免得运营以为分集也会进来。
- 输入：选 CSV（上传）+ 来源标识（选填，写进剧的 `source` 便于追溯这批是哪来的）。第一行要是表头，列名认中英文多种写法；要 UTF-8（Excel 用「CSV UTF-8」另存，BOM 会被自动去掉）；一次最多 2000 行、1 MB，超出让运营拆分文件。别名与标签在单元格内可用中英文逗号、顿号、竖线、分号、斜杠分隔。
- 操作：先预览（不写入、不留记录）、正式导入（带二次确认，写明会新增几部、新剧是草稿、更新只补充哪些字段）。**换了文件要重新预览**：否则会看着旧预览导进新文件。另提供 CSV 模板下载。
- 预览逐行列出处置与原因：新增 / 更新（说明按剧名还是别名匹配到哪部剧，可点进去）/ 跳过（没填剧名、文件内重复）/ 被拒（命中屏蔽词），每种在页面上有中文说明；会自动新建的标签标出「（新）」。
- 统计：总行数、新增剧、更新剧、跳过、被拒、新建标签。（新增分集/更新分集两项在 CSV 场景恒为 0，字段保留是为了让三种采集来源共用同一套统计口径，页面上不展示。）
- 记录：仅记正式导入，可按日期区间筛（按浏览器时区换算，「今天」是用户的今天）。
- 规则：新增剧为草稿；命中屏蔽词不导入（剧名、别名、简介都查，采集**只认 block 类**词，mask 与 review 在这里不生效）。查重按**剧名或别名**双向匹配，**回收站里的剧也算已存在** —— 否则会建一部同名的新剧，把运营刚删掉的东西又带回来。**更新只覆盖 CSV 带来的那几列**：别名取并集、简介留空表示不改，封面、评分、状态、上架时间都不动，标签只追加不删。整批一个事务：出错就什么都没发生，不会一半进去一半没进。
- **未做**：「填服务器路径」。它会引入任意本地文件读取的风险（路径穿越、读 `.env` 与密钥），容器化部署下本地路径对运营也不可见；上传文件已覆盖需求。

### 9. 资源体检（`/admin/resource-checks`）
- 批量检测视频产物与封面的可达性，逐个对象去读。筛选：剧编号、只看打不开、搜剧名/编号；条件写在地址栏。**不分页**，最多 200 条 —— 体检是「扫一遍找出坏的」的工具，运营的用法是筛「只看打不开」逐条去修；超出上限时提示还有多少没显示，让他缩小范围。坏的排在最前。
- 查的是**资源在不在**，不是线路好不好（后者在「选线预览与健康」页）。整条线路挂了这里会全红，那种情况该去看线路健康，不是在这里逐条排查。
- 检哪些：剧的竖封面、横封面；每集的本集封面、首帧图、当前视频产物（HLS 产物探主清单 `master.m3u8`，并把产物目录作为签名前缀，和播放时一致）。空字段与还没转封装的分集跳过 —— 没填与没产物都不是资源故障。
- 类型：视频/封面。结果：正常/404/拒绝访问/服务器错/打不开/连不上，每种在页面上有中文说明（图例）。列：剧集（链到剧集编辑）、资源（类型·字段 + 地址）、结果 + 状态码、说明、线路、耗时、体检时间；行尾可打开剧编辑或在新窗口打开该地址。
- 概览：已体检多少个资源、打不开多少个、最近体检时间。缺某类线路时在页面顶部提示（那类资源会被跳过，不会被误记成「连不上」）。
- 操作：开始体检（全部剧，可勾「含未上架」；或指定一部剧）、清空结果（某剧/全部，带二次确认）。发起后由后台任务按剧逐部跑，不用守着页面。
- 规则：仅清体检表不动源文件；只读源站，不改动任何文件；同一个资源只留最后一次的结果（重复体检是更新，不会让表随次数膨胀）；入库的地址不含签名材料。

### 10. 资源预热（`/admin/resource-warm`）
- 提前把清单与起播的几个切片拉一遍，让边缘先缓存住，观众点开就不用等回源。参数：某剧/全部已上架、仅播放列表/连画面片段（默认后者）、每清晰度片数（1–20，默认 2 ≈ 8 秒起播）、并发集数（1–16，默认 4）、含未上架。
- 预热拉的是**播放器真正会请求的那些地址**：后台复用播放链路取清单，不自己拼地址 —— 签名方式或路径一旦有偏差，边缘缓存的就是另一个地址，预热白做。
- 两层缓存被热到的东西不一样，页面上要说清楚：**切片**走边缘长缓存（按内容哈希、`immutable`），这是预热的正主；**清单**是加密接口、不进边缘缓存，预热它热的是服务端的清单原文缓存，省掉回源读清单那一跳。只拉清单的模式流量极小，但起播体感改善有限。
- 进度：集数进度条与百分比、当前在热什么、热好/有问题/拉取量/流量/开始时间/用时；状态预热中/已完成/已停止/已中断，每种在页面上有中文说明。有问题的资源数可点进「资源体检」页逐条排查（预热拿不到的地址会写进体检结果）。
- 操作：开始预热（选范围与深度）、停止（已热算数，带二次确认写明「缓存里的东西不会退回去」）。
- 规则：同时仅一轮（库里的部分唯一索引保证，冲突报 409）；可关页面回来看进度（进度存库不存内存）；预热进程失去响应超过 5 分钟判定为已中断，不会一直挂着挡下一轮；未上架的剧要勾「含未上架」才会被预热 —— 明天要上的剧提前热好，上架那一刻观众点开就是热的。
- 进度推送用 SSE（`?stream=1`），代理不透传时自动降级成轮询。

## 三、框架组

### 11. 筛选维度（`/admin/taxonomies`）
- 探索页分面筛选条。维度字段：名、slug、状态、可多选/单选、显示在探索页、顺序（拖拽）。
- 取值字段：名、slug、状态、设为频道（独立频道页）、编号（区块/专题引用）。
- 操作：新建维度/新增取值/编辑/删除/调序。规则：取值停用→前台筛选条消失且频道页 404。

### 12. 前台菜单（`/admin/menus`）
- 位置：顶部导航 / 手机底栏 / 手机侧边抽屉 / 页脚。按位置分组显示，一次加载全部（菜单条数很少）。
- 链接类型：站内页（首页 / 刷剧 / 探索 / 排行 / 专题 / 搜索 / 我的 / 回家的路）、静态页、频道、专题、标签、外部网址。填静态页 / 频道 / 专题 / 标签时填对应的 slug，保存时校验目标存在（可以指向草稿，发布后自动出现）。
- 字段：位置、名称（≤ 20 字）、链接、页脚分组标题（只有页脚有）、图标（lucide 图标名）、底栏图标（只有手机底栏有）、角标（≤ 6 字）、谁能看（所有 / 已登录 / 未登录）、设备（全部 / 手机 / 电脑）、新窗口。状态启用 / 停用。
- 操作：新增（排在该位置末尾）/ 编辑（改位置时移到新位置末尾）/ 删除（不可恢复）/ 调序（拖动、方向键或上移下移，按位置分别保存）。
- **防丢地址「回家的路」**（同页，走同一组权限点）：提醒文字、最新 / 永久 / 备用地址（≤ 3）、发布页、客服链接、Telegram、社交账号（名称 + 链接，≤ 10 个）。只收 http(s) 完整地址；保存后站点配置版本 +1，前台秒级生效。
- 规则：菜单与防丢地址都随 `/api/v1/site-config` 下发，改动即时生效。链接目标不可用时**前台自动隐藏该项、后台列表标出原因**（静态页删除或改回草稿、频道取值停用或取消「设为频道」、专题草稿、标签隐藏或已合并），记录保留，目标恢复后自动出现。手机底栏最多 5 项（只算启用的，满了时提示）。「谁能看」与「设备」由前台判断（站点配置是共享缓存的公共数据，不按身份裁剪）。

### 13. 静态页（`/admin/pages`）
- 搜标题 / slug，按状态筛选（条件写在地址栏）。列表显示标题、slug（可复制前台地址）、格式、是否页脚页、状态、最后修改时间。
- 字段：标题、slug（小写字母、数字、连字符，全站唯一，决定前台地址 `/p/:slug`）、正文、SEO 标题 / 简介、标记为页脚页、状态（草稿 / 已发布）。
- 正文一律用富文本编辑器（工具栏：段落样式、加粗 / 斜体 / 下划线、有序 / 无序列表、引用、链接），运营不写 HTML 源码；粘贴内容转纯文本，避免编辑所见与保存结果不一致。保存时按白名单清洗（脚本、样式表、iframe、表单与事件属性会被去掉，站外链接自动加 `noopener` 并新窗口打开），保存后回显清洗结果。后端 `body_format` 字段保留（前台按它渲染），后台统一存 `rich`；历史上存为 `html` 的页面被富文本编辑器打开、再次保存后统一为 `rich`（两种格式后端用同一套白名单，统一无损）。
- 正文图片通过上传组件生成 `img/static_page_image/...` 后自动插入 `<img>` 标签，不提供图片地址输入框；运营可在正文中补充有意义的 `alt` 文本。
- 操作：新建 / 编辑 / 删除（不可恢复）。规则：草稿不对前台下发（`/p/:slug` 返回 404）；标记为页脚页且已发布的会出现在前台页脚「帮助与条款」；删除或改回草稿后，指向它的前台菜单项自动隐藏。

### 14. 专题（`/admin/topics`）
- 搜标题/简介/slug；字段：标题、状态（草稿/发布）、简介、slug、剧来源（手选/规则自动）、FAQ、列在专题列表页。
- 手选：按剧名搜索添加，或填剧编号（逗号隔开=展示顺序）；拖拽排序。规则：手选保存整份替换（未填被移出）。按剧名搜索要有「剧集」的查看权限（填编号不受限）；规则自动的取值、标签分别要「筛选维度」「标签」的查看权限。

### 15. 页面区块编排（`/admin/blocks`）
- 先选要编辑的页面（首页 / 某个启用的频道页），页面选择写进地址栏，刷新或分享链接回到同一页面。
- 区块类型：轮播大图/精选大卡/海报网格/横滑列表/排行榜/专题组/标签云/广告位/公告条/自定义HTML（要「自定义 HTML」权限 `blocks.custom_html`，默认只有超管）。
- 字段：类型、标题（≤50 字）、副标题（≤100 字）、数量（1–60，默认 24）、状态、查看全部链接、电脑每行个数（2–8，默认 6）、设备、自定义 HTML 正文（清洗）。
- 剧类来源：手选编号（按填写顺序显示）/用某专题（自动专题沿用它的规则）/自动选（维度取值编号交集、单标签、排序 最新/最热/推荐、上新 不限/7d/14d/30d/90d）。排行榜选榜单、广告位选位置、公告条选方式（顶部滚动条/弹窗）、专题组与标签云可指定编号（留空分别取「列在专题列表页」的专题与热门标签）。
- 操作：新增/编辑/删除/拖拽调序（调序传该页面全部编号，别人刚增删过时 409 提示刷新）。单个页面最多 50 个区块。
- 规则：非剧类区块不需要来源；每种类型只保存自己用得到的参数（换类型后旧参数不会残留）；手选的剧必须存在且不在回收站（可以是草稿，发布后自动出现）；下架、定时未到点与回收站里的剧前台不显示；列表类区块当前没有内容时前台整块不显示。增删改与调序后前台立即生效（该页面缓存即时清除）。删除不可恢复（不进回收站），操作记审计 `block.create` / `block.update` / `block.delete` / `block.reorder`。

## 四、白标组

### 16. 品牌与主题（`/admin/brand`）
- 品牌：站名（必填，≤30 字）、口号、版权（页脚）、客服链接（完整 http(s)）、头部 Logo（空=站名文字）、favicon。Logo 与 favicon 填上传后的图片路径（如 `img/logo.webp`）或完整地址。
- 配色：皮肤预设（经典红/午夜蓝/墨绿/紫调/中性灰）、深浅色（默认深/浅/跟随）、允许访客切换、各颜色（主色/强调色/页面背景/卡片背景/正文/次要文字，`#RGB` 或 `#RRGGBB`，留空用预设色）、卡片圆角（0–32px）、封面比例（2:3/3:4/16:9）、字体（系统/衬线/圆体）。
- 布局：页头样式（经典/居中/胶囊）、卡片（标题在封面下/压封面上）、播放形态（手机沉浸+桌面详情/全沉浸/全详情）、手机底栏开关。
- 含前台实时预览；各段分别保存（三个 PUT），保存后站点版本 +1、前台几秒内生效。
- 规则：下拉的可选值由后端随 `GET /api/admin/brand` 下发，前端不另抄一份；枚举与色值一律白名单，写错直接报错而不是静默兜底（配色或布局错了全站都会歪）。没保存过的段按默认值显示：深色、经典红、2:3 封面、经典页头、标题在封面下、手机沉浸 + 电脑详情、显示底栏、允许访客切换深浅色（与前台 `normalizeTheme` 的默认值一致，前台外壳本来就带这个开关）。`docs/specs/A3-3.md`

### 17. SEO 与统计（`/admin/seo`）
- 分页面标题/描述模板：覆盖 home/list/play/rank/drama/topic/search/channel/tag，单条 ≤120 字，留空表示该页用前台默认。
- 模板变量（点击插入）：站名、口号、剧名、简介、总集数、第几集、频道名、专题名、标签名、数量、搜索词、榜单名。页面与变量清单由后端随 `GET /api/admin/seo` 下发；模板里出现未登记的 `{变量}` 直接报错（否则前台会把 `{dramaTitle}` 原样显示在标题里给用户看）。
- 收录与分享：允许收录（robots_allow）、提供 sitemap、输出结构化数据、分享图 og_image、站长验证（多组 name+content，≤10 组，名称不区分大小写去重、名称与内容必须成对）、robots.txt 追加（≤2000 字）。没配置过时默认「允许收录 + 提供 sitemap + 输出结构化数据」。
- 统计代码（仅超管）：head_snippet、body_snippet（放 `</body>` 前），各 ≤20000 字。保存后几秒生效。
  - 读写都要 `seo.analytics_code`（没有权限的人连现在埋了什么都看不到），走单独的 `GET/PUT /api/admin/analytics-code`，不混在 SEO 的响应里。
  - **不做 HTML 清洗**：这段代码就是要原样注入页面的第三方脚本，清洗掉 `<script>` 就失去意义；控制手段是「仅超管可改 + 审计记前后全文 + 长度上限 + 前台 CSP（`04` 第 12 节）」。与广告素材、静态页正文的「白名单清洗」路线有意不同。`docs/specs/A3-3.md`

## 五、运营组

### 18. 广告位（`/admin/ads`）
- 搜广告名/跳转网址；按位置、状态筛选（条件写在地址栏）。列表显示广告名、位置、素材、投给谁与投放语言、出现机会、每天上限、曝光 / 点击 / 点击率（每分钟更新）、结束时间、投放中 / 已结束 / 已停用。
- 位置 slot：全站弹窗、首页顶/中/底横幅、页脚横幅、列表信息流、详情页横幅、播放前贴片、暂停贴片、沉浸流插入、文字链、App 下载浮窗。选了位置后表单显示该位置的建议尺寸（如首页顶部约 4:1、沉浸流 9:16、播放前贴片 16:9 视频 5–15 秒）。
- 素材类型：图片（上传图片 + 说明）/视频（上传视频 + 上传封面 + 说明）/文字（≤ 200 字）/自定义HTML（要「自定义 HTML」权限，默认只有超管；保存时清洗，清洗后的结果回显在表单里）。图片在上传前统一压缩为 WebP；视频上传后异步转为 HLS m3u8，完成前不能保存为视频素材。
- 字段：广告名、位置、素材类型与素材、跳转网址（站内路径或 http(s) 地址）、投给谁（手机和电脑 / 只投手机 / 只投电脑）、出现机会（权重 1–100，默认 10）、每天次数上限（每台设备每天，0 = 不限）、投放语言（不选 = 全部语言；需要多语言时按语言各建一条）、结束时间（不填 = 一直投放）。状态投放中/停用。
- 操作：新建（即时生效）/编辑/删除（不可恢复，曝光点击一起删除；暂停请改停用）。没有「自定义 HTML」权限时，新建的素材类型里没有自定义 HTML，HTML 素材的编辑按钮禁用并说明原因（删除只要「修改」权限）。
- 规则：多数位置须在区块加「广告位」区块并选 slot；同一位置按权重随机，频控按设备、按天（北京时间）计曝光。

### 19. 公告（`/admin/announcements`）
- 搜内容/网址；按类型、状态筛选。
- 类型：顶部滚动条、弹窗、站内信（暂不启用）。频率：每次/每人一次/每人每天一次。
- 字段：方式、内容、跳转、出现页面（所有/指定）、投放语言（不选 = 全部语言；需要多语言时按语言各建一条）、频率、弹窗配图上传（约 16:9，只有弹窗有）、定时开始/结束。图片上传前统一压缩为 WebP，状态启用/停用；列表按启用状态与起止时间显示「显示中 / 未开始 / 已结束 / 已停用」。
- 操作：新建（即时）/编辑/删除（不可恢复，暂停请改停用）。规则：多条弹窗前台只弹一条（最新的）。

### 20. 资讯（不做）
- 不提供资讯（文章与分类）；前台、APP 与搜索都没有资讯（`11` S3-7）。保留本节编号，以免后续章节的引用错位。

### 21. 排行干预（`/admin/ranks`）
- 榜单：剧集周榜 / 月榜，前台各显示前 20 名。页面上切换榜单（写在地址栏 `?board=`，人工调整有未保存的修改时先确认）。
- 计分系数（两张榜共用）：播放一次、追剧一次、点赞一次、看完一集各自的系数，0–1000、最多两位小数，默认 1 / 3 / 2 / 2；追剧、点赞、看完的数据接入前按 0 次计。
- 人工调整（每张榜最多 100 部剧）：按剧名搜索或按编号添加（没有「剧集」查看权限时只能按编号）；每部剧选「置顶 / 不让上榜 / 加分 / 减分」并填加分（负数为减分；置顶的也可以加减分，决定多部置顶之间的先后；不让上榜不计分）。剧不在前台显示（草稿、已下架、在回收站）时标出「不上榜」，调整保留。整体保存 / 还原。
- 线上榜单与预览：线上榜单是前台正在显示的前 20 名（带排名时间）；预览按已保存的系数与调整现算前 20 名，标出置顶与相对线上的名次变化（↑↓、新上榜），与线上不同时提示要重新排名。
- 操作：马上重新排名（两张榜一起，最多等 5 秒，没等到时提示稍后自动完成）。规则：改调整 / 系数后须重新排名才生效（后台每 5 分钟也会自动重新排名）；多部置顶之间按分数；不让上榜只影响该榜。只读角色能看到全部内容，控件禁用并说明原因。

**封禁的三重生效**（`11` 的 S2-7「封禁即时踢下线」）。Access Token 是无状态 JWT（15 分钟），光改状态挡不住它，所以三件事都要做：
1. 登录被拒（`domain/user.Login` 查 status）；
2. 吊销该用户的全部会话（`identity.RevokeAllSessions`，原因 `banned_by_admin`）——
   不做这步，30 天滑动有效的 Refresh Token 还能一直轮换，封禁只挡住了登录入口；
3. 发评论/弹幕的前置校验把 banned 一并拦下（`UserMuted` 查 `status IN ('muted','banned')`）——
   不做这步，手上那张最多还活 15 分钟的 Access Token 仍能发言。

禁言与恢复正常不吊销会话：禁言只限制发言，不该顺带把人踢下线。
状态已落库但吊销会话失败时接口返回错误提示重试（重试会重新吊销），不当成功返回 —— 那就回到了封禁半失效的状态。

**本期范围说明**（S2-7 / A2-2）：
- **删除/放回收站未接入**。平台回收站（§31）的仓储接口七个方法都写死了剧的分类（`ListTrashedDramas` / `RestoreDrama` / `PurgeDrama` / `TrashCounts` 等），加「用户」分类要先改签名做分派；
  而弹幕表没有 `deleted_at`，用户的弹幕无法随账号软删一起还原。两件事混在一起会让本切片的验证范围过大，单独排期做。
- 游客只读。`guest_device` 没有账号状态列也没有回收站列，要限制游客参与互动请用站点的「游客互动」功能开关，不是逐个设备处置。
  游客列表走独立路径（`GET /api/admin/guests`，共用 `users` 权限点）：游客与注册用户的字段差太多，塞进同一个列表接口会让一半字段恒空。
- 详情里的会员状态（到期时间、订单入口）、会员等级与成长值、金币余额（入口到金币账户）、邀请关系（邀请人、有效邀请数）、风控标记要等

### 28. 缓存（`/admin/cache`）
- 清缓存范围：站点设置（全站，version+1）、首页、列表、剧详情、播放、专题、排行、运营下发（公告/广告/热搜词）、全部。剧详情/播放需填编号。
  - 「全部」还会清会员状态与按客户端缓存的套餐读缓存；不会改动 `user_vip`、`vip_ledger` 等持久化权益数据，后续读取会自动回源。
  - 「搜索」暂不提供：搜索结果目前没有缓存（搜索功能随 S3-4 实现），列出来清了也没有意义。
  - 「播放」清的是分集 HLS 清单原文的读穿缓存（按该剧各分集当前产物的目录）；转码产物本身不可变，一般只在换存储源或副本异常后才需要清。该剧还没有产物时返回「没有暂存内容」，不算错误。
  - 「排行」只清榜单的下发缓存，不动榜单本体（本体由 worker 每 5 分钟重算，清掉要等下一轮才恢复）。
- 展示暂存量（键总数与内存占用）、站点版本、键前缀。规则：清「站点设置」令 version+1 作废旧缓存（改品牌/菜单/主题后前台没变时用）。
- **只清白名单内的读穿缓存前缀**。后台会话、登录失败计数、各类限流计数、尚未落库的广告曝光与搜索次数、线上榜单本体都是有状态数据，页面上按「不可清」列出并写明原因（清掉会让人掉线、重置限流额度或丢统计），任何范围都不会动它们。新增缓存要同步登记到白名单（`service/internal/domain/platform/cachekeys.go`），否则清不到。

### 29. 配置导出导入（`/admin/config`）
- 导出：下载备份（安全，只要查看权限）。导入：选文件/粘贴→导入并覆盖（危险，需二次确认；校验格式版本与签名）。
- 备份内容：菜单、静态页、区块、维度、广告素材（各显数量）+格式版本。规则：导入前先备份；成功后 5 秒生效；勿手改备份。
  - 当前实际只覆盖**筛选维度（含取值）与广告素材**，备份里菜单、静态页、区块仍是空数组。这三张表与接口已随 S3-1 / S3-2 落地（`menu`、`page`、`block`），把它们填进导出导入是 S4-4 / A4-2 的剩余工作，填上时不必升格式版本。
  - 广告不含曝光与点击计数：那是运行期统计（worker 从 Valkey 累加落库），写进备份再导回去等于把统计回滚到导出那一刻。
- **两类数据的写入策略不同**，页面上要讲清楚：
  - **筛选维度是合并更新**：按标识匹配，备份里有的新增或覆盖，备份里没有的**保留不删**，数量与名称在导入结果里列出，需要时去「筛选维度」页手动删。原因是取值被剧集引用（`drama_term` 外键 `ON DELETE CASCADE`），删一个取值会静默清掉所有剧集对它的归属而且不报错 —— 报错会回滚，级联会成功提交。
  - **广告素材是整表替换**：`ad` 没有外键进出，可以安全重建；代价是曝光与点击计数归零。
- 签名：备份文件是明文 JSON（要能人工检视），用 HMAC 签名保证没被手改过。密钥来自 `CONFIG_BACKUP_KEYS`，格式版本一并参与签名（否则可以只改版本号把新备份伪装成旧版本）。配了密钥就必须验签；没配密钥时也不接受带签名的文件（无法校验，不能假装通过）；两边都没有时放行，供本地开发。
- 备份存档：每次导出、每次导入或回滚前都在库里留一份（`config_backup` 表），列表显示来源、各类数量、有无签名与时间，可下载或一键回滚。**从存档回滚不验签** —— 存档一直在本库里、没离开过系统，要求它带签名会让「刚启用签名」或「轮换过密钥」之前的存档全部失去回滚价值，而那恰恰是出事时最需要的几份；下载下来再上传仍然按文件导入验签。

### 30. 存储源与线路（`/admin/storage/*`，仅超管可改）
- **存储源**：支持 AWS S3（及 S3 兼容云存储）、Cloudflare R2、自定义（自建 S3 兼容 / HTTP 源）；配置桶、Endpoint、凭据（只写不读，加密存储）、用途（视频/图片）、角色（主存储/镜像/只读）；一键连通性测试。
- **线路**：一个存储源可挂多条线路；配置访问域名、访问方式（预签名直连/CDN/公开）、签名方式、有效期、优先级、权重、**地区规则**（国家/省份/运营商/ASN，包含/排除/加分）。
- **选线预览**：输入任意 IP 查看会返回的线路顺序与得分明细；线路 × 地区健康看板。
- **存储设置**：候选线路数量、默认有效期、智能选线、主存储、上传后自动复制、GeoIP 数据库版本。页面顶部显示**交付自检**：主存储上没有可用线路时，上传、转码与复制全部显示成功，前台却拿不到线路、播放提示「暂无可用线路」；自检把这种落差直接报出来并给出「去配置存储线路」入口（`docs/12` 第 8.4 节）。
- **存储运维**（存储设置页底部，需 `storage_settings.edit`）：
  - 手动补副本：范围选全部 / 指定剧集 / 指定存储源，把内容复制到全部镜像；任务幂等，已就绪的镜像跳过，可重复触发。
  - 迁移存储源：选迁出源与迁入源，先复制到迁入源、确认就绪后撤掉迁出源的副本记录；**不删迁出源上的文件**，因此可逆，副本清零后该存储源才能删除。建议先把迁出源设为停写。需二次确认。
  - 接管历史产物：给没有副本记录的旧产物补登记，后台先校验文件真实存在，校验不通过的跳过。
  - 清理孤立产物：展示已标记 / 已过保留期 / 占用空间 / 保留期时长；先点「预览」（`dry_run`，不动数据），没有已过保留期的产物时「立即清理」禁用；确认框标注不可恢复。
  - 这四个操作都只是入队，实际搬运与删除由后台任务执行，界面上报告入队数量。
- 规则：任何变更令 `site.version` +1；无可用线路时前台取不到视频/图片。完整字段与页面见 `12` 第 8 节。

### 30a. 支付渠道（`/admin/payment/channels`，仅超管可改）

### 30b. 对账（`/admin/payment/reconcile`）
- 按日、按渠道展示：系统已支付笔数与金额、渠道账单笔数与金额、差异明细（长款/短款/状态不一致）；差异处理后标记「人工确认」。

### 31. 资源机 FTP（`/admin/ftp`）
- 管理 FTP 并扫描入库。搜名称/地址；按状态（启用/停用）筛选。搜索、筛选与页码写在地址栏。
- 列表列：名称、地址:端口、加密方式（非显式 TLS 的标黄提示）、凭据标识（旁边的钥匙按钮打开「凭据配置」）、状态。
- 添加字段：名称、地址（域名或 IP）、端口（默认 21）、加密（不加密/显式TLS/隐式TLS，默认显式 TLS；非开发环境只能选显式 TLS）、被动模式（只支持被动模式，固定勾选）、凭据标识（留空自动生成）、状态。账号密码（服务器配）：不在后台填写，页面显示两个标识名（如 `FTP_HK1_USER`、`FTP_HK1_PASSWORD`），由技术在 worker 的密钥管理中配置；改凭据标识后要重新配置。
- 流程：①测连→②打开目录→③查新剧（预览对比，只看不入库）→④入库（已有不重复建）。可指定目录。①② 随 S1-6 完成，③④ 随 S4-6。
- 测连逐步显示「解析地址 → 建立连接（含 TLS）→ 登录 → 读取目录」每一步的结果与耗时，失败的一步给出原因；打开目录显示实际路径与条目（目录在前，最多 1000 条，超出提示已截断），可点进子目录。由 worker 执行，最长等 25 秒；只需「查看」权限，停用的资源机也能测。
- 规则：入库命中屏蔽词被拒；重复不重复建；新入库为草稿；③④针对当前目录；连不上把两个标识名发技术配账密。地址解析到内网或保留地址时非开发环境拒绝连接。

### 32. API Key（`/admin/apikeys`）
- 搜用途、使用方或开头几位，可按启用状态筛选；条件与页码写在地址栏。仅存开头 10 位与 SHA-256 哈希，完整密钥仅生成时显示一次 —— 列表、审计、服务端日志都取不回来，丢了只能重新生成一把。
- 权限范围：推送剧集入库、只读运营数据（页面上带中文说明，清单由后端下发）。字段：用途/给谁用。状态：可用/停用/未用过（启用中但从未被调用，常见于刚生成还没交付）。
- 操作：生成、改用途与使用方、停用（即时失效，带二次确认）、重新启用、复制。生成后弹出一次性密钥，勾选「我已经把密钥保存好了」才能关闭。
- 规则：供采集程序对接（消费端是 S4-6 的采集入库）。**权限范围生成后不可改** —— 改范围等于改已经在调用方手里的密钥能做什么，要调整就重新生成一把、换掉旧的。**没有删除**：停用即时失效已经够用，留着记录才能回答「这把密钥曾经存在、被谁用过」。和社区的「接口密钥」（`/admin/feedback/api-keys`）是两套互不相干的东西。

### 33. 管理员（`/admin/admins`，「权限」目录）
- 搜用户名；按角色、状态筛选；列：用户名、角色、状态（可登录/停用/未登录过）、二次验证、最近登录、创建时间。
- 新建：用户名（3–32 位，不区分大小写）+ 初始密码（8–128 位，不能与用户名相同）+ 角色。操作：改角色/状态、重置密码、强制下线（全部会话立即失效）；重置二次验证在 S2-6。
- 规则：不能操作自己；超管账号与超管角色只有超管能操作；至少保留一个可用的超管；已停用的角色不能分配。重置密码只针对后台管理员，前台用户不提供（`adr/0001`）。超管必须开启 TOTP 或 Passkey（S2-6）；其他角色由超管决定是否强制。

### 33a. 角色（`/admin/roles`，「权限」目录）
- 列：名称与编码、说明、成员数、权限点数（超管显示「全部」）、状态、内置/自定义；操作：编辑、配置权限（打开「角色权限」并选中该角色）、删除。
- 系统只内置超级管理员；其余角色按需新建。新建：编码（2–32 位小写字母开头，创建后不能改）、名称、说明、状态、排序；新角色没有任何权限。
- 规则：超管角色不能删除、停用或改权限；有成员的角色不能删除；停用角色后其成员不能登录、已登录的立即下线。

### 33b. 角色权限（`/admin/role-permissions`，「权限」目录）
- 左侧是角色列表（成员数、已停用、我的角色），右侧是所选角色的权限树，按菜单结构排列：一级页面直接列出权限点；目录可展开，下面是二级页面；每个页面一行，行尾是该页的权限点（「查看」「修改」及单独授权的操作，标「高敏」的 S2-6 起操作需重新验证）。
- 目录与页面的勾选框有三态：全部授予为勾选、部分授予为横线；勾选目录即授予其下全部页面的全部权限点。工具栏：搜索（按菜单、权限点名称或编码过滤）、展开全部 / 折叠全部、全选 / 全不选。
- 改动先暂存，显示「已授予 N / 共 M 个权限点 · 已修改 K 处」，修改过的权限点高亮；点「保存」整体保存该角色，「放弃修改」还原；有未保存修改时切换角色或离开页面会提示。地址带 `?role=<ID>`，可直接打开某个角色。
- 规则：勾选某页面的任一权限点自动勾上「查看」，取消「查看」一并取消该页其余权限点；超管角色全部勾选且不可改；非超管不能改自己所属的角色，只能授予或收回自己拥有的权限点（其余勾选框不可用并说明原因）。
- 页面之间的关联选择用对方页面的读接口：例如编辑剧集要搜标签、列出维度取值，给编辑剧集的角色同时授予「标签」「筛选维度」的查看权限（批量加入专题还要「专题」）；缺少时页面中对应的选择禁用并说明原因。

### 33c. 后台菜单（`/admin/admin-menus`，「权限」目录）
- 侧栏分一级菜单和二级菜单：一级菜单是目录、页面或外链，二级菜单是目录下的页面或外链。默认一级菜单为「运营数据看板」「剧集分析」两个页面和内容 / 框架 / 白标 / 运营 / 社区 / 系统 / 权限七个目录。
- 列表为可展开的两级表格：菜单名称（图标、名称、目录下的菜单数、内置 / 已隐藏）、类型（目录 / 页面 / 外链）、层级（一级 / 二级）、地址、页面编码（即权限点前缀）、排序（同级上移 / 下移）、显示开关、操作（目录可「添加外链」、编辑、删除）。目录默认收起，可展开全部 / 折叠全部。
- 页面由系统提供，只能改名称、图标、上级目录（可提为一级菜单）、排序与显示；可新建目录（只能是一级）与外链（http/https，新窗口打开，对所有管理员显示，不选上级目录时为一级菜单）。
- 规则：内置菜单不能删除（可隐藏）；目录下还有菜单时不能删除；隐藏菜单不等于收回权限，直接访问地址仍按权限判定；没有可见二级菜单的目录不显示。前台站点的导航在「前台菜单」（第 12 节）中配置，与这里无关。

### 34. 审计日志（`/admin/audit`）
- 记录所有后台写操作含改动前后对比。搜人名/操作/对象；筛选动作/对象/操作人/日期。
- 对象约 32 种（管理员/角色/后台菜单/剧/分集/标签/维度/取值/专题/菜单/静态页/区块/广告/公告/排行/热搜/评论/弹幕/举报/用户/屏蔽词/表情/表情包/线路/资源机/体检/APIKey/缓存/站点设置/文件/导入/统计）。筛选下拉按**实际出现过的**动作与对象动态生成（带条数），不写死清单。
- 规则：改动按系统原字段名记（英文，给技术）；密码/密钥原文不记（字段名含 password / secret / token / credential / api_key 等，或以 `_enc` / `_hash` 结尾的，值写入前替换为 `***`）。
- **本页只读**：没有新建、修改或删除接口，权限点只有 `audit.view`。列表里动作同时显示中文说明与原始编码（如「新建筛选维度」+ `taxonomy.create`），便于运营看懂、技术排查。
- **完整性校验**（页面右上角「校验完整性」）：每条记录带上一条的哈希，改动或删除任何一条都会让链断开，校验会指出第一处异常是哪条、是「内容被改动过」还是「中间有记录被删除或插入」。
  - 这挡的是「改完库再抹掉痕迹」，挡不住有数据库权限的人写入全新记录 —— 那需要把哈希定期外发到别处对账。
  - 启用哈希链（迁移 00026）之前的历史记录没有哈希，不参与校验，列表里标为未接入链，校验结果里单独报告数量。
- 日期筛选按浏览器所在时区转成带时区的时间戳再查询，所以「今天」是用户的今天，不是服务端 UTC 的今天。

### 35. 回收站（`/admin/trash`）
- 按分类查看，显示到期时间（今天/N天/随时清）。操作：还原（30 天内）、彻底删除（不可撤销）。
- 规则：设置类（菜单/广告/专题等）不进回收站，误删看审计重建；删用户连带评论进。
- **当前只有「剧集」一类**：只有 `drama` 实现了软删（`deleted_at`，迁移 00004）。用户随 A2-2 接入，其余内容模块各自实现软删后在 `service/internal/domain/platform/trash.go` 的分类表里登记即可。
- 列表显示删除前的状态（还原后恢复成它）、附带内容条数（剧集为分集数）、删除时间与到期时间。剩余天数**向上取整**：还剩半天显示「1 天」而不是「今天到期」，宁可让人觉得时间比实际多一点，也不要让人以为已经来不及了。剩余 3 天内的用醒目样式标出。
- **还原**：清掉删除标记。分集与标签、维度取值、专题关联一直保留着，所以还原后内容完整。超过保留期但清理任务还没跑到的也允许还原 —— 东西还在，能救就救。
- **彻底删除**：物理删除，不可恢复。分集与标签 / 维度 / 专题 / 排行干预关联级联删除；分集引用的转码产物随之失去引用，由孤立产物清理任务（`docs/12` 第 5 节）按自己的保留期回收存储上的文件，**这一步不删文件**。删除前读出的标题与附带条数会记进审计 —— 物理删除之后库里查不到了，出问题只能靠审计回溯。
- 保留期由 `TRASH_RETENTION` 配置（默认 30 天），过期内容由 worker 的 `trash_cleanup` 任务每天物理删除，被删的编号与标题记进 worker 日志。

### 36. 功能开关与年龄门（`/admin/features`）
- 功能开关：评论、弹幕、开放注册、游客互动、排行、分享海报、添加到主屏幕(PWA)、搜索联想。每项附关闭影响说明。
  - 开关清单由后端给出（`service/internal/domain/platform/features.go`），不在前端写死；关闭影响说明也放后端 —— 开关的实际行为由后端决定，两边分开写必然漂移。
  - **开启直接生效，关闭要二次确认**并展示该项的关闭影响：关功能是会影响线上体验的操作。
  - 未设置过的开关按打开处理，只有明确 `false` 才算关闭：这样新增开关不会因为老配置里没有而默认关掉功能。
  - 保存时剔除已废弃的键。建表时写入过 `articles`、`actors`，对应模块已在迁移 00010 / 00014 删除，留着会让页面长出已经不存在的功能。
- 年龄确认门：开关、标题、说明文字、确认/拒绝按钮文字、拒绝跳转、重复间隔。保存后几秒生效。
  - **启用时标题与两个按钮文字必填**：开着的年龄门挡在所有访客前面，文案缺失会让人看到无法操作的空白弹层。关闭时允许留空，可以先把文案存成草稿再启用。
  - 拒绝跳转要填完整的 http(s) 网址（挡掉 `javascript:` 这类），留空则停留在当前页并保持遮挡。重复间隔 0–365 天，0 表示每次打开都确认。
- 两段配置分开保存（改开关不影响年龄门），都存在 `site_config` 里，保存后令站点版本 +1 并广播失效，各端几秒内生效。

### 37. 试播/预览（剧集编辑页「分集」里的试播弹窗）
- 入口不另开页面：剧集编辑页分集列表每行一个试播按钮，只有 `media_status = ready` 的分集可点（其余按钮禁用并说明「这一集还没有可播放的视频」）。弹窗内显示第几集/标题/谁能看/可试看/用的哪条线路，用 hls.js 播放（按需动态导入，Safari 走原生 HLS）。
- 地址来自 `POST /api/admin/episodes/:id/preview`（需 `dramas.view`），配套 `GET /api/admin/preview/:token/:file` 与 `GET /api/admin/preview/key/:episode_id/:key_ver`。这三条走后台会话、**不加密**（前台 `/api/v1/hls/*` 强制报文加密，后台播放器给不出密文），清单改写、线路签名与内容密钥与前台复用同一条链路 —— 试播通过才说明产物与线路真的可用。
- 与前台刻意不同的三处：不判观看权限、**不按 `trial_sec` 裁剪**（看完整的一集）、允许试播未上架的剧（运营要在上架前先验）。预览令牌由 `PLAY_TOKEN_KEYS` 按另一个用途派生，与前台播放令牌互不通用，有效期十分钟，过期点「重新获取地址」。
- 没有可用的视频线路时接口返回 503，提示先到「存储 - 线路」为主存储配置并启用视频线路；十几秒没有画面时提示可能是产物路径不对或这条线路连不上。

### 38. 域名与证书（`/admin/domains`，新增，仅超管可改）
- 管理入口域名池：域名、角色（Web 主入口/备用/永久导航/API/媒体）、权重、适用地区、状态（启用/观察/停用）、所属 CDN、DNS 服务商、证书到期日。
- 健康看板：各域名按地区的探测成功率、APP/Web 上报的切换次数与失败原因分布（DNS 失败 / TLS 失败 / 连接超时 / 5xx）。
- 操作：调整权重或停用某域名 → 生成新版域名清单 → 由离线签名工具签名后上传发布（后台不保存签名私钥）；查看历史版本与回滚。
- 证书：入口证书由部署层 ACME（certbot）自动签发（`09` 第 2 节），后台只维护到期日与到期前 21 天告警。另提供「手动生成 SSL 证书」：用标准库现场签出自签证书（EC P-256 / RSA 2048），私钥仅在生成时下载一次、服务端不保存，用于源站回源 mTLS、本地 / 测试 HTTPS 或 certbot 应急占位（浏览器不信任自签证书，不用于公网入口）；也可上传一张已签发证书，解析其到期日回填到对应域名。
- 规则：证书到期前 21 天告警；停用域名后清单版本 +1，客户端下次启动或探测失败时更新。详见 `09`。

### 39. 安全中心（`/admin/security`，新增）
- 管理员登录记录（时间、IP、设备、结果）、异常登录告警。
- 密钥轮换记录（JWT 签名密钥、媒体签名密钥、字段加密密钥版本），只展示版本号与时间，不展示密钥内容。
- 风控概览：限流命中 Top、被标记为异常的设备数、人机验证触发次数。

### 42. 签到与等级（`/admin/welfare/checkin`、`/admin/welfare/levels`）
- 签到：7 日奖励、补签卡规则、提醒文案。

### 43. 天天奖券（`/admin/welfare/tickets`）
- 期次列表：日期、领取人数与张数、`commit`、截止摘要、开奖种子、中奖号码与发放状态；开奖异常（未按时开奖）告警。
- 配置：领券途径与上限、奖项与人数、开奖时间。

### 44. 任务（`/admin/welfare/tasks`）
- 任务：分类、触发事件、目标值、周期、奖励、是否受等级倍率加成、客户端范围、「去完成」跳转、多语言名称与说明、上下线时间、排序。
- 统计：各任务完成率与领取率。第三方任务墙服务商（P4）为超管配置 🔐。

### 45. 推广返利（`/admin/welfare/referral`）
- 规则 🔐：新人礼包、有效邀请条件与奖励、返利比例、冻结天数、上限与预算。
- 审核队列：命中风控的绑定与有效邀请（显示同设备 / 同 IP 段 / 同 UA 等证据），通过或判无效。
- 返利记录：冻结中 / 已到账 / 已撤回，可手动释放或撤回（超管，需填写原因）。
- 邀请排行（只读，用于发现异常）。

### 46. 金币商城、优惠券、装扮（`/admin/welfare/mall`、`/coupons`、`/cosmetics`）
- 商城：商品（分类、奖励、价格、等级折扣、库存、限购、可用金币类型、上下架、多语言、图片）、兑换记录、冲正 🔐（退回金币并收回物品）。
- 优惠券：模板（类型、面额、门槛、封顶、适用套餐、有效期）、定向发放（按用户名列表，需二次验证）、使用统计。
- 装扮：头像框、勋章、昵称颜色、弹幕样式素材上传与预览。

### 47. 金币账户（`/admin/welfare/wallets`）
- 搜用户名：余额（赠送 / 充值）、批次与到期、流水（按类型筛选）、对账状态。
- 人工调整 🔐：增加或扣减（必填原因与关联工单）；单笔超过 10,000 金币进入待复核，由另一位超管批准后生效；全部审计。

### 48. 经济看板（`/admin/welfare/economy`）
- 每日发放 / 消耗 / 过期（按来源）、未到期余额（参考负债）、每 DAU 成本、各活动成本与参与、商城兑换、返利；与预算对比，超预算标红。

### 49. 风控（`/admin/welfare/risk`）
- 黑名单（用户 / 设备 / IP 段，可设到期）、风控审核队列（高价值奖品、可疑邀请、异常任务）、规则阈值（只读展示，修改走配置）。
- 应急「暂停发奖」🔐：一键暂停所有发奖，前台显示「活动维护中」。

### 50. 精选晒图（`/admin/welfare/photos`）
- 晒图活动的参与记录：审核通过的带图评论、点赞数；操作：评为精选（发精选奖励）、取消精选、下架。
