# 11 · 开发任务拆解与本地开发环境

本文把 `03`–`10` 的设计拆成可排期的开发任务，并说明本地 Docker 开发环境的用法与各端接入约定。

## 1. 约定

- **编号**：`X` 跨端/基础设施、`S` 后端 service、`W` 前端 apps、`A` 运营后台 admin、`M` APP mobile。编号形如 `S2-3` = 后端第 2 里程碑第 3 项。
- **估时**：人天，按 1 名熟悉该技术栈的工程师计，含自测与单元测试，不含联调等待。
- **完成标准（全部任务通用）**：代码合入主干、CI 通过（构建 + lint + 测试）、接口与 `service/api/openapi.yaml` 一致、相关文档更新。下表「验收」列只写该任务特有的标准。
- **人员假设**：后端 2、Web 1、后台 1、APP 2、测试 1。人员变化时按依赖关系重排，不改任务边界。

## 9. 本地开发环境（Docker）

### 9.1 一键启动

```bash
./dev.sh up            # 基础设施 + apps + admin + service（service/go.mod 存在时）
./dev.sh up infra      # 只起数据库等依赖，前端/后端在宿主机直接跑
./dev.sh up --obs      # 额外启动 Jaeger 链路追踪
./dev.sh up --ftp      # 额外启动本地资源机（FTP），供后台「资源机 FTP」测连与打开目录
./dev.sh help          # 全部命令
```

首次运行会从 `.env.example` 生成 `.env`，所有 `change-me` 自动替换为随机值（文件权限 600，已加入 `.gitignore`）。之后 `.env.example` 新增的变量会在下次执行 `./dev.sh` 时自动补进已有的 `.env`（已有的值不动）。首次启动需要拉镜像、编译 pg_bigm、安装前端依赖，约 3–5 分钟；之后秒级启动。

| 可信代理 | `TRUSTED_PROXIES`（逗号分隔网段） |
| 迁移 | `AUTO_MIGRATE=true` 时 api 启动执行 Goose、worker 启动执行 River 迁移；production 禁止开启，发布前由 `admintool migrate` 依次执行 Goose 与 River 官方迁移 |
| 数据库 | `DATABASE_URL`（读写）、`DATABASE_RO_URL`（只读） |

| 转封装（worker，S1-5） | `MEDIA_TRANSCODE_CONCURRENCY`（默认 0 = 不消费 `media` 队列；compose 的 worker 为 1）、`MEDIA_TRANSCODE_TIMEOUT`（单次尝试，默认 `1h`）、`MEDIA_X264_PRESET`（默认 `veryfast`）、`MEDIA_WORK_DIR`（默认系统临时目录）、`MEDIA_SOURCE_BUCKET`（源文件桶；compose 中为 `${S3_BUCKET_ASSETS}`，production 不能与图片桶相同）、`MEDIA_KEKS`（内容密钥的包装密钥，compose 中为 `dev1:${MEDIA_KEK_SECRET}`）、`FFMPEG_PATH` / `FFPROBE_PATH`。启用时缺配置、FFmpeg 不可用或缺 `libx264`、`libwebp` 编码器 worker 启动失败 |

| 配置导出导入（S4-4） | `CONFIG_BACKUP_KEYS`（配置备份的签名密钥 `kid:密钥[,…]`，compose 中为 `dev1:${CONFIG_BACKUP_SECRET}`）：备份文件是明文 JSON，用 HMAC 签名保证没被手改过。留空时导出不签名、导入也不验签（本地开发），**非开发环境必须配置**，否则任何人构造一份备份都能导进来覆盖维度与广告。从库里的存档回滚不验签（数据没离开过系统） |

### 9.5 前端与 APP

- **apps**：容器内执行 `bun install --frozen-lockfile && bun run dev`，读取 `apps/.env.development`；新增的 `SERVICE_INTERNAL_URL=http://service:8080` 由 compose 注入。宿主机直接开发时用 `./dev.sh up infra` + `cd apps && bun run dev`。
  - 图片 / 视频线路域名**不需要在本地配**：它随 `/api/v1/site-config` 的 `media` 段从后台线路表下发（契约 0.77.0，`04` F）。`apps/.env.development` 的 `IMAGE_BASE_URLS` 留空即可，它只是补充（后台把封面 / Logo 填成不在线路表里的完整地址时才需要）。
  - 图片缩放 `IMAGE_RESIZE_ORIGINS`（`08` 第 5 节）本地留空：localhost 前面没有 Cloudflare，`/cdn-cgi/image/` 不存在，前台一律用原图。线上由 `apps/docker-compose.yml` 注入 `https://cdn.duanju66.cc`；本地要看缩放后的效果只能用生产构建 + 一个把 `/cdn-cgi/image/*` 转给 `https://duanju66.cc` 的同源代理。
  - 排查「封面图没展示出来」：先 `curl -H "X-Service-Token: …" localhost:8080/api/v1/site-config` 看 `media.image_bases` 是否为空。接口返回的封面是**相对 key**（后台上传的图片都是，形如 `img/drama_cover/xxx.webp`），域名池为空时 `imageSources()` 拼不出地址、前台直接退到渐变占位图——不发请求、没有 404、也没有 CSP 报错，从前端查不出来。池子为空就去后台「存储设置」看顶部的交付自检。
- **admin**：容器内用 pnpm 10.34.7 安装（与现有 `pnpm-lock.yaml` 一致）；A0-5 若改用 Bun，同步修改 `compose.yaml` 中 admin 的镜像与命令。
- **mobile**：Flutter 不进容器，在宿主机 `flutter run --flavor dev --dart-define=API_SEED_HOSTS=10.0.2.2:8080`（Android 模拟器）或 `localhost:8080`（iOS 模拟器）。开发环境不传 `API_ENC_KEYS` 时从 `/api/v1/crypto/keys` 在线取公钥；正式包必须传。联调：`dart run tool/e2e_encryption.dart http://localhost:8080`。
