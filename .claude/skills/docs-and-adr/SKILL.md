# 文档与架构决策记录

## 何时更新哪份文档

| 改动 | 更新 |
| --- | --- |
| 接口 | `docs/07` + `service/api/openapi.yaml` |
| 表结构 | `docs/02`（存储相关 `docs/12` 第 7 节） |
| 后端行为 / 中间件 / 任务 | `docs/03` |
| Web / APP / 后台页面行为 | `docs/04` / `docs/05` / `docs/06` |
| 配置项、端口、本地命令 | `docs/11` 第 9 节、`.env.example` |
| 任务完成或拆分 | `docs/11` 对应行 |
| 性能 / 容灾 / 安全策略 | `docs/08` / `docs/09` / `docs/10` |

## 写法

- 描述当前状态，不写变更历史（历史在 git 里）。
- 简洁：表格和列表优先；只写读者需要的信息。
- 中文书写，标识符与命令保持原样。

## ADR

当决策影响多个模块、或以后有人会问「为什么不用 X」时，写 `docs/adr/NNNN-<标题>.md`：

```
# NNNN 标题
状态：已采纳 / 已废弃（被 NNNN 取代）
日期：YYYY-MM-DD

## 背景
## 决策
## 备选方案与放弃原因
## 影响
```

已有 ADR：`0001` 不提供找回密码、`0002` 用户端接口与视频加密、`0003` 多语言、`0004` VIP 会员与支付。可补写的决策示例：对象存储改用 SeaweedFS 做本地开发（MinIO 社区版归档）、按 IP 选线。

## 红线

- 改了行为却没更新文档
- 文档中保留与实现矛盾的旧描述
