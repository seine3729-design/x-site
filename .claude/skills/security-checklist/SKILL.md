# 安全自查

## 概述

安全要求的完整说明在 `docs/10`（加密与密钥）、`docs/09`（容灾与防护）、`docs/12` 第 9 节（存储凭据与 SSRF）。本技能是写代码时的逐项检查表。

## 输入与输出

- [ ] 所有外部输入都校验类型、长度、范围（Go 用 binding + validator；前端用 zod）
- [ ] SQL 只用占位符；排序/筛选字段走白名单
- [ ] 用户内容按纯文本输出；富文本走白名单清洗（后端 bluemonday）+ 前端 DOMPurify；自定义 HTML 只进沙箱 iframe
- [ ] 错误响应不含堆栈、SQL、内部路径

## 鉴权与会话

- [ ] 新接口默认需要鉴权；公开接口在代码里显式标注
- [ ] 后台接口经过 RBAC 中间件，权限在后端判断
- [ ] Web 与后台令牌只在 HttpOnly Cookie；写接口校验 Origin + CSRF
- [ ] 高敏操作（存储凭据、线路、API Key、管理员、配置导入）要求重新验证二次因子并记审计
- [ ] 登录、注册有限流与防枚举（统一提示、相近耗时）；不提供任何找回或重设用户密码的通道（`docs/adr/0001`）
- [ ] 用户端 `/api/v1/*` 经 `apienc` 报文加密，新增豁免必须在 `docs/10` 第 5.3 节写明理由
- [ ] 支付：到账只认验签后的渠道通知 / 查单 / 链上确认；核对金额、币种、商户号；回调幂等

## 密钥与凭据

- [ ] 代码、日志、提交、前端产物中没有密钥；本地密钥只在 `.env`（已忽略）
- [ ] 存储源凭据信封加密入库，后台只写不读；预签名用只读凭据
- [ ] 密码用 Argon2id；令牌、API Key 只存哈希；支付渠道凭据信封加密、只写不读
- [ ] 比较密钥/签名用常量时间比较

## 外部请求

- [ ] 访问用户可配置地址（自定义存储 Endpoint、线路测试、资源机）时做 SSRF 防护：只允许 https，生产禁止内网与保留地址段，解析后再校验 IP，禁止重定向到内网
- [ ] 所有外部调用有超时

## 日志与隐私

- [ ] 不记录令牌、密码、凭据、完整 IP、`Authorization`/`Cookie`/`X-Enc` 头、支付回调原文
- [ ] 不采集邮箱、手机号、硬件标识（项目明确不收集）

## 依赖

- [ ] 新依赖是维护中的知名包，版本已锁定在锁文件
- [ ] 遵守冷却期（发布不足 3 天的版本不引入）
- [ ] 没有引入 `docs/06` 已移除的依赖（axios、crypto-js 等）

## 红线

- 绕过 RBAC 或二次验证的「临时」后门
- 把凭据下发到前端或 APP
- 关闭 TLS 校验（本地 compose 内网连接除外，且只在 development）
